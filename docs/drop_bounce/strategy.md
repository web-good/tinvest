# drop_bounce — отскок после резкой красной 5m-, 15m- или часовой свечи

Бэктест-стратегия, только лонг, внутридневная. Работает на таймфреймах 5m (`-interval Minutes5`), 15m (`-interval Minutes15`) и 1h (`-interval Hour1`); другие cmd/backtest отклоняет. Правила одинаковы, у тикера на каждый таймфрейм свой литерал параметров (см. ниже). Код: `internal/service/trading_strategy/drop_bounce/strategy/core`, привязка к бэктесту — `internal/service/backtest/drop_bounce_registry.go`.

## Правила

1. **Сигнал.** Свеча таймфрейма прогона, у которой тело падает не меньше `MinDropPct` процентов: `(open − close) / open · 100 ≥ MinDropPct`. Свеча глубже `MaxDropPct` пропускается (0 — без ограничения). При `DropSeries = 1` сигналом служит и серия из `DropSeriesBars` красных свечей подряд (close < open у каждой, все в одну дату МСК), если их общее падение — от open первой до close последней — укладывается в `MinDropPct..MaxDropPct`; одиночная свеча проверяется первой. Для серии `open` в правилах ниже — open первой свечи серии, `close` — close последней.
2. **Подтверждение (опционально).** При `ConfirmBar = 1` свеча падения (или последняя свеча серии) сама вход не даёт. Сигналом служит следующая свеча, если она зелёная (close > open), закрылась выше close свечи падения и лежит в ту же дату МСК; свеча падения при этом тоже должна начинаться не раньше `StartHour:00`. Уровни берутся от свечи падения, а порог `MinTargetPct` меряется от close подтверждения — ближайшей цены, которую получит заявка. Включается в литерале тикера, по умолчанию выключено.
3. **Вход.** По open следующей свечи (`Config.EntryAtNextOpen`): по close свечи-сигнала купить нельзя, она уже закрыта. Если эта свеча открылась уже на цели или выше либо на стопе или ниже, вход отменяется (`Config.SkipFillOutsideLevels`, cmd/backtest включает его для drop_bounce): отскок уже случился, сделка заплатила бы только комиссию.
4. **Уровни.** `body = open − close` свечи-сигнала. Цель `close + TargetBody · body`, а при `TargetPct > 0` — `close · (1 + TargetPct/100)`. Стоп `close − StopBody · body`. Оба уровня считаются от close сигнала и замораживаются на позиции. При `MinTargetPct > 0` сигнал пропускается, если цель ближе `MinTargetPct` процентов к close: такая цель не окупает круг комиссии.
5. **Окно.** Только Пн–Пт МСК. Свеча-сигнал начинается не раньше `StartHour:00`, а свеча исполнения (через один шаг таймфрейма: 5 минут, 15 минут или час) — строго раньше `EODHour:EODMinute`.
6. **Выход.** По порядку: стоп (если свеча задела оба уровня — считается стоп), цель, конец дня, выход по времени. Позиция закрывается по close первой свечи, начинающейся не раньше `EODHour:EODMinute`, на первой свече новой даты или при отсутствии времени свечей. Через ночь позиция не переносится. При `TimeExit = 1` позиция, не дошедшая ни до стопа, ни до цели, закрывается по close `TimeExitBars`-й свечи удержания (свеча входа — первая), причина `TIME`.
7. **Фильтр тренда (опционально).** При `TrendEMA > 0` сигнал берётся, только если close свечи перед падением (перед первой свечой серии) выше EMA(`TrendEMA`) таймфрейма прогона на этой свече. При `TrendDailyEMA > 0` — только если close последнего завершённого дня выше дневной EMA(`TrendDailyEMA`). Если истории на EMA не хватает, сигнал пропускается. Оба выключены по умолчанию.
8. **Пауза в течение дня (опционально).** При `SkipFromHour < SkipToHour` свеча падения, начавшаяся в `[SkipFromHour:00, SkipToHour:00)` МСК, сигнала не даёт (при подтверждении проверяется свеча падения, а не подтверждения). Равные или перевёрнутые часы — пауза выключена.
9. **Без пампа перед падением (опционально).** При `PumpBars > 0` смотрятся `PumpBars` свечей перед свечой падения (перед первой свечой серии). Если среди них есть сильная зелёная свеча, сигнал пропускается: падение лишь отыгрывает недавний рост. Свеча сильная, если её тело (close − open)/open не меньше `PumpPct` процентов или не меньше `PumpRatio` тела падения; нулевой порог выключен, без обоих порогов фильтр выключен. Свечи до начала истории не проверяются.
10. Пока позиция открыта, новые сигналы игнорируются.

Исполнение в движке: стоп — по `min(стоп, open)`, цель — по `max(цель, open)`, EOD и TIME — по close свечи.

## Параметры (`core.Params`)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `MinDropPct` | 1.0 | минимальное падение тела свечи, % |
| `MaxDropPct` | 0 | максимальное падение, % (0 — без ограничения) |
| `TargetBody` | 0.5 | цель — доля тела выше close сигнала |
| `TargetPct` | 0 | цель — процент выше close сигнала вместо доли тела (0 — цель по телу) |
| `MinTargetPct` | 0 | пропустить сигнал, если цель ближе этого процента к close (0 — выключено) |
| `StopBody` | 0.5 | стоп — доля тела ниже close сигнала |
| `StartHour` | 8 | начало окна сигналов, час МСК |
| `EODHour`, `EODMinute` | 17, 0 | принудительный выход и конец окна входа |
| `TimeExit` | 0 | 1 — включить выход по времени, 0 — выключен |
| `TimeExitBars` | 3 | через сколько свечей удержания закрыть позицию (свеча входа — первая) |
| `DropSeries` | 0 | 1 — принимать серию красных свечей, 0 — только одиночная свеча |
| `DropSeriesBars` | 3 | сколько красных свечей подряд в серии |
| `ConfirmBar` | 0 | 1 — входить только после зелёной свечи, закрывшейся выше close падения; 0 — вход сразу после падения |
| `TrendEMA` | 0 | период EMA таймфрейма прогона: падение берётся, только если перед ним цена выше EMA (0 — выключено) |
| `TrendDailyEMA` | 0 | период дневной EMA: падение берётся, только если вчерашний close выше неё (0 — выключено) |
| `SkipFromHour`, `SkipToHour` | 0, 0 | пауза сигналов: свечи падения с `SkipFromHour:00` до `SkipToHour:00` МСК пропускаются (from ≥ to — выключено) |
| `PumpBars` | 0 | сколько свечей перед падением проверять на сильную зелёную свечу (0 — выключено) |
| `PumpPct` | 0 | зелёная свеча с телом ≥ `PumpPct`% блокирует сигнал (0 — порог выключен) |
| `PumpRatio` | 0 | зелёная свеча с телом ≥ `PumpRatio` × тело падения блокирует сигнал (0 — порог выключен) |

Литерал задаётся на таймфрейм: пакет тикера `internal/service/trading_strategy/drop_bounce/strategy/<ticker>/` экспортирует `DefaultParams5m()`, `DefaultParams15m()` и `DefaultParams1h()` (для тех таймфреймов, где он откалиброван), регистрация — `dropBounceRegistry` в `internal/service/backtest/drop_bounce_registry.go` (тикер → таймфрейм → литерал). Если у тикера нет литерала для таймфрейма прогона, берётся `core.DefaultParams`; литерал другого таймфрейма не подставляется — пороги и счёт свечей на разных таймфреймах значат разное. Таймфрейм влияет на код ядра только через шаг свечи в окне входа (`core.NewWithStep`), остальные правила считают свечи. JSON из `-params` / `-calibrate` частично переопределяет поля поверх этих значений. Сетки тикера — `data/params/drop_bounce/<ticker>/`.

## Запуск

```
go run ./cmd/backtest -ticker GAZP -strategy drop_bounce -interval Minutes5 -months 12
go run ./cmd/backtest -ticker GAZP -strategy drop_bounce -interval Minutes15 -months 12
go run ./cmd/backtest -ticker GAZP -strategy drop_bounce -interval Hour1 -months 12
```

Калибровка — штатная сетка `-calibrate <grid.json>` по полям `Params`; сетка накладывается на литерал таймфрейма из `-interval`.
