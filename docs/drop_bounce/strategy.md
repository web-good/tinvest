# drop_bounce — часовой RSI над EMA, вход по MACD на 30m

Бэктест-стратегия, только лонг. Прогон **только на 30m** (`-interval Minutes30`, другие cmd/backtest отклоняет): сигнал ищется на часовом таймфрейме, а для точного входа стратегия переходит на 30m и ждёт подтверждения MACD. Позиция может переноситься через ночь и выходные. Код: `internal/service/trading_strategy/drop_bounce/strategy/core`, привязка к бэктесту — `internal/service/backtest/drop_bounce_registry.go`. Исходная спека 1h-версии: `docs/superpowers/specs/2026-10-13-drop-bounce-h1-rsi-ema-design.md`. 2026-10-14 владелец перевёл стратегию на схему «сигнал 1h → подтверждение 30m»: окна покупки, гейт хода дня, выходы MACD и FRI убраны; в пятницу покупка только до 11:00. Прежние версии — в git.

## Часовые свечи

Часы стратегия собирает сама из 30m свечей окна (`hourBars`): close часа — close его последней 30m свечи. Час считается закрытым на закрытии своей свечи :30, а если её нет в данных — на первой свече более позднего часа. Формирующийся час в расчёт не идёт. Так сигнал виден ровно в момент закрытия часа, без задержки на следующую свечу и без заглядывания вперёд.

## Вход

1. **Сигнал на часе** — на только что закрытом часе, все условия вместе:
   - **тренд:** close часа строго выше EMA(`EMAPeriod`) часовых close; пока EMA не прогрелась, сигнала нет;
   - **зона RSI** (часовой `RSI(RSIPeriod)`, Уайлдер), одна из веток: **ZONE** — `RSI < RSIZone` (только при `ZoneEntry = 1`); **CROSS** — RSI пересёк `RSIZone` снизу вверх на этом часе (`prev < RSIZone ≤ cur`) и `cur ≤ RSICap`.
2. **Взвод:** сигнал взводит вход на `ConfirmBars` 30m свечей, начиная со свечи, закрывшей сигнальный час. Не подтвердился за это время — сгорает. Если в окне закрылся ещё один сигнальный час, действует его окно.
3. **Подтверждение на 30m:** гистограмма MACD(`MACDFast`, `MACDSlow`, `MACDSignal`) по 30m close (линия MACD − сигнальная) зелёная (`≥ 0`; ровно 0 — зелёная). Уже зелёная на свече взвода — вход сразу; иначе ждём перекраски красная → зелёная. Если гистограмма была зелёной раньше в окне и вход не состоялся, повторно он только после новой перекраски. Без гистограммы (неверные периоды) входов нет.
4. **Будни:** свеча покупки (следующая 30m) — Пн–Пт МСК, в ту же дату, что свеча подтверждения. В пятницу свеча покупки должна начаться раньше `FridayTo`:00 (по умолчанию 11:00: покупка в 10:30 ещё можно, в 11:00 уже нет). Других ограничений по времени нет.
5. **Дневной ATR посчитан** и стоп от close подтверждающей свечи выше нуля.
6. **Настоящее падение** (только при `PrevCloseGate = 1`, по умолчанию выключено): close подтверждающей свечи не выше close последней завершённой будничной дневки + `PrevCloseATR` дневных ATR (в понедельник — пятничный close, выходные сессии пропускаются, как в ATR). Отрицательный `PrevCloseATR` требует падения на столько ATR. Нет дневок — входа нет.
7. **Пол RSI** (только при `RSIFloor > 0`, по умолчанию выключено): RSI сигнального часа не ниже `RSIFloor` — слишком глубокая перепроданность означает обвал, а не откат.
8. **Без понедельника** (только при `SkipMonday = 1`, по умолчанию выключено): свеча покупки не в понедельник МСК — выходные копят новости, и понедельник открывается гэпом.

Покупка по open следующей 30m свечи (`Config.EntryAtNextOpen`), `FillBy = время свечи + 30m`: нет этой свечи в данных — сигнал отброшен. Пока позиция открыта, сигналы игнорируются.

Сигнал покупки несёт стоп `close − StopDailyATR · ATR` (`Signal.StopLoss`) — только для размера позиции по риску (`cmd/backtest -risk-pct N`: стоп-аут стоит N% капитала, позиция не больше наличных). Выходы меряют стоп от цены исполнения, расхождение — разница open следующей свечи и close сигнальной.

Дневной ATR — Уайлдер `DailyATRPeriod` по завершённым дневкам Пн–Пт (выходные сессии отброшены: они в разы уже и занижают ATR). Он уходит в сигнал (`Signal.ATR`), движок замораживает его на позицию (`Position.EntryATR`).

## Выход

По приоритету на каждой 30m свече:

1. **SL** — внутри свечи: `low ≤ вход − StopDailyATR · ATR`, ATR замороженный на сигнале (если позиция его не несёт — сегодняшний). Движок исполняет по `min(стоп, open)`, так что ночной гэп ниже стопа закрывается по open. `StopDailyATR = 0` выключает стоп.
2. **BE / TRAIL** — внутри свечи, если `BreakevenATR > 0`: когда high какой-нибудь уже закрытой свечи с покупки дошёл до `вход + BreakevenATR · ATR`, стоп поднимается на цену входа (`BE`), а при `TrailATR > 0` — на `лучший high − TrailATR · ATR`, если это выше входа (`TRAIL`). High текущей свечи её же стоп не взводит: порядок high и low внутри свечи неизвестен. Исполнение по `min(стоп, open)`. По умолчанию `BreakevenATR` 0.5 (владелец 2026-10-14: на окне разработки улучшил PF у GAZP, ENPG и IVAT), трейлинг выключен.
3. **RSI** — на свече, закрывшей час: часовой RSI(`RSIExitPeriod`) пересёк `RSIExit` снизу вверх на этом часе. Продаёт по close этой свечи при любой цене, причина `RSI`. Час должен закончиться не раньше входа (его последняя 30m свеча начинается не раньше времени входа), иначе крест до покупки продал бы позицию. `RSIExit = 0` или `RSIExitPeriod = 0` выключает выход.
4. **STALE** — на close, если `StaleBars > 0`: позиция держится `StaleBars` 30m свечей и ни один high с исполнения не дотянулся до `вход + StaleATR · ATR`. По умолчанию выключен.

Выхода в конце дня нет.

## Параметры

| поле | по умолчанию | смысл |
|---|---|---|
| `RSIPeriod` | 6 | длина часового RSI входа; 0 — входов нет |
| `RSIZone` | 30 | уровень перепроданности: ZONE ниже, CROSS через него вверх |
| `RSICap` | 50 | CROSS засчитывается, только если RSI на часе креста ≤ этого |
| `ZoneEntry` | 1 | 1 — ветка ZONE взводит вход; 0 — только CROSS |
| `EMAPeriod` | 200 | EMA тренда на часовых close; 0 — входов нет |
| `StopDailyATR` | 1.0 | стоп ниже цены входа в дневных ATR; 0 — выключен |
| `BreakevenATR` | 0.5 | ход в дневных ATR над входом, после которого стоп переносится в безубыток; 0 — выключен |
| `TrailATR` | 0 | после безубытка стоп тянется за лучшим high на этом расстоянии в ATR; 0 — стоп остаётся на входе |
| `DailyATRPeriod` | 14 | длина дневного ATR Уайлдера по будним дням |
| `RSIExitPeriod` | 10 | длина часового RSI выхода; 0 — RSI-выход выключен |
| `RSIExit` | 70 | уровень креста часового RSI выхода вверх; 0 — выключен |
| `MACDFast` / `MACDSlow` / `MACDSignal` | 12 / 26 / 9 | MACD на 30m close, подтверждающий вход |
| `ConfirmBars` | 3 | сколько 30m свечей ждать зелёной гистограммы после сигнала (полтора часа); 0 — входов нет |
| `FridayTo` | 11 | в пятницу покупка только на свече, начавшейся раньше этого часа МСК; 24 — без ограничения, 0 — по пятницам не покупать |
| `StaleBars` | 0 | выход по времени STALE в 30m свечах; 0 — выключен |
| `StaleATR` | 0.3 | ход в дневных ATR над входом, который снимает выход STALE |
| `PrevCloseGate` | 0 | 1 — покупка только при close сигнала не выше вчерашнего будничного close + `PrevCloseATR`; 0 — выключено |
| `PrevCloseATR` | 0 | допуск над вчерашним close в дневных ATR; отрицательный — требуемое падение |
| `RSIFloor` | 0 | сигнальный час с RSI ниже пола не взводит вход; 0 — выключено |
| `SkipMonday` | 0 | 1 — не покупать в понедельник (дата свечи покупки, МСК); 0 — выключено |

`Lookback = max(2 · (max(64, 3 · EMAPeriod, 4 · RSIPeriod + 2, 4 · RSIExitPeriod + 2) + 1), 3 · (MACDSlow + MACDSignal) + ConfirmBars + 1)` 30m свечей — при EMA 200 это 1202.

## Калибровка

Один перебор по схеме hold-out (первые 30 из 36 месяцев, точка — центр плато, стресс, hold-out один раз): `RSIPeriod` × `RSIExitPeriod` × `StopDailyATR`, остальное — дефолты ядра. Списки значений и процедура — скилл `drop-bounce-calibrate`; стартовая сетка — `data/params/drop_bounce/grid_example.json`.

## Пакеты тикеров

Реестр `dropBounceRegistry` держит по одному литералу `Params()` на тикер, заведённый калибровкой на этих правилах; тикер без пакета работает на `core.DefaultParams()`; JSON `-params` / `-calibrate` ложится поверх. Поля прежних правил (`VolDailyMult`, `VolAvgPeriod`; до 2026-10-14 — `DaySpentATR`, `StartHour`, окна `MorningFrom/To`, `EveningFrom/To`) в файле `-params` молча игнорируются (прогон идёт на дефолтах), а сетка `-calibrate` с таким полем падает с ошибкой `unknown grid field`.

Кандидатов на калибровку подбирает скринер `cmd/dropscreen` — `docs/drop_bounce/screener.md`.

## Вселенная для live

Живого раннера пока нет; вселенная под него — `DROP_BOUNCE_TICKERS_M30` (`config.DropBounceConfig`). Список ведёт скилл `drop-bounce-calibrate` (`scripts/live_env.py`). Тест `TestDropBounceLiveTickersAreRegistered` требует, чтобы каждый тикер из `env/prod.env` имел пакет в `dropBounceRegistry`.

## Запуск

```bash
go run ./cmd/backtest -strategy drop_bounce -interval Minutes30 -ticker GAZP -months 36
go run ./cmd/backtest -strategy drop_bounce -interval Minutes30 -ticker GAZP -months 36 \
  -calibrate data/params/drop_bounce/grid_example.json -metric profit_factor
# почему на свече был (или не был) вход/выход: каждое условие со значением и ✓/✗, в конце — итог Decide
go run ./cmd/backtest -strategy drop_bounce -interval Minutes30 -ticker GAZP -months 36 -explain "2026-09-03 12:30"
```
`-explain` берёт время начала свечи по МСК и те же параметры, что обычный прогон (литерал тикера или `-params`).
Для калибровочных прогонов — собранный бинарь на одном ядре (см. скилл `drop-bounce-calibrate`).
