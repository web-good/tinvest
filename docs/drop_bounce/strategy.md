# drop_bounce — часовой RSI над EMA, вход по MACD 1h и 15m

Бэктест-стратегия, только лонг. Прогон **только на 15m** (`-interval Minutes15`, другие cmd/backtest отклоняет): сигнал ищется на часовом таймфрейме, затем ждёт зелёный MACD на часе, а для точного входа переходит на 15m и ждёт подтверждения MACD там. Позиция может переноситься через ночь и выходные. Код: `internal/service/trading_strategy/drop_bounce/strategy/core`, привязка к бэктесту — `internal/service/backtest/drop_bounce_registry.go`. Исходная спека 1h-версии: `docs/superpowers/specs/2026-10-13-drop-bounce-h1-rsi-ema-design.md`. 2026-10-14 владелец перевёл стратегию на схему «сигнал 1h → подтверждение 30m»: окна покупки, гейт хода дня, выходы MACD и FRI убраны; в пятницу покупка только до 11:00. 2026-10-15 владелец убрал безубыток, трейлинг и все выключенные фильтры (STALE, «настоящее падение», пол RSI, без понедельника, запас над EMA, только сразу зелёная MACD, выключатель MACD, подтверждение движением, часовой MACD): ни один не подтвердился на проверке. Затем, тоже 2026-10-15, владелец перевёл стратегию на 15m и поставил между сигналом и младшим MACD часовой MACD(8,26,5). Прежние версии — в git.

## Часовые свечи

Часы стратегия собирает сама из 15m свечей окна (`hourBars`): close часа — close его последней 15m свечи. Час считается закрытым на закрытии своей свечи :45, а если её нет в данных — на первой свече более позднего часа. Формирующийся час в расчёт не идёт. Так сигнал виден ровно в момент закрытия часа, без задержки на следующую свечу и без заглядывания вперёд.

## Вход

1. **Сигнал на часе** — на только что закрытом часе, все условия вместе:
   - **тренд:** close часа строго выше EMA(`EMAPeriod`) часовых close; пока EMA не прогрелась, сигнала нет;
   - **зона RSI** (часовой `RSI(RSIPeriod)`, Уайлдер), одна из веток: **ZONE** — `RSI < RSIZone` (только при `ZoneEntry = 1`); **CROSS** — RSI пересёк `RSIZone` снизу вверх на этом часе (`prev < RSIZone ≤ cur`) и `cur ≤ RSICap`.
2. **Часовой MACD:** после сигнала ждём час, на котором гистограмма MACD(`HourMACDFast`, `HourMACDSlow`, `HourMACDSignal`) = (8, 26, 5) по часовым close зелёная (`≥ 0`). Берётся первый зелёный час не позже `HourMACDHours` (20) часов после последнего сигнального часа; если гистограмма зелёная уже на сигнальном часе — он сам. Новый сигнальный час во время ожидания начинает отсчёт заново. Зелёный час, перед которым гистограмма уже была зелёной, вход не взводит. Без гистограммы (неверные периоды) входов нет.
3. **Подтверждение на 15m:** зелёный час взводит вход на `ConfirmBars` (6) 15m свечей, начиная со свечи, закрывшей этот час. Гистограмма MACD(`MACDFast`, `MACDSlow`, `MACDSignal`) по 15m close зелёная (`≥ 0`; ровно 0 — зелёная): уже зелёная на свече взвода — вход сразу; иначе ждём перекраски красная → зелёная. Не подтвердилось за окно — взвод сгорает. Без гистограммы входов нет.
4. **Будни:** свеча покупки (следующая 15m) — Пн–Пт МСК, в ту же дату, что свеча подтверждения. В пятницу свеча покупки должна начаться раньше `FridayTo`:00 (по умолчанию 11:00: покупка в 10:45 ещё можно, в 11:00 уже нет). Других ограничений по времени нет.
5. **Дневной ATR посчитан** и стоп от close подтверждающей свечи выше нуля.

Покупка по open следующей 15m свечи (`Config.EntryAtNextOpen`), `FillBy = время свечи + 15m`: нет этой свечи в данных — сигнал отброшен. Пока позиция открыта, сигналы игнорируются.

Сигнал покупки несёт стоп `close − StopDailyATR · ATR` (`Signal.StopLoss`) — только для размера позиции по риску (`cmd/backtest -risk-pct N`: стоп-аут стоит N% капитала, позиция не больше наличных). Выходы меряют стоп от цены исполнения, расхождение — разница open следующей свечи и close сигнальной.

Дневной ATR — Уайлдер `DailyATRPeriod` по завершённым дневкам Пн–Пт (выходные сессии отброшены: они в разы уже и занижают ATR). Он уходит в сигнал (`Signal.ATR`), движок замораживает его на позицию (`Position.EntryATR`).

## Выход

По приоритету на каждой 15m свече:

1. **SL** — внутри свечи: `low ≤ вход − StopDailyATR · ATR`, ATR замороженный на сигнале (если позиция его не несёт — сегодняшний). Движок исполняет по `min(стоп, open)`, так что ночной гэп ниже стопа закрывается по open. `StopDailyATR = 0` выключает стоп.
2. **RSI** — на свече, закрывшей час: часовой RSI(`RSIExitPeriod`) пересёк `RSIExit` снизу вверх на этом часе. Продаёт по close этой свечи при любой цене, причина `RSI`. Час должен закончиться не раньше входа (его последняя 15m свеча начинается не раньше времени входа), иначе крест до покупки продал бы позицию. `RSIExit = 0` или `RSIExitPeriod = 0` выключает выход.

Стоп не переносится: ни безубытка, ни трейлинга. Выхода в конце дня нет.

## Параметры

| поле | по умолчанию | смысл |
|---|---|---|
| `RSIPeriod` | 6 | длина часового RSI входа; 0 — входов нет |
| `RSIZone` | 30 | уровень перепроданности: ZONE ниже, CROSS через него вверх |
| `RSICap` | 50 | CROSS засчитывается, только если RSI на часе креста ≤ этого |
| `ZoneEntry` | 1 | 1 — ветка ZONE взводит вход; 0 — только CROSS |
| `EMAPeriod` | 200 | EMA тренда на часовых close; 0 — входов нет |
| `StopDailyATR` | 1.0 | стоп ниже цены входа в дневных ATR; 0 — выключен |
| `DailyATRPeriod` | 14 | длина дневного ATR Уайлдера по будним дням |
| `RSIExitPeriod` | 10 | длина часового RSI выхода; 0 — RSI-выход выключен |
| `RSIExit` | 70 | уровень креста часового RSI выхода вверх; 0 — выключен |
| `HourMACDFast` / `HourMACDSlow` / `HourMACDSignal` | 8 / 26 / 5 | MACD на часовых close, чья зелёная гистограмма взводит вход после сигнала |
| `HourMACDHours` | 20 | сколько часов после последнего сигнального часа ждать зелёный часовой MACD; 0 — только если зелёный уже сигнальный час |
| `MACDFast` / `MACDSlow` / `MACDSignal` | 12 / 26 / 9 | MACD на 15m close, подтверждающий вход |
| `ConfirmBars` | 6 | сколько 15m свечей после закрытия зелёного часа ждать зелёной гистограммы 15m (полтора часа); 0 — входов нет |
| `FridayTo` | 11 | в пятницу покупка только на свече, начавшейся раньше этого часа МСК; 24 — без ограничения, 0 — по пятницам не покупать |

`Lookback = max(4 · (max(64, 3 · EMAPeriod, 4 · RSIPeriod + 2, 4 · RSIExitPeriod + 2, 3 · (HourMACDSlow + HourMACDSignal)) + HourMACDHours + 1), 3 · (MACDSlow + MACDSignal) + ConfirmBars + 1)` 15m свечей — при EMA 200 это 2484.

## Калибровка

Один перебор по схеме hold-out (первые 30 из 36 месяцев, точка — центр плато, стресс, hold-out один раз): `RSIPeriod` × `RSIExitPeriod` × `StopDailyATR`, остальное — дефолты ядра. Списки значений и процедура — скилл `drop-bounce-calibrate`; стартовая сетка — `data/params/drop_bounce/grid_example.json`.

## Пакеты тикеров

Реестр `dropBounceRegistry` держит по одному литералу `Params()` на тикер, заведённый калибровкой на этих правилах; тикер без пакета работает на `core.DefaultParams()`; JSON `-params` / `-calibrate` ложится поверх. Поля прежних правил (`VolDailyMult`, `VolAvgPeriod`; до 2026-10-14 — `DaySpentATR`, `StartHour`, окна `MorningFrom/To`, `EveningFrom/To`) в файле `-params` молча игнорируются (прогон идёт на дефолтах), а сетка `-calibrate` с таким полем падает с ошибкой `unknown grid field`.

Кандидатов на калибровку подбирает скринер `cmd/dropscreen` — `docs/drop_bounce/screener.md`.

## Вселенная для live

Живого раннера пока нет; вселенная под него — `DROP_BOUNCE_TICKERS_M30` (`config.DropBounceConfig`). Список ведёт скилл `drop-bounce-calibrate` (`scripts/live_env.py`). Тест `TestDropBounceLiveTickersAreRegistered` требует, чтобы каждый тикер из `env/prod.env` имел пакет в `dropBounceRegistry`.

## Запуск

```bash
go run ./cmd/backtest -strategy drop_bounce -interval Minutes15 -ticker GAZP -months 36
go run ./cmd/backtest -strategy drop_bounce -interval Minutes15 -ticker GAZP -months 36 \
  -calibrate data/params/drop_bounce/grid_example.json -metric profit_factor
# почему на свече был (или не был) вход/выход: каждое условие со значением и ✓/✗, в конце — итог Decide
go run ./cmd/backtest -strategy drop_bounce -interval Minutes15 -ticker GAZP -months 36 -explain "2026-09-03 12:30"
```
`-explain` берёт время начала свечи по МСК и те же параметры, что обычный прогон (литерал тикера или `-params`).
Для калибровочных прогонов — собранный бинарь на одном ядре (см. скилл `drop-bounce-calibrate`).
