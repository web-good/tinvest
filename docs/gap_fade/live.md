# gap_fade: живой раннер

Справочник по живому запуску стратегии `gap_fade`. Саму стратегию (вход, цель, стоп, выходы,
гейт) описывает [strategy.md](strategy.md); подбор тикеров — [screener.md](screener.md).
Здесь только то, чем прод отличается от бэктеста, и как раннер делит счёт с `rsi_pullback`
и `rsi_zone`.

## 1. Что делает

`gap_fade` не имеет собственного раннера: это **гость раннера счёта `rsi_pullback`**, третий
адаптер после `rsi_zone`. Общая механика — расписание, guard протухшего бара, сборка данных,
файл стейта, биржевые стоп-заявки, grace свежей позиции, `pendingExit`, реконструкция —
описана в [../rsi_pullback/live.md](../rsi_pullback/live.md) §§1–7; совместная работа
стратегий на одном счёте — в [../rsi_zone/live.md](../rsi_zone/live.md) §2. Здесь не
дублируется.

Код: `internal/service/trading_strategy/gap_fade/live` (адаптер `strategy.go`, реестр
`registry.go`), литерал параметров — `internal/service/trading_strategy/gap_fade/strategy/shared`.

## 2. Общий счёт

- **Порядок адаптеров** `[rsi_pullback, rsi_zone, gap_fade]`. При BUY двух стратегий на одном
  баре входит старшая.
- **Занятый тикер закрыт.** Пока позиция тикера открыта (любой стратегией), `gap_fade` по нему
  не входит.
- **Тикер вне вселенной.** Реестр отдаёт общий литерал любому непустому тикеру, поэтому
  позиция тикера, убранного из `GAP_FADE_TICKERS`, ведётся до выхода; новых входов нет —
  их ограничивает вселенная, а не реестр.
- **Позиция без стейта и неизвестный владелец** — правила `rsi_zone/live.md` §2. Пример
  ручной разметки записи `gap_fade` в `data/state/rsi_pullback_<accountID>.json`:

  ```json
  "SBER": {
    "ticker": "SBER",
    "strategy": "gap_fade",
    "entryTime": "2026-10-01T07:01:00+03:00",
    "entryPrice": 100.0,
    "entryATR": 2.0,
    "takeProfit": 101.5,
    "stopLoss": 98.0,
    "maxFav": 100.0,
    "quantity": 10
  }
  ```

  `stopLoss` — замороженный уровень стопа, `takeProfit` — замороженная цель (0 — без цели).

## 3. Параметры

Один литерал на все тикеры вселенной:

| Поле | Значение |
|---|---|
| `GapATR` | 0.7 |
| `MaxGapATR` | 3.0 |
| `EntryBar` | 0 |
| `TargetFill` | 0.75 |
| `StopDailyATR` | 1.0 |
| `DailyATRPeriod` | 14 |
| `EODHour:EODMinute` | 18:30 |

Калибровки по тикерам нет. Литерал меняется только вместе со сторожевым тестом реестра,
который сверяет его с этой таблицей.

## 4. Тайминг входа

Сигнал — close бара 06:30 MSK (бар 0 дня, вмещает открывающий аукцион). Пасс в 07:01 видит его
закрытым и покупает рыночным ордером: это live-аналог `EntryAtNextOpen` (покупка по open бара
07:00). Расписание `RSI_PULLBACK_SCHEDULE` (`1,31 6-23 * * *`) уже содержит 07:01.

**Окно входа.** Пасс собирает `MarketData` отдельно на каждую стратегию тикера, а вселенная
`gap_fade` сильно пересекается с вселенной `rsi_pullback`; без ограничения каждый пасс тянул бы
свечи ещё по каждому такому тикеру, хотя `gap_fade` входит только утром. Адаптер реализует
необязательный `adapter.EntryWindow`: `EntryPossible(now)` истинно в будний день MSK, пока время
пасса строго раньше 10:00 MSK. Вне окна по свободному тикеру данные не собираются и стратегия не
спрашивается. Сопровождение открытых позиций окно не трогает.

## 5. Стоп и выходы

Стоп заморожен от close сигнального бара: `stopLoss = close − StopDailyATR·ATR`, пишется в
`Entry.StopLoss` при входе и не меняется. Стоп-заявка — общая биржевая GTC; `DesiredStop`
возвращает `(StopLoss, "SL")`, при нулевом `StopLoss` стопа нет. Цель `TakeProfit` тоже
замораживается при входе: `close + TargetFill·(prevClose − close)`.

| Выход | Механизм |
|---|---|
| SL | биржевая стоп-заявка |
| TP | рыночный SELL на пассе после бара с `high ≥ цели` |
| EOD | рыночный SELL на пассе 19:01 после бара 18:30 |
| новая дата | первый бар новой даты закрывает позицию (ядро, fail-closed) |

Цель рыночная, а не лимитной заявкой: вторая живая SELL-заявка на той же позиции без OCO
опасна (две заявки на одно количество), а продажа по open следующего бара по замеру не хуже
внутрибарной цели бэктеста. Отказ брокера на продаже ловит общий `pendingExit`.

## 6. Дивидендная отсечка

Бэктест выбрасывает сделки дня отсечки: гэп там — дивиденд, а не шум. Live обязан не входить.
Адаптер реализует необязательный `adapter.EntryFilter` (`EntryBlocked`); пасс зовёт его после
BUY-сигнала и до сайзинга.

- Запрос `GetDividends` идёт только на BUY-сигнал, за окно `[время последнего бара − 30 дней,
  время последнего бара + 7 дней]`.
- День отсечки определяет `svc.GapDividendExDays` — функция, общая с `cmd/gapwf`: отменённые
  дивиденды пропускаются, день отсечки — первый бар после `last_buy_date`, без неё — дата
  реестра. Вход блокируется, если дата последнего бара — день отсечки.
- Непустая причина — вход пропущен, уведомление в тему стратегии. **Fail-closed:** при ошибке
  API вход тоже пропущен, алерт в тему стратегии и ERROR-лог.
- Бар не расходуется: следующая по приоритету стратегия на нём спрашивается.

Сверка `pullparity` фильтр не вызывает.

## 7. Реконструкция позиции без стейта

По образцу `rsi_zone`: `EntryTime` — последняя BUY за 180 дней, `EntryPrice` — средняя цена
брокера, `EntryATR` — дневной ATR на дату входа. `StopLoss = EntryPrice − StopDailyATR·EntryATR`
(close сигнального бара неизвестен — приближение ценой входа); `TakeProfit = 0`;
`MaxFav = EntryPrice`. Нулевой ATR — ошибка. Позиция без цели всё равно закрывается EOD или
первым баром новой даты.

## 8. Бумажный режим

Правила те же, что у `rsi_zone`: [../rsi_zone/live.md](../rsi_zone/live.md) §4.

## 9. Конфигурация

Счёт, токен и расписание общие с `rsi_pullback`. Ни одна переменная не `required`.

| Переменная | Дефолт | Смысл |
|---|---|---|
| `GAP_FADE_TICKERS` | `""` | вселенная входов; пусто — стратегия не подключается |
| `GAP_FADE_BUY_PCT` | `5` | доля полной стоимости счёта на сделку, затем ограничение кэшем |
| `GAP_FADE_TRADE_ENABLED` | `false` | ордера и стоп-заявки уходят на биржу |
| `GAP_FADE_NOTIFY_ENABLED` | `false` | уведомления в Telegram |
| `TELEGRAM_TOPIC_GAP_FADE` | — | тема форума; не задана — сообщения идут в General |

Сообщения гостя идут с префиксом «[Gap Fade] » в тему `TELEGRAM_TOPIC_GAP_FADE`.

## 10. Пауза

`GAP_FADE_BUY_PCT=0` при включённой торговле останавливает новые входы с сопровождением: каждый
BUY уходит пропуском по сайзингу в тему стратегии, открытые позиции ведутся как обычно. Остальные
способы (`GAP_FADE_TRADE_ENABLED=false`, пустой `GAP_FADE_TICKERS`) и их цена для открытых
позиций — как у `rsi_zone`, см. «Пауза стратегии» в [../rsi_zone/live.md](../rsi_zone/live.md).

## 11. Сверка с бэктестом

```bash
go run ./cmd/pullparity -strategy gap_fade -tickers <GAP_FADE_TICKERS> -months 24
```

Для каждого бара сравнивается живая сборка `MarketData` с сборкой движка и вердикт `Decide`.
Приёмка — **ноль расхождений** по всей вселенной до выката.

## 12. Порядок выката

1. `pullparity -strategy gap_fade` — ноль расхождений.
2. Прод: `GAP_FADE_TRADE_ENABLED=false`, `GAP_FADE_NOTIFY_ENABLED=true`, заведена тема Telegram.
3. Сверка бумажных сигналов с бэктестом на тех же датах.
4. Решение владельца о торговле и `GAP_FADE_BUY_PCT` под общий счёт.

## 13. Пограничные случаи

- Тикер без вечерней сессии: SELL в 19:01 отклонён — `pendingExit`, повтор на следующих
  пассах; стоп-заявка GTC защищает позицию через ночь.
- Нет дневного ATR (короткая история) — ядро не входит.
- Сбой `GetDividends` — вход не делается (§6).
