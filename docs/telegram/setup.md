# Telegram: ручная настройка форум-группы и тем

Код маршрутизации уведомлений по темам и команд бота уже в `main`
(спека: `docs/superpowers/specs/2026-07-13-telegram-topic-routing-design.md`).
Чтобы всё заработало, нужно один раз выполнить шаги ниже руками — создать
группу, темы и заполнить переменные окружения.

Пока переменные не заполнены, приложение не упадёт: при `TELEGRAM_TOPIC_* = 0`
сообщения уходят в General с предупреждением в логе.

## 1. Создать супергруппу с темами

1. В Telegram создать новую группу.
2. Открыть настройки группы → включить **«Темы» (Topics)** — группа станет
   форум-супергруппой.
3. Добавить бота в группу и назначить его **администратором**. Специальное
   право «Manage topics» не требуется — боту достаточно публиковать сообщения,
   это право есть у любого админа.

## 2. Создать темы

Создать две темы (названия произвольные, важны только их ID):

- **Golden X** — сигналы стратегии Golden X;
- **Reversion** — сигналы и события live-стратегии Reversion.

Тема **General** создаётся Telegram автоматически — туда идут системные
сообщения, ошибки и фолбэк при недоступной теме. Отдельно её настраивать
не нужно.

## 3. Узнать ID группы и тем

1. В каждой теме отправить любое сообщение.
2. Нажать на сообщение → **«Копировать ссылку»**. Ссылка имеет вид:

   ```
   https://t.me/c/<internal_id>/<thread_id>/<msg_id>
   ```

3. Из ссылки взять:
   - `TELEGRAM_GROUP_CHAT_ID` = `-100<internal_id>` (например, для
     `t.me/c/2345678901/5/17` это `-1002345678901`);
   - `<thread_id>` — ID темы (`message_thread_id`), в примере выше — `5`.

Для сообщения в General ссылка без `<thread_id>` — это нормально, его ID
нигде указывать не нужно.

## 4. Заполнить переменные окружения

В `env/local.env` (dev) и `env/prod.env` (prod):

```env
# Telegram forum supergroup (ID вида -100XXXXXXXXXX) и ID тем (message_thread_id)
TELEGRAM_GROUP_CHAT_ID=-1002345678901
TELEGRAM_TOPIC_GOLDEN_X=5
TELEGRAM_TOPIC_REVERSION=7
```

Токен бота — как раньше, в переменной `TELEGRAM`.

## 5. Whitelist пользователей для команд

Команды бота принимает только whitelist по Telegram user ID. Список задан
в коде: `internal/config/telegram_client.go`, поле `AllowedUserIDs` в
`NewTelegramClientConfig()`. Чтобы добавить/убрать пользователя — поправить
список и пересобрать. Узнать свой user ID можно, например, через бота
`@userinfobot`. Команды от посторонних пользователей игнорируются молча.

## 6. Проверка

1. Запустить приложение в dev-режиме: `go run ./cmd/main`.
2. В логе должна появиться строка `telegram commands listener started`
   и не должно быть предупреждений `telegram topic id is not set`.
3. В группе отправить `/help` — бот отвечает списком команд.
4. Отправить `/yield` **внутри любой темы** — ack «⏳ Считаю…» и отчёт
   должны прийти **в ту же тему**, откуда вызвана команда.

Доступные команды:

| Команда | Что делает |
|---|---|
| `/bonds_portfolio` | распределение облигаций в портфеле |
| `/yield` | доходность портфеля YTD (XIRR) |
| `/bonds_screener` | скринер облигаций к покупке |
| `/help`, `/start` | список команд |

Повторный вызов команды, пока предыдущий расчёт не закончился, получает
ответ «⏳ уже выполняется» — это защита от параллельных дублей, не ошибка.

## Если что-то пошло не так

- **Сообщения стратегий приходят в General, а не в тему** — проверить, что
  `TELEGRAM_TOPIC_*` заполнены и совпадают с `thread_id` из ссылок (шаг 3);
  в логе при старте будет предупреждение `telegram topic id is not set`.
- **Сообщение пришло в General с префиксом «⚠️ тема N недоступна»** — тема
  с таким ID удалена или закрыта; сработал фолбэк, сигнал не потерян.
  Пересоздать тему и обновить ID в env.
- **Бот не отвечает на команды** — убедиться, что ваш user ID есть в
  `AllowedUserIDs` (шаг 5) и что запущен именно один экземпляр приложения
  (два инстанса конкурируют за long-polling `getUpdates`).
