# rsi_zone: живой раннер

Справочник по живому запуску стратегии `rsi_zone`. Саму стратегию (вход, выходы, параметры,
калибровка) описывает [strategy.md](strategy.md); подбор тикеров — [screener.md](screener.md).
Здесь только то, чем прод отличается от бэктеста, и как раннер делит счёт с `rsi_pullback`.

Код: `internal/service/trading_strategy/rsi_zone/live` (адаптер `strategy.go`, реестр тикеров
`registry.go`, восстановление стейта). Раннер, пасс и интерфейс адаптера —
`internal/service/trading_strategy/rsi_pullback/live` и `livecore/adapter`.

## 1. Что делает

`rsi_zone` не имеет собственного раннера: это **гость раннера счёта `rsi_pullback`**. Один
процесс, один пасс раз в полчаса, несколько стратегий-адаптеров. Общая механика — расписание,
guard протухшего бара, сборка данных, файл стейта, биржевые стоп-заявки, grace свежей
позиции, `pendingExit`, реконструкция стейта, пограничные случаи — описана в
[../rsi_pullback/live.md](../rsi_pullback/live.md) §§1–7 и здесь не дублируется. Дальше — только
то, что относится к `rsi_zone` и к совместной работе на одном счёте.

Почему один раннер, а не два: два независимых раннера на одном счёте срабатывают в одну
минуту и могут купить один тикер на одном баре, а пасс, рассуждающий по инструменту (снятие
«чужой» стоп-заявки, реконсиляция количества, восстановление входа по последней BUY),
ломал бы позиции друг друга.

## 2. Общий счёт

- **Владение тикером.** В записи стейта есть поле `strategy` — владелец позиции. Пусто
  читается как `rsi_pullback`, поэтому записи, созданные до появления гостя, подхватываются
  без миграции. Позицию ведёт владелец: его стоп, его выходы, его Telegram-тема.
- **Занятый тикер.** Пока позиция открыта, вторая стратегия по тикеру не входит.
- **Приоритет входа.** Порядок адаптеров `[rsi_pullback, rsi_zone]`. Если на одном баре по
  свободному тикеру BUY дают обе, входит `rsi_pullback`; `rsi_zone` на этом баре не
  спрашивается.
- **Тикер вне вселенной.** Пасс охватывает объединение вселенных и все тикеры стейта. Тикер,
  убранный из `RSI_ZONE_TICKERS`, с открытой позицией ведётся владельцем до выхода; новых
  входов по нему нет.
- **Позиция без стейта.** Тикер только во вселенной одной стратегии — эта стратегия
  реконструирует позицию (§5 `rsi_pullback/live.md`). Тикер во вселенных обеих (пересечение) —
  владелец неизвестен: алерт в тему счёта, без реконструкции, стоп-заявки не трогаются.
  Нужна ручная разметка: добавить запись в файл стейта
  `data/state/rsi_pullback_<accountID>.json` с явным владельцем:

  ```json
  "DOMRF": {
    "ticker": "DOMRF",
    "strategy": "rsi_zone",
    "entryTime": "2026-09-30T10:31:00+03:00",
    "entryPrice": 100.0,
    "entryATR": 2.0,
    "takeProfit": 0,
    "maxFav": 100.0,
    "quantity": 10,
    "stopOrderId": "",
    "stopPrice": 0,
    "stopReason": ""
  }
  ```

  Дальше раннер сам выставит стоп-заявку по правилам владельца.
- **Неизвестный владелец.** Запись с `strategy`, которую ни один адаптер не знает, или с
  тикером, которого нет в реестре владельца, — алерт и пропуск, стоп не трогается.
- **Реконструкция гостя.** `EntryPrice` — средняя цена покупки брокера; `EntryTime` —
  последняя BUY-сделка за 180 дней; `EntryATR` — дневной ATR Уайлдера по будним дневкам,
  закрывшимся до MSK-полуночи дня входа (окно 730 дней, период `DailyATRPeriod` тикера);
  `TakeProfit = 0`; `MaxFav = EntryPrice` (ядро zone его не читает).

## 3. Отличия от rsi_pullback

- **Стоп фиксирован на входе** (`core.StopLevel` от `EntryPrice` и замороженного `EntryATR`),
  причина `SL`. Уровень не меняется всю жизнь позиции, поэтому заявка переставляется только
  при расхождении размера с позицией или после внешнего снятия. При `StopDailyATR = 0` стопа
  нет.
- **Нет цели и трейла.**
- **Выходы:** SL — биржевая стоп-заявка; RSI — рыночный SELL на закрытии бара (сигнал
  RSI выше верхней границы).

## 4. Бумажный режим при боевом rsi_pullback

Правило точное: бумажный вход пишет стейт, **только если ни одна подключённая стратегия не
боевая** (это обычный dry-run, как у `rsi_pullback` одного). Если боевая хотя бы одна:

- бумажный вход (и бумажный отказ по сайзингу) уходит только уведомлением, **стейт не
  пишется, тикер не занимается и бар не расходуется**: следующая по приоритету боевая
  стратегия на этом баре всё равно спрашивается;
- выходы бумажных позиций не ведутся — видны только сигналы входа. Выходы zone проверяются
  сверкой (§7);
- бумажная стратегия **не реконструирует** позицию без стейта, даже на тикере только её
  вселенной: реальная позиция могла принадлежать боевой стратегии и осталась бы без
  биржевого стопа. Вместо этого алерт в тему счёта и ручная разметка (§2).

## 5. Деньги

`BuyPct` каждой стратегии считается от **полной стоимости счёта** (кэш + позиции) с
ограничением доступным кэшем. Покупки внутри пасса последовательны, гонки за кэш нет.
Нехватка кэша у второй стратегии — обычный пропуск по сайзингу в её тему. При
`RSI_PULLBACK_BUY_PCT=50` две позиции занимают весь счёт, и входы zone будут часто
пропускаться; значения долей выбирает владелец при включении торговли гостя.

## 6. Конфигурация

Счёт, токен и расписание общие с `rsi_pullback`: `RSI_PULLBACK_ACCOUNT_ID`,
`RSI_PULLBACK_TOKEN`, `RSI_PULLBACK_SCHEDULE` (дефолт `1,31 6-23 * * *`). Раннер поднимается,
когда заведён счёт `rsi_pullback`.

| Переменная | Дефолт | Смысл |
|---|---|---|
| `RSI_ZONE_TICKERS` | `""` | вселенная входов; пусто — стратегия не подключается |
| `RSI_ZONE_BUY_PCT` | `5` | доля полной стоимости счёта на сделку, затем ограничение кэшем |
| `RSI_ZONE_TRADE_ENABLED` | `false` | ордера и стоп-заявки zone уходят на биржу |
| `RSI_ZONE_NOTIFY_ENABLED` | `false` | уведомления zone в Telegram |
| `TELEGRAM_TOPIC_RSI_ZONE` | — | тема форума zone; не задана — сообщения идут в General |

Ни одна переменная не `required` (ошибка загрузки конфига оборвала бы приложение целиком).
Реестр (`registry.go`) знает пакеты параметров тикеров; торгуют только перечисленные в
`RSI_ZONE_TICKERS`. Тикер, чей пакет равен `core.DefaultParams()`, в дефолтную вселенную не
попадает, кроме именных исключений (сторожевой тест реестра).

**Telegram.** Сообщения гостя идут с префиксом «[RSI Zone] » в тему `TELEGRAM_TOPIC_RSI_ZONE`
(нет темы — в General). Счётные сообщения (стартовое, недоступный `GetStopOrders`, алерты
о позиции без владельца) идут в тему `rsi_pullback`. Стартовое сообщение перечисляет
стратегии, их вселенные и режимы.

### Эксплуатация: повторяющиеся алерты

Алерты «позиция без стейта, владелец неизвестен» и «неизвестная стратегия в стейте»
**повторяются на каждом пассе** — до 36 раз в день по расписанию `1,31 6-23` — пока стейт не
размечен вручную (§2). Это намеренно: реальная позиция без сопровождения не должна
теряться в тишине. Размечайте стейт сразу, как пришёл первый алерт.

## 7. Сверка с бэктестом

```bash
go run ./cmd/pullparity -strategy rsi_zone -tickers AFKS,BAZA,DIAS,DOMRF,LENT -months 24
```

Флаг `-strategy` (`rsi_pullback` по умолчанию | `rsi_zone`) выбирает реестр. Сверка работает
по кэшу свечей: для каждого бара сравнивается живая сборка `MarketData` с сборкой движка и
вердикт `Decide`. Приёмка — **ноль расхождений**; это требуется для каждого тикера вселенной
до первой живой сделки. Горизонт — не более 24 месяцев (см. §9 `rsi_pullback/live.md`).

## 8. Порядок выката

1. `pullparity -strategy rsi_zone` — ноль расхождений по всей вселенной.
2. Прод: задан `RSI_ZONE_TICKERS`, `RSI_ZONE_TRADE_ENABLED=false`,
   `RSI_ZONE_NOTIFY_ENABLED=true`, заведена тема Telegram. `rsi_pullback` продолжает
   торговать вживую.
3. Сверка приходящих сигналов zone с бэктестом на тех же датах.
4. Пересмотр `RSI_PULLBACK_BUY_PCT` / `RSI_ZONE_BUY_PCT` под общий счёт и включение торговли
   zone.
