# RSI zone (30m, лонг, многодневный)

Код: `internal/service/trading_strategy/rsi_zone/strategy/core/core.go`
Реестр бэктеста: `internal/service/backtest/rsi_zone_registry.go`
Грид калибровки: `data/params/rsi_zone/grid.json`
Пакеты тикеров: `internal/service/trading_strategy/rsi_zone/strategy/<ticker>/` — откалиброванный литерал
и разбор калибровки в доке пакета; гриды тикера — в `data/params/rsi_zone/<ticker>/`. Незарегистрированный
тикер получает `core.DefaultParams()`.
Спека: `docs/superpowers/specs/2026-09-28-rsi-zone-design.md`
Скринер тикеров: `docs/rsi_zone/screener.md` (`go run ./cmd/zonescreen`).

Живой раннер — гость раннера счёта rsi_pullback: [live.md](live.md).

## 1. Идея

Покупка критической перепроданности в тренде. Тренд — цена закрытия выше одной EMA
(`close > EMA(EMAPeriod)`), момент входа — пересечение коротким RSI нижней критической зоны
сверху вниз, выход — пересечение тем же RSI верхней критической зоны снизу вверх, защита —
стоп в дневных ATR, замороженный на входе. Опционально — выход «застрявшей» сделки, если отскок
так и не начался (§4, `STUCK`), и фиксация прибыли после N баров (§4, `PROFIT`). Фиксированных целей, трейла и закрытия по концу дня нет: позиция переносится
через ночь и выходные.

Отличие от `rsi_pullback` (`docs/rsi_pullback/strategy.md`): тренд задаёт одна EMA против цены,
а не пара EMA; нет гейта состояния дня, цели, объёмного гейта и трейла.

## 2. Параметры

| Поле | Единица | Дефолт | В гриде |
|---|---|---|---|
| `RSIPeriod` | баров | 4 | entry: 4, 5, 6 |
| `RSILower` | пункты RSI | 25 | entry: 10, 15, 20, 25, 30 |
| `RSIUpper` | пункты RSI | 75 | exit: 60, 65, 70, 75, 80, 85 |
| `EMAPeriod` | баров | 200 | trend: 50, 100, 150, 200 |
| `DailyATRPeriod` | будних дневок | 14 | нет (фиксирован) |
| `StopDailyATR` | множитель дневного ATR | 1.0 | risk: 0.5, 0.7, 1.0, 1.5 |
| `UseStoch` | флаг | 0 | stoch: 1 |
| `StochKPeriod` | баров | 0 → 14 | stoch: 5, 9, 14 |
| `StochDSmooth` | баров | 0 → 3 | stoch: 1, 3 |
| `StochLower` | пункты Stoch | 0 → 20 | stoch: 10, 15, 20, 25, 30 |
| `ZoneWindowBars` | баров | 0 → 1 | stoch: 1, 2, 3, 5, 8 |
| `StuckExitBars` | баров после бара входа | 0 (выкл.) | stuck: 0, 1, 2, 3, 4, 5, 6, 8, 10 (`cal_stuck.json` тикера) |
| `ProfitExitBars` | баров после бара входа | 0 | profit: 0, 1, 2, 3, 4, 6, 8, 12 (`cal_profit.json` тикера) |
| `ProfitExitPct` | % от цены входа | 0 (выкл.) | profit: 0, 0.3, 0.5, 0.75, 1.0, 1.5, 2.0 |
| `EntryBlockFrom` | ЧЧММ MSK, включительно | 0 | нет |
| `EntryBlockTo` | ЧЧММ MSK, исключительно | 0 (выкл.) | нет |
| `EntryBlockMonThu` | флаг | 0 (окно во все будни) | нет |

`StopDailyATR = 0` отключает стоп в ядре, но в сетку намеренно не входит.

Поля стохастика действуют только при `UseStoch = 1`. Нулевое значение разрешается в дефолт после
стрелки, поэтому литерал тикера включает гейт одним `UseStoch = 1`. Отрицательный период
стохастика — ошибка конфигурации, вход не открывается.

## 3. Вход

Позиции нет; проверки на закрытии последнего бара `i`, первый несработавший гейт отклоняет вход:

1. **Будний день** по MSK. Нулевое или невыровненное время бара гейт пропускает.
   **Окно запрета входа:** при `0 ≤ EntryBlockFrom < EntryBlockTo` вход отклоняется, если бар
   сигнала ОТКРЫЛСЯ в `[EntryBlockFrom, EntryBlockTo)` по MSK (`1000`–`1400` = бары 10:00…13:30).
   При `EntryBlockMonThu ≠ 0` окно действует только с понедельника по четверг, пятница открыта.
   Выходы окно не трогает; вырожденное окно и нулевое время бара не блокируют.
2. **RSI-крест вниз:** `i-1 ≥ RSIPeriod && rsi[i-1] ≥ RSILower && rsi[i] < RSILower`. Прогрев
   RSI отсекается по индексу, а не по значению: честный RSI 0.00 после серии падающих баров —
   валидное показание. Событие, не состояние: пока RSI сидит в зоне без нового пересечения,
   повторного входа нет.

   **Подтверждение стохастиком (`UseStoch = 1`).** Пункт выше заменяется симметричным триггером.
   На текущем баре `i` вниз пересекает свою нижнюю границу RSI (`RSILower`) или Stoch %D
   (`StochLower`). Второй осциллятор при этом должен быть строго ниже своей границы хотя бы на одном
   баре окна `[i − ZoneWindowBars + 1 … i]`. `ZoneWindowBars = 1` значит «оба в зоне на одном баре».
   Бары прогрева индикаторов не засчитываются; настоящий 0.00 после прогрева засчитывается. Если на
   баре пересекли оба, это один вход, в журнале триггером указан RSI. Остальные пункты (будний день,
   тренд, дневной ATR, стоп) действуют без изменений. Журнал входа получает хвост «подтверждение: крест
   дал …, … в зоне k бар(ов) назад». Stoch %D — `indicators.StochasticSeries`; при плоском диапазоне
   цены за K баров %K равен 0, и такой бар считается «в зоне».
3. **Тренд:** `EMA[i] > 0 && close[i] > EMA[i]`; равенство — не тренд.
4. **Дневной ATR > 0** — ATR Уайлдера по завершённым будним дневкам (субботы и воскресенья
   выброшены; без `DailyTimes` серия берётся как есть).
5. **Стоп выше нуля:** `stop = close − StopDailyATR × dailyATR`; при включённом стопе и
   `stop ≤ 0` вход отклоняется.

Неположительные `RSIPeriod`/`EMAPeriod` дают «нет сигнала», а не панику.

## 4. Выход

Приоритет `SL → RSI → STUCK → PROFIT`:

1. **`SL`** — `low ≤ вход − StopDailyATR × EntryATR`. Уровень строится от дневного ATR,
   замороженного на входе, а не от текущего. Без `EntryATR` стопа нет. Цену исполнения
   определяет движок (`model.IsStopReason`: `min(стоп, open)`).
2. **`RSI`** — RSI пересёк `RSIUpper` снизу вверх на текущем баре; исполнение по close.
3. **`STUCK`** (только при `StuckExitBars > 0`) — RSI читается строго ниже `RSILower` на каждом
   баре после бара входа, и таких баров уже `≥ StuckExitBars`; исполнение по close. Бар входа в
   счёт не входит: на нём RSI по определению только что ушёл под полосу. Один бар с
   `RSI ≥ RSILower` после входа выключает этот выход до конца сделки — повторный нырок в зону его
   не взводит. Бар входа — последний бар, открывшийся не позже `Position.EntryTime`: в бэктесте
   это время открытия сигнального бара, live передаёт время заявки минус один 30-минутный бар
   (`entryBarTime` в раннере). Без `EntryTime`/`Times` или когда бар входа выпал из окна свечей
   выход молчит: окно (≥ 120 баров) много длиннее любого `StuckExitBars`, так что такая сделка
   либо давно вышла, либо уже разоружена.
4. **`PROFIT`** (только при `ProfitExitPct > 0`) — после бара входа прошло больше
   `ProfitExitBars` баров, и close не ниже входа на `ProfitExitPct` процентов; исполнение по
   close. Бар входа определяется так же, как у `STUCK`; без него выход молчит. Выход закрывает
   сделку раньше RSI-выхода, поэтому почти всегда поднимает win rate и PF, но может резать
   доходность: решение о нём принимается по PF и доходности вместе (см. темы калибровки ниже).

Календарного гейта у выходов нет: будний день ограничивает только вход (§3, гейт 1), а стоп и
RSI-выход срабатывают на любом баре, включая выходные сессии MOEX.

На общем баре стоп побеждает RSI-выход, `STUCK` и `PROFIT`: внутрибарный порядок из OHLC неизвестен. `RSI`
и `STUCK` на одном баре совпасть не могут (RSI выше верхней полосы против RSI ниже нижней).

Темы калибровки `stoch` (`cal_stoch.json`), `stuck` (`cal_stuck.json`) и `profit`
(`cal_profit.json`) — источники полей наравне с остальными: шесть базовых полей в них прибиты к дефолтам ядра (при перекалибровке — к литералу
тикера). Ось `StuckExitBars` включает 0, поэтому фолды могут проголосовать за выключенный выход; так же
ось `ProfitExitPct` в `profit`. Метрика калибровки — PF, а `PROFIT` поднимает PF почти всегда, поэтому
фолды `profit` редко голосуют за 0: выход включается, только если он обходит литерал без него и по
pooled PF, и по доходности на всех схемах.
В `stoch` гейт всегда включён, поэтому решение о гейте принимается сравнением pooled OOS темы с
baseline. Процедура — `/rsi-zone-calibrate`; сторожа сеток — `rsi_zone_stoch_grid_test.go` и
`rsi_zone_stuck_grid_test.go`, `rsi_zone_profit_grid_test.go` в `internal/service/backtest/`.

## 5. Запуск

```
go run ./cmd/backtest -ticker <TICKER> -strategy rsi_zone -interval Minutes30 -months 36
go run ./cmd/backtest -ticker <TICKER> -strategy rsi_zone -interval Minutes30 \
  -calibrate data/params/rsi_zone/grid.json -out ./reports/<TICKER> -months 36 \
  -min-trades 20 -test-months 6 -metric profit_factor
```

Калибровка — фазовая (entry → trend → exit → risk, keepTop 5, 85 комбинаций). Судить по pooled
OOS profit factor walk-forward, не по лучшей in-sample точке.

У зарегистрированного тикера поля, которых нет в гриде, берутся из его литерала, а не из дефолтов
ядра. Чтобы свипать оси поверх baseline, перечисляйте в гриде все поля.
