# Скринер тикеров под rsi_zone — дизайн

Статус: черновик, на ревью владельца (2026-09-28).
Стратегия: `docs/rsi_zone/strategy.md`. Предшественник: `docs/rsi_pullback/screener.md`
(спека `2026-08-03-rsi-pullback-screener-design.md`).

## 1. Цель

Ответить на один вопрос: **кому из торгуемой RUB-вселенной MOEX стоит потратить фазовую
калибровку `rsi_zone`**. Скринер не доказывает edge: планка приёмки прежняя — pooled OOS
profit factor ≥ 1.5 в персональном walk-forward.

От `pullscreen` скринер отличается глубиной строки. Кроме рейтинга по медиане PF, он
показывает то, на чём калибровки прошлых тикеров спотыкались уже после скрининга:

- издержки, которые съедают edge (KMAZ: шаг цены 0.1 ₽ при цене 50 ₽; RTKMP: круг 0.234%);
- концентрацию результата в одном отрезке (AFKS: весь профит с 2025 года; IVAT: 85% от одной недели);
- капкан широкого стопа и мёртвый RSI-выход;
- режим рынка: стратегия покупает только при `close > EMA`, в затяжном даунтренде сигналов нет
  по построению.

## 2. Архитектура

Повторяет разделение `pullscreen`: ввод-вывод в `cmd/`, чистое ядро в `internal/service/backtest`.

| Файл | Роль |
|---|---|
| `cmd/zonescreen/main.go` | флаги, загрузка вселенной и свечей, пул воркеров, запись отчёта |
| `internal/service/backtest/screenrun/` | общая обвязка CLI-скринеров, вынесенная из `cmd/pullscreen` |
| `internal/service/backtest/zone_screen.go` | сетка, прогон тикера, агрегация строки, детальные метрики |
| `internal/service/backtest/zone_screen_report.go` | гейты, сортировка, распределение, Markdown |

### 2.1 Переиспользование

Помощники pullback-скринера лежат в том же пакете `backtest` и используются как есть:
`profitFactor`, `splitTrades`, `medianF`, `clampPF`, `MeanDailyATRPct`, `MeanDailyTurnoverM`,
`ScreenOpts`/`DefaultScreenOpts`. `Distribution` завязана на `PullbackRow` и не переиспользуется:
у zone-скринера свой ключ ранжирования (§5), распределение считается по нему.

### 2.2 Экстракция `screenrun`

Из `cmd/pullscreen/main.go` в пакет `internal/service/backtest/screenrun` переезжают:

- `ShareInfo` (бывший `shareInfo`) с новым полем `MinPriceIncrement float64`;
- `LoadUniverse(ctx, client, only)`: заполняет `MinPriceIncrement` из `model.Share`;
- `LoadToken()`;
- `RefreshWorkerCap`, `EffectiveWorkers(requested, refresh)`;
- `PauseAfterTicker(ctx, d)`;
- `SplitCSV(s)`.

Причина: `refreshWorkerCap` защищает 540-мегабайтный кэш свечей от дыр, и копия этой логики во
втором CLI рано или поздно разошлась бы с оригиналом. `cmd/pullscreen` переходит на пакет без
изменения поведения, флагов и формата отчёта. Его тесты (`TestPauseAfterTicker*`,
`TestEffectiveWorkers*`) переезжают в `screenrun` вместе с кодом.

## 3. Сетка

24 конфигурации, как у pullback: полный прогон вселенной укладывается в те же 20–25 минут.

| Поле | Значения | Почему |
|---|---|---|
| `RSIPeriod` | 4, 6 | края диапазона грида калибровки (4–6) |
| `RSILower` | 15, 25 | 25 — дефолт, принят на DOMRF и AFKS; 15 — точка SBER |
| `EMAPeriod` | 50, 100, 200 | EMA 50 — ведущий рычаг DOMRF и AFKS; 200 — дефолт |
| `RSIUpper` | 65, 75 | 75 — дефолт; 65 — более ранний выход |
| `StopDailyATR` | 1.0 | закреплён: стоп — свойство настроенной точки, не инструмента; 1.0 принят на всех трёх откалиброванных тикерах |
| `DailyATRPeriod` | 14 | фиксирован и в стратегии |

`ZoneGrid()` возвращает конфигурации в детерминированном порядке
(`RSIPeriod → RSILower → EMAPeriod → RSIUpper`).

Движок строится через `core.NewWithParams(ticker, p)`, **не** через `RSIZoneLookupOrGeneric`:
иначе SBER, DOMRF и AFKS оценивались бы на своих литералах, и их строки стали бы несравнимы с
остальными.

## 4. Метрики строки

Окно: `-months` (дефолт 36), из них последние `-holdout-months` (дефолт 6) — holdout. Сделка
принадлежит окну по времени входа (`splitTrades`). Все метрики, кроме помеченных HO, считаются на
train. Медианы берутся по 24 конфигурациям.

### 4.1 Базовые (как в pullscreen)

`PFmed`, `TradesMed`, `Plateau` (PF ≥ 1.3 при ≥ 10 сделках), `Capped`, `SilentCfg`, `PFmed HO`,
`Trades HO`, лучшая конфигурация по сырому train-PF. Семантика та же, что в
`docs/rsi_pullback/screener.md`: конфигурация без сделок входит в `PFmed` как PF = 0, PF зажат
на `-pf-cap`.

### 4.2 Издержки

- **`Tick%`** = `2 × MinPriceIncrement / lastClose × 100`, где `lastClose` — close последнего
  30m-бара окна. Это доля двух шагов цены (вход округляется вверх, выход вниз) в текущей цене.
  Если API не отдал шаг (`MinPriceIncrement ≤ 0`) или `lastClose ≤ 0`, `Tick%` = 0 и строка
  помечается флагом `TickUnknown`.
- **`PFmed×2`** — медиана train-PF при стрессе издержек. Пересчитывается из тех же сделок, без
  повторного прогона движка:

  ```
  stressedPnL = PnL − Commission × (EntryPrice + ExitPrice) × Quantity − 2 × MinPriceIncrement × Quantity
  ```

  То есть к уже учтённой комиссии добавляется ещё одна комиссия за каждую сторону и два шага цены.
  Изменение размера позиции из-за иначе сложившегося кэша игнорируется: на отношение PF оно
  пренебрежимо. Зажим `-pf-cap` и правило «нет сделок — PF = 0» те же, что у `PFmed`.
- **`PFmed×2 HO`** — то же на holdout. В сортировке не участвует.

### 4.3 Стабильность по полугодиям

Train-сделки конфигурации группируются по календарному полугодию входа по MSK (январь–июнь,
июль–декабрь). Результат полугодия — сумма сырого `PnL` его сделок.

- **`Halves+`** — медиана по конфигурациям доли прибыльных полугодий (результат > 0) среди
  полугодий, в которых была хотя бы одна сделка. Конфигурации без сделок в медиану не входят; если
  таких все 24, значение 0.
- **`TopHalf`** — медиана по конфигурациям доли лучшего полугодия в сумме положительных
  полугодий: `max(result) / Σ max(result, 0)`. 1.0 — весь профит из одного полугодия. Конфигурации
  без прибыльного полугодия в медиану не входят; если таких все 24, значение 0 и в отчёте «—».

Для детальной таблицы дополнительно хранится раскладка по полугодиям лучшей конфигурации:
результат каждого полугодия окна в виде `2024H1 +3.1% · 2024H2 −1.2% · …`, в процентах от
`-cash`.

### 4.4 Профиль выходов

- **`SL%`** — медиана по конфигурациям доли сделок с `Reason == "SL"`. Около нуля при
  `StopDailyATR = 1.0` — признак, что стоп не работает как защита (капкан широкого стопа); почти 100% —
  признак, что RSI-выход не успевает.
- **`HoldD`** — медиана по конфигурациям медианной длительности сделки в календарных днях
  (`(ExitTime − EntryTime) / 24h`). Считается по времени, а не по `BarsHeld`: вечерняя сессия и
  выходные делают число баров в дне непостоянным.

Конфигурации без сделок в обе медианы не входят.

### 4.5 Режим тренда

**`>EMA50`**, **`>EMA200`** — доля train-баров 30m, у которых `close > EMA(N)`, по `ema.Compute`
(тот же расчёт, что в ядре). Бары прогрева (`EMA == 0`) из знаменателя исключаются. Считается один
раз на тикер, не зависит от сетки, в ранжировании не участвует — это объяснение низкого
`TradesMed`, а не критерий.

## 5. Гейты и ранжирование

Жёсткие гейты, первый несработавший отправляет строку в отсев:

1. оборот ≥ `-min-turnover` (дефолт 50 млн ₽/день);
2. дневной ATR ≥ `-min-atr-pct` (дефолт 1.5%);
3. `Tick%` ≤ `-max-tick-pct` (дефолт 0.3%; 0 отключает гейт). Строка с `TickUnknown` гейт
   проходит и помечается в отчёте.

Прошедшие гейты строки без единой сделки ни в одной конфигурации (ни train, ни holdout) уходят в
секцию «Нет сигналов».

**Ключ сортировки — `PFmed×2` по убыванию**, вторичный — тикер по возрастанию. Это намеренное
расхождение с `pullscreen`: тикер, чей edge съедают издержки, должен падать вниз уже на скрининге,
а не на пятом шаге калибровки.

## 6. Отчёт

`reports/zone_screen/zone_screen_Minutes30_<stamp>.md`:

1. **Шапка** — окно, срез holdout, сетка, гейты, модель стресса издержек, счётчики
   scanned/passed/no-signal/rejected/skipped.
2. **Распределение `PFmed×2`** по ранжированной вселенной: min, Q1, медиана, Q3, max, доля ≥ 1.5.
3. **Рейтинг** (top `-top`): `# | Ticker | Name | Оборот | ATR% | Tick% | Бары | TradesMed |
   PFmed | PFmed×2 | Capped | SilentCfg | Plateau | PFmed×2 HO | Trades HO`.
4. **Детали топа** (те же строки): `Ticker | Halves+ | TopHalf | SL% | HoldD | >EMA50 | >EMA200 |
   Лучшая конфигурация | Полугодия лучшей конфигурации`.
5. **Нет сигналов** — список тикеров.
6. **Отсеяно гейтом шага цены** — тикер и `Tick%`: самый неочевидный из гейтов, отсев должен быть
   виден глазами.
7. **Как это читать** — короткая памятка, те же оговорки, что у `pullscreen`.

## 7. CLI

`go run ./cmd/zonescreen -months 36 -holdout-months 6 -top 50`

Флаги `pullscreen` сохраняются с теми же дефолтами (`-months`, `-holdout-months`,
`-min-turnover`, `-min-atr-pct`, `-top`, `-workers`, `-pf-cap`, `-tickers`, `-refresh`, `-pause`,
`-cash`, `-fraction`, `-commission`), `-out` по умолчанию `reports/zone_screen`. Новый флаг:
`-max-tick-pct` (0.3). Дневная серия грузится с годовым прогревом, как в `pullscreen`.
Ограничение воркеров при `-refresh` — через `screenrun.EffectiveWorkers`.

## 8. Ошибки

- Не загрузились свечи тикера — тикер пропускается, счётчик `skipped`, строка в stdout
  (как в `pullscreen`).
- `-holdout-months ≥ -months`, `-workers < 1` — ошибка запуска.
- Пустой ответ вселенной — ошибка запуска.

## 9. Тесты

TDD на чистом ядре, синтетические сделки и свечи:

- `ZoneGrid`: 24 конфигурации, порядок, закреплённые поля (стоп 1.0, ATR 14);
- `stressPnL`: комиссия и два шага на известной сделке; шаг 0 даёт только комиссию;
- `halfYearResults`: граница 30 июня / 1 июля по MSK, сделка у полуночи UTC;
- `Halves+` и `TopHalf`: конфигурация без сделок и без прибыльных полугодий не входит в медиану;
- `SL%` и `HoldD` на смеси `SL`/`RSI`;
- доля выше EMA: бары прогрева не входят в знаменатель;
- гейты: каждый по отдельности, `TickUnknown` проходит, `-max-tick-pct 0` отключает гейт;
- сортировка по `PFmed×2` с тай-брейком по тикеру; рендер отчёта: заголовки обеих таблиц,
  прочерк у `TopHalf = 0`, секция отсева по шагу;
- `ScreenZoneTicker` на синтетике: строит движок в обход реестра (зарегистрированный тикер
  получает сеточные параметры, а не литерал);
- `screenrun`: перенесённые тесты `pullscreen` зелёные; `LoadUniverse` переносит
  `MinPriceIncrement`.

  меряет. Без результатов прогонов по тикерам (правило из CLAUDE.md, применяется и к `rsi_zone`).

## 11. Вне скоупа

- Проскальзывание сверх двух шагов цены, внутрибарные проколы стопа.
- Дивидендные гэпы: ручной контроль на этапе калибровки.
- Стресс по ширине стопа: стоп закреплён, его ось меряется в калибровке.
- Перевод `pullscreen` на стресс-ранжирование — отдельное решение.
