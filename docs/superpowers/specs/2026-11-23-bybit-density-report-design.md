# Недельный отчёт о спотовых плотностях Bybit

Из корня репозитория пользователь запускает `go run ./cmd bybit-density-report SOL`. Принимаются также SOLUSDT и нижний регистр. Обрабатывается одна спотовая пара к USDT за предыдущую календарную неделю (понедельник — воскресенье, UTC). Команда работает отдельно от live-воркера и Telegram.

## Подход

Пользователь выбрал скачивание суточных архивов стакана ob200 и сделок и проигрывание по биржевому времени. Свечной бэктест теряет размер заявок до касания. Накопление собственных наблюдений в live потребовало бы ждать.

## Входные данные

Дневные ZIP стакана брать из quote-saver.bycsi.com/orderbook/spot, CSV.GZ сделок из public.bybit.com/spot. Обрабатывать последовательно, ограничивая временное хранилище одним днём. Показывать покрытие по датам. При отсутствии одного архива пропускать день с указанием причины. Повреждение файла или ошибка сети после ограниченных повторов завершают команду с ошибкой. Если нет ни одного полного дня, отчёт не публикуется. Проверять символ, тип потока, порядок событий, начинать восстановление стакана со snapshot.

## Наблюдения

Использовать ширину зоны из spot.go для известных пар. Для остальных пар по умолчанию брать 0,05% первой пригодной цены, округляя до целого числа ценовых шагов (минимум один шаг), фиксировать ширину на весь прогон и печатать её. Поддержать явный параметр ширины. Общую с live логику группировки bid, исключения неполной глубокой полосы, соседней медианы и допустимого расстояния использовать повторно. Учитывать зоны под текущим minNotional, возраст от 8 секунд, сохранение от 60% исходного количества.

Первое касание — вход цены сделки продавца в подтверждённую зону сверху. Одно касание за непрерывный эпизод. Сохранять объём и кратность из последнего состояния перед сделкой, при равной миллисекунде обрабатывать сделки раньше обновления стакана. Устаревший стакан исключать. Движение после касания измерять всеми последующими сделками. Цель — цена касания плюс один ATR, пробой — нижняя граница минус половина ATR. ATR фиксируется при касании по 14 закрытым M1 (среднее истинных диапазонов). Первый достигнутый рубеж определяет исход, иначе через 5 минут записывать тайм-аут. Без прогретого ATR касание исключать и считать отдельно. Пропуск или конец данных до истечения горизонта даёт незавершённое наблюдение, исключаемое из знаменателя. Сохранять состояние между смежными днями при непрерывных данных.

## Отчёт

Печатать таблицу по диапазонам USDT с количеством касаний, отскоков, пробоев, тайм-аутов и процентом отскоков. Для профилей использовать границы 0, 0.5x, 1x и 2x текущего порога. Для прочих пар границы определить по квартилям на первых днях и зафиксировать для проверки. Выводить также разбивку по кратности к соседней медиане, включая неизвестную медиану. Первые две трети доступных дней использовать для подбора кандидата, остальные для хронологической проверки относительно зон ниже порога. Показывать числа по обе стороны порога и воздерживаться от выбора при малой выборке или отсутствии улучшения. Предлагаемый минимум — 30 завершённых касаний в каждой сравниваемой группе на каждом этапе. Среди пригодных границ выбрать на обучающих днях границу с наибольшей положительной разницей долей отскоков выше и ниже границы, при равенстве — меньшую границу. Проверить ровно её на проверочном периоде. При одном доступном дне вывести только описательную статистику. Результат описывает частоту отскоков по данному определению.

Сохранять CSV касаний и сводку в reports/bybit-density-research/<пара>/<начало-недели>/, указывать путь. Публиковать завершённые результаты после обработки. Не менять настройки live по результатам прогона.

## Проверка

Использовать локальные архивы-фикстуры для проверки snapshot/delta, порядка событий, дедупликации, исходов и границ недели. Проверить команду на реальном архиве и сверить агрегаты с CSV касаний.
