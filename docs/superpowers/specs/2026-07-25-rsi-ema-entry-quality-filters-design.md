# RSI+EMA: фильтр «пилы» и фон объёмов

Дата: 2026-07-25
Расширение стратегии `rsi_ema` (см. `docs/superpowers/specs/2026-07-23-rsi-ema-design.md` и
`docs/superpowers/specs/2026-07-24-rsi-ema-fresh-entry-filter-design.md`).
Код: `internal/service/trading_strategy/rsi_ema/strategy/core`.

## Проблема

Вход `rsi_ema` — крест RSI вверх через `RSIMid` (50) при `EMAFast > EMASlow`. Фильтр свежести
(правка 2026-07-24) отсекает один вид чопа: RSI долго висел выше 50, нырнул на 1–2 бара и тут же
пересёк вверх (`barsAboveMid ≥ EntryAboveMidLimit`). Но он дырявый для **«пилы»** — когда RSI
быстро скачет выше/ниже 50 несколько баров подряд. Пример: окно перед крестом `52, 48, 51, 49,
49(i-1)` даёт всего 2 бара выше 50 (`< 3`, лимит) и **проходит**, хотя это классический боковик с
частыми пересечениями средней линии — ложный перезаход.

Вторая проблема: вход срабатывает и на «мёртвом» рынке, когда объёмы затухли и движение — тонкий
дрейф без участников. Такой пробой средней линии статистически хуже.

Это расширение добавляет два независимых входных под-фильтра: по **частоте пересечений** линии 50
и по **фону объёмов**. Оба чисто индикаторные, ядро остаётся stateless, ticker- и
timeframe-agnostic.

## Дефолты и опциональность

**Все входные фильтры-«качества» опциональны и ВЫКЛЮЧЕНЫ по умолчанию** — как `StopATR=0`. Базовая
стратегия (`DefaultParams`) торгует чистый вход «крест + тренд», а грид включает каждый фильтр
через ненулевые значения и сравнивает с контрольной точкой «выкл». Это меняет и уже существующий
дефолт фильтра свежести:

| Параметр | Старый дефолт | Новый дефолт | Выключение |
|---|---|---|---|
| `EntryAboveMidLimit` (свежесть) | 3 | **0 (выкл)** | `≤ 0` |
| `EntryMaxMidCrossings` (пила) | — | **0 (выкл)** | `≤ 0` |
| `UseVolume` (фон объёмов) | — | **0 (выкл)** | `≠ 1` |

`EntryLookbackBars` остаётся 5 (размер окна для обоих RSI-под-фильтров; работает, только когда
хотя бы один из под-фильтров включён; свипается гридом). При обоих RSI-лимитах `= 0`
`freshEntry` всегда возвращает «пропустить».

## Фильтр 1: «пила» — число пересечений RSIMid

В `enter()`, внутри уже существующего гейта свежести (после подтверждения креста и тренда, перед
Buy), добавляется второй под-фильтр поверх подсчёта `barsAboveMid`.

> В окне из последних `EntryLookbackBars` баров перед баром-крестом (индексы
> `i-EntryLookbackBars … i-1`, с усечением по началу серии) посчитать **пересечения** `RSIMid`
> между соседними барами — переходы, где `rsi[j-1]` и `rsi[j]` лежат по разные стороны от
> `RSIMid`, в любую сторону. Если пересечений **≥ `EntryMaxMidCrossings`**, вход отклоняется.

Крест `i-1 → i` (сам вход) в окно не входит и не считается — окно кончается на `i-1`. Максимум
пересечений в окне = `EntryLookbackBars - 1`.

### Параметр

| Параметр | Дефолт | Смысл |
|---|---|---|
| `EntryMaxMidCrossings` | 0 (выкл) | отклонять вход, если в окне `≥` стольких пересечений `RSIMid`; `≤0` выключает |

### Композиция с фильтром свежести

`freshEntry(rsi, i)` возвращает «отклонить» (false), если сработал **любой** из двух под-фильтров:

```
barsAboveMid(rsi, i) >= EntryAboveMidLimit   ИЛИ   midCrossings(rsi, i) >= EntryMaxMidCrossings
```

Каждый под-фильтр активен независимо и выключается своим параметром `≤0` (и общим
`EntryLookbackBars ≤ 0`, который выключает оба). При обоих лимитах `= 0` (дефолт) гейт не
применяется. Существующее поведение `barsAboveMid` при включённом `EntryAboveMidLimit > 0`
не меняется — новый под-фильтр только добавляет причины отклонить.

### Определение пересечения

Пересечение между барами `j-1` и `j` (оба в окне, `j` от `start+1` до `i-1`):

```
rsi[j-1] > 0 && ( (rsi[j-1] < RSIMid && rsi[j] > RSIMid) || (rsi[j-1] > RSIMid && rsi[j] < RSIMid) )
```

Гвард `rsi[j-1] > 0` отсекает warm-up-нули `RSISeries` (как в `crossedUp`/`crossedDown`). Бар,
равный ровно `RSIMid`, пересечением не считается (float RSI ровно 50 — практически невозможен;
неоднозначный случай трактуем как «не пересёк»).

### Проверка (окно 5, лимит пересечений 3 — при включённом фильтре)

- Пила `52, 48, 51, 49, 49(i-1)`: пересечения `52→48` (вниз), `48→51` (вверх), `51→49` (вниз) =
  **3 ≥ 3 → отклонён** ✓ (счётчик `barsAboveMid`=2 её пропускал).
- Свежий заход `48, 49, 49, 49, 49(i-1)`: **0 пересечений `< 3` → пропущен** ✓.

## Фильтр 2: фон объёмов — режим активности

В `enter()`, после гейта свежести (пилы), перед расчётом ATR/выдачей Buy, добавляется гейт по
объёмам. Семантика — **сравнение двух скользящих средних объёма**: недавняя активность против
более длинного бэкграунда. Вход разрешён, только когда фон живой (растёт/держится), и режется,
когда объёмы затухают.

> Пусть `shortAvg` = средний объём последних `VolShortPeriod` баров (включая текущий бар-вход),
> `longAvg` = средний объём последних `VolLongPeriod` баров. Вход разрешён, только когда
> `shortAvg ≥ longAvg × VolMult`. Иначе — отклонить.

### Параметры

| Параметр | Дефолт | Смысл |
|---|---|---|
| `UseVolume` | 0 (выкл) | тумблер: `0` = фильтр выключен, `1` = включён (грид) |
| `VolShortPeriod` | 10 | окно «недавнего» среднего объёма (последние N баров, включая текущий) |
| `VolLongPeriod` | 50 | окно длинного бэкграунда |
| `VolMult` | 1.0 | вход требует `shortAvg ≥ longAvg × VolMult` |

### Подсчёт среднего

Helper (свой в пакете `rsi_ema`, без кросс-импорта reversion):

```go
// avgVolumeLastN averages the volumes of the last n bars of vols (including the final,
// entry, bar). When times is index-aligned to vols, weekend bars (Sat/Sun MSK) are dropped;
// when times is empty or misaligned, weekend exclusion is skipped. Non-positive volumes are
// ignored. ok is false when no sample survives — the caller must then skip the gate.
func avgVolumeLastN(vols []int64, times []time.Time, n int) (avg float64, ok bool)
```

Окно: индексы `[len(vols)-n … len(vols)-1]`, с усечением по началу. Выходные исключаются
(MSK Sat/Sun) когда `len(times) == len(vols)`; иначе исключение пропускается. Неположительные
объёмы пропускаются. `ok=false`, когда в окне не осталось ни одного валидного бара.

Для исключения выходных используются уже существующие в пакете `mskLoc` и `isWeekend`.

### Гейт и деградация

```
if UseVolume == 1 && VolShortPeriod > 0 && VolLongPeriod > VolShortPeriod {
    shortAvg, okS := avgVolumeLastN(md.Volumes, md.Times, VolShortPeriod)
    longAvg,  okL := avgVolumeLastN(md.Volumes, md.Times, VolLongPeriod)
    if okS && okL && longAvg > 0 && shortAvg < longAvg*VolMult {
        return sig // отклонить
    }
}
```

**Никогда не блокировать вход на пустых данных.** Если `UseVolume != 1`, или окна невалидны
(`VolLongPeriod ≤ VolShortPeriod`), или любое из средних не посчиталось (`!okS || !okL`, нет
объёмов / вся история — выходные), или `longAvg ≤ 0` — гейт пропускается, вход проходит дальше.

### Проверка (short 10, long 50, mult 1.0 — при включённом фильтре)

- Фон живой: `shortAvg=12000 ≥ longAvg=8000 × 1.0 → вход` ✓.
- Затухание: `shortAvg=5000 < 8000 → отклонён` ✓.

## Порядок гейтов в enter()

1. Сессия / не конец дня.
2. Крест RSI↑`RSIMid`.
3. Тренд `EMAFast > EMASlow`.
4. **(3.5) Фильтр свежести** — `barsAboveMid` ИЛИ `midCrossings` (Фильтр 1); no-op при обоих
   лимитах `= 0`.
5. **(3.6) Фон объёмов** (Фильтр 2); no-op при `UseVolume != 1`.
6. ATR-стоп (опционально) и выдача Buy.

## Свойства

- Оба правила чисто индикаторные: считаются из уже имеющихся `RSISeries` и `md.Volumes`, без
  нового межбарного состояния. Ядро остаётся stateless и ticker-agnostic.
- Timeframe-agnostic: окна измеряются в барах.
- Все фильтры выключены по умолчанию → базовое поведение стратегии не меняется; включение —
  только через грид.
- Только вход. Логика выходов (`SL`/`EMAX`/`RSI70`/`RSI50`/`EOD`) не трогается.
- `entryReason` по формату не меняется (гейты тихо отклоняют, ложных Buy не создают); диагностика
  — в `Explain`.

## Explain

`Explain()` (`-explain`) добавляет по строке на каждый под-фильтр:

- Пила: число пересечений `RSIMid` в окне, лимит `EntryMaxMidCrossings` (или «выключен»), прошёл
  ли под-фильтр.
- Фон объёмов: `shortAvg`, `longAvg`, отношение, порог `VolMult`, включён ли (`UseVolume`) и
  прошёл ли гейт (либо «выключен», либо «нет данных → пропущен»).

Существующая строка фильтра свежести (`barsAboveMid`) сохраняется (с пометкой «выключен» при
`EntryAboveMidLimit = 0`).

## Тесты (ядро)

**Дефолты (опциональность):**
- `DefaultParams`: `EntryAboveMidLimit == 0`, `EntryMaxMidCrossings == 0`, `UseVolume == 0`,
  `VolShortPeriod == 10`, `VolLongPeriod == 50`, `VolMult == 1.0`, `EntryLookbackBars == 5`.
- На дефолтах оба чоп-сетапа (и «нырок после долгого выше», и «пила») дают Buy — фильтры выключены.
- Обновить существующий тест `TestDefaultParamsFreshEntryFilter`: ожидание `EntryAboveMidLimit`
  меняется `3 → 0`.

**Фильтр 1 (пила), с явно включённым `EntryMaxMidCrossings=3`:**
- Пила режется: ряд `52,48,51,49,49`→крест при `EMAFast>EMASlow`, `barsAboveMid < лимита`
  (старый под-фильтр, даже если включён, пропускает), но `midCrossings ≥ 3` → Buy НЕ выдаётся.
- Свежий крест проходит: RSI держался под 50 несколько баров (0–1 пересечение) → Buy выдаётся.
- Граница: ровно `EntryMaxMidCrossings-1` пересечений → проходит; `EntryMaxMidCrossings` → режется.
- Независимость: при `EntryMaxMidCrossings=3, EntryAboveMidLimit=0` пила режется, а «нырок» — нет;
  при `EntryAboveMidLimit=3, EntryMaxMidCrossings=0` — наоборот.
- Усечение у начала серии не паникует и не режет по недостатку истории.

**Фильтр 2 (фон объёмов):**
- Выключен по умолчанию: при валидном кресте с затухающими объёмами и `UseVolume=0` Buy выдаётся.
- Включён (`UseVolume=1`), фон живой (`shortAvg ≥ longAvg`) → Buy выдаётся.
- Включён, затухание (`shortAvg < longAvg × VolMult`) → Buy НЕ выдаётся.
- `VolMult` > 1: пограничный фон (`shortAvg` чуть выше `longAvg`, но ниже `× VolMult`) → режется.
- Деградация: `md.Volumes` пуст / короче окна → гейт пропускается (Buy выдаётся при прочих ок).
- Деградация: `VolLongPeriod ≤ VolShortPeriod` → гейт пропускается.
- `avgVolumeLastN`: исключает выходные при выровненных `Times`; при пустых `Times` считает все
  бары; игнорирует неположительные объёмы; `ok=false` на пустом окне.

## Грид

`data/params/rsi_ema/grid.json`: добавить две фазы поверх существующих (по образцу фаз
entry/exits/risk/freshness), каждая — один концепт. Контрольная точка «выкл» совпадает с новым
дефолтом, так что baseline (все фильтры выкл) участвует в сравнении:

- Фаза `chop` (после `freshness`): `EntryMaxMidCrossings ∈ {0, 2, 3}` (0 = выкл — контроль).
  3 комбо × keepTop 5 = 15.
- Фаза `volume` (после `chop`): `UseVolume ∈ {0, 1}` × `VolMult ∈ {1.0, 1.2}` (UseVolume=0 =
  контроль; `VolShortPeriod`/`VolLongPeriod` фиксированы дефолтами, не свипаются).
  4 комбо × keepTop 5 = 20.

Существующая фаза `freshness` (`EntryAboveMidLimit ∈ {0, 2, 3, 4}`) не меняется — она уже включает
контроль `0`; смена дефолта на `0` лишь делает baseline и контрольную точку совпадающими.
