# Дизайн: секторные поправки скоринга + секторный вид отчёта в дивидендном скринере

**Дата:** 2026-07-21
**Ветка:** `feat/dividend-sector-aware`
**Статус:** утверждён к реализации

## Проблема

Дивидендный скринер оценивает все компании по одним и тем же формулам пилляров,
хотя часть метрик неприменима к финансовому сектору. У банка одновременно три
искажения:

1. **Ложная кара.** `Sustainability = 0.7·payoutFit + 0.3·(FCF>0)`. У банков
   `FreeCashFlowTtm` приходит 0 (дыра данных, а не «нет потока») →
   `boolScore(FCF>0)=0` срезает 0.3 от самого тяжёлого пилляра.
2. **Ложная премия по оценке.** `Valuation = 1 − percentile(EV/EBITDA)`. У банков
   нет EBITDA, `EvToEbitdaMrq = 0` → минимальный EV/EBITDA в пуле → оценка ≈0.98
   («самый дешёвый») по ошибке.
3. **Ложная премия по надёжности.** `Safety = leverageScore(NetDebt/EBITDA)`. У
   банков `NetDebtToEbitda = 0` → `leverageScore(0) = 0.9`, хотя leverage для
   банка бессмыслен (депозиты — обязательства).

Эти искажения были вскрыты вопросом «почему Сбер ниже Татнефти/Банка СПб»: часть
ответа — именно FCF=0-артефакт на тяжёлом пилляре Устойчивости.

Отдельно: отчёт бота — плоский список топ-25, без секторного среза; не видно
диверсификации и того, кто в каком секторе.

## Цель

1. **Расчёт места учитывает особенности сектора:** для финансового сектора
   заменить/нейтрализовать неприменимые метрики так, чтобы композит отражал
   реальную картину, а не артефакты данных.
2. **Визуал показывает агрегацию по секторам:** топ-N в Telegram сгруппирован по
   секторам с агрегатом (число имён, средний композит).

## Не-цели (YAGNI)

- **Поправки для не-финансовых секторов.** Единственный доказанный артефакт —
  банки. REIT, металлурги и т.п. не имеют выявленной боли — их формулы не
  трогаем. Все не-финансовые имена считаются байт-в-байт как сейчас. Механизм
  делаем расширяемым (классификатор сектора), но других веток не заводим.
- **Внутрисекторные перцентили** (сравнивать банк только с банками по
  Quality/DivGrowth). Малые сектора РФ (2–3 имени) делают перцентиль
  вырожденным. Quality через ROE и так осмысленно сравним между секторами;
  оставляем глобальные перцентильные пулы.
- **Расчёт capital adequacy для банков.** Данных (CET1 и т.п.) в
  `GetAssetFundamentals` нет. Надёжность банка нейтрализуем, а не изобретаем.

## Дизайн

### 1. Классификация сектора (ядро `rank`)

Сектор приходит из `Shares` (`investapi.Share.Sector`, строковый код). Вводим:

- `model.Share` += поле `Sector string`; маппинг в
  `internal/converter/share.go` (`Sector: share.Sector`).
- В пакете `rank` — тип и классификатор:
  ```go
  type sectorKind int
  const (
      sectorOther sectorKind = iota
      sectorFinancial
  )
  func classifySector(sector string) sectorKind
  ```
  `classifySector` относит к `sectorFinancial` коды финансового сектора Invest
  API. **Точный набор строк калибруется на живых данных** (шаг E): прогон
  `divscreen` перечисляет реальные коды; в классификатор попадают те, что
  соответствуют банкам/финансам (ожидается `"financial"`, но фиксируется по
  факту). Сравнение регистронезависимое; неизвестный код → `sectorOther`.

### 2. Секторные поправки пилляров (ядро `rank`)

Сигнатура ранжирования получает сектор по каждому активу:
```go
func Rank(universe []*model.Fundamentals, sectorByAsset map[string]sectorKind, cfg Config) []ScoredCompany
```
Сектор — метаданные инструмента, а не фундаментал, поэтому в `model.Fundamentals`
**не** кладём; передаём отдельной картой (ключ — `AssetUID`). Отсутствующий ключ →
`sectorOther`.

Для `sectorFinancial` три пилляра считаются иначе; для `sectorOther` — как сейчас:

| Пилляр | `sectorOther` (без изменений) | `sectorFinancial` |
|---|---|---|
| Sustainability | `0.7·sustainabilityPayout(payout) + 0.3·boolScore(FCF>0)` | `sustainabilityPayout(payout)` (FCF-член убран) |
| Valuation | `1 − percentileOrNeutral(evEbitdaPool, EV/EBITDA)` | `bankValuation(PriceToBookTtm, cfg)` — абсолютная полоса P/B |
| Safety | `leverageScore(NetDebt/EBITDA)` | `0.5` (нейтрально — leverage неприменим, capital adequacy нет) |

`bankValuation`:
```go
// P/B ≤ Low → 1.0; линейно к 0 при P/B ≥ High; P/B ≤ 0 (нет данных) → 0.5.
func bankValuation(pb float64, cfg Config) float64 {
    if pb <= 0 {
        return 0.5
    }
    if pb <= cfg.BankPBIdealHigh {
        return 1.0
    }
    span := cfg.BankPBZero - cfg.BankPBIdealHigh
    if span <= 0 {
        return 0
    }
    return clamp01((cfg.BankPBZero - pb) / span)
}
```

Новые поля `Config` (точки калибровки, шаг E):
- `BankPBIdealHigh float64` — P/B, до которого оценка максимальна (ориентир 1.0).
- `BankPBZero float64` — P/B, при котором оценка падает до 0 (ориентир 2.5).

Перцентильные пулы (`divGrowth`, `roic`, `evEbitda`) строятся по всем выжившим,
как сейчас. Банки в пул `evEbitda` по-прежнему попадают (их EV/EBITDA=0), но их
**собственная** Valuation берётся из `bankValuation` и пул EV/EBITDA не читает.
Небанки продолжают ранжироваться перцентилем EV/EBITDA среди всех выживших —
поведение для них не меняется (нулевые EV/EBITDA банков уже сейчас в пуле).

**Судейское решение (утверждено):** Safety банка = 0.5. Это опускает банки на
≈0.4·0.25 = −10 композита относительно нынешней ложной 0.9. Честно относительно
отсутствия данных о капитале; сохранять 0.9 значило бы держать ложную премию.

### 3. Секторный вид отчёта (`render`)

`Render` группирует уже отсортированный топ-N по `rs.Share.Sector`:

- Ярлык+эмодзи по коду сектора: функция `sectorLabel(code string) string` с
  картой известных кодов (RU-названия + эмодзи), фолбэк «Прочее». Карта
  наполняется по факту с живого прогона (шаг E).
- Порядок секторов — по лучшему (максимальному) композиту внутри сектора: сектор,
  где стоит #1 общего списка, идёт первым. Внутри сектора — по композиту (уже
  отсортировано).
- Подзаголовок сектора с агрегатом: `<emoji> <label> · N имён · ср. XX`, где
  `ср.` — средний композит имён этого сектора в показанном топе.
- Под подзаголовком — строки компаний (существующий формат карточки:
  название/тикер/композит/пилляры).

Блок «отсеяно по причинам» и футер с датой — без изменений.

### 4. Проброс данных (`service`)

`service.refresh` уже строит `sharesByAsset`. Дополнительно строит
`sectorByAsset map[string]rank.SectorKind` из тех же `shares` и передаёт в
`rank.Rank`. `RankedShare.Share` уже несёт сектор (через `model.Share.Sector`),
поэтому `Render` читает `rs.Share.Sector` без новых полей.

Экспорт: `sectorKind` и `classifySector` нужны сервису и divscreen — экспортируем
как `rank.SectorKind`, `rank.ClassifySector`. Значения `rank.SectorOther`,
`rank.SectorFinancial`.

### 5. Диагностический CLI (`cmd/divscreen`)

Расширяем для калибровки (шаг E):
- Колонки `Sector` (сырой код) и `P/B` в ранжированной таблице.
- В `-probe`: класс сектора (`financial`/`other`) и какие поправки применены
  (какой Sustainability/Safety/Valuation получился и почему).
- divscreen строит `sectorByAsset` из `Shares` и передаёт в `rank.Rank`
  (сигнатура изменилась).

### 6. Калибровка и верификация (живой Invest API)

Прогнать `go run ./cmd/divscreen -top 0 -gated` до/после и `-probe` по банкам:
1. **Коды секторов:** перечислить реальные строки `Sector`; зафиксировать набор
   финансовых кодов в `classifySector` и ярлыки в `sectorLabel`.
2. **Полоса P/B:** по живым P/B банков подобрать `BankPBIdealHigh` / `BankPBZero`
   (ориентиры 1.0 / 2.5), проверить, что осмысленно разделяет дёшево/дорого.
3. **Регрессия:** curated-11 Golden X целы (8 небанков — композит не изменился;
   банки среди curated, если есть, сместились предсказуемо); SBER/BSPB/TATN сдвиг
   соответствует прогнозу (SBER вниз из-за снятия ложных премий, BSPB выше SBER
   по payout).

## Тесты

`internal/service/screener/dividend/rank/rank_test.go`:
- `classifySector`: финансовый код → `SectorFinancial`; неизвестный/пустой →
  `SectorOther`; регистронезависимость.
- Банк: `Sustainability == sustainabilityPayout(payout)` (FCF>0 не влияет —
  проверить кейсом FCF=0 и FCF>0 при равном payout → одинаковый Sustainability).
- Банк: `Safety == 0.5` независимо от `NetDebtToEbitda`.
- `bankValuation`: P/B ниже `BankPBIdealHigh` → 1.0; на `BankPBZero` → 0;
  посередине → промежуточное; P/B ≤ 0 → 0.5.
- Небанк: все три пилляра считаются по-старому (регрессионный кейс — значения не
  изменились относительно текущих ожиданий).
- `Rank` с `sectorByAsset`: банк и небанк с одинаковыми фундаменталами получают
  разные Safety/Valuation/Sustainability.

`render_test.go`:
- Топ с двумя секторами → в выводе два подзаголовка с корректным `N имён` и
  `ср.`; порядок секторов по лучшему композиту; неизвестный код → «Прочее».

`service_test.go`:
- `refresh` прокидывает сектор из `Share` в `Rank`: банк и небанк с одинаковыми
  фундаменталами дают разные композиты.

## Критерии готовности

1. Для финансового сектора Sustainability не зависит от FCF, Safety = 0.5,
   Valuation считается по P/B; небанки — без изменений.
2. Отчёт бота сгруппирован по секторам с агрегатом (число имён, средний композит);
   порядок секторов по лучшему композиту; неизвестный код → «Прочее».
3. `classifySector`/`sectorLabel` наполнены по реальным кодам живого API; полоса
   P/B откалибрована.
4. Curated-11 Golden X целы; SBER/BSPB/TATN сдвинулись согласно прогнозу.
5. `./bin/mage ci` зелёный; новые тесты покрывают классификатор, три поправки,
   границы P/B и секторный рендер.
6. Документация (`docs/dividend/screener.md`) отражает секторные поправки и
   секторный вид отчёта.
