# Ежечасный дайджест новостей российского фондового рынка в тему Telegram

Дата: 2026-07-15
Статус: дизайн утверждён, ждёт план реализации

## Проблема

В форум-группе Telegram (см. `2026-07-13-telegram-topic-routing-design.md`) есть
темы для сигналов стратегий и отчётов, но нет ленты новостей рынка. Хочется раз
в час получать в отдельную тему сводку свежих новостей по российским акциям,
не выходя из группы.

## Решение (утверждено)

Push-воркер внутри приложения: раз в час тянет RSS-ленту, отбирает записи,
появившиеся с прошлого запуска, и постит один дайджест-пост в тему «Новости»
через существующий topic-bound `telegram.Client`.

### Источник

`https://smart-lab.ru/news/rss/` — «Лента всех новостей акций» smart-lab.ru:
агрегатор Интерфакс/Reuters/раскрытий эмитентов, только фондовая тематика,
обновляется каждые несколько минут, чистый RSS 2.0 без пейволла и без ключей.
Проверен 2026-07-15: ~10–20 записей в час.

URL задаётся конфигом `NEWS_FEED_URL` с этим значением по умолчанию — смена
источника не требует пересборки.

### Компоненты

- **`pkg/client/rss`** — HTTP-клиент + разбор RSS 2.0 стандартной
  `encoding/xml` (новых зависимостей нет). Отдаёт
  `[]Item{Title, Link, GUID, PubDate}`. Скрыт за интерфейсом (мокается
  mockery, как остальные клиенты). User-Agent браузерный, таймаут запроса
  ~30 с.
- **`internal/service/news`** — сервис дайджеста: фильтрация новых записей,
  форматирование, отправка через `telegram.Client`. Получает уже привязанный
  к теме клиент (паттерн Golden X/Reversion: `NewTopicSender` в
  `service_provider`).
- **Конфиг**:
  - `TelegramClient.TopicNews int` (`TELEGRAM_TOPIC_NEWS`) — тема «Новости»;
    нулевое значение → штатный фолбэк в General (уже реализован в
    `Bot.SendMessageToTopic`).
  - `NewsConfig{FeedURL string}` (`NEWS_FEED_URL`), дефолт — smart-lab.
- **Wiring**: геттеры в `service_provider`; воркер в `runProd` по cron
  `5 * * * *` (5-я минута часа — собирает полный прошедший час) через
  существующий `pkg/scheduler`-паттерн; в `runDev` — один немедленный запуск
  при старте для ручной проверки.

### Дедупликация

Состояние в памяти процесса:

- `lastSeen time.Time` — верхняя граница `PubDate` уже отправленных записей;
- множество GUID записей, отправленных в перекрывающемся пограничном окне.

Новыми считаются записи с `PubDate > lastSeen`, GUID отсекает дубли на самой
границе. При старте процесса cutoff = «час назад»: после рестарта возможен
редкий повтор одной-двух новостей — осознанно принято, БД/файл состояния ради
этого не заводим.

### Формат сообщения

Один пост в час:

```
📰 Новости рынка
• <a href="link1">Заголовок 1</a>
• <a href="link2">Заголовок 2</a>
…
```

- ParseMode HTML (как во всех отправках `Bot`), заголовки эскейпятся
  (`html.EscapeString`).
- Лимит Telegram 4096 символов: длинный дайджест режется на несколько
  сообщений по границам пунктов (пункт не рвётся посередине).
- Нет новых записей → ничего не постим.

### Обработка ошибок

- Ошибка фетча/парсинга RSS → лог (`logger.ErrorContext`), пропуск итерации;
  `lastSeen` не сдвигается, следующий час покроет пропущенное. В группу об
  этом не пишем.
- Ошибка отправки в тему → существующий фолбэк в General внутри
  `Bot.SendMessageToTopic`.
- Паника в воркере → recover по образцу остальных горутин приложения.

### Тестирование

- `pkg/client/rss`: разбор XML-фикстуры (валидная лента smart-lab, битые
  даты, пустая лента).
- `internal/service/news`: cutoff по `PubDate` + GUID-дедуп на границе;
  эскейпинг HTML в заголовках; нарезка дайджеста по 4096 по границам пунктов;
  «нет новых → нет отправки»; мок `telegram.Client`.
- `./bin/mage mocks` после добавления интерфейса fetcher'а, `./bin/mage ci`.

### Ручные шаги после реализации (пользователь)

1. Создать тему «Новости» в супергруппе.
2. Прописать `TELEGRAM_TOPIC_NEWS` (и при желании `NEWS_FEED_URL`) в env.

## Отвергнутые альтернативы

- **Сторонний RSS-to-Telegram бот (flowerss и т.п.)** — ноль кода, но каждая
  новость отдельным сообщением (противоречит формату «дайджест»), чужой бот в
  группе, отдельная точка отказа.
- **Pull-команда `/news`** — не соответствует требованию «раз в час по
  расписанию»; можно добавить позже поверх того же сервиса.
- **Finam (`finam.ru/analysis/conews/rsspoint/`)** — рабочий RSS, но больше
  макро/топливной повестки, меньше именно акций; оставлен как запасной
  источник через `NEWS_FEED_URL`.
- **MOEX (`moex.com/export/news.aspx`)** — технично-биржевые пресс-релизы, не
  новости рынка.
- **Хранение состояния дедупа на диске/в БД** — цена (новая инфраструктура)
  не окупает редкий повтор пары новостей после рестарта.
