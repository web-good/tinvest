# Reversion: биржевые стоп-заявки + интрабарная модель стопов — Design

**Date:** 2026-07-09
**Branch:** main (новая ветка на реализацию)
**Status:** Approved design, pending implementation plan

## Цель

Устранить расхождение между моделью исполнения стопов в бэктесте и живым исполнением
стратегии `reversion` — с двух сторон сразу:

1. **Live:** ценовые стопы (SL / TRAIL / ATRSL) переезжают с «рыночная продажа после
   закрытия часа» на **реальные биржевые стоп-заявки** (Tinkoff Invest API
   `StopOrdersService`, stop-market). Стоп исполняется брокером в момент касания уровня
   внутри часа — по уровню, а не по закрытию.
2. **Бэктест:** триггер этих же стопов переводится с `close ≤ уровень` на **интрабарный**
   `low ≤ уровень` с исполнением по `min(уровень, open)` — та же модель, что уже принята
   в стратегии levels. Сейчас бэктест недосчитывает срабатывания (прокол уровня с
   возвратом цены к закрытию не выходил из позиции) и потому оптимистичен по частоте
   выбивания.
3. **Перепрогон:** три «fixed» walk-forward (UGLD / EUTR / NVTK) прогоняются заново под
   новой моделью. Результат **информационный**: тикеры из live-реестра не убираются
   независимо от цифр (решение пользователя), но цифры фиксируются в отчётах и
   сравнительной таблице.

## Контекст (что есть сейчас)

- Live-раннер (`internal/service/trading_strategy/reversion/live/`): часовой тик,
  `buyPass`/`managePass`, продажа всей позиции рыночной заявкой
  (`executor`, `ORDER_TYPE_MARKET`), стейт в JSON (`statestore.Entry`: EntryPrice,
  EntryATR, MaxFav, Quantity, EntryTime), реконструкция стейта из API (`reconstruct`),
  dry-run через `tradeEnabled`.
- Бэктест-движок (`internal/domain/backtest/engine.go`): сигналы по закрытию бара;
  причины `"SL"`/`"TRAIL"` исполняются по `min(sig.StopLoss, c.Open)`, `"ATRSL"` — по
  close. `p.mark(close)` поднимает `MaxFavorablePrice` **до** вызова `Decide`.
- Ядро (`reversion/strategy/core/core.go`): все стоп-условия проверяют
  `in.price` (= close). Приоритет выходов: `OB → SL → TRAIL → RSI50 → BE →
  RSIOS|ATRSL → EMAX`.
- Прото `api/v1/stoporders.proto` в репозитории есть (PostStopOrder / GetStopOrders /
  CancelStopOrder), но **стабы не сгенерированы** (нет в `internal/pb/v1/`, нет
  Makefile-таргета) и клиент нигде не подключён.
- Паттерн интрабарного стопа уже реализован в levels: ядро проверяет low бара против
  уровня, кладёт уровень в `sig.StopLoss`, движок исполняет по `min(уровень, open)`.

## Ключевые решения (зафиксированы с пользователем)

| Решение | Выбор |
|---|---|
| Скоуп | Live + бэктест + перепрогон walk-forward трёх тикеров |
| Какие выходы на биржу / интрабарно | SL, TRAIL, ATRSL. BE остаётся часовой close-проверкой в обоих мирах |
| Судьба тикеров после перепрогона | Оставить все в live, цифры фиксируются информационно |
| Механика трейлинга | Раннер сам ведёт стоп: cancel + repost раз в час (не серверный trailing брокера — тот тянет от тикового максимума и ломает паритет с формулой `MaxFav(closes) − TrailATRMult × EntryATR`) |
| Тип заявки | Stop-market: `STOP_ORDER_TYPE_STOP_LOSS` + `EXCHANGE_ORDER_TYPE_MARKET`, экспирация `GOOD_TILL_CANCEL`, идемпотентный `order_id` (UUID) |

## Часть 1: live-раннер

### Новый пакет `live/stoporders`

Тонкая обёртка над сгенерированным `StopOrdersServiceClient` по образцу `live/executor`:

- `Place(ctx, instrumentID, lots, stopPrice) (orderID string, err error)` — stop-market
  SELL, GTC, UUID order_id.
- `Cancel(ctx, orderID) error`.
- `List(ctx) ([]ActiveStop, error)` — активные стоп-заявки счёта (instrumentID, orderID,
  stopPrice) для сверки.
- Уважает `tradeEnabled`: в dry-run ничего не отправляет, возвращает синтетический
  результат; вызывающий код логирует и шлёт уведомления с пометкой dry-run.

Интерфейс gRPC-клиента объявляется на стороне потребителя (как `executor.OrdersClient`)
и мокается mockery.

### Кодогенерация и wiring

- Makefile: таргет `generate-stoporders-api` по шаблону `generate-orders-api`
  (`api/v1/stoporders.proto` → `internal/pb/v1/`).
- `service_provider`: клиент `StopOrdersServiceClient` рядом с существующим
  orders-клиентом, прокидывается в live-сервис reversion.
- `.mockery.yaml` + `./bin/mage mocks` для нового интерфейса.

### Стейт

`statestore.Entry` получает два поля:

```go
StopOrderID string  `json:"stopOrderId,omitempty"` // активная биржевая стоп-заявка ("" = нет)
StopPrice   float64 `json:"stopPrice,omitempty"`   // уровень, на котором она стоит
```

### Уровень стопа

Желаемый уровень (одна заявка на позицию):

```
want = max(
    EntryPrice − CatStopATRMult × EntryATR,   // если CatStopATRMult > 0
    EntryPrice − StopATRMult  × EntryATR,     // если UseATRStop == 1 и StopATRMult > 0
    MaxFav     − TrailATRMult × EntryATR,     // если UseTrail == 1 и TrailATRMult > 0
)
```

Компонент, задавший максимум, определяет **причину** (`SL` / `ATRSL` / `TRAIL`) — она
пишется в стейт вместе с уровнем и используется в уведомлении при срабатывании. Если ни
один компонент не активен (все выключены параметрами) — стоп-заявка не ставится, поведение
как сегодня.

### Поток `buyPass`

После успешной покупки — сразу `Place` стоп-заявки на `want` (не дожидаясь первого
manage-тика), `StopOrderID`/`StopPrice` в стейт. Ошибка постановки: алерт в Telegram,
поле остаётся пустым, managePass перевыставит на следующем тике.

### Поток `managePass` (позиция есть)

1. Сверка: если в стейте есть `StopOrderID`, проверить его наличие в `List`. Заявки нет,
   а позиция на месте → алерт + перевыставить (кто-то отменил вручную / отклонена).
2. Пересчитать `want` от обновлённого `MaxFav`. Если заявки нет — `Place`. Если есть и
   `want > StopPrice` — `Cancel` старой, `Place` новой, обновить стейт. Уровень вниз не
   двигается (трейлинг монотонный, SL/ATRSL фиксированы).
3. `Cancel` прошёл, `Place` упал: алерт, `StopOrderID=""` в стейте, повтор на следующем
   тике. Час без биржевого стопа страхуется close-проверкой ядра (см. «Бэкстоп» ниже).
4. Осцилляторный выход (OB / RSI50 / RSIOS / EMAX) или BE по решению ядра: **сначала**
   `Cancel` стоп-заявки, **потом** рыночная продажа. `Cancel` упал → продажу не
   отправлять (защита от двойной продажи), алерт, повтор через час.
5. Позиция исчезла из портфеля, в стейте есть `StopOrderID` → наш стоп исполнился:
   уведомление Exit с сохранённой причиной (`SL`/`ATRSL`/`TRAIL`) и уровнем, очистка
   стейта. Позиция исчезла без `StopOrderID` → как сегодня: «продано где-то ещё», тихая
   очистка стейта.
6. Позиция уменьшилась, но не нулевая (частичное исполнение стопа): обновить `Quantity`,
   `Cancel` + `Place` на остаток лотов, алерт.

### Бэкстоп

Стоп-проверка ядра в live **сохраняется** (после части 2 она становится low-триггерной:
low закрытого бара коснулся уровня → SELL). При штатно стоящей биржевой заявке она
недостижима — касание уровня уже исполнило заявку, и позиция исчезнет раньше (случай 5).
Срабатывает она только когда биржевого стопа нет (не встал / отменён): рыночная продажа
на часовом тике, как сегодня. Это осознанный страховочный контур, не дубль. Соответственно
шаг 4 обрабатывает **любой** SELL-сигнал ядра единообразно: cancel (no-op при пустом
`StopOrderID`) → рыночная продажа.

### `reconstruct` (рестарт без стейта)

Дополнительно читает `List`: найденную по инструменту стоп-заявку отменяет и ставит
свежую от восстановленных `EntryATR`/`MaxFav` (собственная заявка после потери стейта
неотличима от чужой, поэтому пересоздание — простейший корректный путь). Причина/уровень
пишутся в восстановленный стейт.

## Часть 2: бэктест

### Ядро (`core.manage`)

- Три стоп-условия (SL / TRAIL / ATRSL) сливаются в **одну объединённую проверку**,
  зеркалящую единственную биржевую заявку: `want = max(активные уровни)`; триггер —
  `low бара ≤ want` (low — последний элемент `md.Lows`); `sig.StopLoss = want`; причина
  (`SL`/`TRAIL`/`ATRSL`) — компонент, задавший максимум. Раздельные ветки в switch дали
  бы неверную атрибуцию и заниженную цену исполнения, когда сработали сразу два уровня.
- **Новый приоритет выходов:** `STOP(SL|TRAIL|ATRSL) → OB → RSI50 → BE → RSIOS → EMAX`.
  Биржевой стоп срабатывает внутри часа — физически раньше любого сигнала по закрытию,
  поэтому объединённый стоп поднимается выше OB. Прежний порядок (OB выше SL) отражал
  close-модель и меняется осознанно.
- Уровень трейлинга для интрабарной проверки считается от **`PrevMaxFavorablePrice`** —
  максимума закрытий по предыдущий бар включительно (стоп-заявка на бирже в течение часа
  `i` выставлена после закрытия `i−1`). Взвод BE продолжает использовать текущий
  `MaxFavorablePrice` (BE остаётся close-выходом).
- RSIOS (средний выход при `UseATRStop=0`) не меняется — это осцилляторный выход.

### `strategy.Position`

Новое поле `PrevMaxFavorablePrice float64` — значение монотонного максимума **до** учёта
текущего бара. В бэктесте заполняет портфель (снимок до `p.mark(close)`); в live —
значение `MaxFav` из стейта до его подъёма текущим тиком. Существующее
`MaxFavorablePrice` не меняет семантику (другие стратегии не затрагиваются).

### Движок (`engine.go`)

Причина `"ATRSL"` добавляется к `"SL", "TRAIL"` в ветке исполнения по
`min(sig.StopLoss, c.Open)`. Больше изменений в движке нет.

## Часть 3: перепрогон и документация

- Три fixed walk-forward теми же дегенеративными сетками:
  `go run ./cmd/backtest -ticker {UGLD|EUTR|NVTK} -strategy reversion -interval Hour1
  -calibrate data/params/<t>/reversion_fixed.json …` с теми же окнами, что в отчётах
  2026-06-18/22 (train 12 мес у UGLD и EUTR, 18 мес у NVTK; OOS-фолд везде 6 мес,
  3 фолда) + по одному одиночному прогону на тикер.
- Сравнительная таблица «close-модель vs интрабар» (PF, win rate, сделки, NetPnL, MaxDD
  по пулу OOS) — в `docs/reversion/strategy.md` или рядом; вывод фиксируется, тикеры из
  live-реестра не убираются.
- Обновить `docs/reversion/strategy.md` (модель исполнения стопов, новый приоритет
  выходов), `docs/reversion/live-runner.md` и `live-code-map.md` (stoporders, стейт,
  потоки).

## Тестирование

- **Ядро** (табличные тесты по образцу levels): прокол low при закрытии выше уровня →
  выход по уровню; гэп под уровень → `min(уровень, open)`; приоритет стопа над OB в
  одном баре; трейлинг от `PrevMaxFav`, а не от текущего `MaxFav` (спайк-бар с новым
  максимумом закрытия и глубоким low не должен выбивать по завышенному уровню); BE
  по-прежнему от close.
- **Движок**: `"ATRSL"` исполняется по `min(stop, open)`.
- **Live** (mockery-моки `StopOrdersClient`): постановка после покупки; перевыставление
  при росте уровня и непере-выставление при том же уровне; cancel-ок/place-fail;
  cancel-fail перед рыночной продажей блокирует продажу; детект исполнившегося стопа
  (позиция исчезла + StopOrderID) с правильной причиной; частичное исполнение;
  reconstruct с чужой заявкой; dry-run не зовёт API.
- Гейт: `./bin/mage ci` (lint + `go test -race ./...` + mock-drift).

## Вне скоупа

- Перекалибровка сеток под интрабарную модель (отдельная задача, если пользователь
  решит по итогам цифр).
- BE как биржевая заявка; серверный trailing-stop брокера.
- Интрабарные стопы для других стратегий (momentum и пр.) — движок меняется только
  добавлением `"ATRSL"` в список stop-fill причин.
- Стоп-заявки на вход (buy-stop) — вход остаётся рыночным по сигналу закрытия часа.
