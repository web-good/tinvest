# ORB — внутридневной пробой утреннего диапазона (long-only)

Дата: 2026-07-16
Статус: дизайн утверждён, ждёт план реализации

## Проблема

Существующее «скальпинг»-ядро (`scalping/strategy/adaptive`, Donchian
dual-regime на Hour1) признано структурно слабым (сравнение RUAL/AFKS
2026-06-06): AFKS не спасают 243 комбинации параметров, тонкий edge RUAL
держался на нереалистичном close-fill исполнении стопов. Реворк качества
(TrailArmATR/ADXMargin/MinRR/MinATRFrac) влит в main, но запланированная
валидация так и не была выполнена. Нужна внутридневная стратегия,
спроектированная с учётом всех накопленных уроков проекта:

- тесные ATR-стопы на внутридневных ТФ выбиваются интрабарными фитилями
  (levels: +2.9% → −17.7% при переходе на честные интрабарные филлы);
- входные фильтры не отделяют победителей от проигравших (loss-анализ
  reversion 2026-06-16) — болото находится в выходах;
- многопараметрные сетки оверфитятся (momentum: pooled OOS PF 0.406);
- комиссия (~0.08% round-trip) убивает сделки с тейком < 0.2%.

## Решение (утверждено): Вариант 1 = kill-test старого ядра + новая стратегия ORB

### Шаг А — kill-test ядра adaptive (прогоны, без нового кода)

Ручные прогоны существующего кода современным инструментарием — rolling
walk-forward, появившимся уже после реворка:

```
go run ./cmd/backtest -ticker RUAL -strategy scalping -interval Hour1 \
  -months 24 -calibrate data/params/scalping/rusal_grid.json \
  -train-months 12 -test-months 6 -min-trades 10 -metric profit_factor
```

Аналогично AFKS (`data/params/scalping/afks_grid.json`) + 3–5 тикеров
корзины через `LookupOrGeneric`. Сетки восстановлены из git-истории
(были удалены случайным коммитом 08d36e6) в `data/params/scalping/` и
дополнены нулевыми значениями, чтобы калибратор мог выбрать «ручка
выключена»: перебираются четыре ручки реворка
TrailArmATR/ADXMargin/MinRR/MinATRFrac (192 комбинации).

- **Критерий выживания** (из исходного плана реворка): pooled OOS
  expectancy > 0 и PF > 1.2.
- **Оговорка о честности**: adaptive триггерит стопы по close бара (движок
  филлит стоп-reasons по уровню `min(stop, open)`, но сам триггер поздний) —
  результат следует читать как *верхнюю оценку*. Не прошёл планку → ядро
  официально хоронится (фиксируется в памяти проекта), возвращаться к нему
  больше не будем. Прошёл → отдельное решение о доводке (вне этой спеки).
- Исполнитель — пользователь (нужны `T_BANK`-токен и сеть); шаг не блокирует
  шаг Б, идут параллельно.

### Шаг Б — стратегия ORB (Opening Range Breakout)

Первые бары основной сессии MOEX задают «утренний диапазон» — рынок
переваривает овернайт и нащупывает баланс. Пробой верха диапазона,
подтверждённый закрытием бара, статистически продолжается до конца дня.
Покупаем пробой, стоп — под структурой диапазона, выход — принудительно в
конце сессии. Флэт каждую ночь.

## Правила стратегии

Все временные правила — по MSK (`Europe/Moscow`, UTC-фолбэк — паттерн
reversion core). Стратегия таймфрейм-агностична: считает бары, а не часы;
таймфрейм задаётся `-interval` при запуске. **Основной ТФ — Minutes30,
контрольный — Hour1** (edge обязан жить на обоих, иначе это запах оверфита).

1. **Диапазон (OR).** Первые `ORBars` баров текущего MSK-дня с временем
   открытия ≥ 10:00 (бары утренней сессии до 10:00 игнорируются).
   ORH = max(high), ORL = min(low) этих баров. Пока диапазон не сформирован —
   никаких действий.
2. **Фильтр дня (опция).** Если `MaxRangeATR > 0` и
   `(ORH − ORL) > MaxRangeATR × ATR` (ATR текущий на момент формирования) —
   день пропускается: риск стопа непропорционален внутридневному тейку.
3. **Вход — только первый пробой дня (stateless).** Начиная с бара
   `ORBars+1` дня: покупка, когда бар **закрывается** выше ORH, при условии
   что ни один более ранний завершённый бар этого дня (после формирования OR)
   не закрывался выше ORH. Это правило «один вход в день» без состояния:
   после стоп-аута повторный вход невозможен — первый пробойный бар уже
   существует в истории дня. Вход по close пробойного бара.
4. **Объёмный гейт (опция).** При `VolMult > 0`: объём пробойного бара ≥
   `VolMult × avg`, где avg — среднее за `volAvgPeriod` (константа 20)
   предшествующих баров с исключением выходных (переиспользуется паттерн
   `averageVolumeExcludingWeekends` из reversion). Нет данных → гейт
   пропускается (graceful degradation, как в reversion).
5. **Стоп — структурный, заморожен на входе.**
   На входе `sig.StopLoss = ORL − Buffer × ATR(14)` (ATR на баре входа);
   движок замораживает его в `Position.StopLoss` (уже штатное поведение) —
   пересчётов на последующих барах нет. Триггер **интрабарный**:
   `low ≤ pos.StopLoss`, reason `"SL"` → движок филлит по `min(stop, open)`
   (`model.IsStopReason`, `internal/domain/backtest/engine.go`). Никаких
   «стоп = entry − 1×ATR».
6. **Выход по времени (EOD).** На первом баре дня с MSK-временем открытия
   ≥ 18:00 открытая позиция закрывается по close бара, reason `"EOD"`
   (не-стоповый reason — филл по close, штатное поведение движка). На этом
   баре и позже входы запрещены. Бары вечерней сессии (открытие ≥ 19:00)
   полностью игнорируются. Позиция никогда не переносится через ночь.
7. **Выходные (Сб/Вс MSK).** Входы запрещены (выходные сессии MOEX —
   мёртвая ликвидность); правило EOD действует и там.
8. **Без Times стратегия не работает.** Если `MarketData.Times` не заполнен
   или не совпадает по длине с закрытиями — no-op (защитный дефолт: не можем
   определить сессию → не торгуем). Бэктест заполняет Times всегда
   (`backtest.buildMarketData`); для live это осознанный стоп-кран.

### Параметры — ровно 4

```go
type Params struct {
    ORBars      int     // баров в утреннем диапазоне; дефолт 2
    VolMult     float64 // объёмный гейт входа; 0 = выкл (дефолт)
    Buffer      float64 // отступ стопа под ORL в долях EntryATR; дефолт 0.25
    MaxRangeATR float64 // пропуск дня с широким OR в долях ATR; 0 = выкл (дефолт)
}
```

Константы (не тюнятся сознательно): ATRPeriod = 14, volAvgPeriod = 20,
начало сессии 10:00, EOD-час 18:00, уровень подтверждения = close бара.
Сетка ~50–100 комбинаций против тысяч у reversion — оверфититься почти не в
чем. Никаких trail/breakeven/тейк-профитов в v1: тюнинг выходов — главное
болото прошлых стратегий, здесь выход константный по построению.

## Архитектура (зеркалит reversion)

- `internal/service/trading_strategy/orb/strategy/core` — ядро: `Params`,
  `Decide` поверх общих типов `scalping/strategy.MarketData/Position` и
  `scalping/model.Signal`, `Lookback`, `Explain` (диагностика бара, как в
  reversion). Чистые функции от свечей — идентичное поведение в бэктесте и
  (в будущем) в live.
- `internal/service/trading_strategy/orb/strategy/<ticker>` — 8 тонких
  пер-тикерных пакетов (sber, gazp, nvtk, plzl, ydex, afks, rusal, mdmg) с
  `DefaultParams()`; на старте все идентичны базовым дефолтам.
- `internal/service/backtest/orb_registry.go` — `ORBLookupOrGeneric` +
  `genericORBDefaults` (паттерн `ReversionLookupOrGeneric`).
- `cmd/backtest`: `case "orb"` в switch стратегий; вся остальная обвязка
  (`-calibrate`, `-train-months`, `-explain`, отчёты) переиспользуется как
  есть — walk-forward и загрузчик Minutes30 уже стратегие-/ТФ-агностичны.
- `data/params/<ticker>/orb_grid.json` — сетки: `ORBars [1,2,3]`,
  `VolMult [0,1.0,1.5]`, `Buffer [0.1,0.25,0.5]`, `MaxRangeATR [0,1.5,2.5]`
  (81 комбинация).
- **Lookback**: полный торговый день баров текущего ТФ + max(ATRPeriod+1,
  volAvgPeriod+1); вычисляется из худшего случая Minutes30 (~28 баров/день
  с вечерней сессией).

Live-раннер — **вне скоупа v1**: стратегия сначала только в бэктесте
(путь reversion: валидация → отдельная спека live). Шорты — вне скоупа
навсегда (решение пользователя: long-only).

## Валидация и приёмка

1. Rolling walk-forward на корзине из 8 тикеров (SBER, GAZP, NVTK, PLZL,
   YDEX, AFKS, RUAL, MDMG): пер-тикерный `-calibrate` +
   `-train-months 12 -test-months 6`, глубина `-months` — по фактической
   доступности 30-минутной истории (гард lookback в `runCalibration` упадёт
   громко, если окно короткое).
2. Прогон на обоих ТФ: Minutes30 (основной) и Hour1 (контрольный).
3. **Приёмка**: pooled OOS PF > 1.5 по корзине при стабильных параметрах по
   фолдам (дрейф параметров между фолдами = красный флаг, критерий EUTR/PIKK);
   тикеры с < 10 OOS-сделок не считаются подтверждением.
4. Интрабарные стопы включены с первого дня — никакой close-fill фазы,
   чтобы не повторить историю levels.

## Риски (честно)

- Канонический ORB строится на 5–15-минутных барах; Minutes30 — компромисс
  между каноном и имеющейся инфраструктурой. Возможно, edge на этих ТФ
  размыт — это главная проверяемая гипотеза, и walk-forward ответит быстро:
  сигнал-кандидат появляется почти каждый день, выборка набирается на
  порядок быстрее reversion-овских 25 сделок.
- Внутридневной формат ограничивает средний размер победителя (~0.5–2%);
  положительное матожидание должно строиться на частоте, а не на редких
  больших победах.
- Глубина 30-минутной истории Tinkoff API неизвестна до первой загрузки;
  если истории мало (< ~18 мес), walk-forward сокращается до 2 фолдов и
  выводы слабеют — тогда Hour1-прогон становится основным.
