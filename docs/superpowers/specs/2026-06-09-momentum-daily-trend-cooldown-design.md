# Momentum: дневной трендовый фильтр + кулдаун

Дата: 2026-06-09
Ветка: `feat/momentum-daily-trend-cooldown` (от `feat/momentum-macd-strategy`)

## Контекст и мотивация

Грид-прогон momentum-стратегии на RUAL (Hour1, год) дал лучший вариант:
PF 1.90, PnL +21.3%, WR 52%, **макс. просадка 10.9%**, 23 сделки, экспозиция 15%.

Вся просадка приходится на **один кластер из 6 убытков подряд — сделки №9–14
(29 сен → 8 дек 2025), все по SL.** Общее у убытков:

- цена входила **впритык к часовой EMA200** (№9 выше на +0.006, №11 +0.32,
  №12 +0.15) — часовой тренд по сути плоский;
- слабые MACD-кроссы у нуля (№9 −0.011, №12 −0.014, №14 −0.0001 — шум).

Регим в сен–дек был боковик/разворот вниз, а часовая EMA200 ещё держалась выше,
поэтому фильтр пропускал входы. В `core.go` уже объявлены два параметра под эту
проблему, но они **мёртвые**: `DailyTrendPeriod` и `CooldownBars` помечены
`// reserved; not yet enforced` и гридом перебирались как no-op. Их и оживляем.

## Цели

1. **Дневной трендовый фильтр** по наклону дневной EMA — отсекать входы, когда
   старший таймфрейм выполаживается/разворачивается.
2. **Кулдаун** после выхода — backstop против повторных заходов в один и тот же
   ломающийся диапазон.
3. Сохранить чистоту ядра `decide()` и обратную совместимость (выключенные
   фильтры = текущее поведение, замороженный baseline-тест зелёный).

Не в scope: захват тренда (partial/trail-гибрид), фильтр силы MACD, фильтр
дистанции до EMA200, out-of-sample на другом тикере — это отдельные итерации.

## Дизайн

### 1. Дневной фильтр по наклону EMA (`DailyTrendPeriod`)

- **Семантика:** при `DailyTrendPeriod > 0` считаем
  `ema.Compute(md.DailyCloses, DailyTrendPeriod)` и пропускаем вход только если
  `EMA[last] > EMA[last - dailyTrendSlopeBars]`.
- **Горизонт наклона:** пакетная константа `dailyTrendSlopeBars = 3`
  (фиксированная политика, как `candleLookbackWeeks` в Golden X; **не** грид-кноб,
  чтобы не раздувать комбинаторику на тонкой выборке).
- **Размещение гейта:** сразу после часового uptrend-гейта (gate 1), до MACD —
  это HTF-подтверждение тренда. Порядок влияет только на короткое замыкание в
  `Explain`, не на итоговое решение (все гейты обязательны).
- **Недостаток дневных данных** (EMA пустая или истории < `DailyTrendPeriod +
  dailyTrendSlopeBars`): гейт **пропускает** (pass) — консистентно с гейтом
  дневного ATR-запаса, который пропускает при отсутствии дневных данных.
- **`DailyTrendPeriod == 0` → фильтр выключен.** Обратная совместимость с
  грид-победителем и замороженным baseline-тестом.

**Реализация:** `buildInput` (грязная оболочка, общая для `Decide` и `Explain`)
вычисляет `dailyEMANow` и `dailyEMAPast` (оба `0`, если данных нет) и кладёт в
`decideInput`. `decide()` и `Explain()` получают по гейту, читающему эти поля.
Ядро остаётся чистой функцией от `decideInput`.

`decideInput` получает новые поля:
- `dailyEMANow float64` — последнее значение дневной EMA (0 если недоступно)
- `dailyEMAPast float64` — значение `dailyTrendSlopeBars` назад (0 если недоступно)
- `dailyTrendKnown bool` — хватило ли истории посчитать обе точки

Логика гейта (псевдокод):

```
if p.DailyTrendPeriod > 0 && in.dailyTrendKnown && !(in.dailyEMANow > in.dailyEMAPast) {
    return sig // дневной тренд не растёт — блок
}
```

### 2. Кулдаун (`CooldownBars`) — чистое ядро + stateful-оболочка

- **Состояние в `Strategy`:** `barsSinceExit int`, `prevInPosition bool`.
- **Обновление в `Decide`** (не в `decide`, не в `buildInput` — `buildInput`
  делит путь с диагностическим `Explain`, который не должен мутировать):
  - переход «была позиция → стала flat» (`prevInPosition && pos == nil`) →
    `barsSinceExit = 0`;
  - иначе, пока flat (`pos == nil`) → `barsSinceExit++`;
  - в позиции — кулдаун нерелевантен, счётчик не трогаем;
  - в конце `prevInPosition = (pos != nil)`.
- **Старт:** `barsSinceExit` инициализируется большим значением (сигнальная
  константа, напр. `math.MaxInt32` или просто достаточно большое), чтобы первые
  входы не блокировались до первого выхода.
- **Гейт в `decide()`:** при `CooldownBars > 0 && pos == nil && barsSinceExit <
  CooldownBars` — вход блокируется. Ставим **первым** entry-гейтом (самый
  дешёвый). Счёт идёт от бара **после** выхода: на баре выхода `decide` вернул
  Sell (не вход), на следующем баре `pos == nil` и `barsSinceExit == 0`.
- **`barsSinceExit` передаётся в `decideInput`** как поле — `decide()` остаётся
  чистым.
- **`Explain`** читает текущий `barsSinceExit` только для отображения статуса
  гейта, **не мутирует**. `Trace` реплеит через `Decide`, поэтому на целевом
  баре счётчик реальный — консистентно с тем, как `Trace` уже показывает позицию.
- **`CooldownBars == 0` → фильтр выключен.**

### Порядок гейтов входа (итог)

1. Кулдаун (`CooldownBars`) — новый, первый
2. Часовой uptrend (`close > EMA200`)
3. **Дневной наклон (`DailyTrendPeriod`) — новый**
4. MACD бычий кросс
5. MACD под нулём (`MACDBelowZeroOnly`)
6. Объём
7. Дневной ATR-запас
8. Анти-черн (`MinATRFrac`)
9. Риск/RR

## Тестирование (TDD — тесты до кода)

`core/core_test.go`, table-driven:

- **Дневной фильтр:** тренд вверх (`dailyEMANow > dailyEMAPast`) → вход разрешён;
  плоский/вниз → блок; `DailyTrendPeriod = 0` → фильтр off (вход проходит при
  любом наклоне); `dailyTrendKnown = false` → pass (данных нет — не блокируем).
- **Кулдаун:** `barsSinceExit < CooldownBars` → блок; `>= CooldownBars` → вход;
  `CooldownBars = 0` → off.
- **Трекинг `barsSinceExit`** на уровне `Strategy`: последовательность `Decide`
  (open → в позиции → close/flat → flat → flat) даёт ожидаемые значения счётчика
  и корректный момент разблокировки.
- **Замороженный baseline-тест** (`DailyTrendPeriod = 0, CooldownBars = 0`) обязан
  остаться зелёным **без изменений** — доказательство обратной совместимости.

## Последовательность калибровки (решение C — измеряем, потом включаем)

1. Реализовать **оба** фильтра (код + тесты), смёржить за зелёным baseline.
2. Прогнать бэктест RUAL **только с дневным фильтром** (`CooldownBars = 0`,
   `DailyTrendPeriod` — кандидат либо sweep через грид). Сравнить с текущим best
   (PF 1.90, DD 10.9%) и проверить, ужался ли кластер №9–14.
3. Кулдаун включать (`CooldownBars > 0`) **только если кластер уцелел**. Иначе
   оставить `0` (код есть, выключен) — YAGNI.

## Риски

- **Переподгонка:** выборка тонкая (23 сделки), грид — best-of-3888. Дневной
  фильтр уменьшаем риск тем, что наклон менее чувствителен к периоду, чем уровень
  EMA200, и горизонт наклона зашит (не калибруется).
- **Чистота ядра:** кулдаун вносит состояние. Митигируем расколом
  stateful-shell (`Strategy.Decide`) / pure-core (`decide`), как уже сделано для
  `buildInput`/`decide`.
