# FVG imbalance — упрощение параметров и проверка третьей свечи

## Цель

Упростить `fvg_imbalance`: полностью удалить из публичных параметров и поведения
`RequireFirstRetest`, `RequireBullishBOS`, `RequireLiquiditySweep`, `SwingK`,
`StructureLookbackBars`, `MaxSweepToFVGBars`, `MaxEntryDistanceATR` и `MaxHoldBars`.
Одновременно усилить определение бычьего FVG обязательным условием
`high[c] > high[b]`, где `c` — третья, а `b` — вторая свеча паттерна.

## Выбранный подход

Выбрано полное удаление, а не сохранение игнорируемых полей для совместимости.
Поля исчезают из `core.Params`, валидации, расчёта lookback, поиска структуры,
ретеста, формирования заявки и сопровождения позиции. JSON с удалённым именем
после изменения считается конфигурацией с неизвестным полем, как и любое другое
неподдерживаемое имя.

Тикерные литералы, актуальные сетки калибровки, тесты, механическая документация
и локальная skill-инструкция калибровки очищаются от удалённых ручек. Исторические
дизайн-документы не переписываются: они фиксируют состояние стратегии на момент
проектирования. Пользовательское изменение `GAZP TakeProfitR = 1.5` сохраняется.

## Итоговое поведение

- FVG по-прежнему требует зелёную вторую свечу, `high[a] < low[c]` и пересечение
  телом второй свечи границ гэпа.
- Дополнительно третья свеча обязана иметь максимум строго выше максимума второй:
  равенство и меньший максимум отвергают паттерн.
- Любой защищённый ретест подходящей глубины допустим в пределах `MaxRetestBars`;
  ограничения «только первый ретест» больше нет.
- Фильтров liquidity sweep и bullish BOS больше нет, поэтому структурные pivot и
  расширенный структурный lookback не рассчитываются.
- Ограничения максимальной цены следующего открытия и выхода по времени больше нет.
  Стоп, цель, H4 EMA и остальные параметры сохраняют текущее поведение.

## Проверка

Сначала добавляется регрессионный тест для `high[c] <= high[b]` и подтверждается
его ожидаемое падение. После минимальной правки удаляются тесты поведения
ликвидируемых функций и обновляются тесты оставшегося API, литералов, registry и
сеток. Затем запускаются focused-тесты `fvg_imbalance`, связанные backtest-тесты и
полный `go test -race ./...` через проектный CI-gate, если существующее состояние
рабочего дерева позволяет его выполнить без вмешательства в чужие изменения.
