# pdl_rsi — вход у вчерашнего лоя по RSI часа и 15 минут

Дата: 2026-10-23. Ветка `feat/pdl-rsi` от `main` (в отдельном worktree: в текущей рабочей копии
на `feat/hammer` лежат незакоммиченные правки `hammer` и `pdl_reclaim`, их не трогаем).

## Зачем

Ещё одна стратегия у вчерашнего лоя (PDL), как `pdl_zone`, но с другим входом: перепроданность на
часе (RSI ниже 30), затем точка входа на 15m по выходу RSI из перепроданности, пока час ещё не
восстановился до 50. Выход — по часовому RSI выше 70, с переносом стопа в безубыток, когда час
пересёк 50. Задача — проверить на бэктесте, есть ли у этого входа край. Параметры по тикерам
настроим потом.

## Цели

- Новая стратегия только для бэктеста: `-strategy pdl_rsi -interval Minutes15`.
- Все числа ниже — параметры (`Params`, int или float64), их перебирает грид `-calibrate`.
- Дефолты в `core.DefaultParams()` — значения владельца из этого документа.

## Не цели

- Живой раннер, конфиг вселенной, Telegram — не делаем.
- Пакеты тикеров сейчас не заводим: литерал появится после калибровки тикера (правило проекта —
  после калибровки пакет тикера заводится всегда). Registry работает с `core.DefaultParams` для любого
  тикера, как `pdl_zone` для тикеров без пакета.
- Цель по цене (take profit), фильтры тренда, окна времени — нет.

## Анти-цели

- Поведение других стратегий (`pdl_zone`, `pdl_reclaim`, `drop_bounce`, `hammer` …) не меняется:
  их тесты и бэктест дают тот же результат. Общий код не рефакторим — копируем.
- Не подглядывать в будущее: часовой RSI — только по завершённым часам, сигнал — по закрытому
  15m-бару, покупка — на открытии следующего.

## Правила (решения владельца)

Таймфрейм данных: 15m. Часовые бары ядро собирает само из 15m, как `drop_bounce` (`hourBars`): час
завершён на закрытии своего бара :45 или, если его нет, на первом баре следующего часа.

**Уровень и ATR.** PDL — лой последнего завершённого буднего дневного бара. Дневной ATR — Wilder по
завершённым будним дневкам, период `DailyATRPeriod` (14), как в `pdl_zone`/`hammer`. ATR берётся на
дату сигнала.

**Зона интереса.** PDL − `ZoneATR` × ATR … PDL + `ZoneATR` × ATR, `ZoneATR` = 0.4. В зоне должен
лежать **лой сигнального 15m-бара**: PDL − Z·ATR ≤ low ≤ PDL + Z·ATR.

**RSI.** Один период `RSIPeriod` = 6 (Wilder) и на часе (по часовым закрытиям), и на 15m (по закрытиям
15m). Уровни: `RSIArm` = 30 (час), `RSIEntry` = 30 (15m), `RSIGate` = 50 (час, запрет входа),
`RSIBreakeven` = 50 (час, перенос стопа), `RSIExit` = 70 (час). `RSIGate` и `RSIBreakeven` — два поля,
чтобы выключение и калибровка одного не задевали другое (моё решение).

**Взвод (час).** Завершённый час с RSI < `RSIArm` взводит сетап: с этого момента ищем вход на 15m.

**Сигнал (15m).** Закрытый 15m-бар, на котором RSI(6) пересёк `RSIEntry` снизу вверх (предыдущий
бар < 30, этот ≥ 30), при условиях:
- сетап взведён, и часовой RSI с момента взвода ещё не пересекал `RSIGate` (50) снизу вверх
  (`RSIGate` = 0 — проверки нет);
- лой этого бара в зоне интереса;
- фильтр объёма пройден;
- фильтр запаса хода пройден;
- бар покупки (следующий 15m) — будний день (Пн–Пт MSK) той же даты, что и сигнальный бар.

Покупка — на открытии следующего 15m-бара (`EntryAtNextOpen`).

**Объём («повышенный фон»).** Средний объём 15m-баров основной сессии от начала окна поиска (см.
ниже) до сигнального бара включительно больше `VolumeMult` × среднего объёма `VolBars` баров
основной сессии перед началом окна. Дефолты `VolumeMult` = 1.5, `VolBars` = 20. Основная сессия —
10:00–18:30 MSK, как в `pdl_zone`. Нет ни одного бара основной сессии в окне или в базе — фильтр не
пройден. `VolumeMult` = 0 выключает фильтр.

**Запас дневного хода.** На сигнале: (лой даты сигнала до сигнального бара включительно + 1 ATR −
close сигнального бара) ≥ `MinRoomATR` × ATR, `MinRoomATR` = 0.6. Как в `pdl_zone`. 0 — выключен.

**Стоп.** Минимальный лой 15m-баров окна поиска, у которых RSI(6) на 15m < `RSIEntry`, и самого
сигнального бара (решение владельца: у бара креста часто длинная нижняя тень). Сигнал
покупки несёт стоп (для `-risk-pct`). Стоп ставится от сигнала и не пересчитывается от цены покупки.

**Безубыток.** Если в позиции часовой RSI пересекает `RSIBreakeven` (50) снизу вверх (на часе,
завершённом после покупки), стоп переносится в цену покупки начиная со следующего 15m-бара.
Только вверх: стоп не опускается. `RSIBreakeven` = 0 выключает перенос.

**Выход.** По порядку на каждом баре:
1. стоп — внутри бара по low (причина `SL`, а после переноса — `TRAIL`: движок исполняет по уровню
   стопа только причины из `model.IsStopReason`; код `BE` занят в `reversion` и исполняется по close,
   а общий код не трогаем — моё решение);
2. на 15m-баре, который завершает час, часовой RSI пересёк `RSIExit` (70) снизу вверх — продажа по
   close этого бара (причина RSI).

Позиция переносится через ночь и выходные. Других выходов нет.

## Решения, принятые мной (проверь)

1. **Окно поиска** начинается с первого 15m-бара часа взвода (того часа, чьё закрытие RSI < 30
   взвело сетап) и идёт до сигнального бара. Из него берутся стоп (бары с 15m RSI < 30) и окно
   объёма. Сигналом может быть только бар после закрытия часа взвода: раньше RSI часа неизвестен.
2. **Повторный взвод не сдвигает окно:** пока сетап жив, следующие часы с RSI < 30 его не
   перевзводят, окно и стоп считаются от первого часа взвода.
3. **Сетап сгорает**, если часовой RSI пересёк `RSIGate` снизу вверх до сигнала, или если на сигнальном
   кресте (15m RSI ≥ 30 с лоем в зоне) не прошли объём, запас хода или день покупки. После этого
   нужен новый завершённый час с RSI < 30. Крест 15m RSI вверх с лоем **вне** зоны сетап не сжигает —
   ждём следующего креста (RSI снова должен уйти ниже 30 и вернуться).
4. **Один сигнал на сетап:** покупка сжигает сетап; новая сделка — только после нового взвода.
   Если в момент сигнала позиция уже открыта, сигнал тоже сжигает сетап (ядро без состояния
   восстанавливает автомат «ожидание → взвод → сигнал/сгорание» по барам окна на каждом баре, как
   `pdl_zone`).
5. **Сетап не переживает свою дату:** взвод и сигнал — одна дата MSK. Взвод вечером, вход утром
   следующего дня — нет. Причина — простота и ограниченный Lookback; если нужно, меняется одним
   условием.
6. **«Час ещё не пересёк 50»** проверяется по завершённым часам: последний завершённый час на
   момент сигнала. Формирующийся час не смотрим.
7. **Гэп ниже стопа:** если открытие бара покупки ниже стопа, движок закрывает по стопу на первой
   проверке — отдельного фильтра нет.
8. **Только Minutes15.** Другие интервалы registry отклоняет.
9. **RSI на часе и на 15m считаются по всем барам окна** движка, прогрев переходит через ночь.
10. **Хелперы копируются** (будние дневки, ATR, PDL, сборка часов, среднее объёма основной сессии)
    из `pdl_zone`/`drop_bounce` в новый `core`, без выноса в общий пакет.

## Что строить

- `internal/service/trading_strategy/pdl_rsi/strategy/core/` — `Params`, `DefaultParams()`,
  `NewWithParams(ticker, step, p)`, `Decide`, `Lookback`, причины входа/выхода по-русски (как у
  соседей, в т.ч. объём, запас хода, стоп, уровень PDL).
- `internal/service/backtest/pdl_rsi_registry.go` (+ тест) — по образцу `pdl_zone_registry.go`, пустой
  реестр тикеров, `core.DefaultParams` по умолчанию, только Minutes15.
- `cmd/backtest/main.go` — кейс `pdl_rsi`, строки помощи, `EntryAtNextOpen`, `-risk-pct`.
- `data/params/pdl_rsi/grid_example.json` — стартовая сетка.
- `docs/pdl_rsi/strategy.md` — только механика (правила, параметры, запуск).
- Строка про `pdl_rsi` в разделе Layout в `CLAUDE.md`.
- Тесты ядра: сборка часов, взвод по часу, сигнал по кресту 15m, лой в зоне / вне зоны (вне — не
  сжигает), час уже пересёк 50 — сгорание, объём пройден/провален/нет баров сессии, запас хода,
  выходные и другая дата покупки, стоп = минимум лоев баров RSI < 30 окна и сигнального бара
  (в т.ч. случай, когда лой сигнального ниже всех), один сигнал на сетап,
  безубыток по кресту 50 после покупки (и не раньше), выход по кресту 70 на баре закрытия часа,
  порядок стоп → RSI, перенос через ночь.

## Калибровка (после реализации, отдельной задачей)

По правилам проекта: скользящий walk-forward `-train-months 3 -test-months 1`, вердикт по пулу OOS,
`-risk-pct 1`. Сетка — `ZoneATR`, `RSIPeriod`, `VolumeMult`, `VolBars`, `MinRoomATR`, уровни RSI.
Тикеры и окно выберет владелец.

## На усмотрение исполнителя

Внутренняя структура ядра, имена хелперов, формат причин, точное значение `Lookback` (должен
покрывать прогрев часового RSI, `VolBars` баров основной сессии до окна, целый день 15m-баров и
выходные).
