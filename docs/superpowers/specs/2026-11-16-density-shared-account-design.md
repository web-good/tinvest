# Density на общем счёте live-стратегий

Пользователь потребовал подключить density к общему счёту и общему учёту
live-стратегий. Это дополнение к утверждённой density-live стратегии: один
лот, одна density-позиция, прежние сигналы/стоп/тейк/отмена по плотности.
Реальные торговые действия во время разработки не выполняются.

## Подход

Density становится непрерывным участником приложения на счёте
`RSI_PULLBACK_ACCOUNT_ID`, с его же `RSI_PULLBACK_TOKEN` и gRPC-соединением.
Поток стакана остаётся независимым от свечного расписания. Раннер RSI и его
гости используют общий координатор владения тикерами и постановки входов.
Пользователь выбрал подключение к общему учёту после объяснения конфликта
независимых процессов. Замена density на свечной адаптер нарушила бы реакцию
на стакан; простое совпадение account ID не согласует позиции и поручения.

## Инварианты

- Один тикер одновременно принадлежит одной стратегии, включая ожидающий вход.
- Density не покупает тикер с записью в общем state или существующим
  чужим остатком/ордером/стопом. Занятый T не мешает попробовать свободный SBER.
- Свечной раннер пропускает density-владение до реконструкции позиции,
  смены стопов, продаж и новых входов.
- Входы density и свечной пасс сериализуются общей блокировкой счёта.
  Это может откладывать новые density-входы на время свечного пасса.
  Сопровождение уже созданной density-заявки/позиции эту блокировку не берёт:
  исчезновение плотности продолжает обрабатываться независимо от свечного пасса.
- Свечной пасс получает снимок владения после общей блокировки и до снимка
  портфеля. Все density-владения из этого снимка пропускаются на всём пассе,
  даже если density успела закрыться: устаревшую позицию нельзя присвоить RSI.
- Владение density сохраняется на диске до отправки BUY и не снимается при
  таймауте, неизвестном исполнении, ошибке журнала или выключении участника.
- После подтверждённого завершения эпизода сначала сохраняются результат и
  намерение освобождения владения, затем запись владения переводится в closed.
  Повтор завершения идемпотентен. Общий раннер удаляет closed-метку только при
  отсутствии позиции и общей записи по тикеру в своём новом снимке.
- Обычный live BUY также резервирует тикер перед отправкой: неопределённый
  результат старого раннера не должен позволять density занять тот же тикер.
  После сохранения обычной позиции в общем state резерв можно снять.
- Ошибки чтения владения блокируют торговые решения; старые записи владельцев
  не перезаписываются и не переводятся автоматически в density.

## Хранение

Координатор хранит отдельные durable-записи владельцев в смонтированном
`data/state` рядом с существующим общим state. Старый JSON RSI/FVG сохраняет
свой формат; density не добавляет в него неполные ATR-записи.
Координатор читает существующий state при разрешении density-входа.
Блокировка и записи привязаны к хешу счёта. Перед разрешением торговых
действий синхронизируются файлы и каталоги. Общая блокировка используется
обоими участниками, включая разные экземпляры нового приложения на одном
общем хранилище. Запуск старой версии приложения без координатора одновременно
с новой не поддерживается.

Density-журнал находится в `data/state/density` (настраиваемый корень), чтобы
пережить перезапуск контейнера вместе с общим state. При смене каталога нельзя
обойти существующее владение. В snapshot хранится идентификатор координатора.
Standalone-режим `cmd/density-live -trade` отключается с явным сообщением:
реальная общая торговля запускается только приложением с координатором.
Команда может оставаться инструментом read-only проверки.

## Настройки и жизненный цикл

`DENSITY_LIVE_ENABLED`, `DENSITY_LIVE_TRADE_ENABLED`, `DENSITY_LIVE_TICKERS`
(T,SBER), `DENSITY_LIVE_STATE_DIR` и параметры существующей стратегии.
По умолчанию реальная торговля выключена. Новый отдельный счёт/токен не нужен.
Отключённый live-участник не снимает чужое/своё незавершённое владение:
общий раннер продолжает его учитывать. При выключенном trade новые реальные
поручения не отправляются. Для recovery вновь включают участника с trade.

В основном App старт/остановка density live — как непрерывного воркера.
Неподнявшийся density не останавливает сопровождение чужих позиций; ошибка
видима в логах, а его сохранённое владение остаётся заблокированным.
Штатная остановка пытается разрешить собственный эпизод; неизвестные результаты
остаются в журнале и общем учёте. Свечной worker получает координатор ещё до
первого пасса, даже если density сейчас выключена.

## Проверки

Тесты без торговых API: общий счёт/токен/координатор в DI; busy-тикер другой
стратегии; свободный соседний тикер; пропуск density до реконструкции RSI;
параллельные входы; реакция на исчезновение при занятой общей блокировке;
snapshot held-позиции после закрытия density; uncertain BUY обычной стратегии;
restart с активным владением/незавершённым освобождением; неверный каталог;
ошибки журнала; выключенный участник; остановка App; запрещённый standalone trade.
Race, vet, сборка и relevant lint. Основной checkout с незакоммиченными
изменениями бэктеста не изменяется; перенос в него остаётся отдельным этапом.


## Уточнения по проверке реализации

- Снимок владельцев, включая closed, остаётся исключением на всём текущем
  свечном пассе; удаление closed-записи не разрешает действие на старом портфеле.
- Завершение density доказано собственными terminal-заявками и читающей сверкой
  отсутствия остатка, биржевых поручений и активных стопов до release intent.
- Отдельный density lifetime-flock и привязка журнала находятся на общем томе,
  а не только в пользовательском cache; резерв ограничен одной density на счёт.
- Перед передачей обычной позиции в legacy state синхронизируются содержимое
  state-файла и каталоги; неуспешный Save не снимает резерв, даже когда новые
  байты уже видны читателю.
