# gap_fade — скринер тикеров (`cmd/gapscreen`)

Дата: 2026-10-02. Подпроект 1 из 2. Подпроект 2 — live gap_fade гостем раннера rsi_pullback на
общем счёте — получит отдельную спеку после того, как этот подпроект даст набор, прошедший гейт.

## Зачем

gap_fade проверялась на вселенной `RSI_PULLBACK_TICKERS`. Этот набор отобран под другую
стратегию: у половины тикеров медианный оборот бара 07:00 меньше 1.5 млн ₽, а крупнейшие
источники прибыли в отчёте гейта (TGKA, LSNGP, BANEP, VSMO, IRKT) не входят даже в топ-60 по
утреннему обороту. В тонком стакане бэктест покупает по open, по которому реально не купить.
gap_fade нужен свой набор тикеров `GAP_FADE_TICKERS`, где вход в 07:00 исполним.

## Принцип отбора

Скринер отбирает тикеры по устройству бумаги, а не по прибыли стратегии на тикере. На один
тикер приходятся единицы сигналов за год — PF по ним шум. Прибыль проверяется один раз, гейтом
`cmd/gapwf` на всём отобранном наборе. Если гейт на ликвидном наборе не пройден, live не делается.

## Метрики (по 30m-свечам за окно `-months`, MSK)

| Метрика | Как считается |
|---|---|
| Утреннее присутствие | доля будних дат окна (дата с хотя бы одним баром), в которых есть бар с началом 07:00 |
| Утренний оборот | медиана по будним датам с баром 07:00 оборота этого бара: `volume · lot · close`, млн ₽ |
| Дневной оборот | `backtest.MeanDailyTurnoverM(bars, lot)`, млн ₽ |
| Доля шага | `2 · MinPriceIncrement / последний close · 100`, %; 0 при неизвестном шаге |
| Сигналов в год | число сделок прогона `gap_fade` с общими параметрами (`GapFadeLookupOrGeneric`, дефолты) тем же вызовом движка, что в `cmd/gapwf` (`EntryAtNextOpen: true`), делённое на длину окна в годах |

Сигналы считаются прогоном движка, а не своей формулой: правило гэпа одно, скринер и бэктест не
расходятся. Прибыль этого прогона в отчёт не выводится и в отборе не участвует.

## Гейты (все флагами)

| Флаг | Дефолт | Отказ, если |
|---|---|---|
| `-min-morning-days` | 0.9 | утреннее присутствие ниже |
| `-min-morning-turnover` | 5 | утренний оборот ниже (5 млн ₽: позиция 100 тыс. ₽ — 2% бара) |
| `-max-tick-pct` | 0.2 | доля шага выше; неизвестный шаг (0) — гейт не применяется |
| `-min-turnover` | 50 | дневной оборот ниже |

Сигналов в год — справочная колонка, не гейт.

## Устройство

- `internal/service/backtest/gap_screen.go` — чистое ядро:
  - `GapScreenOptions` — пороги гейтов;
  - `GapScreenRow` — тикер, метрики, `Pass bool`, `Reasons []string` (по одной причине на
    проваленный гейт, тексты на русском);
  - `GapMorningStats(bars, lot)` — утреннее присутствие и утренний оборот;
  - `GapSignalsPerYear(ticker, bars, daily, lot, months)` — сигналы в год прогоном движка;
  - `ScreenGap(GapScreenInput, opts) GapScreenRow` — собирает строку, гейты применяет
    `ApplyGapGates(row, opts)`.
- `internal/service/backtest/gap_screen_report.go` — markdown: параметры прогона; прошедшие по
  убыванию утреннего оборота; отсеянные с причинами; тикеры «нет данных»; итоговая строка
  `GAP_FADE_TICKERS=A,B,C` (порядок как в таблице прошедших).
- `cmd/gapscreen/main.go` — обвязка по образцу `cmd/zonescreen`: `screenrun.LoadUniverse`, кэш
  свечей `NewCandleProvider`, пул воркеров, флаги `-months 12`, `-tickers`, `-workers 8`,
  `-pause`, `-refresh`, `-out reports/gap_fade` (число сделок от издержек не зависит, флага издержек нет); отчёт
  `reports/gap_fade/screen_<время>.md`; в консоль — число прошедших и путь к отчёту.

## Ошибки

- Свечи тикера не скачались или их нет — строка «нет данных», прогон продолжается.
- Прогон падает только при ошибке загрузки вселенной или записи отчёта.
- Ноль прошедших — отчёт пишется, строка `GAP_FADE_TICKERS=` пустая, в консоли предупреждение.
- Невалидные флаги (порог < 0, доля дней вне [0, 1], `-months` ≤ 0, `-workers` ≤ 0) — ошибка
  до сети.

## `cmd/gapwf`

- Вселенная по умолчанию — `GAP_FADE_TICKERS` из `-env-file` (было `RSI_PULLBACK_TICKERS`).
- Без запасного варианта: пустая переменная — ошибка с подсказкой запустить `cmd/gapscreen`.
  Набор pullback по-прежнему задаётся через `-tickers`.
- Если гейт на наборе скринера пройден, строка `GAP_FADE_TICKERS` вписывается в `env/prod.env`
  (live её пока не читает).

## Тесты

- Ядро, таблично на синтетических барах: утреннее присутствие (дни без бара 07:00, выходные не
  считаются), медиана утреннего оборота с лотом, доля шага и неизвестный шаг, каждая причина
  отказа отдельно, прохождение всех гейтов.
- Сигналы в год: на синтетических барах с одним гэпом прогон даёт ровно одну сделку.
- Отчёт: порядок прошедших, причины отказа, итоговая строка, пустой набор.
- `cmd/gapscreen`: валидация флагов.
- `cmd/gapwf`: `defaultTickers` читает `GAP_FADE_TICKERS`, пустая — ошибка с её именем.
