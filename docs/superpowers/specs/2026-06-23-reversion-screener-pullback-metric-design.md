# Reversion-скринер: переход на pullback-in-trend метрику (Hour1)

**Дата:** 2026-06-23
**Ветка:** feat/reversion-rsi-dip
**Связано:** `[[project_reversion_screener]]`, `[[project_reversion_strategy]]`

## Проблема

Текущий скринер (`-volrank`, `internal/service/backtest/volatility_screen.go`,
математика в `internal/domain/backtest/variance_ratio.go`, запуск в
`cmd/backtest/main.go:runVolRank`) ранжирует вселенную по «пригодности под
mean-reversion» через variance ratio. Эмпирически ранжирование **плохо
предсказывает** успех стратегии: из трёх walk-forward-победителей (EUTR, NVTK,
UGLD) в топ-50 попал только EUTR; NVTK и UGLD пропущены.

Две корневые причины (пункты 1 и 2 бэклога):

1. **Timeframe mismatch.** Метрики возврата (VR, autocorr) считаются на Day1, а
   стратегия торгует **Hour1**. Дневной возврат к среднему не переносится на час.
2. **Неверная цель.** Стратегия — это «покупка отката внутри аптренда»
   (buy-the-dip с трендовым фильтром + HTF EMA), а не чистый mean-reversion.
   Фильтр `VR(2) > 1.05 → trending → exclude` активно выбрасывает трендовые имена
   — ровно тот класс, где стратегия зарабатывает (вероятная причина промаха NVTK).

## Решение (вариант A — лёгкий прокси, без запуска движка)

Заменяем VR-метрику на **прямую симуляцию pullback-in-trend событий на Hour1**.
Скринер сам пробегает по часовым барам и измеряет *наличие ловибельной
возможности*, не запуская полный движок стратегии (тот зависит от некалиброванных
generic-дефолтов выходов и шумит).

### Определение pullback-события

На Hour1, зеркалим суть входа стратегии упрощённо:

1. **Тренд-контекст:** `close > EMA200`. Берём EMA200 (а не пару FastEMA/SlowEMA
   из стратегии — она per-ticker тюнится); EMA200 — стабильный признак аптренда.
   Это замена удалённого VR-фильтра: вместо «отсей трендовые» → «считай события
   **внутри** тренда».
2. **Триггер просадки:** `RSI(RSIPeriod)` пересекает **вниз** порог
   `RSIOversold`. Только RSI, без Stoch (прокси; дуальное подтверждение добавляет
   параметр и шум).
3. **Критерий восстановления (успех):** в течение `RecoverBars` баров после
   провала RSI возвращается **выше** `RecoverRSI`. Берём RSI→50, потому что это
   первичный выход самой стратегии (`RSI50`) — событие «успешно» ровно тогда,
   когда стратегия бы заработала.

Дефолты: `RSIPeriod=14`, `RSIOversold=30`, `RecoverBars=24`, `RecoverRSI=50`.

На тикер получаем:
- **recoveryRate** = доля провалов, восстановившихся за `RecoverBars` (качество edge);
- **eventFreq** = частота событий (число провалов на единицу времени; нормируется
  на число баров — события на 1000 баров, чтобы сравнивать тикеры с разной историей).

### Формула Score

```
Score = wRecov·перцентиль(recoveryRate)
      + wFreq ·перцентиль(eventFreq)
      + wLiq  ·перцентиль(turnover)
```

Дефолты: `wRecov=0.5, wFreq=0.3, wLiq=0.2`. Перцентили — относительно прошедших
фильтр строк (как сейчас). Логика весов: качество edge важнее всего, но без
частоты событий имя неторгуемо, ликвидность — гигиена.

### Что меняется в фильтрах и колонках

- **ATR% убран из Score** (был вес 0.4, тянул к самым опасным именам — пункт 5).
  Остаётся **справочной колонкой**, считается на Hour1 («часовой ATR%»), ранжир
  не двигает.
- **VR(2)/Autocorr** — остаются **справочными колонками** (информативно), но из
  Score убраны и **фильтр `VR2>1.05 → trending` удалён полностью**.
  `DroppedTrending` из меты уходит. VR/autocorr считаются на тех же Hour1-возвратах.
- **Порог ликвидности** (turnover ≥ `MinTurnover`, дефолт 50 млн ₽/день) —
  остаётся фильтром-флором (гигиена, не предсказание).
- **Фильтр истории:** минимум баров = `200 + RecoverBars` (прогрев EMA200 + запас
  на восстановление). Тикеры короче — пропускаются. Частично закрывает пункт 3
  (полную нормировку окна оставляем на потом).

### Данные и ликвидность (нюанс Hour1)

Грузим **только Hour1** (один fetch на тикер, без двойной загрузки Day1). Порог
ликвидности задан в **₽/день**, поэтому дневной оборот считаем, **группируя
часовые бары по календарной дате** (по `Candle.Time`) и усредняя суммы по дням —
точный дневной оборот в тех же единицах, флаг `-min-turnover` не меняется.

Окно — `-months` (дефолт 12); на Hour1 это ~2000+ баров, EMA200 прогревается.

Создать **`docs/reversion/screener.md`** (пользовательская дока, рядом с

## Тестирование (TDD)

- `PullbackStats`: серия без событий → 0/0; серия с известным числом провалов и
  восстановлений → точные recoveryRate/eventFreq/events; провал без
  восстановления за N баров → не считается успехом; провал у самого конца серии
  (нет N баров впереди) → решить и протестировать (исключаем из знаменателя —
  событие незавершённое).
- дневной оборот из Hour1: бары двух дат → корректное среднее по дням; пустой
  вход → 0.
- `ScoreVolRows`: новые веса, проверка перцентильного смешивания; ATR%/VR не
  влияют.
- `RenderVolatilityMarkdown`: новые колонки/заголовок присутствуют, ранжир по
  Score убыв.
