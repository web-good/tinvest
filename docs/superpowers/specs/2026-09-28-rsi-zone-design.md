# RSI zone (30m, лонг, многодневный) — дизайн

Дата: 2026-09-28. Статус: утверждён и реализован.

## Цель

Простая стратегия «купи критическую перепроданность в тренде, продай критическую
перекупленность, защищайся стопом в дневных ATR». Нужна как самостоятельная минимальная
стратегия, отдельная от `rsi_pullback`: без гейта состояния дня, цели, объёмного гейта и трейла,
с трендом по одной EMA (`close > EMA(N)`) вместо пары EMA. Параметры подбираются фазовым
гридом калибратора.

Что сказал владелец:
- таймфрейм — 30 минут;
- покупка, когда RSI в нижней критической зоне и цена выше EMA 200 (период — параметр);
- длина RSI — параметр, варианты 4, 5, 6, по умолчанию 4;
- продажа, когда RSI выше верхней критической зоны;
- защита — стоп-лосс, равный ATR; ATR **дневной**, не внутридневной;
- вход — **событие** пересечения нижней зоны (как в `rsi_pullback`), а не состояние
  «RSI в зоне»;
- отдельный пакет, а не профиль параметров `rsi_pullback`.

Допущения (мои, приняты владельцем вместе с дизайном):
- дефолтные зоны 25/75 (у RSI(4) уровни 30/70 пересекаются почти каждый день);
- стоп по умолчанию 1.0 дневного ATR;
- входы только в будние дни MSK;
- пока только бэктест; live-раннер — отдельная задача после взятой планки
  (pooled OOS PF ≥ 1.5).

## Критерий успеха этой задачи

Стратегия запускается через `go run ./cmd/backtest -strategy rsi_zone -interval Minutes30`,
калибруется файлом `data/params/rsi_zone/grid.json`, покрыта табличными тестами ядра,
`./bin/mage ci` зелёный. Наличие edge — НЕ критерий этой задачи; это вопрос последующей
калибровки.

## Параметры

Все поля `core.Params` — `int` или `float64`, чтобы их видела рефлексивная сетка
(`applyField` в `internal/service/backtest/calibrate.go`).

| Поле | Тип | Дефолт | Смысл |
|---|---|---|---|
| `RSIPeriod` | int | 4 | длина RSI (Уайлдер, `indicators.RSISeries`) |
| `RSILower` | float64 | 25 | нижняя критическая зона; пересечение ВНИЗ — вход |
| `RSIUpper` | float64 | 75 | верхняя критическая зона; пересечение ВВЕРХ — выход |
| `EMAPeriod` | int | 200 | фильтр тренда: `close > EMA(EMAPeriod)` |
| `DailyATRPeriod` | int | 14 | ATR Уайлдера по завершённым будним дневным свечам |
| `StopDailyATR` | float64 | 1.0 | стоп = вход − `StopDailyATR` × дневной ATR |

`DefaultParams()` возвращает эту таблицу.

## Lookback

`Lookback() = max(minLookback, 2*max(EMAPeriod, RSIPeriod) + 20)`, `minLookback = 120`.
Та же причина, что в `rsi_pullback`: `ema.Compute` сидирует SMA по первым `period` закрытиям,
окно короче периода даёт нулевую серию и молча проваливает фильтр тренда.

## Вход

Позиции нет. Проверки на закрытии последнего бара `i = n-1`, по порядку; первый
несработавший гейт отклоняет вход. Нужны `n ≥ 2` и выровненные `Highs`/`Lows`/`Closes`.

1. **Будний день.** Время бара по MSK не суббота и не воскресенье. Нулевое время бара
   (или `Times`, не выровненный с `Closes`) гейт пропускает. Причина: бары выходных сессий
   MOEX много уже и тоньше будних, а стоп меряется дневным ATR будних дней.
2. **RSI-крест вниз.** `rsi[i-1] > 0 && rsi[i-1] ≥ RSILower && rsi[i] < RSILower`. Событие,
   не состояние: пока RSI сидит под порогом без нового пересечения, повторного входа нет.
3. **Тренд.** `ema[i] > 0 && close[i] > ema[i]`. Равенство — не тренд.
4. **Дневной ATR.** `dailyATR > 0`, иначе вход отклоняется.
5. **Стоп положителен.** `stop = close[i] − StopDailyATR × dailyATR`; при
   `StopDailyATR > 0 && stop ≤ 0` вход отклоняется (иначе голый лонг без защиты).

Сигнал входа: `Kind = SignalBuy`, `StopLoss = stop` (0 при `StopDailyATR = 0`),
`TakeProfit = 0`, `ATR = dailyATR` (движок кладёт его в `Position.EntryATR`), `RSI = rsi[i]`,
`EntryReason` — человекочитаемая строка на русском: RSI, EMA, дневной ATR, вход, стоп.

### Дневной ATR

`indicators.ATR(h, l, c, DailyATRPeriod)` по `md.DailyHighs/Lows/Closes`, из которых
выброшены бары суббот и воскресений по MSK (`md.DailyTimes`). Если `DailyTimes` не выровнен с
ценами — серия берётся как есть. Нужно минимум `DailyATRPeriod + 1` дневок, иначе 0.
`DailyATRPeriod ≤ 0` → 0. Движок отдаёт только завершённые до текущего бара дни — lookahead
исключён.

Помощники (`weekdayDaily`, `dailyATR`, `crossedDown`, `crossedUp`, `isWeekend`, MSK-локация)
копируются из `rsi_pullback/strategy/core`, а не импортируются: там они неэкспортированы, и
новая стратегия не должна зависеть от внутренностей чужого ядра (тот же подход, что у
`rsi_ema`).

## Выход

Позиция открыта. Приоритет строго `SL → RSI`, срабатывает первый подошедший. Тайм-стопа,
цели, трейла и закрытия по концу дня нет; позиция переносится через ночь и выходные.

1. **`SL`.** Уровень `level = PurchasePrice − StopDailyATR × EntryATR` (заморожен на входе).
   Стопа нет, если `StopDailyATR ≤ 0`, `EntryATR ≤ 0` или `level ≤ 0`. Срабатывает при
   `low[i] ≤ level`: `Kind = SignalSell`, `Reason = "SL"`, `StopLoss = level`. Цену
   исполнения стопа движок определяет через `model.IsStopReason`.
2. **`RSI`.** `rsi[i-1] > 0 && rsi[i-1] ≤ RSIUpper && rsi[i] > RSIUpper` — пересечение
   верхней зоны снизу вверх на текущем баре; исполнение по close. `Reason = "RSI"`.

Если один бар задевает стоп и одновременно даёт RSI-выход — побеждает `SL` (внутрибарный
порядок из OHLC неизвестен, берётся худший исход).

`ExitReason` — строка на русском с low/уровнем или RSI/close и ценой входа.

## Грид `data/params/rsi_zone/grid.json`

Фазовый формат калибратора (`phases`, `keepTop`, `grid`), `_comment` описывает фазы.

| Фаза | keepTop | Оси |
|---|---|---|
| `entry` | 5 | `RSIPeriod` [4, 5, 6] × `RSILower` [10, 15, 20, 25, 30] |
| `trend` | 5 | `EMAPeriod` [50, 100, 150, 200] |
| `exit` | 5 | `RSIUpper` [60, 65, 70, 75, 80, 85] |
| `risk` | — | `StopDailyATR` [0.5, 0.7, 1.0, 1.5] |

Итого 15 + 5×4 + 5×6 + 5×4 = 85 комбо. `StopDailyATR = 0` в сетку намеренно не входит.
`DailyATRPeriod` фиксирован. Судить по pooled OOS profit factor walk-forward, не по
in-sample лучшему.

## Тесты (TDD)

Табличные тесты ядра на синтетических свечах:
- вход срабатывает при всех гейтах;
- отказ по каждому гейту отдельно: выходные, нет креста (RSI сидит в зоне), close ≤ EMA,
  EMA не прогрета, дневной ATR = 0 (мало дневок), стоп ≤ 0;
- на выходных дневках фильтр отбрасывает бары суббот/воскресений;
- выход `SL` по `low ≤ level`, уровень считается от `EntryATR`, а не от текущего ATR;
- выход `RSI` по пересечению вверх; нет выхода, пока RSI сидит выше без нового креста;
- стоп побеждает RSI-выход на общем баре;
- `EntryATR ≤ 0` — стопа нет;
- `Lookback` покрывает `2*EMAPeriod+20` и не меньше `minLookback`;
- помощники кросса на границах (значение ровно на уровне — не пересечение).

Реестр: binding строит стратегию, `ParseParams` накладывает частичный JSON на дефолты,
отвергает битый JSON. Грид: `grid.json` парсится калибратором, и каждая ось — существующее
поле `core.Params` (по образцу `*_grid_test.go` в `internal/service/backtest`).
