# Density: алерты виртуального исполнения

Пользователь выбрал уведомление при исполнении виртуальной заявки, а не при
её выставлении. `DENSITY_LIVE_ENABLED=false` выключает участника;
`true` + `DENSITY_LIVE_TRADE_ENABLED=false` запускают симуляцию;
оба true сохраняют реальную торговлю. В prod включить симуляцию, реальные заявки
не включать. Общий Telegram-скринер остаётся независимым.

Варианты: алерт при сигнале слишком ранний; выбран существующий paper engine,
который требует последующий trade-through. Подключить к основному приложению
с отдельным журналом и Telegram-уведомлениями. Реальные брокерские методы и
координатор счёта в симуляции не создаются. Рыночный токен — общий T_BANK,
RSI-аккаунт и торговый токен не нужны.

Единый детектор/история/тикеры/вход/стоп/тейк/таймеры как у live. По уточнению
пользователя нужны только цены «купили бы»/«продали бы», без размера позиции,
баланса, комиссии и искусственной задержки. Внутренний paper-вход использует
одну единицу исполнения, IgnoreCapital=true, Commission=0, Latency=0;
эти технические величины в сообщение не попадают и env для них не вводятся.

Только entry_filled и exit_filled порождают Telegram-сообщения с явной пометкой
«СИМУЛЯЦИЯ — реальных заявок нет». Сообщение показывает тикер, цену и время;
выход — также причину. Это оценка исполнения, не гарантия реального fill.

Сетевые отправки выполняются отдельно от потока paper-движка; очередь сообщений
сохраняется на диск и повторяется при ошибке отправки, также после перезапуска.
Журналы виртуальных сессий — STATE_DIR/paper/<session>/, очередь —
STATE_DIR/paper/outbox.json. Каждая сессия начинает наблюдение заново; незакрытые виртуальные позиции при остановке отмечаются unresolved,
фиктивные продажи не создаются. Второй симулятор в том же root не запускается.
При незавершённых реальных density-эпизодах переключение в симуляцию отклоняется,
чтобы не скрыть реальные позиции. Существующие real-журналы не меняются.

Проверки: no alert on placement/touch/pre-latency; fill-only alert; one lot;
retry/restart queue, slow Telegram cannot stop simulation, no broker/account
dependency in simulation, unchanged real routing, state guard, env validation.
