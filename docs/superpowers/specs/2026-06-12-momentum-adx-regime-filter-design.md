# Momentum: единый ADX-режимный фильтр

**Дата:** 2026-06-12
**Ветка:** `feat/momentum-daily-trend-cooldown`
**Статус:** дизайн утверждён, готов к плану

## Мотивация

Walk-forward по корзине на confluence-дизайне (2026-06-12, OOS 2025-06-12→2026-06-12,
`-months 24 -test-months 12 -min-trades 10`) дал **pooled OOS Profit Factor 0.550** —
лучше прежних 0.406, но это по-прежнему убыточная система (PF < 1, expectancy −211/сделку,
133 сделки, WR 28.6%). Отчёт: `reports/basket/basket/basket_momentum_20260612_002947.md`.

Убыток сконцентрирован: GAZP (−12.4%, 42 сделки, PF 0.325), SBER (−6.6%), MDMG (PF 0.094).
Общее у них — **высоковолатильный боковик**: цена болтается вокруг плоской EMA200, MACD-гистограмма
пляшет около нуля, даёт кросс за кроссом, стратегия входит на ложных сигналах и выбрасывается по
стопу. 95 убыточных из 133 — преимущественно такие входы в чопе. Текущий gate `close > EMA200` в
боковике почти ничего не отсекает (цена пересекает плоскую EMA200 многократно).

Единственная прибыльная бумага — RUAL (PF 2.935), и её грид пользователь сужал вручную → это
survivorship, не робастность. На 133 сделках выборка уже приличная и говорит ясно: **edge нет**.

Тот же паттерн уже наблюдался у скальпинга. Поэтому решение — не очередной per-ticker тюнинг
(лечит симптом), а атака на причину убытка: отсечь торговлю в боковике одним общим режимным
фильтром, единым для всех 8 бумаг и **не подбираемым** калибровкой.

## Цель

Добавить **ADX(14) на часовых барах** как entry-gate: вход разрешён только если `ADX ≥ 25`.
Порог фиксирован, един для всех тикеров, не входит в калибровку. Это превращает дизайн в честный
acid test: если pooled OOS PF перепрыгивает 1.0 — фильтр реально отсёк чоп и edge настоящий; если
не перепрыгивает даже с зафиксированным ADX — momentum-ядро мёртвое.

## Объём (что делаем / что НЕ делаем)

**Делаем:**
- Новый индикатор `ADX` в `pkg/indicators`.
- Один gate в `decide()` перед confluence.
- Порог как in-package константа в `core` (не в `Params`, не в гриде).
- Строка в `EntryReason` + зеркало в `Explain()`.
- Тесты (индикатор + ядро), пере-заморозка frozen-baseline.
- Обновление `docs/momentum/strategy.md`.

**НЕ делаем (YAGNI):**
- Не трогаем выходы (SL/TRAIL/TP/MACD/RSI остаются как есть).
- Не делаем ADX направленным (не используем +DI vs −DI как фильтр направления — направление уже
  задаёт `close > EMA200` + бычий MACD-кросс).
- Не свипаем порог и не выносим его в `Params`/гриды.
- Не возвращаем дневную машинерию (`DailyHighs/DailyLows/TodayHigh/TodayLow`) — ADX считается на
  тех же часовых свечах.

## Дизайн

### 1. Индикатор — `pkg/indicators/adx.go`

Чистая функция по образцу существующего `macd.go` (локальная, без зависимостей на `internal`):

```go
func ADX(highs, lows, closes []float64, period int) []float64
```

Классический Wilder ADX:
1. Per-bar: `+DM`, `−DM` (directional movement), `TR` (true range).
2. Сглаживание Уайлдера каждой из трёх серий за `period`.
3. `+DI = 100·smoothed(+DM)/smoothed(TR)`, `−DI = 100·smoothed(−DM)/smoothed(TR)`.
4. `DX = 100·|+DI − −DI| / (+DI + −DI)`.
5. `ADX = Wilder-сглаженный DX` за `period`.

Возвращает срез ADX той же длины, что входные серии; на прогревочных барах (≈ первые `2×period`)
значение 0 (трактуется как «тренда нет» → вход блокируется, что безопасно). Прогрев (~28 баров)
тонет в прогреве EMA200 (200 баров) — новых ограничений на длину истории не вносит.

Отдельный unit-тест `adx_test.go` на known-good значениях (выверенная вручную короткая серия
и/или сверка с эталонной реализацией).

### 2. Порог — фиксированные константы в пакете `core`

```go
const adxPeriod    = 14
const adxThreshold = 25.0
```

Сознательно **не** поля `core.Params` и **не** ключи гридов. Калибровка продолжает крутить
вход/выход/риск per-ticker, но ADX-ворота — неподвижный общий gate поверх всего. Это гарантирует,
что порог невозможно подогнать под train-окно. Аблация (сравнить «с фильтром» / «без») = временно
выставить `adxThreshold = 0` и перегнать — фильтр отключается без иной правки.

### 3. Wiring в ядре

- Импуристый шелл `Strategy` считает `indicators.ADX(highs, lows, closes, adxPeriod)` по часовым
  H/L/C из `MarketData` (там же, где сейчас считаются MACD/RSI/EMA), и кладёт текущее значение бара
  в `decideInput` через новое поле `adx float64`.
- В `decide()` ADX-проверка идёт **первой**, до confluence:
  ```go
  if in.adx < adxThreshold {
      return noEntry // боковик — не торгуем
  }
  ```
- `EntryReason` получает префиксную строку вида `ADX 28.4 ≥ 25 (тренд подтверждён); ...` перед
  блоком про MACD-кросс.
- `Explain()` зеркалит текущий ADX read-only (как сделано для прочих диагностик).

### 4. Влияние на тесты

Фильтр включён всегда → поведение стратегии меняется намеренно:
- **Frozen-baseline тест** (`internal/service/backtest/momentum_registry_test.go`) пере-замораживается
  на новые ADX-гейтнутые числа. Это осознанное изменение стратегии, а не регрессия — в коммите
  отметить старое→новое значение.
- Новые тесты ядра (`core_test.go`):
  - ADX ниже порога блокирует вход даже при полном confluence (MACD+RSI совпали, тренд/объём ок).
  - ADX выше порога вход пропускает (остальное прежнее).
  - `EntryReason` содержит ADX-строку.
- Новый `pkg/indicators/adx_test.go`.

### 5. Документация

`docs/momentum/strategy.md`: добавить ADX в раздел про вход как **первый gate**, пояснить
«25 = граница тренд/боковик» и почему порог зафиксирован (acid test против оверфита).

## Критерий приёмки

После реализации (build/vet/gofmt чисто, все тесты зелёные) пользователь перегоняет ту же корзину
walk-forward:

```
go run ./cmd/backtest -strategy momentum -interval Hour1 \
  -basket RUAL,AFKS,YDEX,PLZL,SBER,GAZP,NVTK,MDMG \
  -months 24 -test-months 12 -min-trades 10 \
  -metric profit_factor -out ./reports/basket
```

Решающая метрика — **pooled OOS Profit Factor**:
- **PF > 1.0** → ADX отсёк чоп, edge настоящий → дальше per-ticker рекалибровка и hardcode
  победителей.
- **PF ≤ 1.0** даже с зафиксированным ADX → momentum-ядро — research dead-end → закрываем ветку
  честно.

Оговорка по данным: PLZL (сплит 1:10, 2024) и YDEX (релистинг ~авг-2024) на 24-мес окне тянут
испорченную до-событийную историю — их числа трактовать со скидкой; MDMG короткая история, может
выпасть по `-min-trades`. Это не меняет решающий pooled-PF тест, но влияет на интерпретацию
per-ticker строк.
