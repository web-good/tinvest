# Дизайн: фильтр ликвидности по free-float в дивидендном скринере

**Дата:** 2026-07-21
**Ветка:** `feat/dividend-freefloat-gate`
**Статус:** утверждён к реализации

## Проблема

Дивидендный скринер (`/dividend_screener`) выводит **Удмуртнефть (UDMN) первой** с
композитом 89. По фундаменталу оценка честная (кэш-корова Роснефти: ROE 47 %,
дёшево по EV/EBITDA, payout 36 % в идеальной зоне), но бумага **физически
неторгуемая**: free-float 0 %, средний объём ≈5 акций в день.

Причина: единственное сито ликвидности в `gate()` — порог по капитализации
(`MarketCapitalization >= ₽50 млрд`). У Удмуртнефти полная капа ₽71 млрд проходит
порог, а свободного обращения нет. **Капитализация ≠ ликвидность**: крупная компания
с околонулевым free-float проскакивает.

Живые данные (41 выживший, срез 2026-07-21) подтверждают разрыв между неликвидным
кластером и легитимными именами по free-float:

| Кластер | Тикеры (float %) |
|---|---|
| Неликвид (≤ 5 %) | UDMN 0, OZON 0, BANE 3, GCHE 3, LEAS 4, AKRN 5, SIBN 5 |
| *разрыв* | *между 5 % и 9 % — пусто* |
| Легитимные (≥ 9 %) | LSNG/PRMD 9, DOMRF/NMTP 10, MSRS/ROSN 11, SVCB/RGSS 13… |

Порог free-float в полосе **5–8 %** отсекает весь неликвид (включая UDMN,
Башнефть-обычку, Черкизово) и не задевает ни одного легитимного имени
(минимальный легит-флоат — 9 %). Все curated-11 имён Golden X — с большим запасом.

## Цель

Добавить в ворота скринера **второй, независимый порог ликвидности по free-float**,
чтобы фунд-бонус и топ отчёта получали только реально торгуемые имена. Порог по
капитализации остаётся без изменений.

## Не-цели (YAGNI)

- Фильтр по среднему обороту (`AverageDailyVolumeLast4Weeks`). Объём приходит в
  штуках (не в рублях) и не сравним между бумагами напрямую; free-float как доля
  0..1 сравним и однозначно разделяет кластеры. Поле уже замаплено — оставляем на
  будущее, но в гейт не вводим.
- Замена market-cap floor на free-float-adjusted cap (`cap × float`). Рассмотрено и
  отклонено: требует полной рекалибровки и меняет уже валидированное поведение
  ₽50 млрд. Выбран инкрементальный путь — два независимых порога.

## Дизайн

### 1. Ворота ликвидности (ядро `rank`)

`internal/service/screener/dividend/rank/config.go`:
- Новое поле `MinFreeFloat float64` в `Config` (доля 0..1).
- Значение в `DefaultConfig()` — **калибруется на живых данных** при реализации в
  полосе 0.05..0.08 (разрыв 5–9 % страхует от ложных отсевов). Начальный ориентир —
  0.07 (посередине разрыва), финал фиксируется после прогона `divscreen`.

`internal/service/screener/dividend/rank/rank.go`:
- Новая причина отсева `reasonThinFloat = "тонкий free-float"`.
- В `gate()` **после** проверки market-cap floor добавить:
  `if f.FreeFloat < cfg.MinFreeFloat { return reasonThinFloat, false }`.
- `FreeFloat == 0` трактуется как неликвид (отсев) — **осознанно и консистентно** с
  тем, как уже отсеивается `MarketCapitalization == 0`. Ноль тут может означать и
  «нет данных» (напр. OZON — вероятная дыра в API), но все затронутые 0 %-имена и
  так с бонусом 0 и внизу списка; альтернатива (нейтрализовать 0) пропустила бы
  UDMN. Риск задокументирован в `docs/dividend/screener.md`.

Порядок ворот после изменения: `нет дивиденда` → `низкая ликвидность` (market-cap)
→ `тонкий free-float` → `yield trap` → `долг > порога` → `payout > порога`.

### 2. Размер отчёта бота

`internal/service/screener/dividend/types.go`: `defaultTopN` 15 → **25**. Влияет
только на `Send` (бот-команда `/dividend_screener`) и на фолбэк `Top(ctx, n<=0)`.
`RankBonus` от этого не зависит. После добавления free-float-гейта выживших ~34–36,
топ-25 умещается.

### 3. Диагностический CLI и маппинг полей (уже сделано на ветке)

Входит в эту ветку как часть работы:
- `cmd/divscreen/` — запуск скринера в stdout без Telegram (`-top N`, `-gated`,
  `-probe TICKER,...`); показывает сырые поля рядом с композитом.
- `model.Fundamentals`: добавлены `FreeFloat` и `AverageDailyVolumeLast4Weeks`;
  маппинг в `internal/converter/fundamentals.go`.
- `rank.GateDecision(f, cfg)` — экспортированная обёртка над `gate` для probe.

### 4. Тесты

`internal/service/screener/dividend/rank/rank_test.go`:
- Кейс: `FreeFloat` ниже порога → отсев с `reasonThinFloat`.
- Кейс: `FreeFloat` ровно на пороге (`== MinFreeFloat`) → проходит (сравнение
  строгое `<`).
- Кейс: `FreeFloat == 0` при валидном market-cap и yield → отсев.
- Существующие survivor-кейсы: проставить `FreeFloat >= MinFreeFloat` в фикстурах,
  чтобы они по-прежнему проходили ворота (иначе новый гейт их срежет).

`internal/service/screener/dividend/service_test.go` / render: проверить, что смена
`defaultTopN` не ломает существующие ожидания (при необходимости — обновить).

## Критерии готовности

1. UDMN и прочий ≤ порога free-float отсеиваются с причиной `тонкий free-float`.
2. Ни одно имя с float ≥ 9 % не отсеяно новым гейтом; все curated-11 Golden X проходят.
3. Бот-команда выводит топ-25.
4. `./bin/mage ci` зелёный; новые тесты покрывают гейт и границу.
5. Документация отражает новый гейт, правило float==0 и топ-25.
