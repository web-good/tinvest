# rsi_zone live на общем счёте с rsi_pullback — дизайн

Дата: 2026-09-30. Ветка: `feat/rsi-zone-live` (от `feat/lent-rsi-zone`, потому что пакет LENT
для rsi_zone пока живёт только там).

## 1. Цель

Вывести стратегию `rsi_zone` в живую торговлю тем же способом, каким сейчас торгует
`rsi_pullback`, и на **том же брокерском счёте**.

Требования владельца:

- Один счёт на обе стратегии.
- У каждой стратегии своя вселенная тикеров; вселенные могут пересекаться (сейчас DOMRF, DIAS,
  LENT есть в обеих).
- Вход, выход и стоп позиции определяет стратегия, которая в неё вошла (владелец).
- Тикер с открытой позицией занят: вторая стратегия по нему не входит, пока владелец не вышел.
- Если на одном баре обе стратегии дают BUY по свободному тикеру — входит `rsi_pullback`.
- Расписание — как у `rsi_pullback`: `1,31 6-23 * * *`, семь дней, guard протухшего бара 60 минут.

Критерии успеха:

- Поведение `rsi_pullback` при пустой вселенной `rsi_zone` бит-в-бит прежнее: существующий
  `rsi_pullback/live/service_test.go` проходит без изменения проверок.
- `go run ./cmd/pullparity -strategy rsi_zone` даёт ноль расхождений на всех тикерах вселенной `rsi_zone` за 24 месяца.
- `./bin/mage ci` зелёный.

Вне рамок: одна позиция на тикер у двух стратегий одновременно (виртуальные подпозиции);
изменение самих ядер стратегий; изменение `reversion`.

## 2. Почему один раннер, а не два

Два независимых раннера на одном счёте срабатывают в одну и ту же минуту (`:01`/`:31`) и могут
купить один тикер на одном баре — занятость пришлось бы защищать межпроцессной блокировкой.
Кроме того, нынешний пасс рассуждает по инструменту, а не по стратегии: снимает любую «чужую»
стоп-заявку по инструменту, реконсилирует количество с портфелем брокера, восстанавливает вход
по последней BUY-сделке. Два таких раннера на общих тикерах ломали бы позиции друг друга.

Решение: **один раннер на счёт**, один пасс в полчаса, несколько стратегий-адаптеров. Владение
позицией — поле в общем файле стейта. Покупки внутри пасса последовательны, гонки за кэш и
тикер нет.

## 3. Компоненты

### 3.1 Раннер счёта — остаётся в `rsi_pullback/live`

Уточнено при планировании: пасс **не переезжает** в отдельный пакет. Раннер уже владеет
счётом, токеном, файлом стейта и темой; тесты `service_test.go` написаны изнутри пакета
(`e.svc.statePath`, `e.svc.now`, `e.svc.store`, моки неэкспортируемых интерфейсов), и
перенос превратил бы «тесты проходят без изменений» в «тесты переписаны» — ровно ту
гарантию, ради которой рефакторинг затевается. Поэтому раннер обобщается на месте:
`rsi_pullback` становится первым адаптером, остальные стратегии подключаются вариадиком
`NewService(..., cfg, guests ...adapter.Strategy)`. Всё, что сейчас зашито на rsi_pullback
(`core.DesiredStop`, `mustParams`, `reconstruct.Entry`, `StrategyFor`, `cfg.BuyPct`,
`alertLabel`, `s.exec`, `s.stops`, `s.notify`), уходит за интерфейс адаптера.

Интерфейс адаптера живёт в новом пакете `livecore/adapter` — чтобы `rsi_zone/live` не
импортировал `rsi_pullback/live`.

Раннер получает упорядоченный список адаптеров; порядок — приоритет входа. В проде порядок
`[rsi_pullback, rsi_zone]`.

```go
// Decider — то, что раннеру нужно от ядра стратегии для одного тикера.
type Decider interface {
    Decide(md strategy.MarketData) model.Signal
    Lookback() int
}

type Strategy interface {
    Name() string                          // "rsi_pullback" | "rsi_zone"; пишется в стейт
    Label() string                         // заголовок алертов: "RSI Pullback" | "RSI Zone"
    Tickers() []string                     // вселенная входов
    Decider(ticker string) (Decider, bool) // из реестра тикеров; false — тикер не зарегистрирован
    // DesiredStop — защитный уровень открытой позиции; reason "" — стопа нет.
    DesiredStop(ticker string, e statestore.Entry) (level float64, reason string)
    // Reconstruct — вход позиции без локального стейта, по API брокера.
    Reconstruct(ctx context.Context, in ReconstructInput) (statestore.Entry, error)
    BuyPct() float64
    TradeEnabled() bool
    Notify(msg string)                     // своя тема Telegram, свой NotifyEnabled
}
```

`ReconstructInput` несёт то, что сейчас передаётся в `reconstruct.Entry`: клиенты ops/market,
счёт, instrument ID, тикер, среднюю цену покупки, `now`.

Исполнители ордеров и стоп-заявок раннер строит сам, по одному на стратегию, с её
`TradeEnabled`. Список активных стоп-заявок (`GetStopOrders`) — счётный, берётся один раз на
пасс отдельным исполнителем, боевым, если боевая хоть одна стратегия (в dry-run `List`
возвращает пустой список).

### 3.2 Адаптеры

- `rsi_pullback/live` — адаптер, реестр тикеров (`registry.go`) и `reconstruct` остаются в
  пакете. `DesiredStop = core.DesiredStop(params, EntryPrice, EntryATR, MaxFav)`.
- `rsi_zone/live` — новый пакет: реестр (AFKS, BAZA, DIAS, DOMRF, LENT; SBER не заведён — планка
  не взята), адаптер, `reconstruct`.
  - `DesiredStop = core.StopLevel(params, EntryPrice, EntryATR)`, reason `SL`; при
    `StopDailyATR = 0` — `("", "")`. Уровень фиксирован на всю жизнь позиции, поэтому общий
    путь переставляет заявку только при расхождении размера или после внешнего снятия.
  - `reconstruct`: `EntryPrice` — средняя цена покупки брокера; `EntryTime` — последняя BUY-
    сделка за 180 дней; `EntryATR` — дневной ATR Уайлдера по будним дневкам, закрывшимся до
    MSK-полуночи дня входа, окно 730 дней, период `DailyATRPeriod` тикера; `TakeProfit = 0`;
    `MaxFav = EntryPrice` (ядро zone его не читает). Общие для двух реконструкций части
    (поиск последней BUY-сделки, будний дневной ATR) выносятся в `livecore`, если совпадают
    дословно; иначе — копия с тестами.
  - Сторожевой тест реестра: тикер на `core.DefaultParams()` в дефолтную вселенную не
    попадает, кроме именных исключений (BAZA, LENT — заведены на дефолтах решением владельца).

### 3.3 Стейт

Файл прежний: `data/state/rsi_pullback_<accountID>.json`, ключ — тикер. В `statestore.Entry`
добавляется поле:

```go
Strategy string `json:"strategy,omitempty"` // владелец позиции; "" — rsi_pullback
```

Пустое значение читается как `rsi_pullback`: живые позиции прода подхватываются без миграции.
`reversion` поле не пишет, формат его файла не меняется (`omitempty`).

### 3.4 Конфиг

Счёт и токен общие: `RSI_PULLBACK_ACCOUNT_ID`, `RSI_PULLBACK_TOKEN` (секрет CI уже заведён),
`RSI_PULLBACK_SCHEDULE` — расписание общего пасса. Новый `RSIZoneConfig`:

| Переменная | Дефолт | Смысл |
|---|---|---|
| `RSI_ZONE_TICKERS` | `""` | вселенная входов rsi_zone; пусто — стратегия не подключается |
| `RSI_ZONE_BUY_PCT` | `5` | доля полной стоимости счёта на сделку, затем ограничение кэшем |
| `RSI_ZONE_TRADE_ENABLED` | `false` | ордера и стоп-заявки rsi_zone уходят на биржу |
| `RSI_ZONE_NOTIFY_ENABLED` | `false` | уведомления rsi_zone в Telegram |
| `TELEGRAM_TOPIC_RSI_ZONE` | — | тема форума rsi_zone; не задана — сообщения идут в General по общему механизму `SendMessageToTopic` |

Как и у rsi_pullback, ни одна переменная не `required` (иначе падение загрузки конфига
обрывает всё приложение). Раннер поднимается по `RSIPullback.Ready()`, как сейчас.

`env/prod.env` на этапе выката: `RSI_ZONE_TICKERS=AFKS,BAZA,DIAS,DOMRF,LENT`,
`RSI_ZONE_TRADE_ENABLED=false`, `RSI_ZONE_NOTIFY_ENABLED=true`. `RSI_PULLBACK_BUY_PCT=50`
при общем счёте означает, что две одновременные позиции занимают весь счёт и входы rsi_zone
будут часто пропускаться по сайзингу; значение пересматривает владелец при включении торговли
zone — код от него не зависит.

## 4. Пасс

1. Загрузить инструменты, портфель, стейт, снапшот стоп-заявок (как сейчас).
2. Множество тикеров пасса = объединение вселенных всех стратегий **плюс все тикеры стейта**.
   Сейчас тикер, убранный из `RSI_PULLBACK_TICKERS`, бросается вместе с открытой позицией;
   теперь владелец ведёт её до выхода, новых входов по нему нет.
3. По каждому тикеру:
   - **Наблюдаемый** (позиция у брокера или запись в стейте):
     - запись есть → владелец `entry.Strategy` (пусто → `rsi_pullback`). Владелец не
       подключён или не знает тикер → алерт, пропуск;
     - записи нет, позиция у брокера есть → кандидаты — стратегии, в чьих вселенных тикер.
       Ровно одна → она реконструирует (как сейчас). Две и больше → алерт «позиция без
       стейта на общем тикере, владелец неизвестен — нужна ручная разметка», пропуск; стоп-
       заявки по инструменту не трогаются. Ни одной → пропуск (не наша бумага).
       Уточнено на финальном ревью: кандидаты-владельцы — только стратегии, которые не
       бумажные при боевой соседке (бумажная при боевой не может владеть реальной позицией);
       ровно один такой кандидат реконструирует, ни одного — алерт «позиция без стейта на
       тикере бумажной стратегии», больше одного — алерт «владелец неизвестен». Запись, чей
       владелец сейчас бумажный при боевой соседке, при реальной позиции у брокера не
       сопровождается: алерт, стейт и стоп-заявки не трогаются;
     - дальше — `manage` существующим кодом с адаптером владельца.
   - **Свободный**: стратегии, в чьей вселенной тикер, по порядку приоритета. Для каждой —
     своя сборка `marketdata.Assemble` со своим `Lookback` (для общих тикеров это две загрузки
     свечей; срез общей загрузки не используется, чтобы не рисковать расхождением с
     бэктестом), guard протухшего бара, `Decide`. Первая стратегия с `SignalBuy` входит;
     остальные на этом баре не спрашиваются.
4. Ошибка по тикеру не обрывает пасс (как сейчас).

**Бумажный режим стратегии** (`TradeEnabled=false`) при боевом режиме другой: бумажный вход
уходит только уведомлением, **стейт не пишется и тикер не занимается**. Иначе бумажная запись
держала бы тикер до чистки по `freshEntryGrace` (2 часа) и блокировала бы боевые входы соседки.
Следствие: в бумажном режиме видны только сигналы входа, выходы бумажных позиций не ведутся.
Уточнено на финальном ревью: `pullparity -strategy rsi_zone` сверяет сборку `MarketData` и
вердикт входа (`md.Position` не строится), поэтому выходы zone сверкой покрыты лишь косвенно
(совпадение `MarketData`) и напрямую — юнит-тестами ядра.

Правило точно: бумажный вход пишет стейт, **только если ни одна подключённая стратегия не
боевая** — это нынешний dry-run rsi_pullback, он сохраняется как есть. Если хотя бы одна
стратегия боевая, бумажные входы стейт не пишут.

**Уведомления.** Сообщения по тикеру — в тему стратегии-владельца (для входа — вошедшей),
с меткой стратегии в тексте. Счётные сообщения (недоступный `GetStopOrders`, алерты о позиции без владельца) — в
тему rsi_pullback. Стартовое сообщение — по одному на стратегию, в её тему: метка, вселенная,
режим (уточнено на финальном ревью).

## 5. Ошибки: что меняется относительно rsi_pullback

Все пограничные случаи `docs/rsi_pullback/live.md` §6 сохраняются: они в общем коде. Новые:

| Случай | Поведение |
|---|---|
| Запись в стейте с неизвестной стратегией | алерт, пропуск, стоп не трогается |
| Владелец не знает тикер (пакет убран из реестра) | алерт, пропуск |
| Позиция без стейта на общем тикере | алерт, без реконструкции, стоп не трогается |
| BUY от обеих на одном баре | входит первая по приоритету (rsi_pullback) |
| Кэша не хватило второй стратегии | обычное `notifier.Skip` в её тему |

## 6. Сверка с бэктестом — `cmd/pullparity -strategy rsi_zone`

Уточнено при планировании: отдельный `cmd/zoneparity` не нужен. `pullparity` сравнивает
сборку и вердикт через два метода ядра (`Decide`, `Lookback`), поэтому получает флаг
`-strategy rsi_pullback|rsi_zone` (дефолт `rsi_pullback` — прежнее поведение) и берёт
`adapter.Decider` из реестра выбранной стратегии. Живая сборка `MarketData` против сборки
движка по кэшу свечей, сравнение всех полей и вердикта `Decide`. Приёмка — ноль расхождений
на AFKS, BAZA, DIAS, DOMRF, LENT за 24 месяца.

## 7. Тесты

- `rsi_pullback/live/service_test.go` остаётся на месте и проходит без изменений — ни сборки
  окружения, ни проверок (раннер с единственным адаптером rsi_pullback).
- Новые тесты раннера:
  - позицию ведёт владелец из стейта, а не первая стратегия по приоритету;
  - BUY от обеих на одном баре → вход rsi_pullback, zone не вызывается;
  - занятый тикер: вторая стратегия не входит;
  - запись без `strategy` ведётся как rsi_pullback;
  - позиция без стейта на общем тикере → алерт, нет реконструкции, нет Cancel/Place;
  - позиция без стейта на тикере одной стратегии → реконструкция этой стратегией;
  - бумажный вход zone при боевом pullback не пишет стейт; следующий BUY pullback по тому же
    тикеру проходит;
  - тикер, убранный из вселенной, с открытой позицией ведётся до выхода;
  - пустой `RSI_ZONE_TICKERS` — стратегия не подключается;
  - неизвестная стратегия в стейте → алерт, пропуск.
- Адаптер zone: `DesiredStop` (включая `StopDailyATR = 0`), `reconstruct` (по образцу
  `rsi_pullback/live/reconstruct` тестов), реестр и сторожевой тест.
- Конфиг: дефолты `RSIZoneConfig`.
- Моки перегенерируются `./bin/mage mocks`.

## 9. Порядок выката

1. `pullparity -strategy rsi_zone` — ноль расхождений по всей вселенной.
2. Прод: `RSI_ZONE_TICKERS` задан, `RSI_ZONE_TRADE_ENABLED=false`,
   `RSI_ZONE_NOTIFY_ENABLED=true`, тема заведена. rsi_pullback продолжает торговать вживую.
3. Сверка приходящих сигналов zone с бэктестом на тех же датах.
4. Пересмотр `RSI_PULLBACK_BUY_PCT` / `RSI_ZONE_BUY_PCT` под общий счёт, включение торговли zone.
