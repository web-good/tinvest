# scalping_rsimacd: RSI-порог на кроссе и трендовый фильтр H1

Дата: 2026-07-23
Статус: спека утверждена, к реализации

## Задача

Ужесточить условие входа стратегии `scalping_rsimacd` (backtest-only, 5m long,
`internal/service/trading_strategy/scalping_rsimacd/strategy/core`) двумя
контекстными гейтами, каждый из которых включается и выключается через грид
калибровки:

1. В момент бычьего пересечения MACD значение RSI должно быть выше порога (по
   умолчанию 50).
2. Тренд старшего таймфрейма (часового) должен быть восходящим.

## Гейт 1: RSI выше порога на баре MACD-кросса

Новое поле `core.Params`:

```go
RSIEntryMin float64 // минимальный RSI на баре MACD-кросса; 0 = гейт выключен
```

Условие: на баре `i` (тот же бар, на котором произошёл бычий кросс MACD)
требуется `rsi[i] > RSIEntryMin`. Используется тот же ряд `RSISeries(closes,
RSIPeriod)`, что и для поиска RSI-триггера — второй индикатор не заводим.

Значение `0` полностью отключает гейт (RSI по построению неотрицателен, но
сравнение строгое, поэтому проверка при 0 не отсекает ничего осмысленного;
реализация всё равно делает ранний выход `if RSIEntryMin <= 0`).

`DefaultParams()`: **50**.

## Гейт 2: трендовый фильтр часового таймфрейма

Новое поле `core.Params`:

```go
HTFTrendEMA int // период EMA на H1-закрытиях; 0 = гейт выключен
```

Условие при `HTFTrendEMA > 0`: последнее закрытие завершённой часовой свечи
должно быть выше `EMA(md.HTFCloses, HTFTrendEMA)`.

**Поведение при нехватке данных — fail-closed.** Если `HTFTrendEMA > 0`, а
`len(md.HTFCloses) < HTFTrendEMA` (или EMA не посчиталась), вход запрещён.

Это сознательное отличие от reversion (`reversion/strategy/core/core.go:198`),
где недостаток HTF-истории молча пропускает гейт. Открытый гейт при отсутствии
данных дал бы в калибровке фантомные сделки, взятые фактически «без фильтра», и
завысил бы PF на прогонах с неполной H1-историей. Стратегия backtest-only, живой
путь без HTF-данных этим не ломается.

`DefaultParams()`: **0** (выключен) — базлайн стратегии не меняется, решение о
включении принимает walk-forward калибровка.

## Порядок гейтов входа

```
сессия / не конец дня
  → бычий кросс MACD (обе линии ниже нуля)
  → RSIEntryMin
  → RSI-триггер в окне подтверждения
  → HTFTrendEMA
  → ATR > 0, стоп, triggerAlive, границы риска
```

Дешёвые проверки идут раньше дорогих; оба новых гейта встают до расчёта ATR и
стопа.

## Часовой HTF в движке бэктеста

Сейчас `internal/domain/backtest/engine.go` фиксирует HTF-интервал константой
`htfInterval = 4 * time.Hour` и передаёт её в `visibleCompletedHTF`.

Изменения:

- В `backtest.Config` добавляется поле `HTFInterval time.Duration`. Ноль
  означает 4 часа — существующее поведение reversion сохраняется без правок
  вызывающего кода.
- `Run` и `Trace` передают `cfg.HTFInterval` (с fallback на 4h) в
  `visibleCompletedHTF`.
- `cmd/backtest/main.go` грузит HTF-свечи и для `scalping_rsimacd`: интервал
  `enum.Hour1`, тот же годичный lead-in (`dailyFrom`), что и у дневного ряда —
  этого достаточно для прогрева EMA(100) на часовках (~3500 баров в год).
  Для `reversion` по-прежнему грузится `enum.Hour4`.
- `cfg.HTFInterval` выставляется в `time.Hour` для `scalping_rsimacd` и остаётся
  нулём (=4h) для остальных стратегий.

Правило видимости не меняется: стратегии виден только полностью закрытый на
момент текущего 5-минутного бара часовой бар (`c.Time.Add(interval) <= cur`).
Заглядывание вперёд исключено.

## Грид калибровки

В `data/params/scalping_rsimacd/grid.json` добавляется фаза `context` между
существующими `entry` и `risk`:

```json
{
  "name": "context",
  "keepTop": 6,
  "grid": {
    "RSIEntryMin": [0, 50, 55],
    "HTFTrendEMA": [0, 20, 50, 100]
  }
}
```

12 комбинаций. Фаза стоит перед `risk`, потому что контекстные гейты меняют саму
выборку сделок, под которую затем настраиваются RR и выходы. Общий размер сетки
27 + 12 + 12 — поверхность подгонки остаётся малой.

## Диагностика

`Explain` (флаг `-explain`) печатает по строке на каждый новый гейт:

- значение RSI на баре кросса, порог и вердикт;
- H1-закрытие, значение EMA, период и вердикт; при нехватке H1-истории —
  отдельная строка «нет данных H1 → вход запрещён».

`entryReason` в журнале сделок дополняется фрагментами о пройденных гейтах
(значение RSI на кроссе; H1-close vs EMA), только когда соответствующий гейт
включён.

## Тесты

Ядро стратегии (`core_test.go`):

- RSI-порог: вход разрешён при `rsi[i] > RSIEntryMin`, заблокирован при
  `rsi[i] <= RSIEntryMin`, гейт не влияет ни на что при `RSIEntryMin = 0`.
- HTF-гейт: вход разрешён при цене выше EMA; заблокирован при цене ниже EMA;
  заблокирован (fail-closed) при `HTFTrendEMA > 0` и пустых/коротких
  `HTFCloses`; полностью отключён при `HTFTrendEMA = 0` даже без HTF-данных.
- Каждый негативный кейс строится от сценария, который БЕЗ нового гейта даёт
  сделку — иначе тест вакуумный.

Движок (`internal/domain/backtest`):

- `HTFInterval = time.Hour` делает видимыми только закрытые часовые бары;
- нулевой `HTFInterval` сохраняет прежнюю 4-часовую семантику.
