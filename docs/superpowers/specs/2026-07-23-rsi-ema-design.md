# RSI + EMA trend strategy (backtest-only, long)

Дата: 2026-07-23
Статус: дизайн утверждён, готово к плану реализации

## Цель

Новая backtest-only лонговая стратегия `rsi_ema`: вход по пересечению RSI уровня 50
снизу вверх при трендовом подтверждении (EMA10 над EMA50), выход строго по сигналам
(EMA-крест вниз, RSI-крест ВВЕРХ через 70 — фиксация в перекупленности, или RSI-крест
ВНИЗ через 50), с опциональным ATR-стопом как страховкой. Интрадей: позиция не
переносится через ночь. Референсный таймфрейм 15m, таймфрейм задаётся флагом `-interval`.

Архитектурно — sibling-клон `scalping_rsimacd`: чистое stateless-ядро, свой `Binding`,
ветка `-strategy rsi_ema` в `cmd/backtest`, свой грид и docs. Правила проще (нет MACD,
нет HTF-фильтра), поэтому ядро короче.

## Таймфрейм

- Базовый таймфрейм — флаг `-interval` (референс `Minutes15`; правила
  timeframe-agnostic, поддерживаются также `Minutes5`, `Minutes30` и т.п.).
- Длина бара выводится из самих данных (медиана интервалов между открытиями баров),
  как в `scalping_rsimacd.barSpanMinutes` — от неё зависят EOD-гейт и `barsSinceEntry`.
- HTF-фильтра тренда нет → `cmd/backtest` не грузит H1-серию для этой стратегии.

## Параметры (`core.Params`)

Все поля `int`/`float64`, чтобы рефлексионный грид мог их свипать.

| Поле | Дефолт | Смысл |
|---|---|---|
| `RSIPeriod` | 12 | длина RSI Уайлдера (грид) |
| `EMAFast` | 10 | период быстрой EMA (грид) |
| `EMASlow` | 50 | период медленной EMA (грид) |
| `RSIMid` | 50 | уровень входа (крест вверх) и один из выходов (крест вниз) |
| `RSIUpper` | 70 | верхний уровень выхода (крест ВВЕРХ — фиксация в перекупленности) |
| `EntryCooldownBars` | 1 | сколько баров после входа игнорировать выход `RSI50` (грид) |
| `StopATR` | 0 | стоп = вход − `StopATR`×ATR; `0` = стоп выключен (грид 0/1/1.5/2) |
| `ATRPeriod` | 14 | период ATR Уайлдера (используется только при `StopATR > 0`) |
| `SessionStartMin` | 420 | начало окна входа, минуты от полуночи MSK (07:00) |
| `SessionEndMin` | 1080 | **конец окна входа** Пн–Чт, минуты от полуночи MSK (18:00) |
| `FridayEndMin` | 840 | **конец окна входа** в пятницу, минуты от полуночи MSK (14:00) |
| `DayEndMin` | 1380 | граница принудительного закрытия (EOD), минуты от полуночи MSK (23:00); едина для всех дней |

`DefaultParams()` возвращает эти дефолты; свипаемые значения приходят из калибровки.

## Правила

### Вход (флэт)

На текущем баре `i = n-1`, только внутри сессии и **не** на баре конца дня
(как в `scalping_rsimacd.enter`: вход на day-end баре нельзя было бы EOD-закрыть на
его же баре):

1. **Окно входа**: `inSession(t)` — будни, `SessionStartMin ≤ m < sessionEndMin(t)`
   (пятница закрывается по `FridayEndMin`). Нулевое время бара пропускает гейт.
   Плюс `!isDayEnd(t, span)` (при разведённых границах вход всегда до `SessionEndMin` <
   `DayEndMin`, так что этот гейт остаётся защитным на случай `DayEndMin ≤ SessionEndMin`).
2. **RSI-крест вверх через `RSIMid`**: `rsi[i-1] < RSIMid && rsi[i] > RSIMid`.
   Guard `rsi[i-1] > 0` отсекает нули прогрева `RSISeries` (иначе прогревный 0
   прочитался бы как «был ниже уровня» и создал фантомный крест).
3. **Тренд EMA**: `emaFast[i] > emaSlow[i]`. Обе EMA должны быть прогреты
   (`> 0`) — `ema.Compute` заполняет прогревные позиции нулём, и сравнение
   непрогретых значений дало бы ложный результат на границе прогрева.
4. **Стоп**: если `StopATR > 0`, `stop = entry − StopATR×ATR` (ATR Уайлдера,
   период `ATRPeriod`, на текущем баре; `atr > 0` обязательно). Иначе стопа нет
   (`StopLoss = 0`). Тейка нет ни в каком режиме.

Вход — `SignalBuy` с `entry = closes[i]`, `StopLoss = stop` (или 0), `RSI = rsi[i]`,
`ATR = atr` (или 0) и человекочитаемым `EntryReason`.

### Выходы (позиция открыта), в порядке приоритета

1. **`SL`** — только если `pos.StopLoss > 0` и `low[i] ≤ pos.StopLoss`. Стоп читается
   из позиции (заморожен движком при входе), не пересчитывается из Params. Заполняется
   как stop-style (`"SL"` уже в `model.IsStopReason`). **Активен всегда** — защитный
   стоп кулдаун не глушит.
2. **`EMAX`** — EMA-крест вниз: `emaFast[i-1] ≥ emaSlow[i-1] && emaFast[i] < emaSlow[i]`
   (обе прошлые EMA прогреты, `> 0`). **Активен всегда** — кулдаун его не глушит.
3. **`RSI70`** — RSI-крест ВВЕРХ через `RSIUpper`: `rsi[i-1] < RSIUpper && rsi[i] > RSIUpper`
   (guard `rsi[i-1] > 0`). Фиксация прибыли при входе RSI в перекупленность. **Активен
   всегда** — кулдаун его не глушит.
4. **`RSI50`** — RSI-крест вниз через `RSIMid`: `rsi[i-1] ≥ RSIMid && rsi[i] < RSIMid`
   (guard `rsi[i-1] > 0`). **Учитывается только когда `barsSinceEntry ≥ EntryCooldownBars`** —
   это единственный выход, который глушит кулдаун (см. ниже). Иначе крест RSI50 на этом
   баре игнорируется.

   `EMAX`, `RSI70`, `RSI50` заполняются по цене закрытия бара (не stop-style,
   в `IsStopReason` не входят).
5. **`EOD`** — принудительное закрытие на последнем баре перед `DayEndMin` (23:00 MSK,
   `isDayEnd(t, span)`), по цене закрытия. Граница конца дня **разведена** с окном входа:
   позиция, открытая до `SessionEndMin`, держится и управляется в вечерней сессии до
   `DayEndMin`. Активен всегда; позиция не переносится через ночь/выходные.

### Кулдаун после входа

Кулдаун глушит **только выход `RSI50`** (крест RSI вниз через `RSIMid`). Причина: вход
покупает как раз крест RSI 50 снизу вверх, поэтому сразу после входа RSI болтается около
50 и на первом же откате мог бы тут же дать крест вниз через 50 и закрыть позицию
преждевременно. Выходы `EMAX`, `RSI70`, `SL` и `EOD` — легитимны в любой момент и
кулдауном **не** глушатся.

- `barsSinceEntry` вычисляется **чисто** из `Position.EntryTime` и времени текущего
  бара, делённых на выведенный из данных span:
  `barsSinceEntry = round((barTime − EntryTime) / span)`.
- Позиция никогда не переносится через ночь (EOD-выход), поэтому кулдаун-окно всегда
  лежит внутри одной сессии — деление на равномерный span корректно, разрывов
  сессий/выходных внутри окна нет.
- Семантика: `EntryCooldownBars = 0` → выход `RSI50` разрешён сразу;
  `= N` → ждём N баров. `manage()` запускается со СЛЕДУЮЩЕГО бара после входа, так что
  на первом управляемом баре `barsSinceEntry = 1`. Значит при дефолте `1` первый
  управляемый бар уже может дать выход `RSI50`; `= 2` пропустит крест `RSI50` на первом
  управляемом баре, и т.д.
- Если `EntryTime` нулевое (не должно случаться в бэктесте — движок его заполняет),
  кулдаун деградирует в «разрешено» (выход `RSI50` не блокируется), чтобы не застрять
  в позиции.

## Чистота и структура

Ядро остаётся чистым (`Decide` не делает I/O, всё пересчитывается из `md`), stateless
между барами и ticker-agnostic — как `scalping_rsimacd`. Публичная поверхность повторяет
контракт `strategy.Strategy`:

- `NewWithParams(ticker, Params) *Strategy`
- `Ticker() string`
- `Lookback() int` — окно с запасом на прогрев RSI(`RSIPeriod`), EMA(`EMASlow`) и ATR
  (порядка `EMASlow + запас`; берём фиксированные ~120, как в rsimacd).
- `Decide(md) model.Signal` — роутит на `enter`/`manage`.
- `Explain(md) string` — погейтовый разбор одного бара для `-explain`.

Вспомогательные (портируются из `scalping_rsimacd`, идентичная семантика): `mskLoc`,
`inSession`, `isWeekend`, `isDayEnd`, `barSpanMinutes`, `barTime`, `sessionEndMin`.

- **Реестр**: `internal/service/backtest/rsi_ema_registry.go` —
  `RSIEMALookupOrGeneric(ticker) Binding` + `rsiEMABindingFor(ticker)` (generic-дефолты,
  per-ticker пакетов пока нет). По образцу `scalping_rsimacd_registry.go`.
- **`cmd/backtest/main.go`**:
  - `case "rsi_ema"` в switch биндинга (около строки 160): `binding = svc.RSIEMALookupOrGeneric(ticker)`;
  - в switch HTF-загрузки (около строки 193) — ветки нет / передаём `nil` htf
    (H1 не грузим, `htfInterval = 0`);
  - обновить строки справки флага `-strategy` (`scalping|reversion|scalping_rsimacd|rsi_ema`)
    и текст ошибки `unknown strategy`.
- **Грид**: `data/params/rsi_ema/grid.json` — фазы:
  - `entry` — `RSIPeriod` × `EMAFast` × `EMASlow`;
  - `exits` — `RSIUpper` × `EntryCooldownBars`;
  - `risk` — `StopATR` (0 = стоп выключен, плюс несколько ATR-множителей).
- **Docs**: `docs/rsi_ema/strategy.md` (правила, запуск, критерий приёмки) + строка в
  `CLAUDE.md` в списке `trading_strategy/`.

## Тестирование (TDD, table-driven)

Юнит-тесты на ядро (по образцу тестов `scalping_rsimacd`):

- **Вход**: RSI-крест вверх через 50 при EMA10>EMA50 → Buy; отсутствие EMA-подтверждения
  → нет входа; RSI без креста (уже выше 50) → нет входа; вне сессии / на day-end баре →
  нет входа; прогревные нули не создают фантомный вход.
- **Стоп**: `StopATR > 0` кладёт `entry − StopATR×ATR`; `StopATR = 0` → `StopLoss = 0`.
- **Выходы**: `SL` при пробое лоу (только когда стоп включён); `EMAX`/`RSI70`/`RSI50`
  каждый по своему кресту; приоритет `SL` над сигнальными; `EOD` на последнем баре сессии.
- **Кулдаун**: крест `RSI50` внутри `barsSinceEntry < EntryCooldownBars` игнорируется;
  на границе `≥` — срабатывает; `EMAX`, `RSI70`, `SL`, `EOD` НЕ глушатся кулдауном (крест
  `EMAX`/`RSI70` внутри окна кулдауна всё равно закрывает позицию); нулевое `EntryTime`
  деградирует в «разрешено».
- **Реестр**: `RSIEMALookupOrGeneric` строит стратегию, `ParseParams` мержит частичный
  JSON поверх дефолтов.

`Explain` покрывается smoke-тестом (не паникует, отражает состояние гейтов).

## Критерий приёмки стратегии

Как у `scalping_rsimacd`: решение только по pooled OOS profit factor на walk-forward —
PF ≥ 1.5 при ≥ 30 OOS-сделок → кандидат на live; 1.0–1.5 → edge не подтверждён;
сходимость всех комбо или < 10 сделок → сетап слишком редок (диагностировать `-explain`).
Дефолтные пороги фиксированы этой спекой; есть ли эдж — решает калибровка, а не
разведочный прогон.

## Вне рамок (YAGNI)

- Live-слой (только бэктест).
- HTF-фильтр тренда, стохастик-выход, трейлинг-стоп, тейк-профит.
- Per-ticker пакеты параметров (появятся, если калибровка докажет необходимость).
- Шорты (только лонг).
