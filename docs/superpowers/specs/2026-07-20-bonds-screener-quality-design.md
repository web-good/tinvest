# Bonds Screener Quality Upgrade — Design

**Дата:** 2026-07-20
**Статус:** согласован, готов к плану реализации
**Контекст:** базовая стратегия пользователя — долгосрочный портфель (≈60% надёжные
облигации + дивидендные акции). Облигационный скринер (`/bonds_screener`) —
основной инструмент подбора бумаг в лесенку (bond ladder). Сейчас он даёт
неполные фильтры надёжности и грубый расчёт доходности.

## Цель

Повысить качество облигационного скринера по двум связанным направлениям:

1. **Надёжность** — явная, настраиваемая и тестируемая политика отбора
   (кредитный риск, ликвидность, суборды, квал-статус) вместо захардкоженного
   и спрятанного в конвертере фильтра.
2. **Корректная доходность** — настоящая YTM (доходность к погашению) через
   `indicators.XIRR` вместо линейной аннуализации, чтобы бумаги любой длины были
   сопоставимы.

Структура «лесенки» (разбиение по окнам погашения) сохраняется — это каркас
долгосрочной облигационной стратегии.

## Текущее состояние (as-is)

- **Точка входа:** `internal/service/trading_strategy/bonds/trade.go` — 4 ступени
  лесенки (3 ОФЗ + 1 корп), каждая ступень — отдельная goroutine с дублированным
  boilerplate; границы окон захардкожены через `time.Now().AddDate(...)` и
  вычисляются дважды (в `Finder` и в `Sender`).
- **Pipeline:** `Bonds()` → `Finder` (фильтр) → `CalculateProfit` (доходность) →
  `Sender` (топ-10 + Telegram).
- **Фильтр надёжности спрятан в конвертере:** `pkg/client/grpc/converter/bond.go`
  `ConvertBondsFromPb` жёстко отсекает всё, кроме `RISK_LEVEL_LOW`, и повторно
  режет флоатеры (дублируя `Finder`). Следствия: политика невидима, не
  настраивается, не тестируется; поле `RiskLevel` в модели всегда `"..._LOW"` и
  бесполезно ниже по стеку.
- **Не проверяются вовсе:** субординированные облигации, «только для квалов»,
  флаг достаточной ликвидности Tinkoff.
- **Расчёт доходности** (`bonds/computable/calculate_profit.go`): линейная
  аннуализация `finalProfit * 365 / daysToMaturity` — искажает доходность длинных
  бумаг (не учитывает тайминг денежных потоков и дисконтирование). Цена берётся из
  последней дневной свечи за 20 дней — по неликвиду может быть устаревшей.
- **Модель `pkgmodel.Bond`** не содержит доступных в proto полей:
  `liquidity_flag`, `subordinated_flag`, `for_qual_investor_flag`,
  `perpetual_flag`, `sector`, `issue_size`.

## Дизайн (to-be)

### 1. Модель и маппинг

Домаппить в `pkgmodel.Bond` (`pkg/client/grpc/model/bond.go`) поля из
`api/v1/instruments.proto` (message `Bond`), которые сейчас теряются:

- `LiquidityFlag bool` (proto `liquidity_flag`)
- `SubordinatedFlag bool` (proto `subordinated_flag`)
- `ForQualInvestorFlag bool` (proto `for_qual_investor_flag`)
- `PerpetualFlag bool` (proto `perpetual_flag`)
- `Sector string` (proto `sector`)
- `IssueSize int64` (proto `issue_size`)

`RiskLevel` остаётся, но перестаёт быть предметом хардкод-фильтра в конвертере.

`ConvertBondModelFromBondPb` дополняется маппингом новых полей.
`ConvertBondsFromPb` перестаёт молча отсеивать по риску/флоатеру — становится
«тупым» маппером (политика отбора переезжает в §2).

### 2. Явная политика надёжности

Вынести фильтрацию из конвертера в **явный шаг скринера** — структуру/функцию
`Filter` рядом с `Finder` (пакет `bonds/pipeline`). Политика по умолчанию для
стратегии «надёжные облигации»:

- `RiskLevel == LOW`
- `!SubordinatedFlag`
- `!PerpetualFlag`
- `!ForQualInvestorFlag`
- `LiquidityFlag == true`
- существующие критерии: окно погашения, `!AmortizationFlag`,
  `!FloatingCouponFlag`, `Nkd > 0`

Политика оформляется как явная конфигурация (набор критериев), чтобы её было
видно, легко менять и тестировать. Дублирующий отсев флоатеров в двух местах
устраняется (единый источник истины — этот шаг).

### 3. Настоящая YTM

Заменить линейную аннуализацию в `calculateProfit` на `indicators.XIRR`
(`pkg/indicators/xirr.go`, уже используется в `/yield`). Денежные потоки:

- `-(цена + НКД)` на сегодня (outflow);
- `+купон` на каждую будущую дату купона, после налога 13%;
- `+номинал` в дату погашения, с учётом налога на разницу цена/номинал.

Результат XIRR (годовая ставка) становится основной метрикой доходности.
Текущая купонная доходность (`CouponPercentByYear`) сохраняется как второй
показатель.

**Guard на устаревшую цену:** если последняя дневная свеча старше порога
(N дней) — бумага пропускается (страховка от неликвида, дополняет фильтр
`LiquidityFlag`).

**Guard на XIRR:** если солвер не сошёлся (`ErrXIRRNoConvergence`) или потоки
некорректны — бумага пропускается, пайплайн не падает.

### 4. Лесенка (bond ladder) — явная конфигурация

Ступени лесенки сохраняются (это каркас стратегии), но выносятся из
захардкоженного boilerplate `trade.go` в **явную настраиваемую конфигурацию** —
список ступеней (`isOfz`, `from`, `to`). `trade.go` итерирует по конфигу; `now`
вычисляется один раз. Границы по умолчанию — те же, что сейчас:

- ОФЗ: 180д–2г, 2–6г, 6–16г
- Корп: 180д–3г

Внутри каждой ступени бумаги сортируются по **YTM** (топ-N). Это убирает
текущий костыль в `Sender` с переключением критерия сортировки по сроку
(`> 6 лет` → купонная доходность).

### 5. Вывод в Telegram

- `domain.BondReport` дополняется полями для строки вывода: `YTM`, `RiskLevel`,
  `Liquidity bool`, `Sector`. (Как именно соотнести с существующим
  `PercentByYear` — переиспользовать под YTM или добавить отдельное поле —
  решается при реализации так, чтобы не ломать тесты пакета `notification`.)
- `Sender` сортирует по YTM внутри ступени (см. §4).
- Формат строки дополняется YTM, купонной доходностью и сектором. Пример:
  `ОФЗ 26238 · погаш. 2041 · YTM 14.2% · купон 12.1% · сектор: gov`
- В шапку сообщения добавляется строка с применённой политикой отбора
  («только LOW risk, несубординированные, ликвидные»), чтобы критерии были
  прозрачны. Отдельную «плашку риска» на каждую бумагу не добавляем — все бумаги
  в списке уже прошли фильтр надёжности.

## Тестирование

Table-driven, по стилю репозитория:

- **Шаг `Filter`** — отдельный кейс на каждый критерий отсева (суборд, квал,
  неликвид, `RiskLevel != LOW`, окно погашения, амортизация, флоатер, `Nkd == 0`).
  Сейчас фильтрация не покрыта тестами.
- **YTM-расчёт** — кейсы: бумага с дисконтом (YTM > купонной), с премией
  (YTM < купонной), короткая vs длинная, проверка знака результата; edge —
  `XIRR` без сходимости → бумага корректно пропускается.
- **Guard устаревшей цены** — свеча старше порога → пропуск.
- **Обновлённый конвертер** — новые поля проставляются; `ConvertBondsFromPb`
  больше не фильтрует.

## Вне scope (осознанно)

- **Диверсификация по секторам в ранжировании** — `Sector` только показываем, не
  строим ограниченный по секторам топ. Отдельная будущая доработка.
- **Внешние кредитные рейтинги (АКРА / Эксперт РА)** — отсутствуют в API Tinkoff;
  сторонний источник — отдельный проект.
- **Автопуш скринера по расписанию** — остаётся `/bonds_screener` по команде.
  Превращение в scheduled-джобу — отдельный дизайн.

## Blast radius / риски

- `Bonds()` / `ConvertBondsFromPb` используется только облигационным скринером —
  вынос фильтра из конвертера не заденет другие части приложения (перепроверить
  grep-ом при реализации).
- Изменение `domain.BondReport` затрагивает пакет `bonds/notification` и его
  тесты — обновить синхронно.
