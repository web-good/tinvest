# Фильтр стохастика для FVG imbalance

## Цель

Добавить в `fvg_imbalance` опциональное подтверждение входа стохастиком: после достижения заданной глубины ретеста не входить немедленно, а дождаться закрытой M30-свечи с медленным `%K` ниже 20. Фильтр должен включаться и выключаться числовым параметром в JSON-гриде.

## Поведение

- `UseStochFilter` — целочисленный переключатель `0/1`.
- При `0` сохраняется текущее поведение: валидный ретест сразу создаёт вход на следующем M30 open.
- При `1` зона сначала должна достичь `MinRetestDepthPct`; затем на этой или любой следующей свече в пределах `MaxRetestBars` проверяется стохастик.
- Используется медленный `%K` с периодами `K=14`, `D=3`; для входа достаточно `%K < 20`, `%D` не является отдельным условием.
- Если глубина достигнута, но `%K >= 20`, вход откладывается. Цена на последующих свечах может оставаться выше или глубже в зоне; любой `low < lower` по-прежнему навсегда инвалидирует зону.
- При достижении срока `MaxRetestBars`, инвалидировании зоны, пропуске временного слота или выходном `FillBy` вход не переносится дальше.
- Проверяются только завершённые свечи; вход выполняется на открытии следующей M30-свечи.
- Невозможность рассчитать стохастик из-за недостатка истории не даёт сигнал.

## Реализация

Параметр и проверка значения добавляются в `strategy/core.Params` и `ValidateParams`. Core рассчитывает стохастик по имеющимся M30 high/low/close через `pkg/indicators.StochasticSeries`; `Lookback` увеличивается настолько, чтобы обеспечить историю `%K`. Гриды GAZP и DOMRF получают фазу `stochastic` со значениями `UseStochFilter: [0, 1]`; явные литералы тикеров сохраняют `0`, поэтому включение фильтра происходит только в калибровке.

Тесты покрывают выключенный фильтр, вход на свече достижения глубины при `%K < 20`, ожидание следующей свечи, отсутствие входа при истечении зоны и инвалидирование при пробое нижней границы. Документация стратегии описывает новый параметр и порядок ожидания.

## Подходы

Выбран state-free подход: момент достижения глубины определяется реконструкцией зоны по всей переданной истории, а не сохраняемым состоянием. Это соответствует текущей архитектуре core и корректно работает в `Run` и `Trace`.

Отклонён вариант входа только на той же свече ретеста: он не соответствует требованию ждать стохастик после достижения глубины. Отклонён вариант с отдельным сроком ожидания: пользователь указал ждать до инвалидирования зоны, а существующий `MaxRetestBars` уже задаёт естественный предел жизни зоны.

## Не входит в изменение

Формирование FVG, формула глубины, H4-фильтр, стопы, цели и правила выходных/пропущенных свечей не меняются.
