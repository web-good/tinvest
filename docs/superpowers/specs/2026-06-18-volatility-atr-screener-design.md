# Спека: скринер волатильности акций по дневному ATR

Дата: 2026-06-18

## Цель

CLI-режим, который готовит отчёт «самые волатильные акции за полгода».
Волатильность меряется по **дневному ATR**, нормированному на цену (ATR%), по всей
ликвидной вселенной MOEX.

## Ключевое методологическое решение

Ранжируем **по ATR% = ATR / цена · 100**, а не по абсолютному ATR. Абсолютный ATR в
рублях несопоставим между бумагами разной цены (дорогая акция всегда «волатильнее»).
ATR% — честная кросс-тикерная мера.

Заголовочная метрика — **средняя ATR% за весь период** (это и есть «волатильность за
полгода», т.к. одиночный Wilder-ATR(14) отражает только ~последние пару недель). Рядом
показываем **текущую ATR%(14)**, чтобы видеть, разгоняется бумага или затихает.

## CLI

```
go run ./cmd/backtest -volrank -months 6 -atr-period 14 -min-turnover 50 -top 50 -out ./reports/volatility
```

- `-volrank` (bool) — включает режим; игнорирует `-ticker` / `-strategy` (как `-screen`).
- `-min-turnover` (float, млн ₽) — порог средней дневной ликвидности. По умолчанию `50`.
- `-atr-period` (int) — период ATR. По умолчанию `14`.
- `-top` (int) — сколько строк в отчёт; `0` = все. По умолчанию `50`.
- `-months` (int) — окно (переиспользуем существующий флаг). По умолчанию задаётся как сейчас.
- `-out` (string) — каталог отчёта. По умолчанию `reports/volatility`.
- интервал жёстко `enum.Day1` (дневной ТФ).

## Пайплайн

1. **Вселенная.** `client.InstrumentsServiceClient().Shares(ctx)` → отфильтровать:
   валюта RUB, биржа MOEX, торгуется (`apiTradeAvailable`). Режет тысячи → ~сотни.
2. **Свечи.** Конкурентно (worker pool через `pkg/semaphore`, ~6 воркеров — как
   `calibWorkers`) для каждого тикера: `CandleProvider.Load(ctx, ticker, id, Day1, from, to, refresh)`
   с кэшем в `data/candles/`. `from = to.AddDate(0, -months, 0)`.
3. **Метрики на тикер:**
   - ATR%-серия: `ATR_t / close_t · 100` по всем барам после прогрева.
   - `meanATRpct` = среднее по серии (заголовочная метрика).
   - `lastATRpct` = последнее значение серии.
   - `turnover` = `mean(volume_t · lot · close_t)` по окну, в млн ₽.
   - `bars` = число загруженных дневных баров.
4. **Отсев:** бумаги с `turnover < min-turnover` или с недостатком баров
   (`bars < atr-period + 1`, нет валидной ATR-серии) → исключить из ранжирования.
5. **Ранжирование:** по убыванию `meanATRpct`. Обрезать до `-top`.

## Отчёт

`reports/volatility/volatility_Day1_<timestamp>.md`, markdown, в стиле `screen.go`.

Шапка: интервал (Day1), период (N месяцев, from—to), период ATR, порог ликвидности,
сколько тикеров просканировано / прошло фильтр.

Таблица:

| # | Тикер | Ср. ATR% (6м) | Тек. ATR%(14) | Тренд | Ликвидность, млн ₽/день | Баров |
|---|---|---|---|---|---|---|

- Сортировка по «Ср. ATR%» вниз.
- «Тренд» = ↑ если `lastATRpct > meanATRpct`, иначе ↓ (разгон/затихание).
- Пропущенные/отсечённые тикеры в отчёт не попадают (но число отсечённых пишем в шапку).
