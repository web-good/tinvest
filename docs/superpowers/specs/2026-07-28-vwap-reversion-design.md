# VWAP-возврат (`vwap_rev`) — дизайн стратегии

Дата: 2026-07-28. Статус: спека согласована, реализация не начата.

## Задача

Внутридневная лонговая стратегия на 30-минутных барах с профилем «маленький, но стабильный
доход со сделки»: цель порядка 0.25–0.35% чистыми, высокий винрейт, высокая частота входов.

Владелец счёта торгует по тарифу «Трейдер» — комиссия 0.05% за сторону, то есть **0.1%
за круг**. Это совпадает с дефолтом бэктеста (`-commission 0.0005`).

## Что задаёт рамки

Медианы по кэшу свечей (`data/candles/*_Minutes30.json`, ~2 года):

| Тикер | ATR(14) на 30m | P(цена даёт +0.3% за 4 бара) |
|---|---|---|
| SBER | 0.188% | 28.5% |
| MOEX / VTBR / MTSS | 0.22–0.25% | 34–35% |
| LKOH | 0.231% | 35.3% |
| YDEX | 0.282% | 41.3% |
| GAZP | 0.294% | 42.0% |
| TATN / CHMF / GMKN / PLZL | 0.29–0.31% | 42–45% |
| ROSN / NVTK / RUAL / AFKS | 0.34–0.38% | 47–52% |

Три следствия, на которых держится весь дизайн:

1. Цель 0.2–0.3% — это примерно **один ATR 30-минутного бара**. Движение достижимое.
2. Издержки 0.1% за круг съедают ~30–40% такой цели. Чтобы осталось 0.25–0.35% чистыми,
   брутто-цель должна быть **0.35–0.45%**.
3. **SBER, MOEX, MTSS, VTBR, LKOH из работы исключены**: их ATR меньше, чем цель плюс
   издержки. Кандидаты — GAZP, NVTK, RUAL, AFKS, PLZL, TATN, GMKN.

## Решения, принятые владельцем

- **Только лонг.** Шорты не используем; движок бэктеста их и не поддерживает.
- **Оценка по одному тикеру**, как и раньше, — не пулом по корзине. Риск оверфита при этом
  был явно обозначен, решение принято сознательно.
- Из-за (2) стратегия обязана быть **достаточно частой**: 200+ сделок на одном тикере за 24
  месяца. Это единственный способ сделать walk-forward на одном тикере статистически
  осмысленным. Все предыдущие провалы в репо (ORB, daylow, momentum, levels, smc,
  reversion-m30) имели 20–40 сделок на фолд-серию.

## Почему именно возврат к сессионному VWAP

У гипотезы есть механизм, а не только корреляция: VWAP — бенчмарк исполнения крупных заявок,
вокруг него реально стоит поток. Это единственный непроверенный в репо класс с внятной
причиной, и его естественный профиль совпадает с запросом: цель равна размеру отклонения
(0.35–0.6%), винрейт структурно выше 50%, прибыль набирается частотой, а не размером.

Стратегия не дублирует существующую `reversion` — там RSI+Stoch без сессионного якоря,
живущие на H1/D1.

Рассмотренная и отклонённая альтернатива: взять готовую `rsi_ema`, прогнать на 30m и добавить
фиксированный тейк (в ней сейчас тейка нет вообще). Дешевле на 3–4 дня, но это шестая вариация
темы «крест индикатора + фильтр тренда», а пять предыдущих walk-forward не пережили;
механизма, объясняющего стабильный мелкий доход, там нет.

## Правила

Лонг, интрадей, референсный таймфрейм 30m, через ночь позиция не переносится.

### Индикаторы

Всё считается из окна баров, межбарного состояния нет.

- `VWAP` — якорь с первого бара календарного дня МСК: `Σ(typical·V) / ΣV`, где
  `typical = (H+L+C)/3`. На баре `i` сумма берётся включительно по `i`.
  Якорь ставится именно на начало дня, а не на открытие основной сессии: тонкие утренние бары
  весят по объёму почти ноль, поэтому взвешивание отсекает их само, без отдельного правила.
- `σ` — взвешенное объёмом СКО типичной цены вокруг VWAP, тоже с начала дня, включительно
  по бару `i`. Самонастраивается под волатильность конкретного дня, в отличие от ATR.
- `ATR(ATRPeriod)` на базовом таймфрейме — только для стопа.
- `EMA(DailyEMAPeriod)` по завершённым дневным свечам (`MarketData.DailyCloses`) — контекст.

### Вход

На закрытии 30m-бара, когда позиции нет. Все условия обязательны.

1. `barsFromOpen ≥ MinBarsFromOpen` (6) — на первых барах дня σ бессмысленна, а утренняя
   сессия неликвидна. Это **единственная** ручка «как рано начинаем торговать»: при 30m-барах
   и дне, стартующем в 07:00, значение 6 соответствует 10:00 МСК.
2. `Close ≤ VWAP − EntryK·σ` (`EntryK` = 1.5) — цена дёшева относительно сессионного консенсуса.
3. `Close ≥ VWAP − MaxDevK·σ` (`MaxDevK` = 4) — отсечка «это обвал, а не откат».
   `MaxDevK ≤ 0` выключает правило.
4. `(VWAP − Close) / Close · 100 ≥ MinEdgePct`, где **`MinEdgePct` задан в процентах**
   (дефолт `0.35` = 0.35%) — **главный гейт против торговли внутри издержек**. Ход до цели
   обязан окупать 0.1% комиссии с запасом; без него на тихих днях стратегия набирает сделки с
   нулевым матожиданием.
5. `Close ≥ Low + MinClosePos·(High − Low)`, где **`MinClosePos` — доля диапазона бара в
   пределах 0..1** (дефолт `0.33`): бар закрылся не в нижней трети своего диапазона, не ловим
   нож. `MinClosePos ≤ 0` выключает правило.
6. При `UseDailyTrend = 1`: `Close > EMA(DailyEMAPeriod)` по дневкам. Не откупаем провал в
   нисходящем тренде. `UseDailyTrend = 0` выключает правило.
7. Окно входа: `SessionStartMin`–`SessionEndMin` МСК (07:00–18:00), пятница — до
   `FridayEndMin` (14:00). Нижнюю границу фактически задаёт `MinBarsFromOpen` (п. 1);
   `SessionStartMin` оставлен на начале дня, чтобы две ручки не дублировали друг друга и
   фаза сетки по `MinBarsFromOpen` не оказалась мёртвой.

### Выходы (в порядке приоритета)

1. `SL` — `Low ≤ вход − StopATR·ATR` (`StopATR` = 1.2). Заполнение по стоп-цене с поправкой
   на гэп вниз (`min(stop, open)` — существующая механика движка).
2. `TP` — `High ≥ VWAP предыдущего бара`. Заполнение по `max(цель, open)`.
   **Цель берётся с предыдущего бара** — так это настоящая лимитная заявка, известная до
   начала бара, без подглядывания в будущее.
3. `TIME` — число закрытых баров с момента входа достигло `MaxHoldBars` (8 = 4 часа) → по
   close. Возврат, не случившийся за полдня, скорее всего не случится. `MaxHoldBars ≤ 0`
   выключает правило.
4. `EOD` — последний бар перед `DayEndMin` (23:00 МСК) → по close.

`SL` проверяется раньше `TP` на одном баре: внутрибарный порядок неизвестен, считаем по
худшему сценарию.

### Параметры

| Поле | Дефолт | В сетке |
|---|---|---|
| `EntryK` | 1.5 | да |
| `MaxDevK` | 4.0 | да (0 = выкл) |
| `MinEdgePct` (в процентах) | 0.35 | да |
| `MinBarsFromOpen` | 6 | да |
| `MinClosePos` (доля 0..1) | 0.33 | да (0 = выкл) |
| `UseDailyTrend` | 1 | да (0 = выкл) |
| `DailyEMAPeriod` | 50 | да |
| `StopATR` | 1.2 | да |
| `ATRPeriod` | 14 | нет |
| `MaxHoldBars` | 8 | да (0 = выкл) |
| `SessionStartMin` | 420 | нет |
| `SessionEndMin` | 1080 | нет |
| `FridayEndMin` | 840 | нет |
| `DayEndMin` | 1380 | нет |

Все поля — `int` или `float64`, чтобы рефлексивная грид-калибровка их перебирала.

## Архитектура

Та же схема, что у `rsi_ema` и `scalping_rsimacd`: чистое ядро без I/O, реестр-биндинг, вся
работа с сетью и файлами — в CLI. Движок, метрики, walk-forward и отчёты не меняются вообще.

### 1. `pkg/indicators/vwap.go` (+ `vwap_test.go`)

```go
// SessionVWAP returns the session-anchored VWAP, the volume-weighted stddev of
// typical price around it, and each bar's index within its session — all
// index-aligned to the input bars.
func SessionVWAP(highs, lows, closes []float64, volumes []int64,
    times []time.Time, loc *time.Location) (vwap, sigma []float64, barsFromOpen []int)
```

Единственное место, знающее, где начинается день. Граница сессии — смена календарной даты МСК;
выходные и праздники обрабатываются этим правилом автоматически.

Три правила деградации, все под тестами:

- `times` пуст или не выровнен по длине с закрытиями → возвращает `nil, nil, nil`; ядро
  трактует это как «не прогрето» и вход запрещает. Гейт закрывается, а не открывается.
- Бары с нулевым объёмом получают вес 0. Если у всей сессии `ΣV = 0`, VWAP остаётся нулём —
  без NaN и деления на ноль.
- **Первая сессия в окне всегда считается неполной** (`barsFromOpen = -1` на всех её барах) —
  безусловно, даже если окно случайно начинается ровно с открытия дня. Скользящее окно почти
  всегда начинается с середины дня, и VWAP такой сессии посчитан от произвольной точки.
  Безусловность здесь принципиальна: она делает значение детерминированным и не зависящим от
  того, где обрезано окно, — именно на этом держится анти-lookahead тест (C). Текущий бар
  всегда принадлежит последней сессии окна, чья открывающая свеча в окно попадает, так что на
  сигналы правило не влияет — но без него стратегия торговала бы по мусорному якорю.

### 2. `internal/service/trading_strategy/vwap_rev/strategy/core/core.go` (+ тесты)

`Params` / `DefaultParams` / `Strategy` / `Decide` → `enter` | `manage`, как в `rsi_ema`.
Ядро stateless между барами: позиция приходит в `MarketData.Position`.

`Lookback()` = `max(300, 2·ATRPeriod + 20)`. Пол в 300 баров гарантирует, что открытие текущего
дня лежит внутри окна для таймфреймов от 15m и выше. Это в 2–2.5 раза больше, чем у `rsi_ema`
(120), поэтому грид-калибровка будет заметно медленнее — плата за сессионный якорь. На
таймфреймах ниже 15m пола не хватит; стратегия для них не предназначена, и это оговорено в
доках.

### 3. `internal/service/backtest/vwap_rev_registry.go` (+ тесты)

`VWAPRevLookupOrGeneric(ticker)` — клон `rsi_ema_registry.go`. Один generic-биндинг;
per-ticker пакетов не заводим, пока калибровка не докажет, что они нужны.

### 4. `cmd/backtest/main.go`

Ветка `case "vwap_rev"` в выборе движка плюс строки помощи (`-strategy`). HTF-серия не нужна.
Дневные свечи движок грузит всегда (`main.go:182`), поэтому дневной фильтр тренда достаётся
бесплатно.

### 5. `data/params/vwap_rev/grid.json`

Фазовая сетка, см. ниже.

### 6. `docs/vwap_rev/strategy.md`

Правила, параметры, команды запуска.

### Границы ответственности

Индикатор ничего не знает о торговле. Ядро ничего не знает о загрузке свечей. Реестр ничего не
знает о правилах. Ядро тестируется синтетическими барами без сети.

## Калибровка

Фазовая сетка, 124 комбинации (у `rsi_ema` 218, но здесь каждый прогон в ~2.5 раза медленнее
из-за окна в 300 баров).

| Фаза | Перебор | Комбо |
|---|---|---|
| 1. entry | `EntryK` [1.0, 1.5, 2.0, 2.5] × `MinEdgePct` [0.25, 0.35, 0.5] | 12 |
| 2. context | `UseDailyTrend` [0, 1] × `DailyEMAPeriod` [20, 50, 100] | 6 × 4 seed |
| 3. quality | `MaxDevK` [0, 3, 4] × `MinClosePos` [0, 0.25, 0.33] | 9 × 4 |
| 4. risk | `StopATR` [0.8, 1.2, 1.6, 2.0] | 4 × 4 |
| 5. hold | `MaxHoldBars` [0, 4, 6, 8, 12] | 5 × 4 |
| 6. timing | `MinBarsFromOpen` [4, 6, 8, 10] | 4 × 4 |

Каждая фаза несёт контрольную точку «фильтр выключен» (`0`), чтобы базовая версия
конкурировала на лидерборде наравне — иначе калибровка всегда «докажет», что фильтр нужен.
Дубликаты выключенных строк в отчёте ожидаемы, как в `rsi_ema`.

Принципиально не перебираем: границы сессии, `DayEndMin` и саму цель на VWAP. Цель — это тезис
стратегии, а не ручка; если её приходится подкручивать, стратегия неверна.

**Основной тикер — GAZP**: ATR 0.294% (цель окупается) и максимальная ликвидность среди
проходящих по волатильности. Для VWAP ликвидность критична: там, где нет реального объёма,
VWAP не является ничьим бенчмарком. Проверочные тикеры — NVTK и RUAL.

```
go run ./cmd/backtest -ticker GAZP -strategy vwap_rev -interval Minutes30 \
  -calibrate data/params/vwap_rev/grid.json -out ./reports/GAZP_vwap \
  -months 24 -train-months 12 -test-months 3 -metric profit_factor -min-trades 40
```

## Критерии приёмки

Все шесть одновременно, по pooled OOS из rolling walk-forward. Никогда по in-sample лучшему.

1. pooled OOS **PF ≥ 1.5**
2. **≥ 150 OOS-сделок**
3. **win rate ≥ 55%** — профильное требование, а не косметика: ниже — значит это не
   «стабильный мелкий доход», а обычный RR-трейдинг под другим именем
4. **средняя чистая сделка ≥ +0.15%** — доказательство, что издержки не съели edge
5. **≥ 3 из 4 фолдов с OOS PF > 1.0**
6. `EntryK` и `MinEdgePct` между фолдами гуляют не более чем на один шаг сетки

Пункты 5 и 6 добавлены прицельно. На них посыпались предыдущие попытки: у NVTK на 30m pooled
PF был 1.055, но весь плюс держался на одном фолде из трёх сделок; у SBER параметры прыгали
30/25/25/40 между фолдами. Один только pooled PF такое пропускает.

**Бонус-чек, не блокирующий:** прогнать победившие параметры GAZP как есть, без
пере-калибровки, на NVTK и RUAL. Если edge настоящий, PF не схлопнется в ноль на обоих. Это
информация, а не ворота — оценка по одному тикеру остаётся решением владельца.

**Критерий смерти.** Если хоть один из шести пунктов не выполнен — стратегия закрывается и в
live не идёт. Не расширяем сетку, не добавляем седьмой фильтр, не перебираем тикеры в поисках
того, где сработало. Именно на этом было потеряно время в ORB и daylow.

## План тестирования

TDD, table-driven, по образцу `rsi_ema/strategy/core/core_test.go`.

### A. `pkg/indicators/vwap_test.go`

- VWAP и σ на трёх барах одной сессии сверяются с числами, посчитанными вручную
- граница сессии: два дня подряд, якорь сбрасывается, второй день не зависит от первого
- пт → пн: граница по календарной дате, а не по числу баров
- первая сессия в окне везде помечена `barsFromOpen = -1`
- `times = nil` и рассинхрон длин → `nil, nil, nil`
- `ΣV = 0` в сессии → VWAP = 0, без NaN и деления на ноль
- одна свеча в сессии → σ = 0, не NaN
- `len(vwap) == len(sigma) == len(closes)` всегда

### B. `core_test.go` — пара «срабатывает / не срабатывает» на каждое правило

Вход: глубина ≥ `EntryK·σ` да, мельче нет; глубже `MaxDevK·σ` нет, при `MaxDevK = 0` отсечка
выключена; **`MinEdgePct` не выполнен → входа нет** (глубина в σ есть, а в процентах мала —
тихий день; этот тест стережёт от торговли внутри комиссии); закрытие в нижней трети бара →
нет, при `MinClosePos = 0` выключено; `Close ≤ EMA` по дневкам → нет, при
`UseDailyTrend = 0` выключено; `barsFromOpen < MinBarsFromOpen` → нет; вне окна и пятница
после `FridayEndMin` → нет; **пустые `DailyCloses` при `UseDailyTrend = 1` → вход запрещён**.

Выходы: `SL` и `TP` задеты на одном баре → выбирается `SL`; цель равна VWAP предыдущего бара —
тест на растущем VWAP ловит подглядывание в будущее; `TIME` по `MaxHoldBars`, `0` выключает;
`EOD` на последнем баре перед `DayEndMin`, через ночь не переносим; поля `Reason`,
`TakeProfit`, `StopLoss` заполнены так, как их ждёт движок (`IsStopReason`, фикс по
`max(TP, open)`).

### C. Тест на отсутствие lookahead

Самый важный из всех. `Decide` прогоняется по префиксам одной серии: решение на баре `i`
обязано совпадать при окне `[0..i]` и при окне `[k..i]` для любого `k`, при котором в окне
остаётся хотя бы одна полная сессия **до** сессии бара `i` (иначе сессия бара `i` окажется
первой в окне и будет корректно помечена `barsFromOpen = -1` — это не lookahead, а работа
правила выше). Если ядро читает будущее или зависит от длины окна — тест падает. Ни у одной
из похороненных стратегий такого теста не было.

### D. `vwap_rev_registry_test.go`

Биндинг собирается; частичный JSON накладывается поверх дефолтов; неизвестное имя стратегии →
ошибка.

### E. Тест сетки

По образцу `scalping_rsimacd_grid_test.go`: `grid.json` парсится; каждое имя поля существует в
`Params` (опечатка иначе молча схлопнет целую фазу); в каждой фазе есть контрольная точка
«выключено».

### F. Интеграционный smoke

Прогон движка на синтетической пиле с заранее известным числом сделок.

Прибыльность юнит-тестами не проверяется — это работа walk-forward.

## Порядок работ

1. `SessionVWAP` + тесты A
2. Ядро: вход + тесты B (вход)
3. Ядро: выходы и приоритет + тесты B (выходы)
4. Анти-lookahead тест C
5. Реестр + ветка в `cmd/backtest` + тесты D
6. `grid.json` + тест E + `docs/vwap_rev/strategy.md`
7. Калибровка на GAZP и вердикт по шести критериям

Ворота на каждой задаче — зелёный `./bin/mage ci`.

По конвенции репо новая backtest-стратегия не мержится в main до прохождения критериев
приёмки.
