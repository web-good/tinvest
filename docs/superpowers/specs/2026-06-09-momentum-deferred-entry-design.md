# Отложенный вход momentum-стратегии (deferred entry)

- Дата: 2026-06-09
- Ветка: feat/momentum-daily-trend-cooldown
- Статус: согласован

## Цель

Перестать терять валидные сетапы из-за того, что **подтверждающий** фильтр
(объём) опоздал на пару баров после MACD-кросса. Сейчас вход требует
`crossUp == true` ровно на текущем баре — это событие одного бара. Если на баре
кросса не было объёма (вечер, неликвид), на следующем баре `crossUp` уже `false`
и сетап потерян навсегда, хотя тренд и MACD остаются в нашу пользу.

Решение: развести **триггер** (MACD-кросс + тренд) и **подтверждение** (объём,
запас ATR, RR). Триггер «взводит» отложенный сигнал, который живёт ограниченное
число баров; вход случается на первом баре в окне, где сходятся остальные
фильтры — при условии, что цена недалеко ушла от цены кросса, а импульс ещё жив.

## Контекст / как устроено сейчас

- Ядро `internal/service/trading_strategy/momentum/strategy/core/core.go`:
  - `crossUp = prevDiff <= 0 && currDiff > 0` (`core.go:150`) — фиксируется на
    закрытии бара.
  - `decide()` — чистое ядро; все входные фильтры идут короткозамкнутой цепочкой
    (тренд → дневной тренд → кросс → below-zero → объём → запас ATR → анти-черн →
    RR).
  - Мутабельное состояние живёт в impure-оболочке `Strategy` (поле
    `barsSinceExit`, продвигается `trackCooldown`). Чистое `decide` получает всё
    через `decideInput`.
- Бэктест/лайв-раннеры вызывают `Decide` последовательно, по одному бару.
- Калибровочные сетки: `data/params/<ticker>/momentum_grid.json` — у всех
  тикеров (rusal/afks/ydex/plzl) идентичная стандартная сетка.
- Документация стратегии: `docs/momentum/strategy.md` (источник истины — код).

## Дизайн

### Состояние

В impure-оболочке `Strategy` добавляется «взведённый» сигнал — рядом с
`barsSinceExit`:

- `armedCrossPrice float64` — цена закрытия на баре кросса (0 = сигнала нет).
- `barsSinceArm int` — сколько баров прошло с момента взведения.
- признак «взведён» = `armedCrossPrice > 0` (вход long, цена всегда > 0).

Состояние продвигается тем же impure-методом, что и кулдаун (одно продвижение на
бар из `Decide`; `Explain` состояние не мутирует). Гасится при входе, при
истечении окна и при потере импульса/тренда.

### Триггер (взведение)

На баре взводим отложенный сигнал, если позиции нет, кулдаун пройден и выполнены
**триггерные** условия:

- `crossUp == true`;
- `price > EMA` (тренд вверх);
- дневной тренд растёт (если `DailyTrendPeriod > 0`);
- below-zero, если `MACDBelowZeroOnly == 1`.

Объём / запас дневного ATR / анти-черн / RR в момент взведения **не требуются**.
При взведении запоминаем `armedCrossPrice = price`, `barsSinceArm = 0`.

Частный случай: если все фильтры (включая объём) сходятся прямо на баре кросса —
вход происходит немедленно, как сейчас (взвели и тут же подтвердили на том же
баре).

### Подтверждение (вход)

На текущем баре, если сигнал взведён, вход происходит при одновременном:

1. **Окно живо:** `barsSinceArm <= SignalValidBars`. Иначе — гасим сигнал.
2. **Импульс жив:** MACD-линия всё ещё над сигнальной (`macd − signal > 0`).
   Иначе — гасим (тезис мёртв).
3. **Тренд держится:** `price > EMA`; дневной тренд растёт (если включён). Иначе
   — гасим.
4. **Снос цены в пределах лимита:** `|price − armedCrossPrice| <= MaxDriftATR ·
   ATR(час)`. Лимит **симметричный**: вверх — защита от погони за ушедшим
   движением, вниз — большой снос означает, что сетап ломается. Мерим в ATR, не в
   процентах, чтобы порог самонастраивался под тикер и волатильность.
5. **Текущие фильтры подтверждения:** объём + запас дневного ATR + анти-черн +
   RR/`MinRR` — без изменений.

### SL/TP

Считаются по бару **фактического входа** (текущий ATR + текущий swing-low), не по
бару кросса — модель риска остаётся консистентной. Если цена снеслась вверх,
риск вырастет и существующий `MinRR` сам отрежет слишком далёкий вход (второй
предохранитель поверх лимита сноса).

### Приоритет кулдауна

Пока идёт кулдаун (`barsSinceExit < CooldownBars`) — **не взводим** сигнал, чтобы
не входить по протухшему кроссу ровно на выходе из кулдауна.

## Новые параметры

Оба калибруемые, оба с «выключающим» дефолтом (сохраняют текущее поведение
один-в-один):

| Параметр | Тип | Дефолт | Смысл |
|---|---|---|---|
| `SignalValidBars` | int | 0 | Сколько баров после кросса сигнал остаётся «взведён». `0` = вход только на самом баре кросса (текущее поведение). |
| `MaxDriftATR` | float64 | 0 | Макс. снос цены от цены кросса в долях ATR(час). `≤0` = лимит сноса отключён. |

Семантика «выключено»: при `SignalValidBars == 0` весь отложенный механизм
эквивалентен текущему коду (взвели и проверили подтверждение на том же баре, окно
нулевое). Существующие захардкоженные параметры RUAL/AFKS остаются валидны.

## Поток данных / совместимость

- `decideInput` расширяется полями для отложенного входа (взведён ли сигнал, цена
  кросса, `barsSinceArm`, признак «MACD ещё бычий»).
- `Lookback()` не меняется (новые knob'ы не требуют большего окна свечей).
- `entryReason` (журнал сделок): при отложенном входе добавляет пометку, что вход
  отложенный — сколько баров ждали и насколько ушла цена от кросса. На немедленном
  входе текст не меняется.
- `Explain` отражает новые гейты (окно сигнала, лимит сноса) в той же
  короткозамкнутой логике, что и `decide`.

## Калибровка

Расширить сетки `data/params/*/momentum_grid.json` диапазонами для новых knob'ов
(например `SignalValidBars: [0, 2, 3, 4]`, `MaxDriftATR: [0, 0.5, 1.0, 1.5]`).
Финальные диапазоны и комбинаторика — на этапе плана; следить за взрывом числа
комбинаций. Запуск `-calibrate` и хардкод winner — вне scope этой итерации
(делает пользователь, как с RUAL/AFKS).

## Тестирование

- Юнит-тесты ядра (`core_test.go`) по образцу существующих:
  - `SignalValidBars == 0` → поведение байт-в-байт как сейчас (нет кросса с
    объёмом на одном баре → нет входа); защищает обратную совместимость.
  - Кросс без объёма на баре N, объём появляется на баре N+1 в пределах окна и
    лимита сноса → вход на N+1.
  - Объём появляется ПОСЛЕ истечения окна → входа нет (сигнал погашен).
  - Цена ушла дальше `MaxDriftATR · ATR` к моменту объёма → входа нет.
  - MACD развернулся обратно (линия ушла под сигнальную) в окне → сигнал погашен,
    входа нет даже при объёме.
  - Кулдаун активен в момент кросса → сигнал не взводится.
- `go build ./...`, `go vet ./...`, `go test ./...` — зелёные.
