# gap_fade — live гостем раннера счёта rsi_pullback

Дата: 2026-10-02. Подпроект 2 из 2. Подпроект 1 — скринер `cmd/gapscreen`
(спека `2026-10-02-gap-fade-screener-design.md`) — смержен, гейт `cmd/gapwf` на его наборе
`GAP_FADE_TICKERS` пройден.

## Зачем

gap_fade прошла гейт на ликвидном наборе тикеров. Следующий шаг — живые сигналы на общем счёте
с rsi_pullback, сначала в бумажном режиме: он показывает реальные цены исполнения и поведение
стратегии на свежих данных без денег. Торговля на деньги включается отдельным решением владельца
после бумажного периода и в эту спеку не входит.

## Принцип

gap_fade — третий адаптер раннера счёта rsi_pullback, по образцу rsi_zone
(`docs/rsi_zone/live.md`): один процесс, один пасс раз в полчаса, общий файл стейта, владение
тикером через поле `strategy`. Общая механика раннера (расписание, guard протухшего бара, сборка
данных, стоп-заявки, grace, `pendingExit`, бумажный режим при боевой соседке) не меняется и
не дублируется.

## Параметры

Один литерал на все тикеры `GAP_FADE_TICKERS` (калибровки по тикерам нет — см. спеку скринера):

| Поле | Значение |
|---|---|
| `GapATR` | 0.7 |
| `MaxGapATR` | 3.0 |
| `EntryBar` | 0 |
| `TargetFill` | 0.75 |
| `StopDailyATR` | 1.0 |
| `DailyATRPeriod` | 14 |
| `EODHour:EODMinute` | 18:30 |

Литерал живёт в пакете `internal/service/trading_strategy/gap_fade/strategy/shared` с
обоснованием выбора в doc-комментарии; `GapATR` 0.7 вместо 0.5 выбран за вдвое меньшее число
сделок при той же сумме доходностей — запас под издержки.

## Устройство

### Адаптер `internal/service/trading_strategy/gap_fade/live`

- `Name() = "gap_fade"`, `Label() = "Gap Fade"`, Telegram-префикс «[Gap Fade] ».
- Реестр `registry.go`: `ParamsFor(ticker)` / `StrategyFor(ticker)` отдают общий литерал для
  любого непустого тикера — и тикера вселенной, и тикера записи стейта с владельцем `gap_fade`,
  убранного из вселенной (позицию надо довести до выхода). Входы ограничивает вселенная
  (`Tickers()`), а не реестр. Пустой тикер — не зарегистрирован.
- `New(cfg, tg, dividends)`; `dividends` — клиент с `GetDividends` (интерфейс в пакете адаптера).
- Порядок адаптеров раннера: `[rsi_pullback, rsi_zone, gap_fade]`. По тикеру, занятому позицией
  другой стратегии, gap_fade не входит; при BUY двух стратегий на одном баре входит старшая.

### Тайминг входа

Сигнал — close бара 06:30 MSK (бар 0 дня, вмещает открывающий аукцион). Пасс в 07:01 видит его
закрытым и покупает рыночным ордером — это live-аналог `EntryAtNextOpen` (покупка по open бара
07:00). Расписание `RSI_PULLBACK_SCHEDULE` (`1,31 6-23 * * *`) уже содержит 07:01. Сборка
данных — общий `marketdata.Assemble`, окно `Strategy.Lookback()` (64 бара), `Opens` заполняет
`backtest.AssembleMarketData`.

### Стоп

Уровни gap_fade замораживаются от close сигнального бара, а не от цены исполнения:
стоп = `close − StopDailyATR·ATR`, цель = `close + TargetFill·(prevClose − close)`. Цель уже
хранится (`Entry.TakeProfit`). Для стопа:

- `statestore.Entry` получает поле `StopLoss float64 \`json:"stopLoss,omitempty"\`` —
  замороженный уровень стопа.
- Пасс при входе пишет `sig.StopLoss` в `Entry.StopLoss` для любой стратегии и передаёт
  `Entry.StopLoss` в `strategy.Position.StopLoss` при сопровождении. Ядра rsi_pullback и rsi_zone
  `Position.StopLoss` не читают — их поведение не меняется.
- `DesiredStop` gap_fade возвращает `(e.StopLoss, "SL")`; при `e.StopLoss <= 0` — `(0, "")`.
- Стоп-заявка — общая биржевая GTC, уровень не меняется всю жизнь позиции.

### Выходы

| Выход | Механизм |
|---|---|
| SL | биржевая стоп-заявка |
| TP | рыночный SELL на пассе после бара с `high ≥ цели` (общий путь раннера) |
| EOD | рыночный SELL на пассе 19:01 после бара 18:30 |
| новая дата | первый бар новой даты закрывает позицию (ядро, fail-closed) |

Лимитной заявки на цель нет: замер 2026-10-02 на 46 тикерах, 36 месяцев, показал, что продажа по
open следующего бара не хуже внутрибарной цели бэктеста, а вторая живая SELL-заявка на позиции
без OCO опасна. Отказ брокера на продаже ловит общий `pendingExit`.

### Дивидендная отсечка

Бэктест выбрасывает сделки дня отсечки: гэп там — дивиденд, а не шум. Live обязан не входить.

- В `livecore/adapter` — необязательный интерфейс
  `EntryFilter { EntryBlocked(ctx, ticker, instrumentID string, md strategy.MarketData) (reason string, err error) }`.
- Пасс (`buy`) после BUY-сигнала и до сайзинга проверяет, реализует ли адаптер `EntryFilter`.
  Непустая причина — вход пропускается с уведомлением в тему стратегии; ошибка — вход
  пропускается, алерт в тему стратегии и ERROR-лог (fail-closed). Бар в обоих случаях не
  расходуется: следующая по приоритету стратегия спрашивается, как при бумажном входе.
- gap_fade: `GetDividends` за окно `[время бара − 30 дней, время бара + 7 дней]` (API фильтрует по
  дате реестра); дни отсечки — общая с `cmd/gapwf` функция `svc.GapDividendExDays(divs, md.Times)`
  (вынесена из `cmd/gapwf`: отменённые пропускаются, первый бар после `last_buy_date`, без неё —
  дата реестра). Вход блокируется, если дата последнего бара `md` — день отсечки.
- Запрос идёт только на BUY-сигнал (единицы в день), отдельного кэша нет.
- Сверка `pullparity` фильтр не вызывает: она сравнивает сборку `MarketData` и вердикт ядра.

### Окно входа (нагрузка на API)

Пасс собирает `MarketData` отдельно на каждую стратегию тикера, а `GAP_FADE_TICKERS` сильно
пересекается с вселенной rsi_pullback: без ограничения каждый пасс тянул бы свечи ещё ~46 раз, хотя
gap_fade может войти только утром. Необязательный интерфейс
`adapter.EntryWindow { EntryPossible(now time.Time) bool }`: пасс по свободному тикеру не собирает
данные и не спрашивает стратегию, если `EntryPossible(now)` ложно. Сопровождение позиций он не
трогает. gap_fade: будний день MSK и время пасса 07:00 ≤ t < 10:00 MSK (запас вокруг бара 06:30 на
сдвиг расписания сессии).

### Реконструкция позиции без стейта

По образцу rsi_zone: `EntryTime` — последняя BUY за 180 дней, `EntryPrice` — средняя цена
брокера, `EntryATR` — `rebuild.WeekdayDailyATRBefore` на дату входа; `StopLoss =
EntryPrice − StopDailyATR·EntryATR` (close сигнального бара неизвестен — приближение ценой
входа); `TakeProfit = 0`; `MaxFav = EntryPrice`. Нулевой ATR — ошибка. Позиция без цели всё
равно закрывается EOD или первым баром новой даты. Правила выбора владельца (бумажная при
боевой соседке не реконструирует) — общие.

### Конфигурация

`internal/config/gap_fade.go`, по образцу `RSIZoneConfig`, ни одной `required` переменной:

| Переменная | Дефолт | Смысл |
|---|---|---|
| `GAP_FADE_TICKERS` | `""` | вселенная входов; пусто — стратегия не подключается |
| `GAP_FADE_BUY_PCT` | `5` | доля полной стоимости счёта на сделку, затем ограничение кэшем |
| `GAP_FADE_TRADE_ENABLED` | `false` | ордера и стоп-заявки уходят на биржу |
| `GAP_FADE_NOTIFY_ENABLED` | `false` | уведомления в Telegram |
| `TELEGRAM_TOPIC_GAP_FADE` | — | тема форума; не задана — General |

Подключение — в `service_provider.GetRSIPullbackLiveService` после rsi_zone, с instruments-клиентом
счёта rsi_pullback как источником дивидендов. `env/prod.env.example` — блок переменных с
`GAP_FADE_TRADE_ENABLED=false`. `env/prod.env` — добавить `GAP_FADE_TRADE_ENABLED=false` и
`GAP_FADE_NOTIFY_ENABLED=true` (бумажный режим).

### Сверка `cmd/pullparity`

`-strategy gap_fade` выбирает реестр gap_fade. Приёмка — ноль расхождений сборки `MarketData`
и вердикта `Decide` по всей вселенной до выката бумажного режима.

## Ошибки и пограничные случаи

- Тикер без вечерней сессии: SELL в 19:01 отклонён — `pendingExit`, повтор на следующих пассах;
  стоп-заявка GTC защищает позицию через ночь.
- Нет дневного ATR (короткая история) — ядро не входит.
- Сбой `GetDividends` — вход не делается (fail-closed), алерт.
- Тикер убран из `GAP_FADE_TICKERS` с открытой позицией — ведётся до выхода, новых входов нет.

## Тесты

- Реестр: тикер вселенной и тикер записи стейта отдают общий литерал; литерал равен таблице
  параметров (сторожевой тест).
- Адаптер: `DesiredStop` от `StopLoss`, ноль — без стопа; `Reconstruct` — стоп от цены входа,
  без цели, нулевой ATR — ошибка; `Notify` с префиксом и выключенным флагом.
- `EntryBlocked`: день отсечки блокирует; отменённый дивиденд не блокирует; дивиденд без
  `last_buy_date` — по дате реестра; ошибка API — ошибка.
- Пасс: `EntryFilter` с причиной — нет ордера, уведомление, следующая стратегия спрашивается на
  том же баре; ошибка фильтра — нет ордера, алерт; адаптер без фильтра — прежнее поведение.
- Пасс: `EntryWindow` ложно — свечи по свободному тикеру не запрашиваются, стратегия не
  спрашивается; позиция стратегии вне окна сопровождается (EOD в 19:01).
- Пасс: `Entry.StopLoss` пишется при входе и попадает в `Position.StopLoss`; стейт pullback/zone
  без поля читается как прежде.
- Сквозной сценарий пасса на фейковых свечах: гэп-день, вход в 07:01, стоп-заявка на
  `StopLoss`, выход TP на пассе после бара касания, выход EOD в 19:01.
- Конфиг: загрузка без переменных, дефолты.
- `pullparity -strategy gap_fade`: выбор реестра.
