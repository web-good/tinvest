# RSI+EMA: фильтр свежести входа

## Проблема

Вход `rsi_ema` — крест RSI вверх через `RSIMid` (50) при `EMAFast > EMASlow`. На боковике вокруг
средней линии это порождает перезаходы-чоп: RSI долго держится выше 50, на один-два бара ныряет
под 50 и тут же снова пересекает вверх — новый вход без реального сброса. Пример — сделка 176
из `reports/SBER/SBER_rsi_ema_Minutes15_20260724_001159.md` (вход 2026-07-14 13:45, RSI 59.5): RSI
шесть баров (12:00–13:15) сидел выше 50, один бар (13:30, RSI 47.9) кольнул вниз, и на 13:45
случился крест — перезаход сразу после того, как предыдущая сделка 175 вышла по RSI50. Убыток.

Для контраста сделка 174 (вход 2026-07-13 10:00, RSI 60.1, вышла по RSI70 с +400) — перед крестом
RSI реально держался под 50 (09:30 49.4, 09:45 49.1), лишь один короткий заскок 09:15 50.2. Это
свежий заход, его отсекать нельзя.

## Правило: фильтр свежести

В `enter()`, после подтверждения креста RSI↑`RSIMid` и тренда `EMAFast > EMASlow`, но перед
выдачей Buy, добавляется гейт:

> В окне из последних `EntryLookbackBars` баров перед баром-крестом (индексы `i-1 … i-EntryLookbackBars`,
> с усечением по началу серии) посчитать бары с `RSI > RSIMid`. Если их **≥ `EntryAboveMidLimit`**,
> вход отклоняется.

Бар `i-1` по определению креста лежит ниже `RSIMid`, поэтому реально считаются бары `i-2 … i-EntryLookbackBars`;
включение `i-1` в окно безвредно и упрощает границы.

### Новые параметры (оба в гриде)

| Параметр | Дефолт | Смысл |
|---|---|---|
| `EntryLookbackBars` | 5 | размер окна перед крестом для подсчёта баров выше `RSIMid` |
| `EntryAboveMidLimit` | 3 | порог: при `≥` стольких баров выше `RSIMid` в окне вход отклоняется |

**Выключение фильтра.** Гейт активен только когда `EntryAboveMidLimit > 0` и `EntryLookbackBars > 0`.
При `EntryAboveMidLimit <= 0` или `EntryLookbackBars <= 0` фильтр не применяется — грид сможет
сравнивать стратегию с фильтром и без него.

### Проверка на дефолтах (окно 5, порог 3)

- Сделка 176 (крест 13:45): окно = 13:30(below), 13:15, 13:00, 12:45, 12:30 → 4 бара выше 50
  `≥ 3` → **отклонён** ✓.
- Сделка 174 (крест 10:00): окно = 09:45(below), 09:30(below), 09:15, 09:00(below), 08:45 →
  2 бара выше 50 `< 3` → **пропущен** ✓.

### Почему окно, а не «серия из 3 подряд»

Голая «серия ≥3 баров выше 50 непосредственно перед провалом» без ограничения окна отсекала бы и
легитимные входы после долгого (10+ баров) сброса под 50 — по интенту такой сброс, наоборот, должен
разрешать вход. Окно кодирует ключевое условие «провал был коротким»: если RSI ушёл под 50 надолго,
серия баров выше 50 выпадает за границу окна и вход проходит.

## Свойства

- Чисто индикаторное правило: считается из уже вычисленной `RSISeries`, без нового межбарного
  состояния. Ядро остаётся stateless и ticker-agnostic.
- Timeframe-agnostic: окно измеряется в барах, длину бара знать не нужно.
- Только вход. Логика выходов (`SL`/`EMAX`/`RSI70`/`RSI50`/`EOD`) не трогается.
- `Explain()` (`-explain`) выводит вердикт гейта: число баров выше `RSIMid` в окне и прошёл ли фильтр.
- `entryReason` не меняется по формату (гейт не даёт ложных Buy, а тихо отклоняет); диагностика — в `Explain`.

## Тесты (ядро)

- `DefaultParams`: `EntryLookbackBars == 5`, `EntryAboveMidLimit == 3`.
- Фильтр режет перезаход-чоп: синтетический ряд, где RSI держится выше 50, один бар ныряет и
  пересекает вверх при `EMAFast>EMASlow` → на дефолтах Buy НЕ выдаётся.
- Свежий крест проходит: RSI держался под 50 несколько баров, затем крест вверх → Buy выдаётся.
- Граница порога: ровно `EntryAboveMidLimit-1` баров выше в окне → проходит; `EntryAboveMidLimit` → режется.
- Выключение: `EntryAboveMidLimit = 0` → перезаход-чоп снова даёт Buy (фильтр не применяется).
- Усечение у начала серии не паникует и не режет по недостатку истории (мало баров → фильтр
  считает по доступным, не блокирует искусственно).
