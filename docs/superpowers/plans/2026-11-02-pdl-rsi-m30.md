# pdl_rsi_m30 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independent backtest-only M30 implementation of the pdl_rsi idea, its RENI pilot literal, calibration assets, documentation, and evidence.

**Architecture:** A new `pdl_rsi_m30/strategy/core` owns all M30 behavior and duplicates the small strategy-specific mechanics needed to keep Hour1 isolated. Backtest registration is a separate binding accepting only `Minutes30`; the sole pilot literal is RENI because it is the current three-universe intersection. Calibration is driven by its own grids and personal Codex skill.

**Tech Stack:** Go 1.25, existing pure backtest/strategy interfaces, project RSI/EMA/ATR indicators, JSON calibration grids, Codex skills.

**Spec:** `docs/superpowers/specs/2026-11-02-pdl-rsi-m30-design.md`

## Global Constraints

- Do not import or call `internal/service/trading_strategy/pdl_rsi` from `pdl_rsi_m30`.
- Do not change Hour1 engine, parameters, literals, registry semantics, or live behavior.
- The new strategy is backtest-only and accepts only `enum.Minutes30`.
- Intraday periods use closed M30 bars; daily ATR remains based on completed weekday dailies.
- RSI exit is cross-up only; there are no `RSITrail*` fields or behavior.
- Use RED-GREEN TDD for production behavior and fresh verification before completion claims.

## Review Focus

- M30 session geometry: 36 exchange bars/day, 44 dealer/weekend bars/day, and 18 main-session volume bars.
- Entry at the final M30 bar of a date must be rejected because the fill would cross the MSK date.
- RSI values before warm-up must neither enter nor exit.
- Same-bar stop and target ambiguity must retain stop-first priority.
- A source scan must prove `pdl_rsi_m30` has no imports of `pdl_rsi` and Hour1 tests still pass.
