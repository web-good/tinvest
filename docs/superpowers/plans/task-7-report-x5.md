применимо: превосходство есть (2.609 > 2.278), большинство по `VolLookbackBars` есть.

| `UseVolume` | обе темы | 4/4 | **1** | 0 |

**Четыре новых поля уходят от дефолтов ядра.** Конфликта между темами нет ни по одному полю:
там, где обе меряют одну ось (`UseVolume`, `VolMult`), они голосуют одинаково.

Все голоса совпали с пре-замером Task 1:

- `VolBaseDays` = 3 → на полном окне 1.851/55 (DD 6 486 ₽) — **вершина оси**;
- `VolMult` = 1.0 → 1.537/55 — **вершина оси** («работают только мягкие пороги»);

## Step 4 — сверка с априором бумаги

Априор, записанный в план: **на X5 объёмный гейт — один из двух реально работающих рычагов**
(1×1 → 1.494/51 против baseline 1.374/76; `VolLookbackBars` 16 → 2.110/70 при просадке на 41%

**Априор подтверждён полностью и с запасом.** Расхождения, которого опасался план (урок темы
`screen` на IRKT — цена гейта, измеренная на полном окне, не переносится в train-окна), здесь
не случилось: голоса единогласны, а pooled OOS обеих тем вдвое выше baseline.

### Почему тема `screen` дала по `UseVolume` ничью 2:2, а эти темы — 4/4

Это кажущееся противоречие внутри одной калибровки, и оно объясняется без натяжки:

- тема `screen` меряет объёмный гейт **на дефолтной настройке** (`VolMult` = 1.2,
  `VolBaseDays` = 14, `VolLookbackBars` = 3). На ней гейт спорен — два фолда за, два против;
- темы `volume` и `vol_window` меряют гейт **на своей настройке** (1.0 / 3 / 12). На ней гейт
  бесспорен — 4/4 и 4/4.

**Цена гейта — функция его настройки, а не самого факта включения.** Ничья темы `screen`
отменяется не потому, что она неверна, а потому, что она мерила другой объект. В точку идёт
`UseVolume` = 1 по голосу тем, которые мерили гейт вместе с его параметрами.
