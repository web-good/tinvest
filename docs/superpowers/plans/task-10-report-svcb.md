### Step 3 — вердикт арбитра (§5.2 спеки)

**Входные данные из более ранних задач:**

- `day` (Task 6): pooled OOS **0.815/156**; `FreshDayATR` 0/0.3/0.4/0 — нет большинства (узел 0
  берёт максимум 2/4); `SpentDayATR` 0.6/1.5/2/0.6 — нет большинства (узел 0.6 берёт максимум 2/4).
  **Ни одна ось `day` не покидает дефолт** (`FreshDayATR`=0 уже совпадает с дефолтом,
  `SpentDayATR`=0.8 остаётся дефолтом ядра).
- `risk` (Task 8): pooled OOS **2.283/97**; `StopDailyATR` 1.5/1.5/1.5/0.8 → большинство 3/4 за
  узлом 1.5, укороченным гейтом A до **1.0** — уход от дефолта состоялся (0.5 → 1.0); `TPDailyATR`
  без большинства, остаётся дефолтом 0.6.

**Правило.** В паре `day`×`risk` за уход от дефолта голосует **только `risk`** (1 тема из 2) —
`day` дефолт не покидает ни по одной из своих осей. Условие «не больше одной темы пары» выполнено.

**Вердикт: `day_stop` — СПРАВОЧНЫЙ.** Арбитр не поставляет полей в точку: `SpentDayATR` остаётся
дефолтом ядра 0.8 (решение Task 6), `StopDailyATR` идёт в точку значением 1.0 — потолком гейта A
(решение Task 8, независимое от Task 10).

**Оговорка — расхождение с прецедентом RTKM.** В отличие от `trend_stop` RTKM, где двойное основание
(отсутствие рычага у входных тем **и** отсутствие большинства у самого арбитра) совпадали, здесь
**собственные голоса арбитра достигают большинства 3/4 по обеим осям** (`SpentDayATR`=0.6,
`StopDailyATR`=0.8) — и эта пара совпадает побайтово с опорной in-sample точкой брифа/`_comment`
(`SpentDayATR 0.6 + стоп 0.8 → 1.367/214`, §6.6 спеки). Это не меняет вердикт: правило §5.2 условие
«обе темы пары голосуют за уход от дефолта» проверяет по голосам **исходных тем-измерителей**
(`day`, `risk`), а не по собственному голосованию арбитра, и §5.2 прямо называет арбитра «не
источником полей» — тема не имеет канала протащить связку в точку в обход правила, пока
тема-измеритель (`day`) сама не даёт большинства на своей отдельной сетке. Связка
`SpentDayATR`×`StopDailyATR` — реальный рычаг *в принципе* (тема прошла гейт фолдов, её собственное
голосование устойчиво воспроизводит связку по всем 4 фолдам почти без разброса), но правило сборки
не даёт механизма его использовать здесь. Записано прямым текстом для Task 12 (округ 2 может строить
зоны от этих голосов).

## Что это значит для дальнейшего плана

1. **Ни `entry_stop`, ни `day_stop` не дают точке ни одного поля.** В обеих парах (`entry`×`risk` и
   `day`×`risk`) за уход от дефолта проголосовала только тема `risk` — правило §5.2 требует ухода от
   дефолта у **обеих** тем пары, прежде чем арбитр сможет разрешить конфликт или подтвердить
   сложение рычагов; здесь это условие не выполняется ни разу.
2. **Точка получает свои поля вход/стоп/день целиком из Task 4/6/8, без корректировок Task 10:**
   `RSILower`=30 (дефолт, Task 4), `SpentDayATR`=0.8 (дефолт, Task 6), `StopDailyATR`=1.0 (потолок
   гейта A, Task 8), `TPDailyATR`=0.6 (дефолт, Task 8).
3. **`day_stop` — не зеркало RTKM `trend_stop` в одном отношении**: его собственные голоса
   (`SpentDayATR`=0.6, `StopDailyATR`=0.8, оба 3/4) реально устойчивы и совпадают с опорной
   in-sample точкой — сильный рычаг *в принципе*, недоступный правилу сборки, потому что
   тема-измеритель `day` сама не набрала большинства. Прямое указание для Task 12 (округ 2): если
   раунд 2 будет строить зоны вокруг этой связки отдельно от правила §5.2, числа для старта — здесь.
4. `entry_stop`, напротив, полностью повторяет прецедент RTKM `trend_stop`: двойное основание
   (ни входные темы, ни сам арбитр большинства не дают).
