## Step 3 — сверка с ожиданием (дословно из брифа)

Бриф: опорный in-sample замер `vol_window` — лучший узел `VolLookbackBars × VolMult` = **1 × 2.0 →
1.519/43** (2025 +4 773 ₽, хвост 6 1.442/13), остальные узлы 1.18–1.40.

Walk-forward подтверждает направление этого ориентира почти буквально: 3 из 3 валидных фолдов
выбрали `VolLookbackBars=1`, 2 из 3 — `VolMult=2.0` (третий — 1.2, тоже из каталожной тройки узла
2). Pooled OOS 1.306/31 ниже in-sample ориентира 1.519/43 (ожидаемое расхождение in-sample/OOS), но
той же полярности и в разумном диапазоне.

Тема `volume`: бриф не даёт отдельного точечного ожидания по осям `VolMult`/`VolBaseDays` (только
напоминание, что `UseVolume` эта тема не решает). Раскол 2×2 по обоим краям грида — сюрприз
относительно «широкий каталожный диапазон, узлов нет» из исходного `_comment`: узлы фактически
выбираются per-fold на самих краях.

Обе темы идут поверх `UseVolume=1`, `UseDayATRGate=1` (не узла `screen` 0×1) — как и предписано
брифом Step 3: «UseVolume зафиксирован на 1, поле не решают».

## Вердикт (для Task 11)

- **Тема `volume`**: pooled OOS PF **1.150** / пул **37** сделок (все 4 фолда невырождены, все
  голоса засчитываются). Ни `VolMult`, ни `VolBaseDays` не набрали большинства — раскол ровно 2×2 по
  обоим краям грида для каждой оси. Тема не даёт рычага для сборки точки (кроме подтверждения, что
  `UseVolume=1` на дефолтных `VolMult`/`VolBaseDays` совместим с положительным, но слабым pooled
  OOS).
- **Тема `vol_window`**: pooled OOS PF **1.306** / пул **31** сделка, из которых фолд 4 (**4** сделки)
  **вырожден** и исключён из голосования и из зачёта «в пользу тикера» (квота ≥3/4 невырожденных
  фолдов выполнена — 3 из 4 валидны). `VolLookbackBars=1` — голос с большинством (3/3 валидных),
  край грида (минимум). `VolMult=2.0` — плюральность без строгого большинства (2/3 валидных), тоже
  край грида (максимум оси в этой теме). Оба значения совпадают по направлению с in-sample
  опорным узлом брифа (1×2.0 → 1.519/43).
- **`UseVolume` не решается ни одной из этих двух тем** — решение приняла тема `screen` (Task 3):
  большинство 3/4 за `UseVolume=1`, но собранный узел `screen` (0×1, дневной гейт выключен) не
  проходит гейт B по просадке (12 937 ₽ in-sample против порога 9 642.93 ₽). Голоса `volume` и
  `vol_window` пишутся полностью (не справочно), так как условие брифа «если объёмный гейт в точку
  не войдёт, голоса — справочно» относится к самому включению `UseVolume`, а не к его отмене здесь;
  окончательное решение по сборке узла (0×1 vs 1×0 vs другое) — за Task 11.
- Если Task 11 включит `UseVolume=1` в собранную точку: кандидат на `VolLookbackBars` — **1** (голос
  с большинством, обе темы согласны — `volume` не свипует эту ось и оставляет её на дефолте 3, но
  `vol_window` явно предпочитает 1); кандидат на `VolMult` — **2.0** (плюральность в `vol_window`,
  но противоречит расколу 2×2 в `volume`, где половина фолдов выбрала 3.0, а другая половина 1.0);
  `VolBaseDays` — большинства нет ни в одной теме, дефолт (14) не выбран ни одним валидным фолдом
  ни там, ни там (`volume`: 3/3/20/20).
