## Step 3 — сверка с ожиданием

Ожидание из брифа: «Обе темы идут с `UseVolume` 1 и поле `UseVolume` не решают — его решает
`screen` (Task 3). Опорный замер: лучшие формы гейта — окно 16–24 бара (1.269–1.274), это в
пределах шума дефолта 1.251 без гейта. Ожидание: объёмный гейт в точку не войдёт; тогда голоса этих
тем пишутся справочно.»

**Подтверждено фактом Task 3.** `cal_screen.json` (`_comment`, результат прогона 2026-09-25):
узел `UseDayATRGate=1 x UseVolume=0` победил **единогласно 4/4 по обеим осям** — `UseVolume`
даже не попал в раздел «Гуляли» отчёта темы `screen`. Объёмный гейт **выключен** в собранной
точке независимо от голосов этой задачи — правило «поле берётся из темы, которая его меряет»
(`UseVolume` меряет `screen`, а не `volume`/`vol_window`) применяется буквально. Все три поля
гейта (`VolMult`, `VolBaseDays`, `VolLookbackBars`) в точку **не входят** и остаются на дефолтах
ядра (`VolMult=1.2`, `VolBaseDays=14`, `VolLookbackBars=3`) — их значение внутри выключенного
гейта не действует.

Опорный замер (in-sample, §6.3 спеки) предсказывал диапазон 1.269–1.274 на окне 16–24 бара —
**walk-forward пула дал ниже этого диапазона** для обеих тем (`vol_window` pooled OOS 1.135,
`volume` pooled OOS 1.212), то есть даже гипотетически (если бы гейт был включён) сигнал не
усилился на OOS, а ослаб — типичная для каталога деградация in-sample → OOS. Итог совпадает с
ожиданием по существу («гейт в точку не войдёт»), хотя по фактической причине это уже решено на
уровне `screen`, а не проверкой этой задачи.

**Справочно, для полноты (правило §5.2 по аналогии с `trend`/`trend_low`, применялось бы только
если бы `UseVolume=1` победил на `screen`):** правило гласит — поля из `vol_window` идут в точку
вместо `volume` только при одновременном выполнении двух условий: большинство ≥3/4 по ведущей оси
**и** pooled OOS `vol_window` выше, чем у канонической `volume`. Формально `vol_window` дал
большинство ≥3/4 сразу по обеим осям (`VolLookbackBars` 3/4, `VolMult` 3/4) — сильнее, чем
`volume` (только `VolBaseDays` 3/4, `VolMult` без большинства). Но **pooled OOS `vol_window`
(1.135) ниже, чем у `volume` (1.212)** — второе условие правила не выполнено. Даже в
гипотетическом мире с включённым гейтом поля `vol_window` не заменили бы поля `volume` целиком.
Это чисто справочное наблюдение — практического значения не имеет, так как гейт выключен решением
`screen`.
