# Реализация часовой сводки inplay для Bybit Spot

**Цель** — каждый полный час публиковать в теме inplay активные спотовые пары USDT с оборотом выше 80 млн USDT и NATR(14) в диапазоне 0,4–1,7%.

**Архитектура** — отдельный воркер пакета inplay, существующий публичный клиент Bybit для справочника инструментов и pkg/indicators.ATR для сглаживания Уайлдера. Для OHLC использовать одно чтение закрытых свечей с ценой закрытия в каждой записи. Текущий SpotM5 не возвращает close.

**Стек** — Go, REST Bybit V5, Telegram. [Спецификация](../specs/2026-11-25-inplay-bybit-spot-design.md).

## Отбор

- [x] В internal/service/screener/inplay/bybit_test.go проверить пороги на равенство и на значения чуть выше и ниже, разрыв истории, влияние предыдущего close и исключение текущей свечи. Запустить тесты до реализации.
- [x] В bybit.go запрашивать все активные пары Spot/USDT и отбирать по turnover24h до загрузки свечей. Для прошедших пар запрашивать историю за сутки до границы часа (до 288 закрытых M5). Для новых инструментов достаточно 15 последовательных свечей, заканчивающихся точно на границе часа. Пропуск внутри истории делает расчёт недоступным.
- [x] Рассчитать NATR как 100 × Wilder ATR(14) / последний close. Сравнить с границами до форматирования. Проверить тесты отбора.

## Отчёт и запуск

- [x] На тестовом источнике проверить порядок по убыванию оборота и по символу при равенстве, корректную пустую сводку и отличие ошибки загрузки от пустой выборки.
- [x] В bybit.go реализовать запуск после закрытия каждого полного часа, отправку символа, оборота и NATR в общем отчёте и разбиение длинной выдачи по лимиту Telegram.
- [x] Подключить воркер в internal/app/app.go под существующим флагом inplay с существующим отправителем темы.
- [x] Проверить go test -race для пакетов inplay, app и клиента Bybit, собрать ./internal/... ./pkg/... ./cmd/... и проверить git diff --check.

## Проверка границ задачи

Расчёт использует денежный оборот в USDT, свежий снимок тикеров и закрытые свечи одного инструмента. В тестах отдельно проверить, что ровно 80 млн исключается, а оба края диапазона NATR принимаются. Профили плотностей и их запуск остаются вне изменений.
