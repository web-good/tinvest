Текущая механика и точки входа:

- RSI_PULLBACK core уже проверяет High >= TakeProfit. live принимает решение после завершённой M30 и вызывает market Sell. У RSI_ZONE другая механика; её не трогать.
- `internal/service/trading_strategy/rsi_pullback/live/fvg_orders.go`: `reconcileFVG` и `placeFVGTarget` уже ведут пару SL/TP для fvg_imbalance: дочерний ордер, частичные исполнения, отстающий портфель, неопределённый результат отправки, отмена второй заявки.
- `livecore/stoporders/stoporders.go`: `PlaceTakeProfit` ставит TAKE_PROFIT с рыночным дочерним SELL, цель округляется вверх до шага цены. Цена исполнения не гарантируется.
- `live/pass.go`: FVG-only условия при входе (~601), безопасной отправке стопа (~649), реконструкции (~741), сверке (~755), маскировании core SL/TP (~852), сопровождении (~949), отмене TP перед Sell (~999), сохранении намерения/результата market Sell (~1025/1037/1057), блокировке входа при осиротевших заявках (~238). Не заменять все проверки имени FVG вслепую: часть относится к расписанию/конкуренции, а не к ордерам.
- `livecore/statestore/statestore.go` содержит `TakeProfitOrderID` и поля FVGExitOrderID/FVGExitStopID/FVGRecovering/FVGStopPending/FVGTargetPending с timestamps. При выделении общего механизма сохранить совместимость существующих JSON файлов и восстановление старых позиций без новых полей.
- RSI_PULLBACK core считает DesiredStop по EntryATR/PrevMaxFav, а не только Position.StopLoss. При StopOnClose=1 сохранить CATSL → TP → SLC/TRAILC → RSI. Нельзя переносить FVG-маскирование StopLoss на RSI без проверки этой механики. Брокерский TP должен убрать программную продажу по старому касанию свечи, но оставить RSI и close-based стопы.

Нужные проверки live:

1. После подтверждённого входа SL и TP; TakeProfit=0 без TP; бумажный режим без реальных заявок.
2. TP активирован — это ещё не исполнение; сохранять state до сверки дочернего ордера и портфеля.
3. После TP снять SL, после SL снять TP; не открывать шорт повторной продажей.
4. RSI/close-based выход: отмена защит, проверка гонки с исполнением, затем market Sell.
5. Частичные исполнения, размер остатка, внешняя отмена, перезапуск/потеря state, восстановление старых позиций.
6. Таймаут отправки не означает отклонение; не повторять вслепую при неизвестном исходе.
7. Регрессии существующего FVG и других гостей общего раннера.

Локальная отмена второй заявки не является атомарным OCO. Существующую схему FVG нужно проверить на гонки отмены/исполнения до повторного использования. Реальные брокерские вызовы и развёртывание в процессе тестирования не выполнять.
