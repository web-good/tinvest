## Step 3 — сверка с ожиданием

Ожидание из брифа: «Обе темы идут с `UseVolume` 1 и поле `UseVolume` не решают — его решает
`screen` (Task 3). Опорный замер `vol_window` in-sample: лучший узел 3 × 2.0 → 1.046/65, остальные
0.88–1.03. Ожидание: объёмный гейт в точку не войдёт; тогда голоса этих тем пишутся справочно.»

**Подтверждено фактом Task 3 — с уточнением.** У RTKM `screen` дал единогласные 4/4 за
`UseVolume=0`; у SVCB `screen` (Task 3, `_comment` `cal_screen.json`, результат прогона
2026-09-25) дал **ничью 2/2** по обеим осям (`UseVolume`: фолды 2 и 4 выбрали 1, фолды 1 и 3
выбрали 0 — большинства нет ни в одну сторону). По правилу §5.2 «нет большинства ⇒ поле остаётся
на дефолте ядра» поле `UseVolume` в собранную точку идёт **дефолтом ядра, то есть 0** — не потому,
что `screen` явно проголосовал за 0, а потому, что голосование не набрало большинства ни за одно
значение. Итог по факту тот же, что у RTKM (объёмный гейт выключен), но причина иная: у RTKM —
единогласная победа 0, у SVCB — отсутствие большинства и откат к дефолту.

Объёмный гейт (`UseVolume`, `VolMult`, `VolBaseDays`, `VolLookbackBars`) в собранную точку **не
входит** независимо от голосов этой задачи — правило «поле берётся из темы, которая его меряет»
(`UseVolume` меряет `screen`, а не `volume`/`vol_window`) применяется буквально. Все три поля
гейта остаются на дефолтах ядра (`VolMult=1.2`, `VolBaseDays=14`, `VolLookbackBars=3`) — их
значение внутри выключенного гейта не действует.

Опорный замер `vol_window` (in-sample, §6.3 спеки) предсказывал лучший узел 3 × 2.0 → 1.046/65 —
**walk-forward воспроизвёл именно этот узел** как победителя обеих осей (`VolLookbackBars=3`,
`VolMult=2`), но pooled OOS этого набора (0.896/72) оказался **ниже** in-sample-ориентира
(1.046/65) и ниже дефолта ядра без гейта (0.951/130) — типичная для каталога деградация
in-sample → OOS. Тема `volume` дала pooled OOS 0.947/64 — тоже ниже дефолта ядра, хотя и ближе к
нему, чем `vol_window`. Итог совпадает с ожиданием по существу («объёмный гейт в точку не
войдёт»), хотя фактическая причина решена на уровне `screen` (отсутствие большинства), а не
проверкой этой задачи.

**Справочно, для полноты (правило §5.2 по аналогии с `trend`/`trend_low`, применялось бы только
если бы `UseVolume=1` набрал большинство на `screen`):** правило гласит — поля из `vol_window` идут
в точку вместо `volume` только при одновременном выполнении двух условий: большинство ≥3/4 по
ведущей оси **и** pooled OOS `vol_window` выше, чем у канонической `volume`. Формально
`vol_window` дал большинство ≥3/4 сразу по обеим осям (`VolLookbackBars` 3/4, `VolMult` 3/4) —
сильнее, чем `volume` (ни одна ось большинства не набрала). Но **pooled OOS `vol_window` (0.896)
ниже, чем у `volume` (0.947)** — второе условие правила не выполнено. Даже в гипотетическом мире
с включённым гейтом поля `vol_window` не заменили бы поля `volume` целиком. Это чисто справочное
наблюдение — практического значения не имеет, так как гейт выключен решением `screen`.
