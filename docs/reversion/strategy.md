# Стратегия Reversion (двойное подтверждение RSI + Stochastic)

Только лонг, **часовой таймфрейм** (`-interval Hour1`). Ядро возврата к среднему
(mean-reversion), управляемое согласием двух осцилляторов — RSI и линии %D Stochastic.
Покупка происходит, когда один осциллятор уже находится в зоне перепроданности, а второй
входит в неё. Выход — по одному из шести сигналов, в порядке приоритета
`STOP(SL|TRAIL|ATRSL) → OB → RSI50 → BE → RSIOS → EMAX`: комбинированный защитный стоп
(STOP — наивысший приоритет, срабатывает **интрабарно** по low, а не по close; объединяет до
трёх компонент — катастрофический ATR-стоп SL, ATR-трейлинг TRAIL и средний ATR-стоп ATRSL —
и берёт максимум из активных), тейк-профит на перекупленности (OB, опциональный), пересечение
RSI вниз через 50 (опционально через `UseRSI50`), безубыток-выход (BE, опциональный),
несостоявшийся отскок (RSIOS, включается только когда компонента ATRSL внутри STOP выключена
— `UseATRStop=0`) и медвежий кросс FastEMA/SlowEMA. Покупки дополнительно сужают четыре
опциональных фильтра входа: фильтр старшего таймфрейма (подтверждённый аптренд на 4H), фильтр
тренда (только подтверждённый аптренд на рабочем ТФ), фильтр режима (только боковик по ADX) и
фильтр объёма (только бар входа с объёмом выше среднего).

Рабочая линия Stochastic — **%D** (SMA от %K за `StochDSmooth`; при `StochDSmooth=1`
получается «сырой» %K). Тайм-стоп и обязательный фиксированный %-стоп из прежних версий
убраны; защитный стоп есть только когда включена хотя бы одна компонента STOP —
катастрофический ATR-стоп (`CatStopATRMult>0`), средний ATR-стоп (`UseATRStop=1`) или
ATR-трейлинг (`UseTrail=1`). Фильтрация по объёму возвращается только как
опциональный фильтр входа `UseVolume`. ATR на рабочем ТФ (длина `ATRPeriod`), зафиксированный
на входе, питает катастрофический стоп, трейлинг, безубыток, средний ATR-стоп и риск-сайзинг.

## Вход (фильтры в порядке короткого замыкания)

0. **Фильтр старшего таймфрейма (опционально, `HTFTrendEMA`):** `0` (по умолчанию)
   выключает фильтр; значение `> 0` задаёт период EMA на **4H**-свечах и пропускает
   покупку только в подтверждённом аптренде старшего ТФ — последняя закрытая 4H-свеча
   должна закрыться выше своей 4H-EMA. Используются только полностью закрытые 4H-бары
   (текущий формирующийся бар не виден — нет заглядывания вперёд). Если 4H-EMA ещё не
   прогрета (`htfOK=false`), фильтр **блокирует** вход: защитный фильтр не торгует, пока не
   может подтвердить старший тренд. 4H-свечи грузятся автоматически для стратегии
   `reversion` (отдельного флага не нужно).
1. **Фильтр тренда (опционально, `UseTrend`):** `1` (по умолчанию) требует
   `EMA(FastEMA) > EMA(SlowEMA)` и `close > EMA(SlowEMA)` (по умолчанию 50/200); `0`
   игнорирует тренд.
1b. **Фильтр режима (опционально, `UseRegime`):** `0` (по умолчанию) выключает фильтр; `1`
   пропускает покупку только в боковике — когда `ADX(ADXPeriod) < ADXMax` (Wilder ADX). Если
   ADX ещё не прогрет (`adxOK=false`), фильтр **блокирует** вход: защитный гейт не торгует,
   пока не может подтвердить режим. Идея — торговать возврат к среднему только при слабом
   тренде, где он работает.
2. **Двойное подтверждение перепроданности** — хотя бы одно из:
   - RSI(`RSIPeriod`) пересекает **вниз** уровень `RSIOversold` **и** %D Stochastic уже
     `< StochOversold`;
   - %D Stochastic пересекает **вниз** уровень `StochOversold` **и** RSI уже
     `< RSIOversold`.
   Если оба входят в зону на одном баре — тоже срабатывает. Бар на прогреве без двух
   валидных значений осцилляторов никогда не проходит этот фильтр (сентинел `0` не
   считается «в зоне»).
3. **Фильтр объёма (опционально, `UseVolume`):** `0` (по умолчанию) игнорирует объём; `1`
   блокирует покупку, если объём бара входа ниже `avg × VolMult`, где `avg` — средний
   объём за `VolAvgPeriod` предыдущих баров с исключением баров выходных (сб/вс по MSK) и с
   исключением самого бара входа из его собственного среднего. Фильтр пропускается (вход
   **разрешён**), когда базу нельзя посчитать достоверно: нет таймстемпов баров — выходные
   не исключаются (среднее всё равно считается по всем предыдущим барам); нет ни одного
   валидного бара или объём бара входа не положителен — блокировки нет. Эта деградация
   держит фильтр инертным в live-торговле, пока туда не проведены таймстемпы баров.

## Выход (срабатывает первый по приоритету)

Открытый лонг закрывается по одному из шести сигналов, в таком порядке приоритета:
`STOP(SL|TRAIL|ATRSL) → OB → RSI50 → BE → RSIOS → EMAX`. STOP исполняется **интрабарно**
(по low бара); все остальные — по цене **закрытия** бара (подробности — в
[«Модель исполнения стопов»](#модель-исполнения-стопов) ниже).

1. **STOP (SL|TRAIL|ATRSL):** единый защитный стоп, посчитанный `core.DesiredStop` как
   максимум (ближайший к цене, а значит первый, до которого дойдёт падающая цена) из **до
   трёх** активных компонент:
   - **SL** (`CatStopATRMult > 0`): катастрофический ATR-стоп на
     `PurchasePrice − CatStopATRMult × EntryATR`. Всегда активный защитный бэкстоп
     (не зависит от `UseATRStop`) и одновременно якорь риск-сайзинга (см. ниже). Этот же
     уровень пишется на входе в `sig.StopLoss`.
   - **ATRSL** (`UseATRStop=1`, `StopATRMult > 0`): средний ATR-стоп на
     `PurchasePrice − StopATRMult × EntryATR`.
   - **TRAIL** (`UseTrail=1`, `TrailATRMult > 0`): ATR-трейлинг на
     `PrevMaxFavorablePrice − TrailATRMult × EntryATR`, где `PrevMaxFavorablePrice` —
     монотонный максимум хода **по предыдущий бар** (не включая текущий) — см. модель
     исполнения ниже.

   Побеждает компонента с наибольшим уровнем; её код (`SL`/`ATRSL`/`TRAIL`) идёт в
   `sig.Reason`. Все компоненты требуют `EntryATR > 0` — в live это условие выполняется,
   так как `EntryATR` персистится в state на входе и передаётся обратно в `core.Decide` на
   каждом manage-проходе (см. `live-runner.md`), поэтому STOP реально работает и в бою, а не
   только в бэктесте. Если ни одна компонента не включена, STOP выключен и приоритет
   переходит к следующему сигналу. Наивысший приоритет — сработавший STOP на баре опережает
   любой close-based выход, включая OB.
2. **OB (опционально, `UseOverbought`):** тейк-профит на перекупленности — RSI **и** %D
   Stochastic одновременно в своих зонах перекупленности (`RSI ≥ RSIOverbought` **и**
   `%D ≥ StochOverbought`). Требует прогретых осцилляторов (`rsiOK && stochOK`). При
   `UseOverbought=0` выход выключен.
3. **RSI50 (опционально, `UseRSI50`):** RSI пересекает уровень 50 сверху вниз (`prev ≥ 50`,
   `now < 50`) — выход на затухании импульса. `UseRSI50=1` (по умолчанию) включает его;
   `0` выключает.
4. **BE (опционально, `UseBreakeven`):** чистый безубыток. После того как цена ушла в плюс
   на `BreakevenArmATR × EntryATR` (взвод через монотонный максимум хода `MaxFavorablePrice`),
   при возврате к/ниже цены входа позиция закрывается. Исполнение по закрытию, поэтому выход —
   по первому закрытию на/ниже входа (возможен небольшой минус). Требует `EntryATR>0` и
   `BreakevenArmATR>0`; в live `EntryATR` персистится (см. `live-runner.md`), поэтому выход
   работает и в бою. При `UseBreakeven=0` выключен.
5. **RSIOS (только когда `UseATRStop=0`):** RSI пересекает `RSIOversold` сверху вниз
   (`prev ≥ RSIOversold`, `now < RSIOversold`) — выход на несостоявшемся отскоке. Не может
   сработать на баре сразу после входа, где RSI уже ниже зоны. При `UseATRStop=1` этот шаг
   пропускается — тот же самый выход уже покрыт компонентой ATRSL внутри STOP.
6. **EMAX:** медвежий кросс EMA — `EMA(FastEMA)` уходит ниже `EMA(SlowEMA)`. Медленный
   бэкстоп на слом режима; переиспользует те же EMA, что и фильтр тренда.

Если на одном баре срабатывает несколько close-based сигналов — сообщается самый ранний по
этому порядку. STOP всегда выигрывает у close-based сигналов того же бара, если сработал
(интрабарное событие логически предшествует close).

## Модель исполнения стопов

STOP — единственный из шести выходов, смоделированный как **биржевая стоп-заявка**, а не
как проверка по close:

- **Триггер:** бар `i` исполняет STOP, если его `low` касается или пробивает уровень
  (`in.low > 0 && in.low <= stopLevel`) — так же, как реальная стоп-заявка срабатывает в
  момент, когда цена прошла сквозь уровень внутри бара, а не ждёт закрытия.
- **Уровень TRAIL считается от `PrevMaxFavorablePrice`** — максимума хода **по предыдущий**
  бар, а не текущего. Причина: биржевая заявка, работающая во время бара `i`, была
  выставлена/переставлена после закрытия бара `i-1` и физически не могла знать о новом
  максимуме, сделанном внутри самого бара `i`.
- **Исполнение (бэктест):** `min(stopLevel, Open бара)` — если бар открылся ниже уровня
  (гэп), заявка исполняется по факту доступной цены на открытии, а не по номинальному
  уровню (`internal/domain/backtest/engine.go`, кейсы `"SL"`, `"TRAIL"`, `"ATRSL"` внутри
  `switch sig.Reason`).
- **В live** этой связке SL/TRAIL/ATRSL соответствует **одна** биржевая GTC
  stop-market-заявка на продажу, которую раннер выставляет сразу после входа и
  перевыставляет на каждом часовом тике при подъёме уровня (подробный жизненный цикл — в
  `docs/reversion/live-runner.md`, раздел «Стоп-заявки»). Поэтому интрабарная
  low-триггерная модель бэктеста — это попытка смоделировать поведение именно такой
  резидентной биржевой заявки, а не приближение «как если бы стоп проверялся по close».

## Запуск

```bash
# одиночный прогон (часовой таймфрейм)
go run ./cmd/backtest -ticker SBER -strategy reversion -interval Hour1 \
  -months 12 -out ./reports/SBER

# калибровка по сетке с walk-forward OOS (свипаются зоны/периоды Stochastic и др.)
go run ./cmd/backtest -ticker SBER -strategy reversion -interval Hour1 \
  -calibrate data/params/sber/reversion_grid.json -out ./reports/SBER \
  -months 24 -test-months 6 -min-trades 20 -metric profit_factor

# диагностика одного бара
go run ./cmd/backtest -ticker SBER -strategy reversion -interval Hour1 \
  -explain '2026-03-14 12:00' -months 12

# риск-сайзинг: рисковать 1% капитала на сделку, считая от стопа входа
# (требует CatStopATRMult>0 в Params, иначе стопа входа нет)
go run ./cmd/backtest -ticker SBER -strategy reversion -interval Hour1 \
  -risk-pct 1 -months 12 -out ./reports/SBER

# скрининг вселенной по variance ratio (отдельный режим; -ticker/-strategy игнорируются)
go run ./cmd/backtest -strategy reversion -interval Hour1 \
  -screen SBER,GAZP,LKOH,NVTK,YDEX -months 24 -out ./reports/screen
```

### Риск-сайзинг (`-risk-pct`)

По умолчанию размер позиции задаётся `-fraction` (доля капитала). Флаг `-risk-pct N`
переключает на риск-сайзинг: на каждую сделку рискуется `N%` капитала, а объём считается от
дистанции до **стопа входа** — катастрофического ATR-стопа `PurchasePrice − CatStopATRMult ×
EntryATR`. Поэтому риск-сайзинг **требует `CatStopATRMult > 0`** (иначе у входа нет стопа, от
которого считать риск). При `-risk-pct 0` (по умолчанию) используется фиксированный сайзинг
по `-fraction`.

### Скрининг по variance ratio (`-screen`)

Режим `-screen TICKER1,TICKER2,…` ранжирует тикеры по их склонности к возврату к среднему и
**не** запускает бэктест (флаги `-ticker`/`-strategy`/`-calibrate`/`-basket`/`-explain` сюда
не подмешиваются). Для каждого тикера считается отношение дисперсий Lo–MacKinlay на
горизонтах 2/4/8 баров и автокорреляция лага 1; результат пишется в
`screen_<interval>_<stamp>.md` (таблица, ранжир по VR(2) по возрастанию — самые
mean-reverting сверху).

`VR < 1` — возврат к среднему, `VR > 1` — тренд, `VR ≈ 1` — случайное блуждание. Вердикт:
`mean-reverting` при `VR(2) < 0.95`, `trending` при `VR(2) > 1.05`, иначе `neutral`.
Отрицательная автокорреляция лага 1 также указывает на возврат к среднему. Инструмент
помогает выбрать, на каких тикерах стратегия в принципе уместна.

## Параметры

Все 27 настраиваемых параметров лежат в `core.Params`. Каждое поле — `int` или `float64`
(флаги кодируются как int `0/1`), поэтому калибратор сетки на рефлексии может свипать любой
из них. Уровень выхода RSI-50 — фиксированная константа (`50`), **не** параметр (но сам
выход переключается флагом `UseRSI50`). Стартовые
значения по каждому тикеру лежат в пакете `reversion/strategy/<ticker>`; калибруй через
`-calibrate` и зашивай победителей.

**Фильтр старшего таймфрейма (вход)**
- `HTFTrendEMA` — период EMA на 4H-свечах для фильтра старшего тренда; `0` (по умолчанию)
  выключает фильтр. При `> 0` вход разрешён только когда последняя закрытая 4H-свеча выше
  своей 4H-EMA (и эта EMA прогрета). 4H-свечи грузятся автоматически для `reversion`.

**Фильтр тренда**
- `UseTrend` — `1` (по умолчанию) требует подтверждённого аптренда перед любой покупкой
  (`EMA(FastEMA) > EMA(SlowEMA)` и `close > EMA(SlowEMA)`); `0` игнорирует тренд.
- `FastEMA` — длина быстрой режимной EMA (например, 50). Одновременно быстрая линия
  медвежьего кросса-выхода `EMAX`.
- `SlowEMA` — длина медленной режимной EMA и ценовой «пол» (например, 200). Одновременно
  медленная линия выхода `EMAX`. Также доминирующий член в окне предыстории по свечам.

**Фильтр режима (вход)**
- `UseRegime` — `0` (по умолчанию): без фильтра режима; `1`: пропускать вход только в
  боковике (`ADX < ADXMax`).
- `ADXPeriod` — длина Wilder ADX; учитывается только при `UseRegime=1`.
- `ADXMax` — порог: вход разрешён только когда `ADX < ADXMax` (низкий тренд); учитывается
  только при `UseRegime=1`.

**RSI (триггер входа + выходы)**
- `RSIPeriod` — длина RSI; обязателен (`> 0`).
- `RSIOversold` — зона перепроданности RSI на стороне входа (двойное подтверждение) и, при
  `UseATRStop=0`, граница выхода `RSIOS`.
- `UseRSI50` — `1` (по умолчанию) включает выход `RSI50` (пересечение RSI вниз через 50);
  `0` отключает его. Сам уровень `50` — фиксированная константа.

**Stochastic (триггер входа)**
- `StochKPeriod` — окно %K Stochastic; обязателен (`> 0`).
- `StochDSmooth` — сглаживание %D (SMA от %K); обязателен (`> 0`). `1` = «сырой» %K. Рабочая
  линия везде — %D.
- `StochOversold` — зона перепроданности Stochastic на стороне входа.

**Тейк-профит на перекупленности (выход OB)**
- `UseOverbought` — `1` включает выход OB (закрытие, когда RSI и %D Stochastic одновременно
  в зонах перекупленности); `0` выключает. Наивысший приоритет среди **close-based** выходов
  (второй в общем порядке, после STOP — см. «Выход» выше).
- `RSIOverbought` — зона перекупленности RSI для выхода OB (по умолчанию `70`); учитывается
  только при `UseOverbought=1`.
- `StochOverbought` — зона перекупленности %D Stochastic для выхода OB (по умолчанию `80`);
  учитывается только при `UseOverbought=1`.

**Селектор компоненты ATRSL внутри STOP / RSIOS**
- `UseATRStop` — `0` (по умолчанию): использовать `RSIOS` как отдельный выход;
  `1`: вместо него включить компоненту `ATRSL` **внутри** комбинированного STOP (см. «Выход»
  выше) — RSIOS тогда пропускается, так как тот же самый случай уже покрыт STOP.
- `ATRPeriod` — длина окна ATR рабочего ТФ; ATR считается, когда нужен хотя бы одному
  потребителю: `UseATRStop=1`, `UseBreakeven=1`, `CatStopATRMult>0` или `UseTrail=1`.
- `StopATRMult` — множитель дистанции компоненты ATRSL: уровень —
  `PurchasePrice − StopATRMult × EntryATR`; по умолчанию `1.0`; `0` отключает эту компоненту
  даже при `UseATRStop=1` (если другие компоненты STOP тоже выключены, STOP целиком неактивен).

**Катастрофический ATR-стоп (компонента SL внутри STOP + якорь риск-сайзинга)**
- `CatStopATRMult` — дистанция катастрофического стопа в кратных `EntryATR`: `> 0` включает
  всегда активную компоненту STOP `PurchasePrice − CatStopATRMult × EntryATR` (срабатывает
  независимо от `UseATRStop`) и одновременно служит якорём для риск-сайзинга `-risk-pct`; `0`
  (по умолчанию) выключает. Этот же уровень пишется в `sig.StopLoss` на входе.

**ATR-трейлинг (компонента TRAIL внутри STOP)**
- `UseTrail` — `1` включает компоненту STOP-трейлинга по максимуму хода; `0` (по умолчанию)
  выключает.
- `TrailATRMult` — дистанция трейлинга в кратных `EntryATR` ниже `PrevMaxFavorablePrice`
  (максимум хода **по предыдущий бар** — см. «Модель исполнения стопов»); учитывается только
  при `UseTrail=1` (нужен `> 0`).

**Выход в безубыток (BE)**
- `UseBreakeven` — `1` включает безубыток-выход; `0` (по умолчанию) выключает.
- `BreakevenArmATR` — порог взвода в кратных EntryATR (по умолчанию `1.0`); учитывается
  только при `UseBreakeven=1`. EntryATR берётся из ATR рабочего ТФ, посчитанного на входе
  (при `UseBreakeven=1` ATR считается, даже если ATR-стоп выключен).

**Фильтр объёма (вход)**
- `UseVolume` — `0` (по умолчанию): без фильтра объёма; `1`: блокировать входы на барах с
  объёмом ниже среднего.
- `VolAvgPeriod` — число предыдущих баров для усреднения базы объёма (по умолчанию `20`);
  бары выходных (сб/вс по MSK) исключаются из этого среднего, а сам бар входа исключается из
  своего собственного среднего. Учитывается только при `UseVolume=1`.
- `VolMult` — множитель порога объёма входа: для покупки нужно `entryVolume ≥ avg × VolMult`;
  по умолчанию `1.0` (строго на уровне среднего или выше). Повышение требует более сильного
  участия.

## Пока не поддерживается

`-basket` walk-forward (раннер корзины сейчас только для momentum).
