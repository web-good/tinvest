# Reversion: перепрогон walk-forward с интрабарным стопом (2026-07)

**Статус:** информационный (не решает судьбу тикеров). Ветка `feat/reversion-stop-orders`
заменила исполнение стопа в бэктест-движке: раньше стоп срабатывал по цене **закрытия**
бара (close-модель), теперь — интрабарно, по **low ≤ уровень**, с филлом по
`min(уровень, open)` (см. `docs/superpowers/specs/2026-07-09-reversion-stop-orders-design.md`
и `f462235`). Это делает исполнение стопов строже (реалистичнее) и по построению не может
улучшить PF относительно старой close-модели на тех же данных — новый филл либо совпадает
со старым, либо хуже. Цель этого документа — зафиксировать фактическую величину эффекта на
трёх боевых тикерах (UGLD, EUTR, NVTK) и решить, требует ли это перекалибровки.

**Тикеры остаются в live-реестре независимо от цифр ниже** — это решение пользователя,
зафиксированное в спеке `2026-07-09-reversion-stop-orders-design.md`. Данный документ —
только констатация фактов.

## Методология

- Гейт качества (`./bin/mage ci`: lint + `go test -race ./...` + mock-drift) прогнан и
  зелёный перед перепрогоном (Task 8, Step 1).
- Walk-forward: те же параметры окон, что в июньских отчётах (`-train-months`/`-test-months`,
  `-calibrate` на тот же `reversion_fixed*.json`), но т.к. окна считаются от текущей даты
  (`data/candles/*` содержит свежие данные), фактические границы фолдов сдвинулись на
  ~3 недели относительно июньских прогонов — это ожидаемо и допустимо по бригу задачи.
  Использован `-min-trades 1` (как задано в брифе); понижать до `0` не понадобилось —
  все комбинации прошли порог.
- Единственная техническая накладка: кэш `data/candles/NVTK_Hour1.json` оказался пустым
  (0 байт, файл датирован 18 июня) — первый прогон NVTK упал с ошибкой парсинга JSON.
  Восстановлен через `-refresh` (перекачка через Tinkoff Invest API, токен из
  `env/token.env`); повторный прогон прошёл штатно. Кэши UGLD/EUTR были валидны, `-refresh`
  для них не понадобился.
- Новые отчёты (walk-forward + одиночный полноисторийный прогон для журнала сделок) лежат в
  `reports/<TICKER>/intrabar/`.

## Вывод

- Интрабарная модель стопа систематически снижает PF на всех трёх тикерах относительно
  июньской close-модели — ожидаемо, т.к. она исполняет стоп строже (ловит внутрибарные
  проколы, которых close-модель не видела).
- **NVTK** — эффект умеренный (PF 5.762 → 4.842), профиль остаётся сильным.
- **UGLD** — эффект существенный (PF 3.385 → 1.418), но PF всё ещё выше 1 с запасом.
- **EUTR** — эффект самый сильный (PF 2.529 → 1.084); запас над PF=1 минимален, один из
  трёх OOS-фолдов (PF 1.017, NetPnL% 0.16%) практически на грани безубыточности. EUTR
  помечается как **кандидат на перекалибровку** под интрабарную модель стопа — это вне
  скоупа текущей ветки (`feat/reversion-stop-orders`) и требует отдельной задачи
  (повторный grid-search по `data/params/eutr/reversion_cal_*.json` с интрабарным стопом
  в бэктест-движке).
- Ни один тикер не пересёк PF < 1 по пулу OOS, поэтому формального требования брифа
  «пометить кандидата на перекалибровку» по этому критерию нет; пометка EUTR выше сделана
  по признаку минимального запаса, а не как обязательное следствие брифа.
- Все три тикера **остаются в live-реестре** — это решение пользователя, зафиксированное в
  спеке `2026-07-09-reversion-stop-orders-design.md`, документ его не пересматривает.
