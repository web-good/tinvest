# FVG imbalance — стратегия возврата к бычьему дисбалансу

## Кратко

`fvg_imbalance` — стратегия только для бэктеста, только для лонга и только для завершённых M30-свечей. Она находит бычий FVG из трёх свечей, ждёт ретеста заданной глубины по телу либо тени и покупает по открытию следующей M30-свечи. Опциональный фильтр стохастика после достижения глубины требует медленный `%K < 20` на той же или последующей свече. Одновременно может быть открыта только одна позиция. Для GAZP и DOMRF заданы отдельные литералы параметров; незарегистрированные тикеры используют параметры ядра. Стратегия не хранит состояние зон между вызовами: на каждом решении восстанавливает их по переданной истории.

Основной код: `internal/service/trading_strategy/fvg_imbalance/strategy/core/core.go`; привязка к бэктесту: `internal/service/backtest/fvg_imbalance_registry.go`.

## Формирование зоны

Для трёх подряд идущих 30-минутных свечей `a, b, c` зона появляется после закрытия `c`, если:

1. `close[b] > open[b]`: средняя свеча зелёная;
2. при `RequireThirdCandleHigherHigh = 1` выполняется `high[c] > high[b]`: максимум третьей свечи строго выше максимума второй; при `0` эта проверка отключена;
3. `high[a] < low[c]`: между крайними свечами есть строгий разрыв;
4. `open[b] <= high[a]` и `close[b] >= low[c]`: тело зелёной свечи проходит разрыв снизу вверх;
5. `low[c] - high[a] >= MinGapATR × ATR_formation`.

Границы зоны: `lower = high[a]`, `upper = low[c]`. Временные метки `a → b → c` должны отличаться ровно на 30 минут: через пропуск свечи, ночь или выходной FVG не образуется. `ATR_formation` — ATR Уайлдера по ровно `2 × ATRPeriod` свечам, заканчивающимся на `c`. Его значение фиксируется для зоны и впоследствии используется для отступа стопа. Неположительный ATR или недостаток истории исключают зону.

**Пример.** Пусть `high[a] = 100`, свеча `b` открылась по `99` и закрылась по `103`, `low[c] = 102`, а ATR при формировании равен `2`. Зона — `[100, 102]`, высота — `1 ATR`; она проходит порог `MinGapATR = 0.8`. Если бы `b` открылась по `101`, её тело не пересекло бы нижнюю границу и FVG был бы отклонён.

## Ретест и вход

Зона может дать сигнал на свечах `c+1 ... c+MaxRetestBars` включительно. Ретест на текущей свече `k` должен коснуться зоны и достичь нужной глубины выбранной ценой:

```text
bodyLow   = min(open[k], close[k])
depthPrice = bodyLow, если RetestDepthByBody = 1
             low[k],  если RetestDepthByBody = 0
threshold = upper - MinRetestDepthPct / 100 × (upper - lower)
lower <= low[k] <= upper и depthPrice <= threshold
```

`MinRetestDepthPct` — конечное число от `0` до `100`, по умолчанию `50`: выбранная цена должна попасть в нижнюю половину FVG. `RetestDepthByBody = 1` считает глубину по нижней границе тела, `0` — по минимуму тени. При глубине `0` выбранная цена должна хотя бы коснуться зоны, при `100` — дойти до `lower`; равенство порогу допускается. Любой `low < lower` после образования зоны всегда инвалидирует её, включая саму свечу ретеста, независимо от режима глубины.

Предыдущее защищённое касание не расходует зону: в пределах `MaxRetestBars` допустим последующий ретест, если после формирования не было `low < lower`. Если одновременно подходят несколько зон, выбирается самая новая.

При `UseStochFilter = 0` достижение глубины на текущей завершённой свече позволяет сразу сформировать сигнал. При `1` глубина может быть достигнута на любой свече в пределах `MaxRetestBars`; затем стратегия ждёт медленный стохастик `%K(14,3) < 20` на той же или одной из следующих завершённых M30-свечей. `%D` не является отдельным условием. Повторное касание зоны при ожидании не требуется. Медленный `%K` — среднее трёх сырых `%K(14)`; в API `StochasticSeries(..., 14, 3)` это второй возвращаемый ряд, названный `%D`. Первое полностью сглаженное значение появляется на 16-й свече. Если истории меньше, сигнала нет.

Ожидание заканчивается с истечением `MaxRetestBars` или при любом `low < lower`, даже после достижения глубины. Сигнал возможен на первом совместном подтверждении `%K < 20` и H4-фильтра: отказ H4 сам по себе не расходует возможность входа, зона ждёт следующей подходящей свечи. Если следующий точный M30-слот после совместного подтверждения отсутствует либо `FillBy` приходится на выходной, вход не переносится на последующие свечи. Для восстановления прежних проверок H4 бэктест передаёт время завершения каждой H4-свечи; позднейшие H4-закрытия не учитываются задним числом.

При `HTFTrendEMA > 0` вход разрешён, только если последнее **завершённое** закрытие H4 строго выше EMA H4 с этим периодом. Требуется не менее `HTFTrendEMA` корректных H4-закрытий; отсутствие данных, нечисловые значения и незавершённая H4-свеча не дают пройти фильтр. Для такого прогона бэктест загружает H4 с годом предварительной истории. Значение `0` выключает фильтр; на выходы из уже открытой позиции H4 не влияет.

Сигнал формируется **после закрытия** свечи подтверждения входа (ретеста при выключенном фильтре). Бэктест покупает по фактическому `open` следующей M30-свечи. `FillBy = time[k] + 30 минут`: если точного следующего слота нет, отложенная покупка отменяется и не переносится через ночь или пропуск данных. Если расчётный момент входа приходится на субботу или воскресенье, стратегия вообще не выдаёт сигнал. Ограничения на гэп цены входа нет.

Основной стоп фиксируется на входе: `primary = lower - StopBufferATR × ATR_formation`. Неположительный или нечисловой основной стоп блокирует сигнал. При `-risk-pct > 0` объём позиции считается из расстояния между **фактическим open** и основным стопом, затем округляется до целых лотов с учётом доступных денег. При `-risk-pct 0` используется доля средств из `-fraction`.

## Выходы

Риск сделки и цель считаются от фактической цены исполнения:

```text
risk   = actual_fill - primary
target = actual_fill + TakeProfitR × risk
```

Предварительная цель в сигнале рассчитана от закрытия свечи подтверждения входа, но позиция управляется целью от `actual_fill`. `TakeProfitR = 0` отключает цель. Основной стоп не подтягивается, частичных выходов нет. Аварийный стоп не меняет расчёт риска, объёма и цели.

Для открытой позиции действуют два уровня, рассчитанные из замороженного ATR формирования зоны:

```text
primary   = lower - StopBufferATR × ATR_formation
emergency = primary - 2 × StopBufferATR × ATR_formation
```

Основной стоп подтверждается завершённой M30-свечой: при `close <= primary` выход `SL_CLOSE` в обоих путях бэктеста (`Run` и `Trace`) исполняется по фактическому `close`. Тень ниже `primary` с закрытием выше него сама по себе не закрывает позицию. Аварийный стоп `SL_EMERGENCY` срабатывает внутри свечи при `low <= emergency`; исполнение — по `min(open, emergency)`, включая гэп ниже аварийного уровня.

На каждой обработанной M30-свече приоритет таков: **SL_EMERGENCY → SL_CLOSE → TP**. Поэтому при достижении аварийного уровня и цели на одной свече побеждает аварийный стоп; закрытие на основном уровне или ниже также проверяется раньше цели. При гэпе выше цели бэктест использует `max(open, target)`. Свеча исполнения покупки сразу проверяется на выход по тем же правилам: открытие на основном стопе или ниже само по себе не вызывает `SL_CLOSE`, если свеча затем закрылась выше него и не достигла аварийного уровня. При `StopBufferATR = 0` оба уровня совпадают, и первым срабатывает внутрисвечный аварийный стоп. Принудительного закрытия по времени или в конце дня нет.

**Пример выхода.** Для зоны `[100, 102]`, ATR `2` и `StopBufferATR = 0.1` основной стоп равен `99.8`, аварийный — `99.4`. Если ретест закрылся по `101`, а следующая свеча открылась по `102.5`, фактический риск — `2.7`. При `TakeProfitR = 1` цель позиции — `105.2`, хотя предварительная цель сигнала была бы `102.2`.

## Параметры

| Параметр | Ядро | GAZP | Смысл |
|---|---:|---:|---|
| `ATRPeriod` | 14 | 14 | Период M30 ATR Уайлдера; положительное целое |
| `MinGapATR` | 0.25 | 0.6 | Минимальная высота FVG в ATR; конечное число ≥ 0 |
| `MaxRetestBars` | 8 | 10 | Максимальный возраст ретеста в свечах; положительное целое |
| `MinRetestDepthPct` | 50 | 80 | Минимальная глубина выбранной цены от верхней границы FVG, %; конечное число от 0 до 100 |
| `TakeProfitR` | 1.5 | 2 | Цель в единицах риска; 0 отключает |
| `RequireThirdCandleHigherHigh` | 1 | 0 | `1` требует `high[c] > high[b]`; `0` отключает дополнительный фильтр формирования |
| `RetestDepthByBody` | 1 | 0 | `1` считает глубину ретеста по нижней границе тела; `0` — по тени |
| `UseStochFilter` | 0 | 0 | `1` ждёт медленный `%K(14,3) < 20` после достижения глубины; `0` даёт сигнал сразу |
| `HTFTrendEMA` | 0 | 200 | Период H4 EMA; 0 отключает |
| `StopBufferATR` | 0 | 1 | Отступ основного стопа под зоной, в ATR; аварийный ещё на два таких отступа ниже |

Частичный JSON накладывается на литерал тикера (либо на значения ядра) и валидируется; неизвестные поля отклоняются с указанием имени. Другие интервалы бэктест отклоняет; при неверном шаге или параметрах ядро не даёт сигналов.

## Бэктест и калибровка

Прогон GAZP с текущим литералом:

```bash
go run ./cmd/backtest \
  -ticker GAZP -strategy fvg_imbalance -interval Minutes30 \
  -out reports/GAZP/fvg_imbalance/baseline \
  -months 24 -risk-pct 1 -commission 0.0005 -refresh
```

Сетка `data/params/fvg_imbalance/gazp/grid.json` поэтапно перебирает формирование FVG, H4-контекст, отступ стопа и фазу `stochastic` с `UseStochFilter: [0, 1]`. Walk-forward прогон:

```bash
go run ./cmd/backtest \
  -ticker GAZP -strategy fvg_imbalance -interval Minutes30 \
  -calibrate data/params/fvg_imbalance/gazp/grid.json \
  -out reports/GAZP/fvg_imbalance/quality_wf \
  -months 24 -train-months 12 -test-months 3 \
  -min-trades 20 -metric profit_factor \
  -risk-pct 1 -commission 0.0005 -refresh
```

`-risk-pct 1` нормализует объём позиции по риску до стопа. `-min-trades 20` относится к ранжированию на обучающем участке: фазы, где все комбинации ниже порога, нужно отдельно изучать в отчёте. Результаты калибровки не меняют литерал GAZP автоматически.
