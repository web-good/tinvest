# RSI pullback (30m, лонг)

Код: `internal/service/trading_strategy/rsi_pullback/strategy/core/core.go`
Реестр/движок бэктеста: `internal/service/backtest/rsi_pullback_registry.go`
Backtest-only: стратегия не подключена к `internal/app`, к live-раннерам и к Telegram.

## 1. Идея

Покупка отката внутри восходящего тренда на 30-минутках: тренд задаёт пара EMA
(`EMAFast > EMASlow`), момент входа — заход короткого RSI в нижнюю зону (откат внутри
тренда), выход — заход того же RSI в верхнюю зону (отскок исчерпался).

Отличие от `rsi_ema` (`docs/rsi_ema/strategy.md`): там вход — это крест RSI **вверх**
через 50 (покупка продолжения импульса после короткой паузы), здесь — крест RSI **вниз**
через нижний порог `RSILower` (покупка самого отката, а не его завершения).

## 2. Правила входа

Все условия проверяются на закрытии одного бара (`i` — последний бар окна), позиции нет
(`md.Position == nil`):

1. Будний день и `07:00 ≤ время < 17:00 MSK` (`SessionStartMin=420`, `SessionEndMin=1020`).
   Бар конца дня (см. §3) для входа исключён отдельно — вход на нём не мог бы получить
   собственный EOD-выход, так как `manage()` начинает работать только со следующего бара.
2. `EMAFast > EMASlow` на текущем баре (обе EMA прогреты).
3. `RSI[i-1] ≥ RSILower` и `RSI[i] < RSILower` — короткий RSI **пересёк вниз** нижнюю
   границу на этом самом баре.
4. Если `StopATR > 0`, ATR должен быть посчитан (`ATR > 0`) — иначе вход отклоняется:
   защита без данных для стопа не открывается.

Важно: вход — это **событие** (крест на конкретном баре), а не состояние
(«RSI сейчас ниже порога»). Пока RSI сидит под `RSILower` без нового пересечения,
повторного входа не будет; но как только он вернётся выше и снова уйдёт вниз в тот же
день — сигнал сработает заново. Повторный вход в тот же торговый день разрешён
(ограничения «один вход в день» в коде нет).

## 3. Правила выхода

Приоритет строго `SL → RSI → TIME → EOD`; на каждом баре с открытой позицией проверяются
по порядку, срабатывает первый подошедший:

1. **SL** — лоу бара пробил стоп-цену (`pos.StopLoss`, заморожена на входе, не
   пересчитывается). Активен всегда, при `StopATR > 0`.
2. **RSI** — короткий RSI пересёк `RSIUpper` **снизу вверх** на текущем баре (отскок
   дошёл до перекупленности). Активен всегда.
3. **TIME** — удержание в барах (`EntryTime` позиции до текущего бара, по фактическому
   шагу серии) `≥ MaxHoldBars`, при `MaxHoldBars > 0`. Если время входа позиции неизвестно
   (`EntryTime` нулевое или бар без времени), тайм-стоп **не срабатывает** — он расценивает
   неизвестность как «рано закрывать», а не как повод форсировать выход.
4. **EOD** — принудительное закрытие. Срабатывает по любому из двух условий: (а) от начала
   текущего бара до `DayEndMin` (23:00 MSK) осталось **не больше одного шага серии**, либо
   бар выпал на выходной; (б) MSK-календарная дата текущего бара **отличается** от даты
   входа позиции. Активен всегда.

Если на одном баре одновременно выполняются условия стопа и RSI-выхода, побеждает **SL**
(проверяется первым в `manage()`).

Позиция **не переносится на следующий день**: `DayEndMin = 1380` (23:00 MSK) — то есть
позиция, открытая в окне входа (до 17:00), продолжает жить и управляться (SL/RSI/TIME)
всю вечернюю сессию и принудительно закрывается только на последнем баре перед 23:00.

Условие (б) — страховка на усечённую сессию. Условие (а) может сработать только на баре,
который реально существует в данных; если сессия оборвалась раньше (пропуск данных,
остановка торгов, короткий день — например, 2025-02-13 в кэше GAZP/NVTK/RUAL кончается
в 20:30), такого бара просто нет. Тогда позицию закрывает первый же бар нового торгового
дня — с тем же кодом `EOD` и в том же приоритете. Без этого при `MaxHoldBars = 0`
(значение в гриде есть) позиция уехала бы через ночь под гэпом, защищённая только
замороженным стопом. При неизвестном времени входа (`EntryTime` нулевое) условие (б)
молчит — ровно как тайм-стоп.

## 4. Таблица параметров

| Поле | Единица | Дефолт | В гриде |
|---|---|---|---|
| `RSIPeriod` | длина RSI, баров | 4 | да (entry: 4, 5, 6) |
| `RSILower` | пункты RSI | 15 | да (entry: 5, 10, 15, 20) |
| `RSIUpper` | пункты RSI | 70 | да (exit: 60, 70, 80) |
| `EMAFast` | баров | 10 | да (trend: 5, 10, 20) |
| `EMASlow` | баров | 100 | да (trend: 50, 100, 200) |
| `StopATR` | множитель ATR | 1.2 | да (risk: 0.8, 1.2, 1.6, 2.0) |
| `ATRPeriod` | баров | 14 | нет (фиксирован) |
| `MaxHoldBars` | баров | 8 | да (hold: 0, 4, 8, 12) |
| `SessionStartMin` | минут от полуночи MSK | 420 (07:00) | нет (фиксирован) |
| `SessionEndMin` | минут от полуночи MSK | 1020 (17:00) | нет (фиксирован) |
| `DayEndMin` | минут от полуночи MSK | 1380 (23:00) | нет (фиксирован) |

Risk-фаза грида перебирает только множители `0.8–2.0` и **никогда** не выключает стоп:
вариант «без стопа» намеренно не является кандидатом калибровки, хотя само ядро
выключение поддерживает (`StopATR = 0` — стоп не считается и не выставляется, см.
`enter()`/`Explain`). Для `MaxHoldBars`, наоборот, `0` в сетке **есть** и означает
«тайм-стоп выключен» — это единственная опциональная защита, которую калибровке
разрешено выключать.

## 5. Ограничение по таймфрейму

Референсный таймфрейм — 30 минут (`-interval Minutes30`). Правила не завязаны на
конкретный шаг: EOD-гейт сам определяет длину бара по медианной разнице соседних
`md.Times` (`barSpanMinutes`), так что другие `-interval` тоже работают.

`Lookback()` — окно свечей, которое движок подаёт в `Decide` на каждом баре:
`max(120, 2×max(EMASlow, EMAFast, RSIPeriod, ATRPeriod) + 20)`. При дефолтных
параметрах и `EMASlow = 200` (крайняя точка грида) это `2×200+20 = 420` баров. Движок
подаёт в `Decide` **все** загруженные 30-минутки, а не только бары окна входа: в реальных
сессиях MOEX (кэш `data/candles/GAZP_Minutes30.json` — от 06:30 до 23:30, медиана 35 баров
в торговый день) 420 баров — это ≈12 торговых дней, а не 21.
На более мелких интервалах (например, `Minutes5`) правила продолжают работать, но окно
прогрева растёт по **числу баров**, а не по времени — то же `Lookback()` в 5-минутках
покрывает заметно меньше календарных дней, чем в 30-минутках.

## 6. Команды

```
# разведочный прогон на дефолтах
go run ./cmd/backtest -ticker GAZP -strategy rsi_pullback -interval Minutes30 \
  -out ./reports/GAZP_rsipb -months 24

# диагностика одного бара
go run ./cmd/backtest -ticker GAZP -strategy rsi_pullback -interval Minutes30 \
  -months 24 -explain "2026-05-14 14:30"

# walk-forward калибровка
go run ./cmd/backtest -ticker GAZP -strategy rsi_pullback -interval Minutes30 \
  -calibrate data/params/rsi_pullback/grid.json -out ./reports/GAZP_rsipb \
  -months 24 -train-months 12 -test-months 3 -metric profit_factor -min-trades 40

# проверка переносимости победивших параметров без пере-калибровки
go run ./cmd/backtest -ticker NVTK -strategy rsi_pullback -interval Minutes30 \
  -params data/params/rsi_pullback/gazp_cal.json -out ./reports/NVTK_rsipb -months 24
```

## 7. Заметка про вердикт

Эта дока описывает правила и грид как они реализованы в коде — она не содержит вердикта
о жизнеспособности стратегии. Вердикт выносит владелец по собственным прогонам, и читается
он **по pooled OOS profit factor из walk-forward-калибровки**, а не по in-sample лучшему
результату одной сетки. Комиссию (`-commission`, дефолт `0.0005` за сторону) в этих
прогонах переопределять не нужно — она уже отражает реальные издержки круглого трейда.
