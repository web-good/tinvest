# Скринер плотностей стакана

Скринер непрерывно наблюдает заявки **на покупку** в биржевых стаканах рублёвых акций MOEX. Он ищет уровни с большим денежным объёмом, заметно превышающим объём соседних уровней, и отправляет сообщение в Telegram, если плотность достаточно долго наблюдается и по акции подключена лента сделок.

Скринер не открывает позиции и не выставляет, не изменяет и не отменяет торговые заявки. Уведомление не является рекомендацией или гарантией исполнения по указанной цене.

## Как проходит работа

1. При запуске воркер получает справочник акций и дневные свечи, отбирает инструменты по ликвидности и стоимости лота.
2. Подписывается на биржевые стаканы и торговые статусы отобранных акций.
3. В каждом пригодном снимке ищет подходящие bid-уровни и ведёт для каждого отдельный эпизод наблюдения.
4. Из подходящих уровней выбирает акции-кандидаты и подключает для них биржевую ленту обезличенных сделок.
5. Когда уровень выдержал заданное время, а лента подтверждена и работает достаточно долго, ставит сигнал в очередь Telegram.
6. Перед отправкой ещё раз проверяет актуальность эпизода. После успешной отправки повтор по той же цене ограничивается cooldown.

Воркер запускается в `dev` и `prod`, если включён `DENSITY_ENABLED`. Он использует общий токен T-Bank `T_BANK` и существующего Telegram-бота; отдельный торговый счёт для скринера не нужен.

## Отбор акций

На старте и затем раз в 24 часа скринер запрашивает базовый список акций, доступных через API. Для дальнейшего отбора акция должна:

- иметь UID, тикер и положительный размер лота;
- торговаться на MOEX и иметь валюту расчётов RUB;
- быть доступной для покупки и торгов через API.

Текущий статус сессии на этом этапе не проверяется. Поэтому при ночном запуске закрытая сессия сама по себе не исключает акцию из списка. Разрешение наблюдения и отправки определяется позднее по потоку торговых статусов.

Для каждой подходящей по справочнику акции запрашиваются дневные свечи за последние 70 календарных дней. Из ответа берутся не более 20 последних завершённых свечей с корректным временем, положительными ценой закрытия и объёмом. Нужно минимум 10 таких свечей. Незавершённые и некорректные свечи не учитываются.

Для каждой свечи рассчитывается приближение дневного оборота:

```text
оборот дня = цена закрытия × объём торгов в лотах × размер лота
средний оборот = сумма оборотов учтённых дней / число учтённых дней
```

Это оценка по цене закрытия, а не точная сумма денег всех сделок. Стоимость лота рассчитывается по последнему завершённому и пригодному закрытию. По умолчанию средний оборот должен быть не меньше **100 млн ₽ в день**, а стоимость лота — не больше **30 000 ₽**. Границы включительны.

Прошедшие фильтры акции сортируются по среднему обороту по убыванию; при равенстве — по UID. В список попадает не более 80 акций. Для них далее используются размер лота и тикер из справочника.

### Запросы истории и ошибки

Между запросами свечей выдерживается настраиваемый интервал, по умолчанию одна секунда. При временных ошибках `Unavailable`, `ResourceExhausted` и `DeadlineExceeded` запрос повторяется до трёх попыток с тем же интервалом; ожидание прерывается при остановке приложения. Ошибка `NotFound` исключает конкретную акцию из этого обновления.

Другие ошибки запроса списка или истории прерывают обновление целиком. Если предыдущий список есть, он сохраняется и после ошибки используется снова; новая попытка обновления назначается через минуту. Если начальный отбор не удался и предыдущего списка нет, подписка на произвольные акции не запускается. Успешное обновление, даже если список оказался пустым, планирует следующее обновление через 24 часа.

При наступлении времени обновления текущее потоковое соединение закрывается, выполняется новый отбор, затем открывается новое соединение. Наблюдения плотностей при этом начинаются заново.

## Стакан и торговый статус

Для отобранных акций запрашивается биржевой стакан типа `ORDERBOOK_TYPE_EXCHANGE` глубиной до 50 уровней. Отдельная подписка Info передаёт торговые статусы. Сделки запрашиваются отдельно и только для кандидатов, описанных ниже.

Обработка стакана для акции начинается после успешного подтверждения подписок на стакан и Info и получения подходящего торгового статуса: **нормальные торги** с доступностью лимитной заявки. При остановке торгов наблюдения акции сбрасываются. Если подписка на стакан или Info для отдельной акции отклонена, она исключается из обработки текущего соединения; здоровые инструменты продолжают работать. После нового подключения список подписок строится заново.

Для расчёта пригоден только биржевой снимок, отмеченный источником как консистентный, с корректным временем и обеими сторонами стакана. Дополнительно проверяются положительные цены и количества, порядок уровней и отсутствие пересечения лучшего bid с лучшим ask. Недостоверный снимок сбрасывает наблюдения соответствующей акции.

### Свежесть снимка

По умолчанию допускается возраст биржевого timestamp не больше **3 секунд**. Повторный или более старый timestamp не продвигает наблюдение. Время между последним принятым снимком и текущим моментом также ограничено тремя секундами; периодическая проверка удаляет устаревшие наблюдения даже тогда, когда соединение остаётся открытым и приходят ping.

Снимок с timestamp дальше порога свежести в будущем отклоняется. Допустимое небольшое расхождение часов не означает подтверждения непрерывности объёма на бирже. При редко меняющемся стакане отсутствие новых снимков может приводить к сбросам и пропуску плотности.

## Как определяется плотность

Скринер рассматривает уровни **bid** — предложения на покупку. Лучший bid — наибольшая цена покупки в текущем стакане. Для каждого уровня рассчитываются:

```text
расстояние = (лучший bid − цена уровня) / лучший bid
объём уровня в ₽ = цена уровня × количество лотов × размер лота
```

По умолчанию уровень должен удовлетворять всем условиям одновременно:

1. Расстояние от лучшего bid — не более **1%**.
2. Денежный объём — не менее **5 млн ₽**.
3. Денежный объём — не менее чем в **5 раз** больше медианы соседних bid-уровней.

Все три границы включительны. Для медианы берутся до 10 ближайших по цене **других** bid-уровней; сам проверяемый уровень исключён. Нужно минимум пять соседних уровней с положительным объёмом. Для чётного числа значений медиана — среднее двух центральных после сортировки денежных объёмов.

Например, при лучшем bid 250 ₽ цена 247,50 ₽ находится ровно на границе 1% и допускается; цена ниже границы не проходит этот фильтр. Если на уровне стоит 200 лотов, размер лота — 100 акций, а цена — 250 ₽, денежный объём равен `250 × 200 × 100 = 5 000 000 ₽`. При медиане соседей 1 млн ₽ кратность равна 5 и уровень проходит оба объёмных порога.

### Индивидуальный объём и поддержка H1

В `env/prod.env` для скринера и live-входов включён индивидуальный порог
объёма. Фильтр поддержек H1 отключён для всех тикеров: уровни не рассчитываются
и близость плотности к ним не требуется.

```env
DENSITY_TURNOVER_FRACTION=0.004
DENSITY_SUPPORT_ENABLED=false
```

Индивидуальный минимум — максимум из `DENSITY_MIN_RUBLES` и среднего дневного
оборота × `DENSITY_TURNOVER_FRACTION`. Оборот оценивается как цена закрытия ×
объём в лотах × размер лота по последним 20 завершённым дням (минимум 10).
Например, при обороте 2 млрд ₽ и доле 0.004 минимум составляет 8 млн ₽.
Это сравнение заявок с масштабом совершённых торгов, не доказательство отскока.

При `DENSITY_SUPPORT_ENABLED=true` включается дополнительный фильтр.
Ниже описан его расчёт с настройками по умолчанию.
Поддержки рассчитываются по завершённым часовым свечам за 60 календарных дней.
Локальный минимум должен быть строго ниже минимумов двух свечей с каждой стороны.
Закрытие одной из следующих шести свечей должно быть выше минимума минимум на
0.5%, прежде чем произойдёт закрытие ниже него более чем на 0.2%.
Используются только минимумы с полностью завершённым окном подтверждения.
Близкие минимумы объединяются с допуском 0.2% относительно первого уровня;
последовательное расширение зоны через цепочку соседних минимумов не допускается.
Нужны минимум два подтверждённых подхода с разницей не менее шести часов.
Закрытие ниже центра зоны более чем на 0.2% аннулирует предшествующие подходы.

Цена текущей плотности должна находиться в пределах ±0.2% от поддержки.
Например, для поддержки 250 ₽ допускаются плотности от 249.50 до 250.50 ₽.
Допуск `DENSITY_SUPPORT_TOLERANCE` независим от расстояния между лучшим bid и
плотностью (`DENSITY_MAX_DISTANCE`). Проверяются оба ограничения.

Профили оборота и поддержек загружаются при запуске и обновляются раз в сутки.
На каждом снимке стакана проверяется готовый профиль. Профиль действителен
24 часа; отсутствующая поддержка либо просроченный профиль запрещают новые
сигналы. Ошибка загрузки не продлевает профиль. В live обновление выполняется
в фоне и не блокирует сопровождение заявок/позиций; обновление профиля
перезапускает подтверждение новых сигналов, но не закрывает позиции.

Без env-настроек новые фильтры отключены: `DENSITY_TURNOVER_FRACTION=0`,
`DENSITY_SUPPORT_ENABLED=false`. При включении поддержек остальные значения
по умолчанию соответствуют примеру выше. Lookback допускается от 1 до 90 дней,
фланг минимума — от 1 до 24 свечей, окно отскока — от фланга до 48 свечей,
минимум подходов — 2, разделение — от часа, допуск — больше 0 и не более 0.1.

### Эпизод и устойчивость

Эпизод определяется парой **UID инструмента и точная цена уровня** в представлении `units/nano`. Отдельные заявки на этой цене скринер не видит: биржа передаёт агрегированный уровень. Таймер начинается при первом принятом снимке, на котором уровень соответствует фильтрам. Уровень должен оставаться подходящим в каждом следующем принятом снимке; снижение количества допустимо, пока оба объёмных порога сохраняются.

Минимальное время наблюдения задаёт `DENSITY_PERSISTENCE`. По умолчанию это **60 секунд**, в `env/prod.env` задано **10 секунд**. Если цена изменилась, объём перестал проходить фильтры или уровень исчез из доступной глубины, прежний эпизод заканчивается. Недостоверный или устаревший стакан, остановка торгов и переподключение также сбрасывают наблюдение. Для сигнала на новой цене или после сброса время отсчитывается заново.

Возраст в сообщении — время непрерывного наблюдения **скринером в доступных снимках**, а не возраст конкретной заявки. По агрегированному стакану нельзя узнать личность владельца, отличить одну заявку от нескольких или доказать, что объём сохранялся между снимками.

## Выбор кандидатов и лента сделок

Кандидаты выбираются из всех подходящих наблюдаемых уровней с начала наблюдения. Для одной акции в ранжировании используется её лучший уровень: сначала по убыванию кратности медиане, затем по убыванию денежного объёма. При равных показателях сохраняется уже выбранная акция; дальнейшие совпадения разрешаются по UID и цене.

Состав кандидатов пересматривается не чаще одного раза в **15 секунд**. Несколько уровней одной акции занимают одну подписку на сделки. По умолчанию выбирается до **10 акций**; при смене состава ненужные подписки снимаются до добавления новых. Запрашиваются только биржевые сделки `TRADE_SOURCE_EXCHANGE`.

Подписка на ленту считается пригодной для сигнала после успешного подтверждения и **15 секунд** непрерывной работы. Для отправки сигнала должны быть выполнены оба условия: готовность ленты и минимальное время наблюдения плотности. При переподключении подтверждение, таймер готовности и накопленная статистика ленты сбрасываются; запоздалые подтверждения предыдущего состояния не должны подтверждать новую подписку.

После подтверждения скринер суммирует полученные количества сделок в лотах по UID и точной цене уровня. Одинаковые по полям сообщения считаются отдельно: в текущем API нет ID сделки, позволяющего надёжно различить повтор и две разные сделки. Поэтому объём — **наблюдаемый по текущей подписке**, без гарантии отсутствия повторов или пропусков. Лента не доказывает, что исполнена или снята конкретная заявка из плотности. Отсутствие сделок само по себе сигнал не запрещает.

## Сообщение и повторные сигналы

Сообщение содержит тикер, сторону «покупка», цену, текущий объём в лотах и рублях, возраст наблюдения, расстояние от лучшего bid и кратность медиане. Для готовой ленты также показываются наблюдаемые сделки на этой цене и отдельная длительность покрытия лентой. Длительность ленты может быть меньше возраста плотности: она не выдаётся за наблюдение сделок на протяжении всего эпизода.

Пример формата; значения условные:

```text
TICKER — покупка
Цена: 250 ₽
Объём: 200 лотов (5000000 ₽)
Наблюдается: 60 с
Расстояние от лучшего bid: 0.00%
Кратность медиане: 5.00
Сделки на уровне: 12 лотов за 20 с наблюдения ленты
```

Уведомления отправляет отдельный воркер через ограниченную очередь на 32 события. Чтение рынка не ждёт ответа Telegram. Непосредственно перед сетевой отправкой проверяется, что тот же эпизод ещё существует, стакан свеж, статус торгов подходит, выдержка достигнута и лента готова; значения сообщения обновляются по текущему состоянию. Устаревшее событие отбрасывается. Если очередь переполнена, сигнал не считается отправленным и может быть поставлен в неё при следующем подходящем снимке.

После успешной отправки повтор внутри того же эпизода запрещён. Для нового эпизода на той же паре UID/цена дополнительно действует **30 минут** от последней успешной отправки. При ошибке Telegram сигнал не помечается успешным: следующая попытка допускается через пять секунд, пока эпизод актуален. На сетевую отправку выделяется до 30 секунд; при остановке приложения её контекст отменяется. Ошибка отправки в указанный топик не перенаправляет сообщение в General.

Состояние наблюдений, ленты и cooldown хранится в памяти процесса. Переподключение сбрасывает наблюдения и ленту; cooldown успешных отправок сохраняется в работающем процессе. После перезапуска приложения память скринера очищается.

## Переподключение и диагностика

При ошибке потока скринер закрывает текущее соединение и заново открывает подписки. Между попытками применяется экспоненциальная задержка с разбросом: сначала примерно 0,5–1 секунды, затем задержка увеличивается с ограничением базового интервала одной минутой. Ожидание прекращается при остановке приложения. После переподключения плотности должны заново пройти выдержку, а лента — получить подтверждение и отработать время готовности.

Основные сообщения в логах:

- `density screener started` — воркер запущен;
- `density universe refreshed` — отбор завершён, поле `instruments` содержит размер списка;
- `density universe refresh failed` — обновление справочника или свечей завершилось ошибкой;
- `density stream disconnected` — поток завершился с ошибкой и будет переподключён;
- `density book subscription rejected`, `density info subscription rejected`, `density trade subscription rejected` — отклонена подписка отдельного инструмента;
- `density notification failed` — Telegram не принял сообщение, возможен повтор для актуального эпизода.

Отсутствие алертов само по себе не означает ошибку: выбранные акции могут не иметь плотностей, удовлетворяющих всем условиям, или свежих снимков для выдержки. Первый отбор также занимает время из-за ограниченной частоты запросов свечей.

## Настройка и запуск

В `env/prod.env` для production или `env/local.env` для локального режима задайте:

```env
DENSITY_ENABLED=true
DENSITY_CHAT_ID=<числовой ID чата>
DENSITY_TOPIC_ID=<числовой ID топика>
```

Можно использовать существующую Telegram-группу: тогда `DENSITY_CHAT_ID` совпадает с `TELEGRAM_GROUP_CHAT_ID`, а `DENSITY_TOPIC_ID` указывает на выделенный топик. Бот должен быть добавлен в группу и иметь право отправлять сообщения. Если topic ID не задан или равен `0`, сообщение отправляется в чат без указания темы. При включении без chat ID приложение отклоняет конфигурацию. После изменения env приложение нужно перезапустить.

ID можно получить через Telegram Bot API, например из `getUpdates` после сообщения в нужный чат или топик. Не публикуйте токен и полный ответ API.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DENSITY_ENABLED` | `false` | Включить постоянный воркер |
| `DENSITY_CHAT_ID` | `0` | Чат назначения; обязателен при включении |
| `DENSITY_TOPIC_ID` | `0` | Необязательная тема чата |
| `DENSITY_MAX_BOOKS` | `80` | Максимум стаканов; от 1 до 80 |
| `DENSITY_MAX_TRADES` | `10` | Максимум подписок на сделки; от 1 до 10 |
| `DENSITY_BOOK_DEPTH` | `50` | Запрашиваемая глубина стакана; от 1 до 50 |
| `DENSITY_MIN_RUBLES` | `5000000` | Минимальный денежный объём уровня, ₽ |
| `DENSITY_MIN_MULTIPLE` | `5` | Минимальная кратность медиане |
| `DENSITY_MAX_DISTANCE` | `0.01` | Максимальное относительное расстояние от лучшего bid: `0.01` означает 1% |
| `DENSITY_MIN_NEIGHBORS` | `5` | Минимальное число соседей для медианы |
| `DENSITY_MAX_NEIGHBORS` | `10` | Максимальное число ближайших соседей для медианы |
| `DENSITY_PERSISTENCE` | `1m` | Минимальная длительность наблюдения плотности |
| `DENSITY_FRESHNESS` | `3s` | Максимальный возраст снимка и промежуток без свежих данных |
| `DENSITY_MIN_TURNOVER` | `100000000` | Минимальный средний дневной оборот, ₽ |
| `DENSITY_MAX_LOT_PRICE` | `30000` | Максимальная стоимость лота, ₽ |
| `DENSITY_HISTORY_INTERVAL` | `1s` | Интервал перед запросом дневных свечей |

Длительности задаются в формате Go, например `3s`, `1m` или `500ms`. Числовые пороги и длительности должны быть положительными; максимальное расстояние не может превышать `1`, максимум соседей должен быть не меньше минимума и меньше глубины стакана. Интервал пересмотра кандидатов, 15-секундная готовность ленты, суточное обновление и 30-минутный cooldown в текущей версии не вынесены в env.
