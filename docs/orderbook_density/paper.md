# Форвард-тест плотностей

`cmd/density-paper` получает настоящий биржевой стакан и ленту сделок Т-Банка, но ведёт **виртуальные** заявки, позиции и деньги. Команда создаёт только клиент рыночных данных, не создаёт клиент торговых поручений и не использует брокерский счёт. Работает независимо от основного приложения и Telegram.

## Запуск

Для автоматического запуска симуляции с Telegram-алертами при обычном деплое
основного приложения задайте `DENSITY_LIVE_ENABLED=true` и
`DENSITY_LIVE_TRADE_ENABLED=false`. Используются `DENSITY_LIVE_TICKERS` и общие
фильтры скринера. Алерты показывают только тикер, цену входа/выхода и причину
выхода; размер позиции, баланс, комиссии и искусственная задержка не нужны.
Алерты генерируются только на виртуальные исполнения. Подробнее —
[режимы участника](live.md#виртуальная-торговля-и-алерты).

Ниже описан отдельный CLI `density-paper`, который остаётся независимым
форвард-тестом без Telegram и с собственными настройками размера позиции.

Из корня этого checkout:

```bash
go run ./cmd/density-paper -env-file /путь/к/token.env -tickers T,SBER -duration 2h
```

В dotenv-файле или окружении нужен `T_BANK`. Токен передаётся только API по TLS и не записывается в отчёты. Существующие переменные окружения имеют приоритет перед dotenv. Допускается токен с доступом только на чтение. Содержимое токена не передавайте в аргументах командной строки.

С `-tickers` запрашиваются только указанные акции основной площадки MOEX (`TQBR`) через `ShareBy`, без загрузки общего справочника. Неизвестный тикер приводит к явной ошибке.

Без `-duration` процесс работает до Ctrl+C. Без `-tickers` загружается общий список акций, проверяются история и ликвидность; это может занять несколько минут. Из прошедших фильтры инструментов выбираются до **10 наиболее ликвидных**, чтобы для каждого постоянно держать подписки и на стакан, и на ленту. Это отличается от обычного скринера (до 80 стаканов с динамическим выбором 10 лент). Список фиксируется на один запуск; для обновления запускайте новую сессию.

Тест не проверяет, хватило бы на реальном счёте денег, допуска и доступного лимита торговых поручений: он распоряжается только указанным виртуальным капиталом.

## Начальные параметры

Команда также применяет `DENSITY_TURNOVER_FRACTION` и `DENSITY_SUPPORT_*` из
окружения/dotenv. Эти фильтры одинаковы для paper, скринера и live-покупки:
индивидуальный минимум от оборота и близость к поддержкам H1. Профили загружаются
при запуске и обновляются раз в сутки в фоне; до получения свежего профиля
новые виртуальные входы запрещены. Сопровождение открытых позиций продолжается.
Параметры и механика — в [документации скринера](screener.md).

Это исходные гипотезы для проверки, а не калиброванные торговые рекомендации.

| Флаг | По умолчанию | Смысл |
|---|---:|---|
| `-cash` | 100000 | Начальный виртуальный капитал, ₽ |
| `-position-rubles` | 10000 | Лимит денег на вход с комиссией, ₽ |
| `-max-positions` | 3 | Общий лимит инструментов с ожидающей заявкой или позицией |
| `-commission` | 0.0005 | Комиссия с каждой стороны, 0,05%; замените на свой тариф |
| `-entry-ticks` | 1 | Шагов цены выше плотности до покупки |
| `-stop-ticks` | 2 | Шагов цены ниже исходной плотности до стопа |
| `-rr` | 2 | Тейк в долях расстояния от входа до стопа, округляется вверх до шага |
| `-min-remaining` | 0.5 | Минимальная оставшаяся доля исходного объёма плотности |
| `-latency` | 250ms | Задержка активации входа, тейка и аварийного выхода |
| `-entry-ttl` | 2m | Время ожидания исполнения входа |
| `-max-hold` | 10m | Предельное время удержания позиции |
| `-cooldown` | 5m | Пауза по инструменту после отмены/закрытия |
| `-tls-classic` | false | Явный режим совместимости TLS: X25519/P-256 вместо стандартного набора Go |
| `-instruments` | 10 | Лимит инструментов, от 1 до 10 |
| `-out` | reports/density-paper | Корень каталогов результатов |

Условия обнаружения берутся из `DENSITY_*`, как в основном скринере. Явные флаги `-min-rubles`, `-min-multiple`, `-max-distance`, `-persistence` перекрывают соответствующие переменные. Стандартно это 5 млн ₽, 5 медиан, расстояние 1% (`0.01`) и 60 секунд. Сохраняются также проверка свежести данных, торгового статуса и 15 секунд готовности подписки на ленту. Опции Telegram и `DENSITY_ENABLED` не включают отправку сообщений в этой команде.

```bash
go run ./cmd/density-paper -env-file /путь/к/token.env \
  -tickers T -commission 0.0005 -entry-ticks 1 -stop-ticks 2 \
  -rr 2 -min-remaining 0.5 -duration 2h
```

## Модель исполнения

1. После непрерывного подтверждения плотности выставляется виртуальная лимитная покупка выше неё. Шаг цены и размер лота берутся из справочника инструмента. Если лимит пересекает лучшую продажу, вход пропускается. Деньги резервируются, поэтому одни средства нельзя одновременно использовать в нескольких заявках.
2. Вход исполняется только по **последующей** биржевой сделке строго ниже цены лимита, после задержки активации. Касание лимита не считается исполнением. Цена исполнения в модели — лимит, объём не больше наблюдаемой сделки и объёма нашей заявки. После первого частичного исполнения остаток входа снимается, защищается фактически купленный объём.
3. Плотность отслеживается по исходной цене. Если видимый объём падает ниже `min-remaining` от исходного (либо уровня больше нет среди видимых bid), ожидающая покупка отменяется. Отмена ожидающего входа в первой версии моделируется немедленно на полученном событии: гонка отмены с исполнением и задержка снятия остатка частичного входа не воспроизводятся. Это может завышать результат. Открытая позиция переводится в выход с задержкой. Изменение медианы само по себе выход не вызывает, цена стопа вниз не переносится.
4. Стоп активируется по лучшему bid или наблюдаемой сделке на/ниже стопа. Удаление плотности и истечение `max-hold` также вызывают выход. После задержки виртуальная продажа проходит по bid **нового** свежего стакана, учитывая объём каждого видимого уровня. При недостатке глубины остаток остаётся открытым до следующих снимков. Один снимок не используется для исполнения повторно.
5. Тейк — виртуальная лимитная продажа. Нужна последующая сделка строго выше цели после активации; объём ограничен наблюдаемой сделкой. При касании цели продажа не засчитывается.
6. Старые/некорректные стаканы, пропуски данных и переподключение снимают ожидающий вход и помечают удерживаемую позицию как неопределённую. Выход выполняется только после возврата новых пригодных данных. События стакана до границы разрыва повторно исполнять сделки не могут.

Биржевая очередь не восстанавливается. Сделки без времени биржи, с повторяющимся временем или опоздавшие более допуска свежести отбрасываются: API не даёт надёжного уникального ID сделки для дедупликации. Модель может пропускать реальные исполнения, но это **не гарантирует**, что суммарная прибыль будет ниже реальной: выбор исполненных сделок тоже меняет результат. Последовательные снимки могут содержать одну и ту же реальную ликвидность; влияние наших виртуальных заявок на рынок не моделируется. Для плотности, вышедшей за видимую глубину, используется осторожное предположение потери поддержки. Налоги, биржевые ограничения реальных поручений и точная инфраструктурная задержка не моделируются.

## Результаты

Каждый запуск создаёт отдельный каталог, например `reports/density-paper/20261116T100000Z-123456/`:

- `events.jsonl` — настройки без секретов, состав инструментов, постановки/отмены/исполнения, причины выходов и проблемы данных. Каждая запись синхронизируется с диском. В записи есть удобные цены в рублях; целочисленные цены в `order` указаны в **нанорублях** (делить на 1 000 000 000), объёмы — в лотах.
- `summary.json` — атомарно обновляемая примерно раз в 10 секунд и при штатной остановке сводка. Если процесс аварийно убит, последние события могут быть новее сводки.

`realized_pnl` — прибыль/убыток по уже проданному объёму после обеих комиссий, включая частичные выходы. `estimated_unrealized_pnl` — оценка оставшихся позиций по видимым bid с учётом уплаченной комиссии входа и предполагаемой комиссии выхода. `estimated_net_pnl` — сумма этих величин, `estimated_equity` — деньги плюс оценка ликвидации позиций. `paid_fees` показывает уже уплаченные виртуальные комиссии. `reserved_cash` включён в `cash`, его не нужно прибавлять к капиталу.

При отсутствии свежей полной оценки портфеля `valuation_fresh=false`, а три оценочных финансовых поля записываются как `null`. Реализованный результат при этом остаётся доступным. `data_complete=false` означает, что в сессии были разрывы или неопределённые позиции: сравнивать такую сессию с непрерывной без оговорок нельзя. Просадка считается в рублях по доступным оценкам капитала и может пропускать движение во время разрывов.

`closed_trades` и `win_rate` относятся только к полностью закрытым позициям. В `orders` сводки хранится последний эпизод по каждому инструменту; полная история всех эпизодов находится в `events.jsonl`.

Ctrl+C снимает виртуальные ожидающие входы, но **не придумывает продажу** удерживаемых акций. Они остаются в отчёте открытыми и неопределёнными. Следующий запуск начинает новую независимую сессию с исходным капиталом, без восстановления старых позиций. Ошибки записи останавливают симулятор и выводятся как ошибки процесса.

## Тайм-аут при запуске

`DeadlineExceeded` сам по себе не доказывает медленную обработку справочника: запрос может ждать установления TLS-соединения. Если в ошибке есть `transport: authentication handshake failed: context deadline exceeded`, или curl подключается, а Go-клиент стабильно зависает до ответа, попробуйте явный режим совместимости:

```bash
go run ./cmd/density-paper -env-file ../tinvest/env/token.env \
  -tickers T,SBER -tls-classic -duration 2h
```

`-tls-classic` меняет только набор групп обмена ключами на X25519/P-256. Проверка сертификата и имени сервера остаётся включена, минимальная версия — TLS 1.2. Флаг не исправляет неправильный токен, отсутствие доступа, ошибочный тикер и все возможные сетевые сбои. Он не меняет настройки TLS основного приложения.

Для небольшой выборки всегда передавайте `-tickers`: это устраняет скачивание многомегабайтного общего списка. При повторной ошибке сохраните полный текст и этап сбоя, а не только слово `DeadlineExceeded`.
