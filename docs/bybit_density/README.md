# Скринер плотностей Bybit

Bybit Density — воркер основного приложения TInvest. Он следит за спотовыми парами с котировкой в USDT на Bybit. Для чтения рынка не требуется API-ключ Bybit. Виртуальные входы и выходы обрабатываются локально.

## Запуск

Дайте Telegram-боту право отправлять сообщения в настроенные чаты. В одном форуме укажите разные темы. В dotenv-файле или окружении процесса задайте переменные:

```dotenv
BYBIT_DENSITY_ENABLED=true
BYBIT_DENSITY_TELEGRAM_TOKEN=<токен бота>
BYBIT_DENSITY_SCREENER_CHAT_ID=<ID чата плотностей>
BYBIT_DENSITY_SIMULATION_CHAT_ID=<ID чата виртуальных сделок>
```

При использовании существующего токена `TELEGRAM` отдельная переменная `BYBIT_DENSITY_TELEGRAM_TOKEN` не нужна. Для тем задайте `BYBIT_DENSITY_SCREENER_TOPIC_ID` и `BYBIT_DENSITY_SIMULATION_TOPIC_ID`. Значение `0` означает отправку без указания темы. В `env/prod.env` настроена существующая группа DENSITY с темами `9686` для плотностей Bybit и `9688` для виртуальных исполнений Bybit.

Основное приложение читает `env/prod.env` в проде и `env/local.env` при локальном запуске. По умолчанию воркер выключен. `BYBIT_DENSITY_ENABLED=true` включает скринер и симуляцию вместе.

Проверка публичного подключения без Telegram и локального журнала:

```bash
go run ./cmd/main.go bybit-check-feed
```

Проверка ждёт стакан, публичную сделку и закрытие минутной свечи BTCUSDT на споте. По умолчанию ей отводится 90 секунд. `-help` выводит все параметры. Явные флаги имеют приоритет над переменными окружения, а окружение имеет приоритет над dotenv-файлом.

## Проверка на проде

Основной контейнер `tinvest-container` запускает воркер по настройке `BYBIT_DENSITY_ENABLED=true` из `env/prod.env`. Он использует токен `TELEGRAM` и сохраняет журнал в подкаталоге `bybit-density` постоянного тома `tinvest-state`.

```bash
docker logs --tail 200 -f tinvest-container 2>&1 | grep --line-buffered -i bybit
docker exec tinvest-container /application/build bybit-check-feed
```

Строка `Bybit Density worker started` подтверждает запуск воркера и открытие журнала. `Bybit order book connected` для `spot` подтверждает свежий стакан. `Bybit Telegram alert delivered` означает, что Telegram принял сообщение в указанную тему. Первый алерт о плотности возможен после заданной выдержки и прохождения остальных фильтров.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BYBIT_DENSITY_SYMBOL_LIMIT` | 20 | Число спотовых пар по обороту за 24 часа |
| `BYBIT_DENSITY_SPOT_SYMBOLS` | — | Явный список пар спота через запятую, например `BTCUSDT,ETHUSDT` |
| `BYBIT_DENSITY_DEPTH` | 200 | Глубина стакана с каждой стороны, 50, 200 или 1000 |
| `BYBIT_DENSITY_MIN_NOTIONAL` | 100000 | Минимальная сумма на уровне в USDT |
| `BYBIT_DENSITY_ALERT_M5_VOLUME_MULTIPLIER` | 0.5 | Минимальный объём уровня для алерта в долях среднего объёма M5 |
| `BYBIT_DENSITY_MIN_MULTIPLE` | 5 | Минимальная кратность к медиане соседей |
| `BYBIT_DENSITY_PERSISTENCE` | 60s | Время непрерывного подтверждения |
| `BYBIT_DENSITY_FRESHNESS` | 3s | Допустимый возраст данных стакана |
| `BYBIT_DENSITY_STOP_TICKS` | 2 | Совместимость со старой конфигурацией |
| `BYBIT_DENSITY_REWARD_RISK` | 2 | Множитель расстояния от фактического входа до стопа для расчёта тейка |
| `BYBIT_DENSITY_MIN_TARGET` | 0.003 | Минимальное расстояние от входа до тейка, 0,3% |
| `BYBIT_DENSITY_PAPER_NOTIONAL` | 250 | Максимальная сумма виртуального входа в USDT |
| `BYBIT_DENSITY_SPOT_FEE` | 0.001 | Модельная комиссия спота на сторону, 0,10% |
| `BYBIT_DENSITY_STATE_DIR` | `reports/bybit-density` | Журнал симуляции и очередь виртуальных уведомлений |

В 03:00 МСК работающий скринер очищает всё содержимое `/application/data/state/bybit-density`, включая историю виртуальных сделок, открытые виртуальные позиции и очередь уведомлений. После очистки скринер создаёт новый журнал и запускает новую сессию симуляции. Для других путей очистка отключена.

При запуске выбор инструментов фиксируется до следующего запуска. Скринер ищет плотности на покупку (bid) в пределах 2 тиков от лучшего bid и сравнивает денежный объём уровня с медианой ближайших уровней покупки. Сумма уровня рассчитывается как цена × количество монет. Сигналы показывают объём уровня и наблюдаемый объём публичных сделок по этой цене. Повторы сделок отфильтровываются по последним 8192 ID на инструмент.

Для алерта количество монет на уровне должно быть не меньше `BYBIT_DENSITY_ALERT_M5_VOLUME_MULTIPLIER` × среднего объёма завершённых пятиминутных свечей за предыдущий будний день с 09:00 до 18:00 МСК. Симулятор отскока использует полный средний объём. В понедельник используется пятница. Без истории для этого окна новые сигналы и входы по паре пропускаются.

Симулятор открывает только лонги на споте и отслеживает плотности в пределах 25 тиков от лучшего bid. После подтверждения плотности выставляется виртуальная лимитная покупка на один тик выше её цены. Заявка ждёт доступный ask в пределах лимита. Падение объёма на исходном уровне ниже 40% от объёма при выставлении или разрыв потока снимает заявку. Стоп ставится на 0,2% ниже фактической цены исполнения с округлением вниз до шага цены.

Выходы происходят по стопу, тейку или при исчезновении плотности. По каждой полностью закрытой виртуальной сделке приходит одно сообщение с ценами и временем входа и выхода по МСК, уровнем и объёмом исходной плотности, стопом, тейком, причинами выхода и чистым результатом. При закрытии частями цена выхода усредняется по объёму, а время соответствует последнему исполнению. Результат учитывает модельные комиссии. Funding и место заявки в биржевой очереди в модели отсутствуют.

## Эксперимент с пробоем ask на SOL/USDT

`BYBIT_DENSITY_SOL_BREAKOUT=true` добавляет сравнение двух вариантов бумажной торговли для спота SOLUSDT. Если SOLUSDT отсутствует в обычной выборке воркера, он добавляется к ней. Эксперимент по умолчанию выключен. Скринер и симуляция отскока работают параллельно с ним.

- **Подтверждение пробоя.** Ищем крупный уровень в пределах 25 тиков от лучшего ask по настройкам `MIN_NOTIONAL`, `MIN_MULTIPLE` и `PERSISTENCE`. Когда подтверждённый уровень становится лучшим ask, фиксируем его объём. Учитываем последующие агрессивные покупки по этой цене и прибавляем к требуемому объёму наблюдаемое пополнение уровня. Блок-сделки и RPI исключаются. После ухода ask выше уровня даём до 500 мс на получение запоздавших сделок и подъём лучшего bid до уровня. В объём выкупа включаем только сделки с биржевым временем до ухода ask включительно.
- **Дисбаланс.** В момент подтверждения берём по три ближайших уровня покупки и продажи. `I = (BidVol − AskVol) / (BidVol + AskVol)`, где объёмы выражены в монетах. Вариант `breakout` принимает каждый подтверждённый пробой при свободном симуляторе. Вариант `breakout_imbalance` берёт те же сигналы при `I > +0.33`.
- **Виртуальное исполнение.** На следующем свежем обновлении стакана в пределах окна подтверждения, пока bid держится на уровне или выше, оба варианта независимо моделируют покупку по лучшему ask с учётом его доступного объёма. На первом свежем обновлении с bid ниже уровня или по истечении 10 секунд после входа выставляется виртуальный выход по доступным bid. Размер и комиссии берутся из `BYBIT_DENSITY_PAPER_NOTIONAL` и `BYBIT_DENSITY_SPOT_FEE`. При разрыве потока ожидание входа сбрасывается, открытые позиции ждут свежего стакана.
- **Результаты.** Сообщение в теме симуляции содержит вариант, дисбаланс, причину выхода и чистый P&L. Для наблюдения за несколькими сутками задайте `BYBIT_DENSITY_STATE_DIR` с постоянным хранением и без ежедневной очистки.

Сравнение закрытых сделок по сохранённому журналу:

```bash
jq -s '
  map(.fill | select(.variant != null and .closed != null))
  | group_by(.variant)
  | map({
      variant: .[0].variant,
      trades: length,
      net_usdt: (map(.closed.NetPnL) | add),
      mean_usdt: ((map(.closed.NetPnL) | add) / length)
    })
' reports/bybit-density/events.jsonl
```
