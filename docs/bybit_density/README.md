# Скринер плотностей Bybit

Bybit Density — воркер основного приложения TInvest. Он следит за спотовыми парами с котировкой в USDT и линейными бессрочными USDT-фьючерсами на Bybit. Для чтения рынка не требуется API-ключ Bybit. Виртуальные входы и выходы обрабатываются локально.

## Запуск

Дайте Telegram-боту право отправлять сообщения в настроенные чаты. В одном форуме укажите разные темы. В dotenv-файле или окружении процесса задайте переменные:

```dotenv
BYBIT_DENSITY_ENABLED=true
BYBIT_DENSITY_TELEGRAM_TOKEN=<токен бота>
BYBIT_DENSITY_SCREENER_CHAT_ID=<ID чата плотностей>
BYBIT_DENSITY_SIMULATION_CHAT_ID=<ID чата виртуальных сделок>
```

При использовании существующего токена `TELEGRAM` отдельная переменная `BYBIT_DENSITY_TELEGRAM_TOKEN` не нужна. Для тем задайте `BYBIT_DENSITY_SCREENER_TOPIC_ID` и `BYBIT_DENSITY_SIMULATION_TOPIC_ID`. Значение `0` означает отправку без указания темы. В `env/prod.env` настроена существующая группа DENSITY с темами `9686` для плотностей Bybit и `9688` для виртуальных исполнений Bybit.

Основное приложение читает `env/prod.env` в проде и `env/local.env` при локальном запуске. По умолчанию воркер выключен. `BYBIT_DENSITY_ENABLED=true` включает скринер и симуляцию вместе.

Проверка публичного подключения без Telegram и локального журнала:

```bash
go run ./cmd/main.go bybit-check-feed
```

Проверка ждёт стакан, публичную сделку и закрытие минутной свечи BTCUSDT с обоих рынков. По умолчанию ей отводится 90 секунд. `-help` выводит все параметры. Явные флаги имеют приоритет над переменными окружения, а окружение имеет приоритет над dotenv-файлом.

## Проверка на проде

Основной контейнер `tinvest-container` запускает воркер по настройке `BYBIT_DENSITY_ENABLED=true` из `env/prod.env`. Он использует токен `TELEGRAM` и сохраняет журнал в подкаталоге `bybit-density` постоянного тома `tinvest-state`.

```bash
docker logs --tail 200 -f tinvest-container 2>&1 | grep --line-buffered -i bybit
docker exec tinvest-container /application/build bybit-check-feed
```

Строка `Bybit Density worker started` подтверждает запуск воркера и открытие журнала. `Bybit order book connected` для `spot` и `linear` подтверждает свежий стакан на обоих рынках. `Bybit Telegram alert delivered` означает, что Telegram принял сообщение в указанную тему. Первый алерт о плотности возможен после заданной выдержки и прохождения остальных фильтров.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BYBIT_DENSITY_SYMBOL_LIMIT` | 20 | Число пар по обороту за 24 часа отдельно на каждом рынке |
| `BYBIT_DENSITY_SPOT_SYMBOLS` | — | Явный список пар спота через запятую, например `BTCUSDT,ETHUSDT` |
| `BYBIT_DENSITY_LINEAR_SYMBOLS` | — | Явный список бессрочных USDT-фьючерсов |
| `BYBIT_DENSITY_DEPTH` | 200 | Глубина стакана с каждой стороны, 50, 200 или 1000 |
| `BYBIT_DENSITY_MIN_NOTIONAL` | 100000 | Минимальная сумма на уровне в USDT |
| `BYBIT_DENSITY_MIN_MULTIPLE` | 5 | Минимальная кратность к медиане соседей |
| `BYBIT_DENSITY_MAX_DISTANCE` | 0.01 | Максимальное расстояние от лучшей цены на своей стороне, 1% |
| `BYBIT_DENSITY_PERSISTENCE` | 60s | Время непрерывного подтверждения |
| `BYBIT_DENSITY_FRESHNESS` | 3s | Допустимый возраст данных стакана |
| `BYBIT_DENSITY_ENTRY_TICKS` | 1 | Отступ лимитки от плотности в сторону рынка, в тиках цены |
| `BYBIT_DENSITY_STOP_TICKS` | 2 | Отступ стопа за плотность, в тиках цены |
| `BYBIT_DENSITY_REWARD_RISK` | 2 | Множитель расстояния от фактического входа до стопа для расчёта тейка |
| `BYBIT_DENSITY_MIN_TARGET` | 0.003 | Минимальное расстояние от входа до тейка, 0,3% |
| `BYBIT_DENSITY_PAPER_NOTIONAL` | 250 | Максимальная сумма виртуального входа в USDT |
| `BYBIT_DENSITY_SPOT_FEE` | 0.001 | Модельная комиссия спота на сторону, 0,10% |
| `BYBIT_DENSITY_LINEAR_FEE` | 0.00055 | Модельная комиссия фьючерса на сторону, 0,055% |
| `BYBIT_DENSITY_STATE_DIR` | `reports/bybit-density` | Журнал симуляции и очередь виртуальных уведомлений |

При запуске выбор инструментов фиксируется до следующего запуска. Скринер сравнивает денежный объём отдельного биржевого уровня с медианой ближайших уровней на той же стороне. Сумма уровня рассчитывается как цена × количество монет. Сигналы показывают объём уровня и наблюдаемый объём публичных сделок по этой цене. Повторы сделок отфильтровываются по последним 8192 ID на инструмент.

Симулятор открывает только лонги на споте и USDT-фьючерсах. Сразу после подтверждения bid-плотности он выставляет виртуальную лимитку на покупку, по умолчанию на один тик выше плотности. Скринер продолжает показывать bid- и ask-плотности. Исполнение моделируется по доступной встречной ликвидности по цене лимитки или лучше. До исполнения заявка отменяется, если исходный уровень исчезает, теряет больше половины своего объёма на момент выставления или стакан теряет свежесть. Выходы происходят по стопу, тейку или при исчезновении плотности. По каждой полностью закрытой виртуальной сделке приходит одно сообщение с ценами и временем входа и выхода по МСК, уровнем и объёмом исходной плотности, стопом, тейком, причинами выхода и чистым результатом. При закрытии частями цена выхода усредняется по объёму, а время соответствует последнему исполнению. Результат учитывает модельные комиссии. Funding и место заявки в биржевой очереди в модели отсутствуют.

Переменные `DENSITY_LIVE_*` относятся к скринеру Мосбиржи. Для Bybit отступ лимитки задаёт `BYBIT_DENSITY_ENTRY_TICKS`. Прежняя настройка Bybit `BYBIT_DENSITY_ENTRY_ZONE_TICKS` относилась к поиску пинбара и больше не используется.

Симуляция работает с публичными рыночными данными и зависит от их свежести. Цена и объём симулированного исполнения могут отличаться от реального исполнения. После перезапуска начинается новая виртуальная сессия, а очередь неотправленных сообщений восстанавливается из `events.jsonl` в каталоге состояния. При завершении с открытой позицией журнал сохраняет её незавершённой.
