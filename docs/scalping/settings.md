# Параметры RUSAL — `Params`

Все «ручки» стратегии вынесены в структуру `Params`
(`internal/service/trading_strategy/scalping/strategy/rusal/rusal.go:14`). Это сделано,
чтобы стратегию можно было откалибровать на реальной истории, **не трогая логику** —
меняются только числа.

- `New()` — стратегия с дефолтными (неоткалиброванными) параметрами `DefaultParams()`.
- `NewWithParams(p Params)` — стратегия с явными параметрами (для калибровки и тестов).

> **Дефолты не откалиброваны.** Значения ниже — стандартные стартовые величины
> технического анализа, а не результат бэктеста RUAL. Их нужно подбирать на реальных
> данных. См. раздел «Калибровка».

## Полный список

| Поле | Дефолт | Назначение |
|---|---|---|
| `EMAPeriod` | 21 | период быстрой EMA для отката в тренде |
| `ADXPeriod` | 14 | период ADX/DMI |
| `ADXTrendLevel` | 25 | `ADX >=` → режим тренда |
| `ADXRangeLevel` | 20 | `ADX <=` → режим боковика (между 20 и 25 — мёртвая зона) |
| `RSIPeriod` | 14 | период RSI |
| `RSITrendLevel` | 45 | порог разворота RSI в тренде (неглубокие откаты) |
| `RSIRangeLevel` | 35 | порог разворота RSI в боковике (перепроданность) |
| `PullbackWindow` | 5 | сколько последних баров засчитывают «касание» EMA |
| `DonchianPeriod` | 20 | период канала: нижняя граница для входа, середина для выхода |
| `ATRPeriod` | 14 | период ATR для стопов/трейлинга |
| `SLMult` | 1.0 | начальный стоп = `entry − SLMult*ATR` |
| `TrailMult` | 2.5 | chandelier = `max(High за окно) − TrailMult*ATR` |
| `ChandelierWindow` | 20 | окно для максимума High в chandelier |
| `EMATouchTol` | 0.002 | допуск «касания» EMA (доля, 0.2 %) |
| `BandTol` | 0.003 | допуск близости к нижней границе канала (доля, 0.3 %) |

`Lookback()` производный: `6*ADXPeriod + DonchianPeriod + 50` (≈ 154 с дефолтами).
Раннер грузит столько свечей, поэтому при увеличении `ADXPeriod`/`DonchianPeriod` окно
данных растёт автоматически.

## Как параметры влияют на поведение

### Чувствительность режима
- **`ADXTrendLevel` ↑** — реже срабатывает трендовая логика (входим только в сильные
  тренды), шире мёртвая зона.
- **`ADXRangeLevel` ↑** (ближе к `ADXTrendLevel`) — уже мёртвая зона; при равенстве
  порогов мёртвая зона исчезает (рынок всегда либо trend, либо range).
- Инвариант: держите `ADXRangeLevel <= ADXTrendLevel`. Иначе перекрытие порогов делает
  классификацию неоднозначной.

### Агрессивность входа
- **`RSITrendLevel` / `RSIRangeLevel` ↑** — раньше считаем разворот состоявшимся, больше
  входов (и больше ложных).
- **`PullbackWindow` ↑** — дольше «помним» откат к EMA, легче поймать трендовый вход.
- **`BandTol` ↑** — шире зона у нижней границы канала, больше боковых входов.
- **`EMATouchTol` ↑** — «касанием» EMA считается более далёкий от неё бар.

### Управление риском / выходом
- **`SLMult` ↑** — дальше стоп, больше риск на сделку, реже выбивает шумом.
- **`TrailMult` ↑** — свободнее трейлинг в тренде (даёт прибыли «дышать», но отдаёт
  больше на развороте).
- **`ChandelierWindow` ↑** — chandelier считается от более старого максимума, трейлинг
  становится свободнее.
- **`DonchianPeriod` ↑** — шире канал, дальше цель `mid` в боковике.

## Калибровка

Подбор параметров на реальной истории RUAL — это follow-up из спеки, а не часть текущей
реализации. Структура `Params` существует именно для того, чтобы калибровка была
изменением **только значений**.

Для калибровки нужно одно из двух:
1. экспорт часовых свечей RUAL, прогнанный через sizing/бэктест-проход; либо
2. достроенный харнесс `internal/domain/backtest` (сейчас заглушка).

Практический порядок подбора:
1. Сначала режимные пороги (`ADXTrendLevel`, `ADXRangeLevel`) — от них зависит, какая
   ветка вообще работает.
2. Затем пороги входа (`RSITrendLevel`, `RSIRangeLevel`, `BandTol`, `PullbackWindow`).
3. В последнюю очередь — риск-параметры (`SLMult`, `TrailMult`, `ChandelierWindow`),
   оптимизируя на метрику доходности/просадки, а не на число сделок.

См. также [strategy.md](strategy.md) — как именно каждый параметр входит в решение.
