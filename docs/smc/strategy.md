# SMC — liquidity sweep (свинговая, long-only)

Спека: `docs/superpowers/specs/2026-07-17-smc-liquidity-sweep-design.md`.
Ядро: `internal/service/trading_strategy/smc/strategy/core`.

## Идея

Smart Money Concepts объясняют стоп-охоту так: крупный игрок не может набрать
позицию, не сдвинув цену, поэтому он сначала выносит очевидную ликвидность —
стопы толпы, лежащие сразу за локальным swing-low, — коротким проколом ниже
уровня, а затем возвращает цену обратно наверх на своём объёме. Розничные
стопы срабатывают на проколе (продавая на дне), крупный игрок покупает
дёшево. Внешний наблюдатель видит это как «sweep» (прокол) и «reclaim»
(быстрый возврат close выше уровня) — если reclaim произошёл, вынос был не
пробоем структуры, а охотой за ликвидностью, и в эту сторону можно входить.

Потенциальный edge: (1) уровень (swing-low) объективен и виден заранее — не
подгоняется под факт входа; (2) reclaim — это фильтр, отсекающий настоящие
пробои (уровень не reclaim-нулся → уходим, а не входим против тренда); (3)
стоп естественно короткий (под sweepLow), что даёт хорошее R при частых
попаданиях. Риск: паттерн общеизвестен, могут быть переполненные входы и
низкий edge на реальных данных — поэтому судьба стратегии решается
walk-forward валидацией, как у ORB (см. «Критерий судьбы»).

## Механика сигнала

1. **Уровни.** Swing-low — фрактал с крылом `SwingK`: `Low[i]` строго ниже
   лоу `SwingK` баров слева и справа. Уровень подтверждается (становится
   видимым для проверки прокола) только через `SwingK` баров после экстремума
   — анти-lookahead: на момент подтверждения бар экстремума уже в прошлом.
   Активные уровни держатся в скользящем окне глубиной `levelWindowDays` (10
   торговых дней MSK); уровни старше окна забываются.
2. **Sweep.** Первый бар после подтверждения с `Low < level` — уровень «в
   снятии» (`pierceIdx`), фиксируется `sweepLow` — минимальный `Low` от
   прокола и далее.
3. **Reclaim.** Если бар в диапазоне `[pierceIdx, pierceIdx + ReclaimBars]`
   (прокол-бар сам может быть reclaim-баром — 0 баров задержки) закрывается
   выше уровня — сигнал Buy на этом баре, вход по close. Не закрылся за
   `ReclaimBars` — уровень мёртв (это был настоящий пробой структуры, не
   охота), больше не проверяется. Вход разрешён только если reclaim-бар
   открылся в основной сессии MSK (час ∈ [10, 19)) и не в выходной; сигнал не
   переносится на следующий день. Если один бар reclaim-ит несколько
   уровней — берётся уровень с самым глубоким `sweepLow` (его стоп ниже,
   накрывает все остальные), сигнал один. Уровень расходуется первым же
   reclaim — повторные проколы той же линии сигнала больше не дают.

**Числовой пример** (дефолты SBER: `SwingK=3`, `ReclaimBars=4`, `Buffer=0.5`,
`TPR=2`):

- Бар `i`: `Low = 250.00`, и по 3 бара слева/справа лежат выше — фрактал
  подтверждён на баре `i+3`. Уровень = `250.00`.
- Бар `i+7`: `Low = 249.50` (< 250.00) — прокол, `sweepLow` пока `249.50`.
- Бар `i+9` (2 бара после прокола, ≤ `ReclaimBars=4`): `Close = 250.30`
  (> 250.00) — reclaim, `sweepLow` за это время не обновился, остался
  `249.50`. Сигнал Buy по close `250.30`.
- `ATR(14)` на входе = `1.20`. Стоп = `sweepLow − Buffer×ATR` =
  `249.50 − 0.5×1.20 = 248.90`.
- Риск на акцию = `250.30 − 248.90 = 1.40`. Тейк = `entry + TPR×риск` =
  `250.30 + 2×1.40 = 253.10`.

## Фильтры

Ядро (уровни → sweep → reclaim) всегда включено; три опциональных фильтра —
булевы тумблеры (`int` 0/1, потому что калибровочный `Grid` умеет только
числа), внутренние константы каждого фильтра фиксированы, гридом не тюнятся:

- **`UseOB`** (order block) — reclaim-бар должен закрыться внутри
  непогашенного бычьего order block: последняя свеча с закрытием ниже
  предыдущего закрытия перед баром, пробившим локальный swing-high в окне
  уровней. Зона — `[Low, High]` этой свечи; погашается первым последующим
  закрытием ниже её `Low`. Нет зоны под ценой входа → сигнал отклоняется.
- **`UseFVG`** (fair value gap) — между проколом и reclaim-баром
  (включительно) должен образоваться бычий разрыв: `Low[i+1] > High[i-1]`
  для какого-то `i` в этом окне. У same-bar reclaim (0 баров задержки) для
  разрыва физически нет места — фильтр всегда режет такие сигналы.
- **`UseDiscount`** — цена входа (close) должна быть ниже середины диапазона
  `[minLow..maxHigh]` за всё окно уровней («дешёвая половина» диапазона).

Каждый фильтр — независимый предикат; первый провалившийся называет себя в
причине отказа (видно через `-explain`).

## Выходы

Приоритет внутри бара сверху вниз — стоп проверяется раньше тейка, потому что
он логически срабатывает раньше в реальном времени:

1. **Hard stop** (интрабарно, `Low[бара] ≤ StopLoss`): `sweepLow −
   Buffer×ATR(14)`, ATR берётся на момент входа; стоп не двигается (без
   трейлинга и безубытка — сознательно, как у ORB).
2. **Take-profit** (интрабарно, `High[бара] ≥ TakeProfit`): `entry + TPR ×
   (entry − stop)`. Пересчитывается stateless из позиции на каждом баре:
   `PurchasePrice + TPR×(PurchasePrice − StopLoss)`. `TPR ≤ 0` выключает TP.
3. **Time-stop:** как только число различных торговых дней MSK строго после
   дня входа достигает `MaxHoldDays` — Sell с `Reason = "TIME"`, исполняется
   по close текущего бара (первый бар нового дня, где условие выполнилось).
   Использует `Position.EntryTime`, которое движок бэктеста заполняет из
   портфеля; в live это поле нулевое, и тайм-стоп деградирует в no-op.
   `MaxHoldDays ≤ 0` выключает тайм-стоп.

## Параметры и константы

Тюнингуемые параметры (`core.Params`), значения — дефолт SBER
(`internal/service/trading_strategy/smc/strategy/sber/sber.go`) и грид
(`data/params/sber/smc_grid.json`, двухфазный: core → filters, keepTop 5 после
фазы core):

| Параметр | Смысл | Дефолт (SBER) | Значения грида |
|---|---|---|---|
| `SwingK` | крыло фрактала для swing-low (баров с каждой стороны) | 3 | 2, 3, 5 |
| `ReclaimBars` | макс. баров от прокола до reclaim-close (0 = только same-bar) | 4 | 2, 4, 6 |
| `Buffer` | отступ стопа под `sweepLow`, в долях ATR(14) | 0.5 | 0.25, 0.5, 1.0 |
| `TPR` | множитель R для тейк-профита (`≤0` выкл.) | 2 | 1.5, 2, 3 |
| `MaxHoldDays` | тайм-стоп, торговых дней после входа (`≤0` выкл.) | 3 | 2, 3, 5 |
| `UseOB` | тумблер фильтра order block (0/1) | 0 (выкл.) | 0, 1 |
| `UseFVG` | тумблер фильтра fair value gap (0/1) | 0 (выкл.) | 0, 1 |
| `UseDiscount` | тумблер фильтра discount-половины диапазона (0/1) | 0 (выкл.) | 0, 1 |

Фаза `core` грида — 3×3×3×3×3 = 243 комбинации (keepTop 5 по метрике), фаза
`filters` — 2×2×2 = 8 комбинаций тумблеров поверх каждого выжившего набора.

Фиксированные константы (вне грида — не тюнятся, чтобы не переобучаться на
механике окна, как это уже случалось с прошлыми стратегиями):

| Константа | Значение | Смысл |
|---|---|---|
| `atrPeriod` | 14 | период ATR для стопа |
| `levelWindowDays` | 10 | глубина скользящего окна уровней, торговых дней MSK |
| `sessionOpenHour` | 10 | MSK: часы до этого — утренняя сессия, входов нет |
| `eveningStartHour` | 19 | MSK: часы от этого — вечерняя сессия, входов нет |
| `barsPerDayMax` | 17 | худший случай числа Hour1-баров в одном дне MSK (утро+основная+вечер); определяет `Lookback()` |

## Калибровка и walk-forward

```
go run ./cmd/backtest -ticker SBER -strategy smc -interval Hour1 -months 24 \
  -calibrate data/params/sber/smc_grid.json -train-months 12 -test-months 6 \
  -min-trades 10 -metric profit_factor
```

Для остальных тикеров — тот же вызов с `-ticker <T> -calibrate
data/params/<t>/smc_grid.json` (корзина: AFKS, GAZP, MDMG, NVTK, PLZL, RUAL,
SBER, YDEX — та же, что у ORB). `-basket` жёстко зашит под `momentum` и для
`smc` недоступен: pooled OOS собирается вручную из пер-тикерных отчётов
(`-out ./reports/<T>`), как это делалось для ORB.

## Критерий судьбы

Вердикт по спеке: **pooled OOS profit factor ≥ 1.5** при `min-trades ≥ 10` на
тикер — стратегия живёт, дефолты хардкодятся по тикерным пакетам. Ниже
планки — хороним, как ORB, и фиксируем результат в памяти/доке (не
дорабатываем дальше на том же ядре).
