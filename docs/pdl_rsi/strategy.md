# pdl_rsi — вход, когда часовой RSI ниже 30 и стохастик ниже 20 на одном часе

Стратегия (бэктест и live-гость), только лонг, таймфрейм **только 1h** (`-interval Hour1`, другие cmd/backtest отклоняет). Позиция переносится через ночь и выходные. Код: `internal/service/trading_strategy/pdl_rsi/strategy/core`, привязка к бэктесту — `internal/service/backtest/pdl_rsi_registry.go`. Спека первой версии (15m): `docs/superpowers/specs/2026-10-23-pdl-rsi-design.md`. Живой запуск (гость раннера счёта `rsi_pullback`, выключен по умолчанию) — [live.md](live.md).

RSI — Уайлдер с периодом `HourRSIPeriod` по закрытиям часовых свечей. Стохастик — медленный %K (`StochK`, `StochSmooth`; по умолчанию 14, 1): сырой %K за `StochK` баров, сглаженный средней за `StochSmooth`; %D — средняя %K за `StochD` (3), идёт только в причину входа. Гейт — %K ниже 20, порог зашит в ядро (`stochZone`); креста %K над %D и настраиваемого уровня нет. Сигналы — только по закрытым часовым свечам, покупка — по open следующей (`EntryAtNextOpen`).

## Вход

1. **Сигнал** — закрытый час, на котором RSI и стохастик внизу одновременно. Никто никого не ждёт: неважно, кто опустился первым, оба условия проверяются на одном и том же часе. Режимов два:
   - **без стохастика** (`StochK` 0): сигнал — час, на котором RSI пересёк `RSIArm` сверху вниз (предыдущий час той же даты МСК закрылся с RSI не ниже `RSIArm`, этот — ниже);
   - **со стохастиком**: RSI ниже `RSIArm` и %K ниже 20.

   Со стохастиком сигнал — каждый такой час, а не только первый: если вход на одном часе отсекли другие условия, следующий час, где RSI и стохастик всё ещё внизу, может купить. Пока позиция открыта, новых входов нет; после выхода, если оба всё ещё внизу, вход возможен снова.
2. **Условия на часе сигнала:**
   - RSI часа сигнала не ниже `RSIFloor` — слишком глубокий провал не покупаем;
   - тренд: close часа сигнала строго выше прогретой EMA(`TrendEMA`) по часовым закрытиям;
   - необязательные фильтры (по умолчанию выключены): объём часа сигнала, запас хода дня на часе сигнала (см. таблицу);
   - свеча покупки (следующий час) лежит в ту же дату МСК, день — Пн–Пт и биржевой (см. «Неторговые будни»).
3. **Стоп и цель** — стоп `StopATR` дневных ATR (Уайлдер `DailyATRPeriod` по дневкам Пн–Пт, замороженный на сигнале) ниже цены покупки, но не дальше `MaxStopPct` процентов от цены (при большом ATR стоп подтягивается к этому потолку), цель — `TargetR` стопов выше неё. Сигнал несёт оба уровня от close часа сигнала для риск-сайзинга (`-risk-pct`), позиция пересчитывает их от цены покупки.

**Фильтр объёма** сравнивает объём часа сигнала со средним `VolBars` часов основной сессии (10:00–18:00 МСК, Пн–Пт биржевые даты) до него. Если этот час не из основной сессии, фильтр не пропускает вход.

**Неторговые будни.** В биржевой будний день первая часовая свеча начинается в 06:00 МСК. В будний праздник биржи (например, 31 декабря, 2 и 7 января) идут только дилерские сделки: свечи с 02:00, дневной свечи нет. Будняя дата, первая свеча которой в окне начинается раньше 06:00, считается неторговой: входов в неё нет, а её часы не попадают в базу `VolBars`. Выходные обрабатываются как выходные.

## Выход

По приоритету на каждом часе:

1. **SL** — `low ≤ стоп`; движок исполняет по `min(стоп, open)`.
2. **TP** — `high ≥ цель`; движок исполняет по `max(цель, open)`.
3. **RSI** — часовой RSI пересёк `RSIExit` сверху вниз (вышел из верхней зоны): продажа по close часа, причина `RSI`. Вход в зону снизу вверх выхода не даёт.
4. **RSITR — лесенка RSI** (по умолчанию выключена, `RSITrailFrom` 0). Ступени — от `RSITrailFrom` до `RSITrailTo` через `RSITrailStep`. Берётся наивысшая ступень, которой часовой RSI достиг на закрытом часе позиции, считая от часа покупки. Выход — по close часа, на котором RSI пересёк вниз уровень «эта ступень − `RSITrailStep`». При 50/70/10: дошёл до 50 — выход при кресте 40 вниз, до 60 — 50, до 70 и выше — 60. Уровень только поднимается. Пик RSI до покупки не считается. С `RSIExit` 70 ступень 70 не успевает сработать: RSI, падая, пересекает 70 раньше 60, и позиция закрывается выходом `RSI`. Ступени 50 и 60 работают, если RSI до 70 не дошёл.

Выхода в конце дня нет. Позиция переносится через выходные: дилерские часы выходных — обычные свечи для выхода.

## Параметры (`core.Params`)

| поле | по умолчанию | смысл |
|---|---|---|
| `HourRSIPeriod` | 6 | период часового RSI; 0 — входов нет |
| `RSIArm` | 30 | RSI часа сигнала ниже этого (без стохастика — крест через это вниз) |
| `RSIFloor` | 22 | нет входа, если RSI часа сигнала ниже этого; 0 — без ограничения |
| `RSIExit` | 70 | крест часового RSI вниз (выход из верхней зоны) — выход; 0 — RSI-выхода нет |
| `RSITrailFrom` | 0 | первая ступень лесенки RSI; 0 — лесенка выключена |
| `RSITrailTo` | 70 | верхняя ступень лесенки |
| `RSITrailStep` | 10 | шаг ступеней; уровень выхода — ступень минус шаг |
| `StochK` | 14 | длина сырого %K; 0 — стохастик выключен, сигнал — крест RSI вниз |
| `StochSmooth` | 1 | сглаживание %K (1 — быстрый %K); 0 — стохастик выключен |
| `StochD` | 3 | длина %D (средняя %K); на гейт не влияет, пишется в причину входа |
| `VolumeMult` | 0 | объём часа сигнала выше `VolumeMult` × среднего `VolBars` часов основной сессии до него; 0 — фильтра нет |
| `VolBars` | 20 | длина базы объёма, часов |
| `MinRoomATR` | 0 | на часе сигнала должно оставаться столько дневных ATR хода вверх (лой дня + ATR − close); 0 — фильтра нет |
| `StopATR` | 0.5 | стоп — столько дневных ATR ниже цены покупки; 0 — входов нет |
| `MaxStopPct` | 0 | потолок стопа — не дальше этого процента от цены, как бы ни был велик ATR; цель считается от урезанного стопа; 0 — без потолка |
| `TargetR` | 2 | цель — столько стопов выше цены покупки; 0 — цели нет |
| `TrendEMA` | 200 | close часа сигнала строго выше EMA этого периода (EMA не прогрета — входа нет); 0 — фильтра нет |
| `DailyATRPeriod` | 14 | период дневного ATR |

Частичный JSON параметров ложится поверх дефолтов ядра (или литерала тикера, когда он заведён в `pdlRSIRegistry`).

## Запуск

```
go run ./cmd/backtest -ticker NVTK -strategy pdl_rsi -interval Hour1 -months 12 -risk-pct 1 -out ./reports/NVTK
```

Калибровка — скользящий walk-forward по стартовой сетке `data/params/pdl_rsi/grid_example.json`. Режима `-explain` у стратегии нет.
