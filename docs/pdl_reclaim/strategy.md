# pdl_reclaim — возврат над PDL и удержанный пробой PDH на 15m

Бэктест-стратегия, только лонг. Прогон **только на 15m** (`-interval Minutes15`, другие таймфреймы cmd/backtest отклоняет). Уровни — лой (PDL) и хай (PDH) вчерашнего буднего дня. Сетап у уровня — возврат над PDL после пробоя вниз или пробой PDH на объёме. Возврат над PDL покупается сразу, пробой PDH — после `HoldBars` свечей с закрытием не ниже хая. Подтверждение возврата зелёной гистограммой MACD удалено 2026-10-19: на GAZP вход без него был лучше во всех точках перебора (ожидание сдвигало вход вверх при той же цели); версия с MACD — в git-истории. Проверены и удалены 2026-10-19: объём под PDL, рывок свечи возврата и структурный стоп за минимумом провала — ни один не дал прироста на GAZP и SBER, структурный стоп снижал долю прибыльных сделок с ~85% до ~30–55% (сетки `sweep_confirm.json`, `sweep_structstop.json`, код — в git-истории). Позиция переносится через ночь и выходные (с 2026-10-19): закрывается только по стопу или цели. Код: `internal/service/trading_strategy/pdl_reclaim/strategy/core`, привязка к бэктесту — `internal/service/backtest/pdl_reclaim_registry.go`. Спека первой версии: `docs/superpowers/specs/2026-10-15-pdl-reclaim-design.md`. Прежние версии — 5m/30m с RSI-гейтом и 15m с формациями A/B/C и выходом по MACD — заменены 2026-10-16 и лежат в git-истории.

## Уровни

- **PDL / PDH** — low и high последней завершённой будней дневки (выходные дневки отброшены; в понедельник это пятница). Дневка биржевая — со всеми сессиями дня.
- **Дневной ATR** — Уайлдер `DailyATRPeriod` по завершённым будним дневкам; уходит в сигнал и замораживается на позицию.
- Нет дневок для уровней или ATR — входов нет.

## Сетап

Свечи сетапа ищутся в ту же дату, что и текущая.

- **Возврат над PDL** (`EntryPDL = 1`): свеча зелёная и закрылась выше PDL; если идти от неё назад по свечам той же даты, красная свеча с close ниже PDL встречается раньше любой свечи с close выше PDL. То есть был пробой лоя красной свечой с закрытием под ним, и это первое зелёное закрытие обратно над лоем. Между пробоем и возвратом может быть сколько угодно свечей под лоем. Прокол лоя тенью без красного закрытия под ним сетапом не считается.
- **Пробой PDH** (`EntryPDH = 1`): свеча зелёная, close > PDH, предыдущая свеча той же даты закрылась не выше PDH — первое закрытие над вчерашним хаем. Объём свечи пробоя строго больше `VolumeMult ×` среднего объёма `VolBars` предыдущих 15m свечей основной сессии (сама свеча в среднее не входит). В среднее идут только будние свечи с 10:00 по 18:30 МСК: утренняя и вечерняя сессии, свеча закрывающего аукциона 18:45 и выходные пропускаются, окно уходит назад за них к прошлым дневным свечам — иначе тонкие ночные свечи занижают среднее и утренний пробой проходит фильтр почти всегда. Сама свеча пробоя может быть любой из окна входа: утренняя свеча сравнивается с дневным средним. Меньше `VolBars` дневных свечей в истории или нет объёмов — сетапа нет; `VolumeMult = 0` выключает фильтр.

Если на одной свече подтверждены и пробой PDH, и возврат над PDL, побеждает пробой.

## Вход

Свеча-триггер ищется на текущей свече без открытой позиции.

**Пробой PDH — удержание.** Свеча за `HoldBars` свечей до текущей, в ту же дату, — пробой PDH с объёмом, и ни одна свеча после неё до текущей включительно не закрылась ниже PDH (`close < PDH`; закрытие ровно на PDH удержание не рвёт). Тогда текущая свеча — триггер. Закрытие ниже PDH во время ожидания сжигает пробой; следующее закрытие над PDH — новый пробой (при объёме), и ожидание начинается заново. Через полночь ожидание не переходит. `HoldBars = 0` — покупка сразу после свечи пробоя; `HoldBars < 0` — входов по PDH нет. Свеча, завершившая удержание вне окна, сжигает пробой.

**Возврат над PDL — сразу.** Свеча возврата и есть триггер: покупка по open следующей свечи. Возврат, пришедшийся вне окна входа, сгорает — следующие свечи его не подхватывают.

Вход на свече-триггере, если:

- будни МСК, текущая свеча начинается не раньше `EntryFromHour:EntryFromMinute` (07:00), свеча покупки (следующая 15m) — раньше `EntryToHour:EntryToMinute` (18:00) в ту же дату;
- close текущей свечи ниже цели;
- стоп `close − StopDailyATR · ATR` выше нуля;
- запас хода (`MaxDayRangeATR > 0`): диапазон дня — `max(high) − min(low)` свечей даты триггера с первой свечи дня по триггер включительно — меньше `MaxDayRangeATR · ATR`. День, уже прошедший свой средний ход, редко доходит до цели после возврата;
- тренд индекса (`IndexTrendEMA > 0`): EMA(`IndexTrendEMA`) дневных закрытий IMOEX (будни, только даты раньше даты триггера) ниже своего значения 5 дневок назад — рынок падает. Возврат над PDL на растущем рынке — слабость самой бумаги, на падающем — общая волна продаж, после которой отскок к середине диапазона естественнее. Нет дневок индекса или их меньше `IndexTrendEMA + 5` — входа нет. Движок отдаёт стратегии только дневки тикера, поэтому дневки IMOEX cmd/backtest грузит сам и прикрепляет к стратегии при сборке (`backtest.PDLReclaimWithIndex`, `core.Strategy.WithIndex`).

**Цель** — уровень сетапа плюс половина вчерашнего диапазона: у возврата над PDL это середина `(PDL + PDH) / 2`, у пробоя PDH — `PDH + (PDH − PDL) / 2`.

Покупка по open следующей 15m свечи (`Config.EntryAtNextOpen`, `FillBy` = время текущей свечи + 15m). Сигнал несёт стоп (для `-risk-pct`), цель и ATR; `Level` — уровень сетапа. После выхода перевход в тот же день разрешён.

## Выход

По приоритету на каждой 15m свече:

1. **SL** — `low ≤ вход − StopDailyATR · ATR` (стоп от цены исполнения, ATR замороженный). Исполнение `min(стоп, open)`.
2. **TP** — `high ≥ цели` (заморожена на входе). Исполнение `max(цель, open)`. Стоп и цель в одной свече — стоп.

Выхода по времени нет: позиция держится через ночь и выходные, пока не сработает стоп или цель. Гэп открытия через стоп исполняется по open (`min(стоп, open)`).

## Параметры

| поле | по умолчанию | смысл |
|---|---|---|
| `EntryPDL` | 1 | сетап «возврат над PDL»; 0 — выключен |
| `EntryPDH` | 1 | сетап «пробой PDH на объёме»; 0 — выключен |
| `HoldBars` | 1 | сколько свечей после пробоя PDH все закрытия не ниже PDH до покупки; 0 — сразу после пробоя; < 0 — входов по PDH нет |
| `StopDailyATR` | 0.5 | стоп ниже входа в дневных ATR; 0 — входов нет |
| `DailyATRPeriod` | 14 | длина дневного ATR Уайлдера по будням |
| `EntryFromHour` / `EntryFromMinute` | 7 / 0 | свеча-триггер не раньше |
| `EntryToHour` / `EntryToMinute` | 18 / 0 | свеча покупки раньше |
| `VolumeMult` | 1.5 | объём свечи пробоя PDH выше этого × средний объём; 0 — фильтр выключен |
| `VolBars` | 20 | число предыдущих свечей основной сессии (10:00–18:30 МСК, будни) в среднем объёма |
| `MaxDayRangeATR` | 0 | вход, только если диапазон дня до триггера меньше этого × дневной ATR; 0 — фильтр выключен |
| `IndexTrendEMA` | 0 | вход, только пока EMA этого периода дневных закрытий IMOEX ниже значения 5 дневок назад; 0 — фильтр выключен |

`Lookback = (⌈VolBars / 35⌉ + 2) · 68 + 68` 15m свечей при включённом фильтре объёма, иначе 68; 68 — свечи от 07:00 до 23:45, 35 — свечи основной сессии; два лишних дня покрывают выходные между сессиями. При дефолтах 272.

## Пакеты тикеров

Реестр `pdlReclaimRegistry` держит по одному литералу `Params()` на тикер (`internal/service/trading_strategy/pdl_reclaim/strategy/<ticker>/`); тикер без пакета работает на `core.DefaultParams()`; JSON `-params` / `-calibrate` ложится поверх. Стартовая сетка — `data/params/pdl_reclaim/grid_example.json`.

## Вселенная для live

Живого раннера нет; вселенная под него — `PDL_RECLAIM_TICKERS_M15` (`config.PDLReclaimConfig`). Тест `TestPDLReclaimLiveTickersAreRegistered` требует пакет в `pdlReclaimRegistry` у каждого тикера из `env/prod.env`.

## Запуск

```bash
go run ./cmd/backtest -strategy pdl_reclaim -interval Minutes15 -ticker GAZP -months 12
go run ./cmd/backtest -strategy pdl_reclaim -interval Minutes15 -ticker GAZP -months 12 \
  -calibrate data/params/pdl_reclaim/grid_example.json -metric profit_factor
# почему на свече был (или не был) вход/выход
go run ./cmd/backtest -strategy pdl_reclaim -interval Minutes15 -ticker GAZP -months 12 -explain "2026-09-03 10:00"
```
Окно бэктеста и калибровки — 12 месяцев (`-months 12`); три года не нужны. Для калибровочных прогонов — собранный бинарь на одном ядре.
