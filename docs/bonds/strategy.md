# Стратегия Bonds — подбор облигаций по доходности

## Назначение

Стратегия `internal/service/trading_strategy/bonds` не торгует автоматически, а выступает
**скринером облигаций**: периодически проходит по всему списку облигаций Tinkoff Invest,
отбирает подходящие бумаги, считает по каждой доходность к погашению (с учётом налогов),
выбирает топ‑10 в каждой категории и присылает отчёт в Telegram.

Бумаги разбиваются на **4 категории** одновременно (4 параллельных конвейера):

| # | Тип | Срок до погашения | Критерий сортировки топ‑10 |
|---|-----|-------------------|----------------------------|
| 1 | ОФЗ / Региональные | 180 дней – 2 года   | Чистая доходность/год (`PercentByYear`) |
| 2 | ОФЗ / Региональные | 2 – 6 лет           | Чистая доходность/год (`PercentByYear`) |
| 3 | ОФЗ / Региональные | 6 – 16 лет          | Купонная доходность/год (`CouponPercentByYear`) |
| 4 | Корпоративные       | 180 дней – 3 года   | Чистая доходность/год (`PercentByYear`) |

> Для длинных бумаг (срок ≥ 6 лет) сортировка идёт по **купонной** доходности, для
> остальных — по **чистой** доходности к погашению. См. `pipeline/sender.go`.

---

## Архитектура: конвейер (pipeline)

Точка входа — `service.Trade(ctx)` (`trade.go`). Сначала одним запросом загружается весь
список облигаций (`InstrumentsServiceClient.Bonds`), затем для каждой из 4 категорий
запускается отдельная goroutine с конвейером из трёх стадий, соединённых каналами:

```
Bonds()  ──►  Finder  ──►  CalculateProfit  ──►  Sender  ──►  Telegram
            (фильтрация)   (расчёт доходности)  (сортировка,
                                                 топ-10, отправка)
```

Все 4 конвейера работают параллельно и синхронизируются через `sync.WaitGroup`;
`Trade` завершается, когда все категории отправили свои сообщения.

Каждый конвейер использует собственный `doneCh chan struct{}` для досрочной остановки:
если на стадии расчёта возникает ошибка, канал закрывается и все стадии этого конвейера
завершаются (паттерн cancellation).

### Стадия 1 — Finder (`pipeline/finder.go`)

Генератор, отдающий в канал только подходящие облигации. Бумага **пропускается**, если:

- срок погашения вне окна категории: `dateTo < MaturityDate` или `dateFrom > MaturityDate`;
- у бумаги плавающий купон (`FloatingCouponFlag`);
- у бумаги есть амортизация номинала (`AmortizationFlag`);
- НКД равен нулю (`Nkd == 0`);
- категория ОФЗ (`isOfz == true`), но имя **не** содержит `ОФЗ` и не содержит `Реги`;
- категория корпоративных (`isOfz == false`), но имя содержит `ОФЗ` или `Реги`.

Тип бумаги определяется регулярными выражениями по полю `Name`: `ОФЗ` или `Реги`(ональные)
→ государственные/региональные; всё остальное → корпоративные.

> Между обработкой бумаг стоит `time.Sleep(100 * time.Millisecond)` — это троттлинг,
> чтобы не упереться в лимиты API при последующих запросах свечей/купонов.

### Стадия 2 — CalculateProfit (`pipeline/calculate_profit.go` + `computable/calculate_profit.go`)

Для каждой пришедшей облигации:

1. Запрашиваются дневные свечи за последние 20 дней (`GetCandles`, интервал `Day1`,
   `limit = 10`); берётся **цена закрытия последней свечи** как текущая рыночная цена.
   Если свечей нет — бумага пропускается с ошибкой.
2. Запрашиваются купоны с начала текущего года до даты погашения (`GetBondCoupons`).
3. Вызывается чистая функция `calculateProfit(...)`, которая считает доходность.

При ошибке расчёта закрывается `doneCh` — конвейер этой категории останавливается.

### Стадия 3 — Sender (`pipeline/sender.go`)

Собирает все `BondReport` из канала в коллекцию. Если коллекция пуста — выходит молча.
Иначе сортирует и берёт топ‑10 (`GetTopByCriteria`):

- если до конца окна категории ≥ 6 лет — по `CouponPercentByYear` (убыв.);
- иначе — по `PercentByYear` (убыв.).

Результат форматируется (`notification.Send`) и отправляется в Telegram.

## Формула расчёта доходности

Реализована в `computable/calculate_profit.go` → `calculateProfit`. Все денежные величины — в рублях.

### Исходные данные

- `Nominal` — номинал облигации;
- `Nkd` — накопленный купонный доход (то, что доплачиваешь продавцу при покупке);
- `CouponQuantityPerYear` — число купонных выплат в год;
- последняя цена закрытия `closePrice` — в **процентах от номинала** (биржевая котировка);
- купоны с начала года до погашения (дата + сумма выплаты).

### Промежуточные суммы по купонам

```
totalFutureCoupons  = Σ купонов, дата которых > сейчас      // все будущие купоны до погашения
currentYearCoupons  = Σ купонов, выплаченных в текущем году  // для оценки годовой купонной доходности
```

### Цена и вложение

```
bondPrice        = closePrice * Nominal / 100   // цена бумаги в рублях из котировки в %
totalInvestment  = bondPrice + Nkd              // полная сумма покупки (цена + НКД)
```

### Купонная доходность за год

```
annualCouponIncome = currentYearCoupons                          // если в этом году купоны были
                   | купон[0] * CouponQuantityPerYear            // иначе — оценка по первому купону
couponPercentByYear = annualCouponIncome * 100 / totalInvestment  // % годовых по купонам
```

### Налоги (НДФЛ 13%)

```
couponTax       = max( (totalFutureCoupons - Nkd) * 0.13, 0 )    // налог на купоны; НКД вычитается,
                                                                 // т.к. он уже оплачен при покупке
nominalPriceTax = (Nominal - bondPrice) * 0.13   если bondPrice < Nominal, иначе 0
                                                                 // налог на доход от роста цены к номиналу
```

### Итоговая прибыль и доходность

```
totalReturn   = Nominal + totalFutureCoupons                     // что вернётся: номинал + будущие купоны
finalProfit   = totalReturn - totalInvestment - couponTax - nominalPriceTax  // чистая прибыль за весь срок

daysToMaturity = max( дней до погашения, 1 )
profitPerYear  = finalProfit * 365 / daysToMaturity              // прибыль, приведённая к году, ₽
percentByYear  = 100 * profitPerYear / totalInvestment           // чистая доходность, % годовых
```

### Что попадает в отчёт (`factory/bond_report.go` → `domain.BondReport`)

| Поле | Смысл | Округление |
|------|-------|------------|
| `Name` | Название бумаги | — |
| `FinalSum` (`finalProfit`) | Чистая прибыль к погашению, ₽ | до 0.1 |
| `ManyByYear` (`profitPerYear`) | Прибыль в год, ₽ | до 0.1 |
| `PercentByYear` | Чистая доходность, % годовых | до 0.1 |
| `CouponPercentByYear` | Купонная доходность, % годовых | до 0.1 |
| `Nkd` | НКД при покупке, ₽ | до 0.01 |
| `ExecutionDate` (`MaturityDate`) | Дата погашения | — |
| `Type` | `ОФЗ` или `Корпоративная` (по regexp имени) | — |

> Тип в фабрике определяется повторно: имя с `ОФЗ`/`Реги` → `OfzBondEnum`, иначе `CorpBondEnum`.

## Формат уведомления (`notification/telegram.go`)

Сообщение в HTML‑разметке Telegram:

- заголовок `📊 Облигации` и период категории (`dateFrom – dateTo`);
- тип облигаций (`ОФЗ` / `КОРПОРАТИВНАЯ`) в верхнем регистре;
- пронумерованный список топ‑10 бумаг, по каждой:
  - 💰 чистая доходность/год (`PercentByYear`);
  - 🎯 купонная доходность/год (`CouponPercentByYear`);
  - 📈 прибыль/год в ₽ (`ManyByYear`);
  - 💳 НКД в ₽;
  - 💵 доходность к погашению в ₽ (`FinalSum`);
  - ⏰ дата погашения;
- футер с отметкой времени актуальности данных.

Вспомогательные функции: `htmlEscape` (экранирование `& < >`), `formatPercent`
(1 знак после запятой + `%`), `formatMoney` (разделитель тысяч пробелом для длинных чисел).

## Запуск и расписание

- **dev** (`APP_ENV=dev`): воркер запускается как goroutine напрямую.
- **prod**: через cron‑планировщик `pkg/scheduler` (`scheduler/trade.go`).
  Расписание — `0 */10 * * *`, т.е. **каждые 10 часов** в нулевую минуту.

> ⚠️ В логах планировщика осталась строка `"Воркер Golden RSI начал работу"` — это
> копипаст из другой стратегии, к Bonds отношения не имеет.

## Ограничения и нюансы

- Стратегия **не выставляет ордера** — это аналитический отчёт для ручного решения.
- Сознательно **исключаются** бумаги с плавающим купоном и амортизацией: для них формула
  «номинал + фиксированные будущие купоны» неверна.
- Текущая цена берётся из последней дневной свечи, а не из стакана — возможна неактуальность
  на неликвидных бумагах.
- Налоговая модель упрощённая (НДФЛ 13% без учёта прогрессивной шкалы, ЛДВ, вычетов ИИС).
- `GetBondCoupons` запрашивается с начала календарного года — прошлые купоны года нужны
  только для оценки годовой купонной доходности; в `finalProfit` входят лишь будущие купоны.
