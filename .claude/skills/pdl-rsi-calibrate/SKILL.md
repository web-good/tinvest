# pdl_rsi: пошаговая калибровка тикера

Аргументы: `<TICKER> [заметки владельца]`. Владелец ждёт вердикт, а не меню: сам гоняешь, сам решаешь,
доводишь до литерала тикера, в конце не больше одного вопроса. Механика стратегии описана в
`docs/pdl_rsi/strategy.md`. Скрипт лежит в `.claude/skills/pdl-rsi-calibrate/scripts/steps.py`, запускай
`python3 -I` (ниже `S`).

**Почему по шагам.** Полная сетка по 19 параметрам — это тысячи точек при ~7 сделках в год. Максимум
такой сетки — шум, и соседних точек для плато не видно. Поэтому калибровка идёт покоординатным
спуском: на каждом шаге перебирается одна группа связанных параметров, всё остальное прибито к
точке, выбранной раньше. Каждый шаг — 3–48 точек, и у каждой есть соседи.

**Нарушить букву правила — значит нарушить его дух.**

## Порядок шагов и почему он такой

| # | Шаг | Оси | Зачем здесь |
|---|---|---|---|
| 1 | signal | `HourRSIPeriod` 4/5/6/8 × `RSIArm` 25/30/35 | что считается сетапом; больше всего влияет на число сделок |
| 2 | trigger | `StochK` 5/10/14 × `StochBars` 2/4/6 × `StochCrossMax` 0/30/40/50 | вход внутри сетапа |
| 3 | trend | `TrendEMA` 0/100/150/200 | фильтры по одному: каждый срезает сделки и должен окупиться |
| 4 | floor | `RSIFloor` 0/15/20/22 | |
| 5 | trigmax | `RSITriggerMax` 0/40/50 | |
| 6 | volume | `VolumeMult` 0/0.5/0.8/1.2 | |
| 7 | room | `MinRoomATR` 0/0.3/0.6 | |
| 8 | risk | `StopATR` 0.3/0.5/0.7/1.0 × `TargetR` 1.5/2/3 × `MaxStopPct` 0/1/1.5 | стоп и цель подбираются на итоговом наборе сделок, а не на сырых |
| 9 | exits | `RSIExit` 0/65/70/75 × `StochExitAbove` 0/40/60 | мягкие выходы на найденных входах |
| 10–12 | signal2, trigger2, risk2 | те же оси, что у шагов 1, 2, 8 | второй проход: после фильтров оптимум сигнала и стопа мог сдвинуться |

- **Старт открытый** (`steps.py init`): дефолты ядра, все фильтры и необязательные выходы выключены
  (`TrendEMA`, `RSIFloor`, `RSITriggerMax`, `VolumeMult`, `MinRoomATR`, `StochExitAbove`, `MaxStopPct` = 0).
  Так шаги 1–2 видят самую большую выборку. Стоп 0.5 ATR, цель 2R и выход по RSI 70 стоят до шага 8.
- **Не калибруются:** `StochSmooth` 3, `StochD` 3, `VolBars` 20, `DailyATRPeriod` 14.
- **Выбор на шаге** (`steps.py pick`): к выбору допускаются точки с ≥ 20 сделками за 36 месяцев. Каждая
  точка получает оценку — медиану PF её самой и соседей (шаг по одной оси). Точка двигается к лучшему
  центру, **только если его медиана выше текущей точки на 5%**. Иначе точка остаётся, и для фильтра это
  значит «выключен». Текущее значение всегда есть в сетке шага. Так шум в 2–3% не тащит точку.
- `ОСТРЫЙ ПИК` на шаге не останавливает спуск: вердикт выносит walk-forward. В итоге пик упоминается.

## 0. Правила каждого прогона

- Окно **36 месяцев**, `-interval Hour1`, `-risk-pct 1`, метрика `profit_factor`. Команду печатает `steps.py grid`.
- **Одно ядро**: собранный бинарь, `taskset -c 0 nice -n 19 env GOMAXPROCS=1`, без `go run`, прогоны строго
  последовательно, долгие — в фоне (`run_in_background`).
  ```bash
  mkdir -p reports/pdl_rsi_cal && GOMAXPROCS=1 nice -n 19 go build -o reports/pdl_rsi_cal/backtest ./cmd/backtest
  ```
  Пересобирай бинарь после каждой правки ядра, литерала или реестра.
- Сетки генерирует только `steps.py`; каждая прибивает все поля Params (JSON ложится поверх литерала тикера).
  Файлы шагов лежат в `data/params/pdl_rsi/<t>/cal/`, текущая точка — в `cal/point.json`, отчёты — в `reports/<T>_pdl_rsi/<шаг>/`.
- **Сбой API** (`unexpected EOF`, `DeadlineExceeded`, DNS) не считается результатом: перезапусти тот же прогон, до трёх раз.
- Оси и порядок шагов меняет только владелец.

## 1. Пакет тикера

Если `internal/service/trading_strategy/pdl_rsi/strategy/<ticker>/` нет, заведи его сразу. Литерал `Params()` —
явно выписанные `core.DefaultParams()`, тест `TestLiteralIsPinned` со снимком, строка в `pdlRSIRegistry`
(`internal/service/backtest/pdl_rsi_registry.go` и его тест), тикер в списке pdl_rsi в `CLAUDE.md`.
Затем `go test ./internal/service/backtest/ ./internal/service/trading_strategy/pdl_rsi/...` должен быть зелёным.

## 2. База — литерал как есть

```bash
taskset -c 0 nice -n 19 env GOMAXPROCS=1 reports/pdl_rsi_cal/backtest -ticker <T> -strategy pdl_rsi -interval Hour1 -risk-pct 1 -months 36 -out reports/<T>_pdl_rsi/base
```
PF и сделки базы нужны, чтобы в итоге сравнить с ними найденную точку.

## 3. Шаги

```bash
python3 -I $S init <T>                       # один раз; если cal/point.json уже есть — steps.py status <T>
python3 -I $S grid <T> <шаг>                 # печатает файл сетки и команду
<команда>                                    # в конце печатает путь calibration.md
python3 -I $S pick <T> <шаг> <calibration.md>
```
Повторяй для всех 12 шагов по порядку. Скрипт не даст пропустить шаг или выбрать шаг дважды. Продолжение
в новом окне начинается с `steps.py status <T>`: он печатает пройденные шаги и следующую команду.

## 4. Вердикт — скользящий walk-forward

```bash
python3 -I $S wf <T>          # cal/wf_rolling.json: точка ± один шаг по HourRSIPeriod, StopATR, TargetR (≤ 27 точек)
<команда>                     # -train-months 3 -test-months 1 -min-trades 3
python3 -I $S verdict <_walkforward.md>
```
Судят по пулу OOS: **ГОДЕН** — PF ≥ 1.2, net > 0, ≥ 10 сделок. In-sample PF фолдов не считается.
3 месяца подбора — это 1–3 сделки: фолды выбирают почти наугад. Поэтому walk-forward проверяет,
держится ли окрестность точки вне выборки, а не выбирает точку.

## 5. Литерал и запись

- `Params()` = `cal/point.json` (`steps.py literal <T>` печатает поля). Это делается и при ГОДЕН, и при НЕ ГОДЕН: вердикт
  записывается в doc-комментарий, а не в литерал.
- Обнови снимок в `<ticker>_test.go`; `go test` из §1 должен быть зелёным; пересобери бинарь.
- Финальный прогон: `-months 36 -out reports/<T>_pdl_rsi/final` без `-params` (литерал вшит), PF и сделки сравни с базой §2.
- Doc-комментарий пакета (по-русски): дата, «пошаговая калибровка», точка, результат каждого шага одной строкой
  (из `_steps` в `point.json`), база и финал, пул OOS, решение. `docs/pdl_rsi/` описывает только механику и не трогается.
- Не коммить, пока владелец не попросил.

## 6. Итог владельцу

Одна таблица: шаг — выбор — PF/сделки — сдвинулась ли точка. Под ней: база и финал на 36 месяцах, пул OOS и
вердикт, острые пики, если были. Не больше одного вопроса.

## Красные флаги — остановись

| Мысль | Что на самом деле |
|---|---|
| «Сведу все оси в одну сетку — так найдём совместный оптимум» | Тысячи точек на ~7 сделках в год — максимум шума. Для этого и нужны шаги. |
| «На шаге выиграла точка с PF 3 на 8 сделках» | Без 20 сделок точка не участвует в выборе. |
| «Лучший центр выше на 3% — сдвину» | Порог 5% нужен, чтобы шум не тащил точку. Точка остаётся. |
| «Фильтр поднял PF, но срезал сделки ниже 20 — включу» | Ниже 20 сделок фильтр не участвует, остаётся выключенным. |
| «Вернусь к шагу 3 и переберу снова» | Повторный проход — только шаги 10–12. Третий заход на те же данные — подгонка. |
| «Walk-forward НЕ ГОДЕН — расширю сетку WF / сменю оси» | Вердикт окончательный. Литерал = точка, решение — «не годен». |
| «Начну с литерала владельца вместо открытого старта» | Старт открытый: литерал владельца — база §2 для сравнения. |
| «Добавлю ось / значение — так будет лучше» | Оси меняет только владелец. |
| «Запущу два бэктеста параллельно» | Одно ядро, строго последовательно. |
| «Литерал поправил — проверю старым бинарём» | Сначала пересобери бинарь. |
