# pdl_rsi: пошаговая калибровка тикера

Аргументы: `<TICKER> [заметки владельца]`. Владелец ждёт вердикт, а не меню: сам гоняешь, сам решаешь,
доводишь до литерала тикера, в конце не больше одного вопроса. Механика стратегии описана в
`docs/pdl_rsi/strategy.md`. Скрипт лежит в `.claude/skills/pdl-rsi-calibrate/scripts/steps.py`, запускай
`python3 -I` (ниже `S`).

**Почему по шагам.** Полная сетка по 18 параметрам — это тысячи точек при ~7 сделках в год. Максимум
такой сетки — шум, и соседних точек для плато не видно. Поэтому калибровка идёт покоординатным
спуском: на каждом шаге перебирается одна группа связанных параметров, всё остальное прибито к
точке, выбранной раньше. Каждый шаг — 3–72 точки, и у каждой есть соседи.

**Цель стратегии — консервативность** (решение владельца 2026-10-26). Нужно много прибыльных сделок,
пусть мелких, и мало убыточных, тоже с мелкими минусами. Поэтому выход по RSI обязателен всегда:
позиция закрывается, когда часовой RSI пересёк `RSIExit` сверху вниз (вышел из верхней зоны), даже если
цель ещё не взята. Плюс получается мельче, зато убыток по сделкам, которые развернулись бы до стопа, тоже меньше.
Владелец согласен платить за это частью PF. **`RSIExit` 0 запрещён**: его нет в сетке шага exits, и
`steps.py` откажется строить сетку, если в ней или в точке есть `RSIExit` 0. Литерал без выхода RSI
не пишется ни при каком PF. Вариант «без выхода RSI даёт PF выше» — не довод, а противоположность цели.

**Фильтр тренда обязателен** (решение владельца 2026-10-26). `TrendEMA` 0 запрещён в литерале: вход только
выше EMA. Шаги signal и trigger идут с `TrendEMA` 0 (открытый старт, самая большая выборка), а шаг trend
обязан выбрать один из периодов 100/150/200. Выключенное значение в его сетку не входит, правило 5% к нему
не применяется: точка всегда сдвигается к лучшему центру. После шага trend `steps.py` откажется строить
сетку, если в точке `TrendEMA` 0. `best` не берёт комбинации с `TrendEMA` 0 (отчёты шагов signal и trigger).

**Рынок меняется — у каждого тикера свои параметры, и они не вечные.** Цена каждой бумаги ходит
по-своему, и режим рынка со временем меняется. Поэтому:
- у каждого тикера свой литерал; параметры другого тикера не переносятся и не служат «общим знаменателем»;
- в walk-forward каждый фолд подбирает свои значения на своём окне. Разные значения по фолдам — ожидаемый
  ответ на смену рынка, а не признак нестабильной точки. Плохо не то, что фолды гуляют, а то, что пул OOS
  теряет деньги;
- литерал — снимок на сегодня; владелец периодически перекалибровывает тикер (§7).

**Нарушить букву правила — значит нарушить его дух.**

## Порядок шагов и почему он такой

| # | Шаг | Оси | Зачем здесь |
|---|---|---|---|
| 1 | signal | `HourRSIPeriod` 4/5/6/8 × `RSIArm` 25/30/35 | что считается сетапом; больше всего влияет на число сделок |
| 2 | trigger | `StochK` 14/13/12/11/10/9/8 × `StochSmooth` 1/2/3 (21 точка); без стохастика шага нет | длины стохастика гейта %K < 20 на том же часе |
| 3 | trend | `TrendEMA` 100/150/200 (0 запрещён, выбор обязателен) | фильтр тренда включён всегда; дальше фильтры по одному: каждый срезает сделки и должен окупиться |
| 4 | floor | `RSIFloor` 0/15/20/22 | |
| 5 | volume | `VolumeMult` 0/0.5/0.8/1.2 | |
| 6 | room | `MinRoomATR` 0/0.3/0.6 | |
| 7 | risk | `StopATR` 0.3/0.5/0.7/1.0 × `TargetR` 1.5/2/3 × `MaxStopPct` 0/1/1.5 | стоп и цель подбираются на итоговом наборе сделок, а не на сырых |
| 8 | exits | `RSIExit` 65/70/75 × `RSITrailFrom` 0/40/50/60 × `RSITrailStep` 10/15/20 × `RSITrailTo` 70/80 (72 точки) | мягкие выходы на найденных входах: выход из верхней зоны RSI (крест `RSIExit` вниз, с 2026-10-26; раньше — крест вверх) и лесенка RSI (с 2026-10-26) перебираются вместе — они мешают друг другу; `RSIExit` 0 запрещён (цель — консервативность, см. выше) |
| 9–11 | signal2, trigger2, risk2 | те же оси, что у шагов 1, 2, 7 | второй проход: после фильтров оптимум сигнала и стопа мог сдвинуться |

- **Старт открытый** (`steps.py init`): дефолты ядра, все фильтры и необязательные выходы выключены
  (`TrendEMA`, `RSIFloor`, `VolumeMult`, `MinRoomATR`, `MaxStopPct`, `RSITrailFrom` = 0).
  Стохастик — часть входа, а не фильтр: его режим задаёт вариант калибровки (ниже), а не шаг.
  Со стохастиком старт — правило владельца `StochK` 14, `StochSmooth` 1, `StochD` 3 (с 2026-10-26),
  без стохастика — `StochK` 0. Так шаги 1–2 видят самую большую выборку. Стоп 0.5 ATR, цель 2R и выход по RSI 70 (крест вниз — RSI вышел из верхней зоны) без лесенки стоят до шага 7.
- **Не калибруются:** `StochD` 3 (на гейт не влияет — с 20 сравнивается только %K, %D пишется лишь в причину входа), `VolBars` 20, `DailyATRPeriod` 14; порог %K 20 зашит в ядро. Лесенка RSI перебирается целиком на шаге exits (с 2026-10-26, решение владельца): первая ступень `RSITrailFrom`, шаг `RSITrailStep` и верх `RSITrailTo`; шаг задаёт и расстояние между ступенями, и отступ уровня выхода под ступенью (50/10/70: дошёл до 50/60/70 — выход на кресте 40/50/60 вниз; 50/20/70: дошёл до 50/70 — выход на 30/50; 40/20/80 — лесенка владельца для шага 20: дошёл до 40/60/80 — выход на 20/40/60). Ступень 40 и верх 80 введены ради шага 20, но сетка декартова, поэтому они перебираются и с шагами 10 и 15. При `RSITrailFrom` 0 остальные оси лесенки ни на что не влияют.
- **Выход RSI — крест вниз** (с 2026-10-26, решение владельца): позиция закрывается по close часа, на котором
  часовой RSI пересёк `RSIExit` сверху вниз, то есть вышел из верхней зоны, а не вошёл в неё. Литералы и
  калибровки до этой даты подбирались на кресте вверх — их шаг exits и всё, что после, устарели. С лесенкой:
  крест `RSIExit` вниз случается раньше креста «ступень − шаг», поэтому ступени не выше `RSIExit` + шаг
  при включённом `RSIExit` почти не срабатывают; работают нижние ступени, если RSI до `RSIExit` не дошёл.
- **Выбор на шаге** (`steps.py pick`): к выбору допускаются точки с ≥ 20 сделками за 36 месяцев. Каждая
  точка получает оценку — медиану PF её самой и соседей (шаг по одной оси). Точка двигается к лучшему
  центру, **только если его медиана выше текущей точки на 5%**. Иначе точка остаётся, и для фильтра это
  значит «выключен». Текущее значение всегда есть в сетке шага. Так шум в 2–3% не тащит точку.
- `ОСТРЫЙ ПИК` на шаге не останавливает спуск: вердикт выносит walk-forward. В итоге пик упоминается.

### Два режима входа — каждый калибруется отдельно, всегда

Режимы отличаются подтверждением стохастиком. Со стохастиком (с 2026-10-26) никто никого не ждёт: сигнал —
любой час, на котором часовой RSI ниже `RSIArm` и %K ниже 20 на том же часе. Порог 20 зашит в ядро
(`stochZone`), креста %K над %D нет, полей `StochBelow` и `StochCross` нет (решение владельца 2026-10-26).
Без стохастика сигнал — крест RSI через `RSIArm` вниз:

| Режим | Вход | Поля | Флаг `steps.py` | Файлы / отчёты |
|---|---|---|---|---|
| 1. без стохастика | крест RSI через `RSIArm` вниз | `StochK` 0 | `--no-stoch` | `cal_nostoch/`, `nostoch_<шаг>/` |
| 2. со стохастиком | час, где RSI ниже `RSIArm` и %K ниже 20 | `StochK` > 0 | нет | `cal/`, `<шаг>/` |

**Каждая калибровка тикера проходит оба режима целиком**: свои шаги с открытого старта, свой `best`,
свой walk-forward. Так решил владелец 2026-10-25: у каждого тикера свой режим, и выбирать его надо по
калибровке, а не по привычке (на MDMG уровень дал пул OOS 0.61 на 18 сделках за 36 мес, без стохастика — 1.32
на 158). Флаг режима ставится к **каждой** команде `steps.py`, кроме `verdict`. Скрипт откажется смешивать режимы;
флаг `--cross` он отвергает.

- Фильтры, стоп/цель и выход в каждом режиме подбираются заново под его входы. Нельзя взять литерал одного
  режима и включить или выключить в нём стохастик (`StochK`): фильтры подбирались под другие сделки.
- Без стохастика шаги trigger и trigger2 выкинуты (длины стохастика без гейта ни на что не влияют),
  остаётся 9 шагов; walk-forward свободен по `HourRSIPeriod`, `RSIArm`, `StopATR`, `TargetR` (≤ 81 точка).
- Со стохастиком 11 шагов, walk-forward свободен ещё по `StochK` (≤ 243 точки).

**Финальный выбор режима.** После обоих режимов в литерал идёт лучшая комбинация (§5) того режима, у
которого лучший вердикт §4: сначала ГОДЕН побеждает НЕ ГОДЕН, затем PF пула OOS, при равенстве — net. В итог
и doc-комментарий идут оба режима: шаги, лучшая комбинация, пул OOS, свежий год, выборы фолдов.

## 0. Правила каждого прогона

- Окно **36 месяцев**, `-interval Hour1`, `-risk-pct 1`, метрика `profit_factor`. Команду печатает `steps.py grid`.
- **Не больше трёх ядер**: собранный бинарь, `nice -n 19 env GOMAXPROCS=1`, без `go run`, долгие — в фоне
  (`run_in_background`). Три очереди: `taskset -c 0`, `-c 1` и `-c 2` (владелец разрешил 3 ядра 2026-10-25). Внутри очереди
  прогоны строго последовательно. Режимы входа независимы, поэтому каждый идёт в своей очереди:
  без стохастика на ядре 0, со стохастиком на ядре 1; ядро 2 — под walk-forward первого готового режима
  (в команде из `steps.py` заменить `-c 0` на нужное ядро).
  ```bash
  mkdir -p reports/pdl_rsi_cal && GOMAXPROCS=1 nice -n 19 go build -o reports/pdl_rsi_cal/backtest ./cmd/backtest
  ```
  Пересобирай бинарь после каждой правки ядра, литерала или реестра.
- Сетки генерирует только `steps.py`; каждая прибивает все поля Params (JSON ложится поверх литерала тикера).
  Файлы шагов лежат в `data/params/pdl_rsi/<t>/cal/`, текущая точка — в `cal/point.json`, отчёты — в `reports/<T>_pdl_rsi/<шаг>/`.
- **Сбой API** (`unexpected EOF`, `DeadlineExceeded`, `ResourceExhausted`, DNS) не считается результатом: перезапусти тот же
  прогон, до пяти раз, с паузой в минуту. `ResourceExhausted` — лимит запросов API; при нескольких очередях он бьёт чаще.
- Оси и порядок шагов меняет только владелец.

Если `internal/service/trading_strategy/pdl_rsi/strategy/<ticker>/` нет, заведи его сразу. Литерал `Params()` —

## 2. База — литерал как есть

```bash
taskset -c 0 nice -n 19 env GOMAXPROCS=1 reports/pdl_rsi_cal/backtest -ticker <T> -strategy pdl_rsi -interval Hour1 -risk-pct 1 -months 36 -out reports/<T>_pdl_rsi/base
```
PF и сделки базы нужны, чтобы в итоге сравнить с ними найденную точку.

## 3. Шаги

```bash
python3 -I $S init <T>                       # один раз; если cal/point.json уже есть — steps.py status <T>
                                             # режим: --no-stoch в каждой команде (со стохастиком — без флага)
python3 -I $S grid <T> <шаг>                 # печатает файл сетки и команду
<команда>                                    # в конце печатает путь calibration.md
python3 -I $S pick <T> <шаг> <calibration.md>
```
Повторяй для всех шагов по порядку (11; без стохастика — 9), затем то же для второго режима. Скрипт не даст пропустить шаг или выбрать шаг дважды. Продолжение
в новом окне начинается с `steps.py status <T>`: он печатает пройденные шаги и следующую команду.

## 4. Вердикт — скользящий walk-forward

```bash
python3 -I $S best <T>        # лучшая комбинация всей калибровки (§5) — она пойдёт в литерал; пишет "best" в point.json
python3 -I $S wf <T>          # cal/wf_rolling.json: лучшая комбинация ± один шаг по HourRSIPeriod, RSIArm, StochK, StopATR, TargetR (≤ 243 точки)
<команда>                     # -train-months 3 -test-months 1 -min-trades 3; долгий — в фоне
python3 -I $S verdict <_walkforward.md>
```
Walk-forward имитирует то, как тикер будет торговаться на деле: раз в месяц перекалибровка на последних
3 месяцах, торговля следующий месяц. Поэтому сигнал, триггер и стоп/цель в нём свободны: каждый фолд
выбирает свои значения из окрестности литерала (лучшей комбинации). Фильтры (EMA, объём, запас хода, пол RSI) и
выход прибиты к точке: на 1–3 сделках окна подбора их включение — чистый шум.

**ГОДЕН** — оба условия: пул OOS PF ≥ 1.2, net > 0, ≥ 10 сделок **и** последние 12 фолдов (свежий год)
вместе в плюсе с запасом: compounded > 0 и PF пула их OOS-сделок ≥ 1.1. Второе условие добавлено
2026-10-25 после MDMG: пул 36 месяцев PF 1.32 прошёл за счёт прибыльного 2024 года, а последний год тикер
терял. Прибыльное прошлое не делает тикер годным сегодня. Порог PF 1.1 добавлен 2026-10-26 после SVCB:
свежий год +1.5% — это ноль с учётом издержек, а не край. PF свежего года `verdict` считает по колонке
`OOS gross +/−` таблицы фолдов; отчёт без неё (старый бинарь) — пересобери и перезапусти walk-forward.
In-sample PF фолдов не считается. `verdict` печатает оба условия.
`verdict` печатает и выборы фолдов по каждой гулявшей оси (сколько фолдов выбрало какое значение и что
выбрал последний, самый свежий фолд). Отчёт сам называет одинаковые во всех фолдах параметры
«стабильными» — это не достоинство: если на свободной оси все фолды выбрали одно, значит, рынок этой оси
не различает.

## 5. Литерал и запись

- `Params()` = **лучшая комбинация всей калибровки** (`steps.py best <T>`, поля печатает `steps.py literal <T>`):
  наибольший PF среди комбинаций всех отчётов шагов с ≥ 10 сделками за 36 месяцев (при равенстве — больше сделок,
  затем net). Так решил владелец (2026-10-25, GAZP и MDMG): в литерал идёт лучшее, что нашла калибровка, даже ниже
  20 сделок, при которых спуск её не выбирал. Порог 10 — планка сделок walk-forward: ниже PF — пара удачных
  сделок. Точка спуска служит путём к этой комбинации и записывается в doc-комментарий рядом с ней.
- Это делается и при ГОДЕН, и при НЕ ГОДЕН: вердикт записывается в doc-комментарий, а не в литерал.
- Обнови снимок в `<ticker>_test.go`; `go test` из §1 должен быть зелёным; пересобери бинарь.
- Финальный прогон: `-months 36 -out reports/<T>_pdl_rsi/final` без `-params` (литерал вшит), PF и сделки сравни с базой §2.
- Doc-комментарий пакета (по-русски): дата, «пошаговая калибровка», результат каждого шага одной строкой
  (из `_steps` в `point.json`), точка спуска и лучшая комбинация (шаг, PF/сделки, чем отличается от точки),
  база и финал, пул OOS, решение. `docs/pdl_rsi/` описывает только механику и не трогается.
- В doc-комментарий идут и выборы фолдов из `verdict` одной строкой на ось, и дата калибровки: от неё
  считается срок следующей перекалибровки.
- Не коммить, пока владелец не попросил.

## 7. Перекалибровка

Владелец перекалибровывает тикеры периодически: рынок ушёл — параметры должны уйти за ним. Перекалибровка —
это тот же скилл с нуля на свежем окне 36 месяцев, а не подстройка старой точки:
- старую калибровку перенеси в `data/params/pdl_rsi/<t>/cal_<дата старой калибровки>/` (как историю; `cal_nostoch/` —
  в `cal_nostoch_<дата>/`, старый `cal_cross/` — в `cal_cross_<дата>/`), затем `steps.py init` в обоих режимах — открытый старт;
- база §2 — действующий литерал тикера; итог сравнивает новую точку с ним на одном и том же окне;
- новый литерал заменяет старый, даже если числа сильно разошлись: так и должно быть;
- в doc-комментарии пакета старые записи остаются, новая добавляется разделом с датой, а ссылки старых
  разделов переводятся на `cal_<дата>/`.

## Красные флаги — остановись

| Мысль | Что на самом деле |
|---|---|
| «Сведу все оси в одну сетку — так найдём совместный оптимум» | Тысячи точек на ~7 сделках в год — максимум шума. Для этого и нужны шаги. |
| «На шаге выиграла точка с PF 3 на 8 сделках» | Без 20 сделок точка не участвует в выборе шага. В литерал (§5) идёт лучшая комбинация с ≥ 10 сделками — 8 мало и для него. |
| «В литерал — точка спуска, она прошла порог 20» | В литерал — лучшая комбинация всей калибровки (`steps.py best`), так решил владелец. |
| «Лучший центр выше на 3% — сдвину» | Порог 5% нужен, чтобы шум не тащил точку. Точка остаётся. |
| «Фильтр поднял PF, но срезал сделки ниже 20 — включу» | Ниже 20 сделок фильтр не участвует, остаётся выключенным. |
| «Вернусь к шагу 3 и переберу снова» | Повторный проход — только шаги 10–12. Третий заход на те же данные — подгонка. |
| «Пул OOS годен — значит, тикер годен» | Ещё и последние 12 фолдов должны быть в плюсе с PF ≥ 1.1: старый прибыльный год не перекрывает убыточный или нулевой свежий. |
| «Walk-forward НЕ ГОДЕН — расширю сетку WF / сменю оси» | Вердикт окончательный. Литерал = точка, решение — «не годен». |
| «Фолды выбрали разные параметры — точка нестабильна, тикер плохой» | Рынок меняется, фолды обязаны гулять. Судит только пул OOS. |
| «Прибью оси WF к точке, чтобы фолды выбрали одно и то же» | Тогда WF проверяет одну точку, а не перекалибровку, по которой тикер будет торговаться. |
| «У соседнего тикера сработало — возьму его параметры» | У каждого тикера свой литерал из своей калибровки. |
| «Перекалибровка — подкручу старую точку» | Перекалибровка — с нуля, старая калибровка уходит в `cal_<дата>/`. |
| «Начну с литерала владельца вместо открытого старта» | Старт открытый: литерал владельца — база §2 для сравнения. |
| «Добавлю ось / значение — так будет лучше» | Оси меняет только владелец. |
| «Без EMA PF выше — поставлю `TrendEMA` 0» | Запрещено. Фильтр тренда в литерале всегда включён, шаг trend выбирает период. |
| «Без выхода RSI PF выше — поставлю `RSIExit` 0» | Запрещено. Цель — много мелких плюсов и мелкие минусы, выход по RSI обязателен при любом PF. |
| «Один режим прошёл — второй можно не гонять» | Оба режима всегда, литерал — по лучшему вердикту. |
| «Переключу режим в готовом литерале (`StochK` 0 / `StochK` 14)» | Фильтры и стоп подбирались под входы другого режима. Каждый режим — своя калибровка с открытого старта. |
| «Запущу четыре бэктеста параллельно» | Максимум три очереди (ядра 0, 1, 2), в каждой — строго последовательно. |
| «Литерал поправил — проверю старым бинарём» | Сначала пересобери бинарь. |
